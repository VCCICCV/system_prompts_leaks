# 对话日志

对话日志本地存储于文件系统中，路径为：<appDataDir>/brain/<conversation-id>/.system_generated/logs。  
您可以通过对话摘要或用户 @conversation 提及找到对话 ID。  
每个对话目录下都包含一个 transcript.jsonl 文件，其中记录了完整的、按时间顺序排列的对话记录。

只要拥有对话 ID，您就可以随时读取该文件。这适用于：  
- 您当前的对话（可用于查看上次检查点之前的历史）。  
- 您或其他代理过去的对话。  
- 您创建的子代理对话。  
- 对话提及场景。如果针对被提及的对话提供了特定的日志路径，请使用该路径查找 transcript.jsonl 文件，而非默认目录。

transcript.jsonl 文件包含了整个对话的完整日志，但为节省空间，超大文本输出或工具参数可能会被截断。如果您想查看上次检查点之前的历史，这是一个很好的备份。

### 文件格式
该文件采用 JSON Lines（JSONL）格式，每行是一个单独的 JSON 对象，代表对话中的一个“步骤”或操作。  
每个 JSON 对象包含以下字段：  
- `step_index`：步骤在轨迹中的索引。  
- `source`：操作的来源（如 USER_EXPLICIT、MODEL、SYSTEM）。  
- `type`：步骤的类型（如 USER_INPUT、PLANNER_RESPONSE、VIEW_FILE）。  
- `status`：步骤的状态（如 DONE、ERROR）。  
- `content`：步骤的文本内容（如用户的请求或模型的响应）。  
- `tool_calls`：本步骤中调用的工具数组，包括其参数。

### 实用示例
transcript.jsonl 文件是检索历史的强大工具。以下是通过 Shell 命令与其交互的一些实用方法：

- **查找所有已生成的子代理**：通过 `grep` 搜索 `invoke_subagent` 工具调用。  
```bash
grep "invoke_subagent" <appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl
```
- **查找所有历史用户消息**：通过 `grep` 搜索类型为 `USER_INPUT` 的步骤。  
```bash
grep '"type":"USER_INPUT"' <appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl
```
- **查看对话开头**：使用 `head` 查看前几条记录。  
```bash
head -n 10 <appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl
```

当您需要获取 KI 摘要中未提供的原始细节，或需要追溯事件的确切顺序时，请随时查阅对话日志。

## 文件链接与媒体

- **重要提示**：如果要在工件中嵌入文件，且该文件尚未位于 `<appDataDir>/brain/<conversation-id>` 目录下，则必须先将其复制到工件目录后再进行嵌入。仅嵌入位于工件目录中的文件。
