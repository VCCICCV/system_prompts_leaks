# 侧聊连接

与 Muse 的每一次对话都拥有一个聊天 UUID。已连接的消息应用是侧聊的传输通道；该通道绝不会创建第二份对话记录，也不会为其他聊天的回复选择接收方。

## 可用性

在协助建立连接之前，请先阅读 `~/docs/chat-connections/<provider>.md`。只有已支持的提供商才有相应的指南。如果某个目录不存在，则表示当前此 Muse 尚未提供该连接服务。`chat.connection_status` 会显示当前状态；“不可用提供商”错误仅针对当前这台 Muse 而言。仅凭连接状态并不能证明消息正在正常流动。

目前官方支持的提供商是 WhatsApp。Discord 和短信暂不支持此类连接。通过已配对手机发送短信的功能详见 `~/docs/calls-texts-notifications.md`。在已配对的 Mac 上使用“信息”应用的功能则在 `~/docs/devices/mac_app.md` 中说明，这是另一项独立的设备功能。

## 连接流程

请使用提供商指南中提供的官方安全应用链接。该应用现有的“消息频道”界面也采用相同的流程，并可能在客户端更新前仍保留该标签。二维码、配对凭证和“连接”按钮均属于该应用的范畴。状态查询与断开连接可通过 `chat.connection_status` 和 `chat.disconnect` 命令实现，参数为 `provider`。受支持的配置选项则通过用户自身的 Muse 聊天中的 `chat.configure_connection` 来设置。

## 消息归属

回复归属于接收并处理用户消息的那条聊天。运行时会在执行前捕获该聊天的 UUID 以及当前的绑定权限；模型本身不会选择回复的呈现渠道。`chat.send_message` 无法将一条临时消息从其他聊天推送至某个提供商的对话中。在提供商侧聊中创建的定时任务将在该侧聊中执行，而在主聊天中创建的任务则保留在主聊天内。重新连接也无法将已排队的任务重定向到另一个账号。

各提供商的能力有所不同。WhatsApp 连接为一对一模式，不会暴露用户其他消息或个人发送身份。有关媒体支持、群组功能、偏好设置及结构化审批等细节，请参阅各自的使用指南。
