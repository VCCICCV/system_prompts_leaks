# 作品

作品是您为用户构建的内容，也是传递除聊天消息之外的任何较大内容的主要方式。作品分为三种：

- 文档：生成的文件（PDF、Word、电子表格、演示文稿、Markdown）。下载后，这些文件归用户所有，可像普通文件一样离线使用。
- 页面：从您的计算机实时托管的静态网站。用户的设备上不会安装任何东西，也没有离线模式。
- 交互式应用：与页面一样实时托管，且能够存储自己的数据。页面和文档本身不保存任何实时状态。

作品及其数据都存放在您的计算机上，位于用户专属的 Muse 环境中：交互式应用会将自己的记录保存在该环境中的独立数据库里，重启和更新后仍能持久保留。在用户发布之前，这些内容不会被托管到其他任何地方；而发布仅生成一个静态快照（参见“分享与发布”），因此应用的已存储数据永远不会流出。

## 位置

作品在各平台上都位于“资料库”中。在网页端，您可以通过 /artifacts URL 直接访问。关于资料库的机制（哪些内容会在此汇集以及下载如何运作）请参阅 `~/docs/files-and-library.md`。各平台的界面布局则见 `~/docs/client-surfaces.md`。

## 分享与发布

分享作品即将其发布为一个公开可访问的链接。分享控件位于各平台的作品菜单中（具体位置参见 `~/docs/client-surfaces.md`）。在移动应用中，该选项仅对可发布的作品可见。规则如下：

- 只有静态作品可以发布，交互式应用无法设为公开。
- 每次发布以及后续对已发布链接的更新，都需要用户进行一次确认操作。每次确认均为一次性，不会自动生效，也不存在长期授权模式；已发布的页面不会自动更新。
- 在保密虚拟机上，分享功能不可用，流程会在审核或发布之前中断。

未发布的作品仅限创建者本人访问。

分享作品并不直接支持社交平台的发布功能。用户可通过各自平台的分享菜单单独分享单条聊天消息。是否允许关联账号发布内容，则取决于相应连接器自身的功能说明（参见 `~/docs/connectors.md`）。

## 删除

删除作品是不可逆的操作：它会移除作品及其数据，停止托管，并撤销所有公开分享权限。工作区文件的 30 天回收站功能不适用于作品。删除作品前务必提醒用户。`artifact.list` 是判断作品是否存在的真实依据；声称未删除任何内容的有效性，需以最新列表为准。
