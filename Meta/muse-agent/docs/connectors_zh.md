# 连接器及其功能

连接器仅提供其技能文档中列出的命令，不多也不少。

## 核心规则

只有在连接器的技能文档中明确记载的命令才是可用的。连接 Facebook 并不会自动启用发布动态的功能；因为“发布动态”这一命令并未包含在 facebook-cli 中。连接 Spotify 也不会提供收听记录或热门艺人统计信息；这些命令同样不在 spotify-api 的文档里。Messenger 配套仅适用于 Messenger，无法操作用户自己的 WhatsApp 账号。如果某个命令未在文档中提及，则该命令并不存在。对于未 documented 的命令，正确的回答是：“此功能无法通过该连接器实现。”跨平台同步发布仅在各连接器的技能文档中分别明确支持的情况下才存在。

电子邮件可通过 Gmail 和 Outlook 连接器进行连接。即使不使用连接器，只要用户自行配置，仍可读取其他邮箱。邮箱协议默认处于关闭状态。您可以在 Web 应用的“设置 > 权限 > 直接网络协议”中找到该选项。当用户启用邮箱协议后，您可以直接访问其邮件服务器。每次连接都需先获得用户的授权。服务器地址和登录凭据必须由用户提供，通常为应用专用密码。请按照 ~/docs/privacy-and-credentials.md 中的临时规则处理这些敏感信息，仅用于当前任务，切勿重复使用或保存。如果邮箱连接被拒绝，错误提示会告知您需要调整哪项设置，请直接询问用户，不要反复尝试。

在安装了 Mac 应用的 Mac 设备上，您还可以直接使用 macOS 自带的“邮件”、“信息”（iMessage）、“备忘录”、“日历”、“提醒事项”和“通讯录”等应用，并且在该 Mac 上安装了 WhatsApp 的情况下，无需连接任何账号即可搜索 WhatsApp 桌面版的消息记录。这些属于 Mac 设备的原生功能，而非连接器：它们没有技能文件，也没有连接状态查询命令。关于这些功能的工作原理、用户如何授予权限，以及如何在 Mac 应用与已连接账号之间进行选择，请参阅 ~/docs/devices/mac_app.md。

## 连接状态：本回合验证

连接状态应通过状态检查获取（如 `facebook-cli me`、`instagram-cli accounts`、`spotify-api status`、`opentable status`），绝不能依赖对过往对话的记忆。即使是在本次对话中稍早进行的状态检查，仍然有效。

如果后续命令因身份验证或连接错误而失败，请立即重新检查。对于新创建的账号，可能尚未完成任何连接，此时状态检查仍是判断依据。若命令因作用域或权限问题失败，重新连接也无法解决。

Meta Catalog 不需要登录或状态检查。它始终处于连接状态，并在商品搜索中提供目录结果，也无需断开连接。搜索权限的默认设置为“允许”。在保密虚拟机上，用户可在 Web 应用的“设置 > 连接器 > Meta Catalog”中更改此设置。在其他虚拟机上则无相关设置，目录搜索会直接运行。如果用户将权限设为“询问”，则任务中的首次目录搜索会向其请求授权，该次批准将覆盖同一任务内的所有目录搜索。若设为“拒绝”，则目录搜索不可用，但浏览器商品搜索和 Facebook Marketplace 搜索仍可正常工作。请展示这些功能的返回结果，切勿将其视为目录功能失效。在保密虚拟机上，用户可通过将“搜索”权限设为“拒绝”来关闭目录搜索功能。

此处的 Shopify 指的是用户自己从连接器目录中连接的 Shopify 商店，这与在聊天中向 Shopify 商家购物的行为不同，后者属于购买行为（详见 ~/docs/payments-and-purchases.md）。Shopify 连接器在保密虚拟机上不可用。出现确切的 `reauthorization_required` 失败，意味着提供商已永久拒绝了已保存的 OAuth 授权。请勿重试该命令，也切勿将其描述为临时性故障。应告知用户，指定的连接器需要重新获得权限。如果失败信息中包含 `action_url`，请将该 URL 单独放在一行，并以“连接”链接的形式显示。对于“添加账户”链接，应提示用户选择同一受影响的账户。若未提供操作 URL，则只需说明需要重新连接，而无需自行生成链接。用户重新连接后，请引导其重试原始请求；切勿自动重放写入操作。

## 区域可用性

部分连接器并非在所有区域均提供服务。对于受限账户，该连接器不会在设置中显示任何行或条目，也不会出现在客户端技能列表中；其所有命令都会返回“此连接器不适用于该账户或该区域”的提示。这种拒绝是设计使然，并非故障或错误。请如实转达此信息，且无需重试。切勿透露哪些区域或国家已支持或尚未支持，也勿承诺该连接器未来会开放。可提供当前仍可用的替代方案：例如，在浏览器中直接访问提供商网站完成相同任务，或基于通用知识给出解答。某些受限连接器仍允许断开现有连接，但除此之外无法执行任何操作。

## 操作权限

用户可在 Muse 设置中限制各受支持的读取和写入操作。例如，Gmail 和 Outlook 邮箱可以允许读取，但禁止发送及其他写入操作。这些操作权限与提供商的 OAuth 范围是独立的。请查阅连接器的技能文档以了解其支持的操作，并在存在时参考其配套的 `manifest.yaml` 文件，以获取权限默认值及范围要求。有关设置导航，请参阅 `~/docs/client-surfaces.md`。

方法的 `default` 设置会覆盖其所属操作组的默认值；仅当方法未单独设置时，才使用组的默认值。汇总默认值前，请先解析这些设置。`Ask` 表示需要批准；`Deny` 则会阻止该操作。对于只读访问，应拒绝所有写入操作，包括任何单独的邀请或通知类操作。默认设置并不反映用户的当前配置或已授予的 OAuth 范围。

## 附加 OAuth 访问权限

部分连接器在当前账户授权不足以执行某项已记录的命令时，可能会请求额外的 OAuth 访问权限。请根据连接器技能中的能力状态及附加访问流程，判断是否需要更多权限。若无附加访问流程，则应告知用户无法获取额外权限。此外，用户也可在连接器的权限页面上手动授予缺失的权限。

附加访问选项并不意味着初始连接仅为只读。清单文件中列出的范围要求仅说明可接受的范围，并不等同于初始请求或当前授权。在声称需要特定范围之前，请务必核实所有可接受的范围。若无法确认初始或已授的范围，请明确告知用户。

## 技能文件为权威依据

每个连接器的技能文档（如 facebook-cli、instagram-cli、spotify-api、opentable 等）均准确列出了该连接器能够读取和写入的内容。“连接器 Y 是否能执行 X 操作”的答案，应直接从该技能文件中获取；无论服务是否已连接，该文件均可查阅。若技能文件中未列出某项功能的命令，则表明该功能在该连接器上并不存在：既不会在未来推出，也无法通过重新连接来启用。

## 提供商限制

服务会强制执行各自的速率限制，因此当提供商进行限流时，请控制请求频率并适当退避。大多数连接器也有自己的请求上限，一旦超过该上限，超出部分的调用将失败，并返回 `connector_rate_limited` 错误以及 `retry_after_seconds` 值。Google 日历、联系人、文档、表单、表格、幻灯片和任务的上限最为严格，因此请尽可能利用连接器支持的批量操作，而不是逐个发起单次调用。遇到速率限制错误意味着该服务暂时繁忙，而非连接器本身出现故障或断开连接。如果 `connector_rate_limited` 结果中包含 `terminal_for_attempt: true`，则本次尝试的连接器工作将终止。此时应上报已处理的部分进度，但不应休眠、重试、委托处理或安排替代任务；父级代理或后续的定时运行可在 `retry_after_seconds` 指定的冷却期结束后继续执行。

## 自定义连接流程

当某项服务没有现成的技能（例如智能音箱、任意应用的 MCP 服务器，或本身不提供内置连接器的服务）时，系统不会提供设置面板、服务器 URL 字段、传输方式或认证头等配置选项。您也无法引导用户完成自定义的认证流程。唯一可行的途径是使用自定义连接器流程：通过 `credentials.request_api_access` 先向提供商确认，并生成一个托管的连接链接，用户可在该链接上输入 API 密钥或通过提供商自身的 OAuth 进行登录。对于采用密码登录、会话 Cookie、请求签名或需要多个密钥的提供商，应明确予以拒绝，并如实告知原因。不过，用户仍可通过普通浏览器访问该服务的公开站点以获取帮助。

连接器并非渠道。在 WhatsApp 上与 Muse 的对话属于渠道会话，而非连接器；关于哪些渠道存在及其路由方式的管理由 chat-connections.md 负责。

## 邮件与验证码

您可以读取已连接的邮箱。当活跃用户发起的登录或结账操作确认当前站点已向其连接的邮箱发送了验证码时，请结合报告的站点、步骤及脱敏后的收件人信息，以常规技能的读取权限并借助验证码保护机制来执行精准查询。切勿要求用户单独发起查询或手动粘贴验证码。Gmail 的常规消息读取功能会自动应用此保护机制；仅列出邮件主题不足以获取相关消息内容。被接受的验证码会被替换为 `[credential:<uuid>]`，并在身份验证期间暂存该值。该引用仅可用于浏览器的一次性授权后的 `credential_fill` 操作，而不得用于直接暴露验证码。切勿提取工具输出的原始验证码或绕过授权流程。完整规则详见 privacy-and-credentials.md。
