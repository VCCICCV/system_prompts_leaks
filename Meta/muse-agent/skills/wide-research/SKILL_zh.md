# 广度研究

## 目的
协调一个管理子代理，将同一项研究任务分发到多个独立的输入上，并返回一个统一的标准化结果集。

## 使用场景
- 任务可以拆分为多个相互独立的子任务（例如，每个输入对应一家公司/一个人/一个主题）。
- 每个子任务应返回相同的结构化字段。
- 用户提出“广度研究”、“并行研究”或高量级查找/筛选的需求。

请勿将此工作流用于单个事项的任务，或当子任务之间存在依赖关系时。

## 工具配置
在整个操作中仅使用一个管理子代理。

管理子代理的输入规范：
- `operation_brief`：一句简明扼要的说明。
- `inputs`：每个元素对应一个独立的输入项。
- `output_schema`：必填字段及其允许的数据类型。
- `worker_prompt_template`：针对每个输入的执行指令模板。
- `completion_format`：管理子代理最终响应的精确 JSON 对象结构。

管理子代理的输出规范：
- `total`：总输入数。
- `success_count`：成功处理的输入数。
- `failure_count`：失败的输入数。
- `results`：成功处理的输入对应的完整结果列表。
- `failures`：失败的输入及其原因。
- `notes`：附加说明。

## 操作规则
1. 在启动管理子代理之前，对输入列表进行去重和规范化处理。
2. 输出模式应尽量简洁、明确；除非用户特别要求，否则避免使用可选字段或自由格式字段。
3. 一个管理协调器仅负责实现一个用户目标；不要同时启动多个同级根节点子代理。
4. 指导管理子代理为每个输入分配一名工作者，并确保每位工作者仅处理其对应的单一输入项。
5. 如果完整性至关重要且部分输入失败，在可行的情况下，仅对失败的输入进行一次重试。
6. 立即向用户反馈广度研究已启动，无需等待全部完成后再回复。
7. 在最终面向用户的输出中，始终报告覆盖率（`success_count/total`）及未解决的缺口。
