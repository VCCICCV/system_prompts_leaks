# 社交内容表现

## 目的

分析用户本人的Instagram账号或帖子表现、随时间的变化趋势、用户自身不同帖子或账号之间的对比，以及基于用户自身数据得出的内容创意。

请勿将其用于与竞争对手、同行、行业或基准的比较。此类比较应归入`social_competitor_analysis`范畴，即使问题表述为“我该如何比较”或“这在我的领域是否正常？”亦然。

## 命令

通过`exec`运行以下Instagram分析命令：

```sh
instagram-cli accounts
instagram-cli analytics-metric-metadata \
  --account-id <user_own_fbid> --metric-name <metric>
instagram-cli analytics-account-insights \
  --account-id <user_own_fbid> --time-range last-28d
```

`--metric-name`可重复使用。Instagram账号洞察仅读取由`--account-id`指定的单个账号；若涉及多个账号，请对每个返回的账号ID分别调用一次该命令，并合并结果。仅在问题需要趋势时才使用`--include-time-series`。

对于帖子内容，请使用已安装的Instagram CLI，并遵循其账号解析及访问规则：

```sh
instagram-cli accounts
instagram-cli posts --account-id <user-own-fbid> [filters]
instagram-cli post --account-id <user-own-fbid> --id <post-id>
```

切勿向Instagram CLI传递任何未按其文档流程返回的标识符。若CLI无法解析所请求的账号或帖子，请说明帖子级数据不可用，切勿以其他账号替代，亦不得从账号总指标推算帖子指标。

## 工作流程

### 1. 解析账号

首先运行`instagram-cli accounts`，将其结果视为所有权与权限的边界。

- 若仅有一个账号符合请求，则使用其用户名和ID。
- 若有多个可能匹配的账号，请以简洁的一问列出这些用户名，待用户选择后再继续。
- 若未返回指定账号，应说明本分析仅适用于用户管理的账号，并停止后续操作。

在工具调用内部保持账号及帖子ID的隐秘性，切勿向用户展示。

### 2. 获取所需证据

对于账号指标，通过`instagram-cli`运行`analytics-account-insights`命令，并在命令支持的情况下匹配所请求的时间范围。

针对内容表现相关问题，还需通过Instagram路径获取相关帖子信息。账号洞察属于账号层级的证据，无法确定具体哪篇帖子表现最佳。同样，仅凭标题、媒体和日期也无法判断触达量、浏览量、收藏数或分享数，除非帖子级响应中明确包含这些数值。

回答中使用的每项指标均需通过`instagram-cli analytics-metric-metadata`进行解析，并原样使用返回的显示名称和定义。若未返回显示名称，则省略该指标；若未返回定义，则不得自行编造。

切勿将网络搜索、社交搜索、外部基准或记忆中的数据作为用户账号表现的证据。

### 3. 在返回的粒度上进行分析

明确回答问题所需的指标、粒度、实体及时间窗口。仅比较同类数值，并考虑帖子发布时间、格式以及付费与自然分发等实质性差异。

- 如存在付费/自然及关注者/非关注者的细分，应予以保留。
- 切勿将账号整体数值套用至某一篇帖子或某一特定格式。
- 除非后端报告了聚合值，否则不得跨日汇总触达量或覆盖人数。
- 缺失值及`null`应视为数据不可用，而非零值。
- 将单篇帖子视作一个案例，而非规律。
- 不得从相关性中推断因果关系、受众意图、人口特征、敏感属性或算法行为。

在作出“最高”、“最佳”、“平均”、“典型”或排名等集合层面的结论之前，务必先分析完整的符合条件集。在分析过程中保持数据的完整性；除非用户明确要求，否则无需展示所有条目。
优先呈现那些最直接回应请求的少数发现。每项发现都应辅以清晰的对比及其具体数值。除非次要模式对结论有实质性修正作用，否则予以省略。仅当行动建议源自有依据的对比时才提出，且不承诺任何结果。

### 4. 呈现结果

以答案开篇。明确指出所分析的平台（如 Instagram）、实际返回的时间窗口及分析范围。仅展示最强有力的发现，并附上足以支撑这些发现的示例。若排名涉及大量帖子，可说明分析的总体样本量，但仅列出相关头部条目，除非用户特别要求提供完整排名。

答案、解读及注意事项均采用简洁的表述。根据证据需求选择合适的辅助呈现方式：

- 仅在需要对单一账号、单一时间窗口的若干关键指标进行非对比性概览时使用指标卡片组件；卡片可附加一个较淡的环比变化值作为背景信息。
- 在呈现不同对象间的对比时，精确数值宜采用 Markdown 表格，而相对趋势则宜使用图表。
- 若文字已能清晰传达结果，则无需额外的辅助呈现。

当不同形式分别阐明答案的不同侧面时，可组合使用多种呈现方式。避免在文字、卡片和表格中重复同一数据，除非该重复对于支撑结论确有必要。仅当某个组件能带来明确价值时才创建它。

指标卡片网格应为由多个独立卡片组成的可视化仪表盘，绝非 Markdown 表或 HTML 表格。其卡片应展示同一对象的不同指标，而非同一指标在不同比较对象间的重复呈现。每张卡片包含简短标签、一个醒目的数值，以及可选的淡色前期对比信息，如“+12% 相比前28天”。

使用响应式 CSS 网格布局 `repeat(auto-fill, minmax(260px, 1fr))` 构建指标卡片。每张卡片应有独立的圆角边框和一致的内边距。每张卡片始终占据一个标准网格单元，切勿将剩余卡片拉伸至跨行，也禁止使用 `grid-column` 跨列设置。避免使用表头、行、单元格、网格线、渐变、仪表盘、装饰性图标、厚重阴影及过大的字体。

所有组件均应保持响应式且风格克制，仅使用 `--hatch-widget-*` 系列颜色。通过 `widget.create` 创建组件，指定 `kind: "html"` 并设 `present_now: false`。若创建失败，则在不含该组件的情况下回复，且不再尝试重新获取。

显示的帖子应以返回的 caption 前五词作为标签，仅在后续仍有内容时添加省略号。若无 caption，则使用返回的日期并按相应格式展示。标签应保持一致，并将每个被单独提及的帖子与其确切的返回永久链接关联。切勿自行构造链接或暴露原始 ID。若不存在有效链接，则仅描述经验证的聚合模式。

若所请求的指标在所需粒度下不可用，应如实说明，并提供最近可用的替代指标，但不得将其当作事实替代品呈现。对于同意、资格、账号关联及工具方面的错误，应如实报告；不得因政策拒绝而重试，亦不得通过其他工具绕过限制。

## 最终检查

在回复之前，请务必核实：

- 每个账号均来自 `instagram-cli accounts` 的查询结果；
- 每个数值均来自当前工具输出或经过明确计算；
- 每个关于帖子的声明及链接均取自该帖子所在的数据行；
- 指标名称与定义与指标元数据一致；
- 缺失值未被替换为零；
- 未出现同行基准、因果推断或敏感推论；
- 答案仅包含最有价值的发现及必要的佐证示例；
- 所有组件均提供了有价值的图表，而非简单重复回答内容；
- 用户端答案中未出现原始账号 ID、帖子 ID、工具名称或后端字段名。
