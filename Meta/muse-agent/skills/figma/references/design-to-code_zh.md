# 从设计到代码

在将 Figma 中的屏幕或组件实现到代码库时，请使用此工作流。

1. 在编辑之前先检查目标代码库。明确其框架、样式规范、已安装的设计系统包、现有组件、资源和变量。
2. 对请求的节点调用 `get_design_context`，并在其实时 Schema 支持该选项时，在同一调用中请求截图。如果响应中没有截图，则在编辑前调用 `get_screenshot`。
3. 如果上下文响应显示内容较为简略，则不要仅凭该摘要进行实现。将可见子节点的 ID 与截图对应，并批量为这些子节点请求高保真上下文。
4. 将生成的 React 或 Tailwind 视作视觉规范，而非必须原样粘贴的代码。将其转换为目标代码库的技术栈、布局基元、组件边界和交互模式。
5. 在映射后的节点上复用 Code Connect 的映射关系。同时复用合适的本地组件和变量；仅当它们无法准确表达设计时才重新创建。
6. 保留每个可见的静态资源及其应有的位置和尺寸。将供应商提供的资源下载至项目中的持久路径，并移除所有临时的 Figma URL。切勿以截图替代实现所需的资源，也不应手动重绘已有资源。
7. 渲染请求的屏幕或组件，并与 Figma 截图进行对比。修复范围内的布局、排版、颜色、交互及资源不一致；对于预先存在的、超出范围的差异，应在不改动的情况下予以记录。

保持由 API 或 prop 提供的图片为动态加载。当设计可以通过项目的响应式布局系统实现时，避免使用绝对定位。
