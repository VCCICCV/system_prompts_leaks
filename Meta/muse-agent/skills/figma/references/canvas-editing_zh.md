# 画布编辑

使用 `use_figma` 进行原生画布的检查与变更。该脚本在 Figma 内部执行；脚本显式返回的值即为可用的输出。

## 编辑前准备

- 先用只读脚本检查文件，了解其编辑器类型、页面、组件、变量、字体、命名及布局规范。
- 根据 URL 推断编辑器类型：`/design/`、`/board/` 或 `/slides/`。Design、FigJam 和 Slides 的 API 及支持的节点类型各不相同。
- 尽量复用现有组件、样式和变量，避免创建重复的替代品。
- 在确保可理解且易于回滚的前提下，尽量将相关操作批量处理。避免发出大量细碎的变更调用后又拍摄冗余截图。

## 变更规则

- 使用 `return` 返回一个包含所有新建或变更节点 ID 的结构化结果。仅在控制台打印日志不能替代返回变更证据。
- 等待每个异步 API 调用完成。在修改文本之前先加载现有字体数据，切勿猜测字体样式名称。
- 异步切换到目标页面，且每次调用最多切换一次。将跨多个页面的独立工作拆分为并行调用。
- 对于具有结构关联的子元素，使用自动布局。在设置填充或自适应尺寸之前，先将子元素添加到其自动布局父容器中，并在最终确定尺寸模式之前调整大小。
- Figma 中的颜色通道值范围为 0 到 1。应将透明度设置在填充上，而非嵌套在颜色对象内部。修改并重新赋值只读的填充和描边数组时，需先进行克隆。
- 新建页面级内容时，应放置在空白区域，而非采用默认原点。

## 回滚与验证

将超时或错误视为写入不确定的情况。如果结果提示在未读取画布的情况下重试不安全，则应在再次尝试变更之前先检查并核对已创建的 ID。切勿盲目地重复执行整个写入操作。

要求每次变更都提供结构性证据：受影响的 ID，以及有用的计数、名称或边界信息。在完成有意义的布局后拍摄一张截图，并仅在验证视觉修复时再拍摄一次。一旦结构和视觉检查均通过，即停止操作；重复拍摄不变的截图会浪费用户的配额。
