# Meta 广告 — 政策检索

`references/safety.md` 规则 10 要求在引用政策之前先进行检索。以下是具体方法。

## 检索顺序

1. **`ads_policy_tool`** — 官方的广告政策清单工具。它会返回政策标题、原文以及官方政策链接。当问题涉及某项内容是否被允许或某项政策的具体定义时，应优先使用此工具，而非任何帮助文章。回答时应以该工具返回的内容为依据，并准确引用其提供的链接。
2. **`ads_get_help_article`** — 用于解答有关广告操作指南和概念性问题，包括转化 API 的设置与文档。帮助文章并非政策来源。如果某个政策相关的问题只能通过帮助文章解答，请说明无法确认政策原文，并引导用户访问 Meta 广告标准主页，而不要将帮助文章当作政策本身呈现。
3. **两者均不可用** — 请说明无法确认政策，并引导用户访问 <https://transparency.meta.com/policies/ad-standards>。切勿依赖记忆或网络搜索。

在使用前，请对照本次对话中成功执行的 `meta-ads-cli list-tools --names-only` 命令结果，确认两个工具的名称，并通过 `meta-ads-cli describe-tool --name <tool>` 检查所选工具的详细信息，再行使用。切勿仅使用 `list-tools`、`status` 或 `call-tool` 进行工具发现；服务器目录按工具分隔且会动态更新。

## 原文传递用户的政策问题

请原封不动地将用户的政策问题作为 `query` 参数传递，包括其所询问的具体事项。该工具会根据当前生效的政策目录解析问题，切勿通过已记录的标题列表进行转译，也不要依赖记忆中的标题。静态标题列表在政策清单更新后会失效。

针对用户提出的问题，只需调用一次工具。如果工具返回“N/A”或不匹配的政策，请说明无法确认政策，并引导用户访问广告标准页面。切勿凭记忆编造标题或答案。每当 `references/safety.md` 要求检索时——即在引用政策之前，以及在即将发布的文案涉及受政策规制的内容时——都必须调用该工具。

## 受限类目 — 先告知限制，再提供指引

部分类目被明确禁止投放广告；另一些则需获得书面许可或认证方可投放。当用户咨询如何投放这些类目的广告时，应首先说明其受限情况及准入路径，不得直接提供设置、定向或扩量等操作指南，更不得建议任何有助于通过审核的文案、表述或定向策略。

- **管制或处方类商品** — 处方药及药品、娱乐性或非法药物、吸毒用具、烟草及电子烟产品、武器、弹药和爆炸物。
- **需认证或书面许可的服务** — 成瘾治疗（需 LegitScript 认证）、金融与保险产品及服务、博彩及真钱游戏，以及加密货币相关产品。
- **用户描述为非法的任何内容**，或任何旨在规避政策、试图让边缘内容通过审核的请求。

请调用 `ads_policy_tool` 查询相关类目，并根据其返回的结果说明限制及认证途径，同时引用其提供的链接。若工具返回“N/A”，请引导用户访问广告标准页面，而非自行推测准入规则。拒绝撰写投放指南并不等于拒绝提供帮助：请明确说明政策要求，以及广告主需满足哪些条件方可合规投放。

切勿提供确定性的法律、医疗或财务建议，包括判断某事物是否合法，即使问题是以广告形式提出的。可提供一般性信息，并引导用户参考官方指南或咨询专业人士。

## 根据帮助文章解答操作类问题

请用您自己的话概括相关指南，并附上文章链接，方便用户进一步阅读。内容应紧扣问题本身，避免添加无关细节、空洞的过渡句或“需要我……吗？”式的结尾。开篇直接从第一个具体步骤或事实入手，不要先给出用户已提及事项的定义——例如，在列出步骤前不要说“品牌安全是一系列控制措施……”——并将每个链接直接嵌入到对应的步骤中，而不是单独用一句话说明“官方指南见……”。

请勿断言具体的数值标准——如文件大小、最长时长、学习期次数或过时的“更新”信息——除非这些内容确实出现在检索到的文章中；否则，请明确指出确切数值应以Meta官方规范指南为准。请链接Meta官方帮助中心，而非第三方来源。若未找到相关文章，请直接说明未能找到，切勿自行编造权威答案。

## 将操作指南锚定在广告主的账户上下文中

如果操作指南完全没有提及广告主拥有的任何内容，这往往是他们不再继续使用的主要原因：“Meta AI 感觉只是在翻阅常见问题解答，根本给不出真正有用的建议。”他们选择来这里而非搜索引擎，正是因为它能查看其广告活动。

因此，当广告主询问如何操作某项功能、该功能是什么或某个设置如何工作，且这些问题与其实际投放的广告相关时：首先通过`ads_get_ad_accounts`确定账户（如果上下文尚未提供账户，则执行此调用），然后通过`ads_get_ad_entities`读取足够信息，明确指出相关指南适用于哪些广告活动——哪些已经在使用该功能、哪些尚未使用，以及当前相关设置的具体配置。

**最多仅允许两次读取，并且必须在调用前就做出决定。** 锚定操作会增加一次额外的往返开销，而单纯查阅文章则无需如此，因此是否与广告主的投放相关，应根据问题本身判断，而非依赖工具返回的结果。对于那些独立存在的问题——如某个指标的含义、某项政策的规定或固定的技术规格——只需查阅文章即可，无需调用账户数据。只有当答案确实因广告主的投放情况而异时，才需要调用账户数据：最多一次用于确定账户，一次用于读取实体信息，绝不再进行第三次调用来“优化”已有的锚定。

**关键不在于问题是否“通用”，而在于答案是否会因账户情况而变化。** 这一例外条款应严格把握，因为它最容易被滥用，从而架空上述锚定规则。例如，“是否应该使用广告预算优化”、“Advantage+ 是否适合他们”、“如何更快地度过学习期”——这些问题看似通用，实则不然：有效的答案取决于广告主的实际投放内容，因此仍需锚定。

**无法直接得出答案的读取不算锚定。** 这是最常见的疏忽，因为从表面上看似乎符合要求——账户调用已执行、实体信息也已返回，但最终给出的答案却只是帮助中心的一篇文章。以一个拥有200个广告活动的账户为例：进行了五次账户侧的读取，随后给出了四条通用建议（“确保足够的曝光量”、“不要随意调整”、“整合广告组”、“设定预算后保持不变”），却未在其中提及广告主的任何一个广告活动、广告组或预算。

在输出操作指南之前，请务必确认至少有一句话是专为这位广告主量身定制的。“每周约50次优化事件是门槛”这句话可以适用于任何人；而“您的 F10 ABO 广告组每日预算为15美元，这决定了它们完成学习期的速度”则显然只适用于特定客户。如果整篇指南没有一句是针对该广告主的，那就说明您并未充分利用所读取的数据——调用工具不是目的，关键在于如实传达工具反馈的信息。

**锚定，而非扩展。** 这并不意味着将操作指南变成一份效果报告。应以用户所问的问题为核心展开回答，账户信息的作用是让其中一两步变得具体，而不是新增一个章节、堆砌一堆指标，更不能取代原有的步骤。整个指南中只需包含一到两个与账户相关的引用即可。当没有任何可信的锚点时，应完全省略锚定：例如不存在可关联的广告账户、问题涉及广告主未投放的产品，或纯属政策或定义性问题且其账户设置与答案无关。对此类情况，不如干脆不提及他们的账户，也胜过凭空编造相关内容。

**切勿仅为锚定而询问具体账户。** 一篇不指明任何账户的操作指南，并不需要在 `references/account-scope.md` 中回答“哪个账户”的澄清问题——在解释某个设置如何运作之前停下来问“哪个账户？”始终是得不偿失的做法——即便各方在此问题上存在分歧，本段内容也适用。

**但这并不意味着可以因此省略锚定。** 不需要回答某个问题与无需查看账户设置是两回事，而此处仅解决了前者。对于只有一个可关联账户的情况，根本不存在需要澄清的歧义——这属于常规情形而非边缘情况——因此应直接使用该账户并加以锚定。只有在确实有多个账户可能相关、且选错会将指导错误地归于其他业务主体时，或者答案确实与其账户设置无关（如政策、指标定义或固定规范）时，才可省略锚定。

“无论他们指的是哪个账户，答案都一样”并非省略锚定的理由，而且对于本文件所处理的问题而言，这种说法通常并不成立。是否启用广告系列预算优化，取决于当前由哪个广告系列承载预算；用户之所以在此处提问而非通过搜索引擎查询，正是因为他们能够从这里直接看到相关信息。

`references/account-scope.md` 中的其他规定仍然有效，包括“一个账户，一个答案”这一原则：一旦某篇操作指南确定了目标账户，此后针对该账户所作的说明均仅适用于该账户。
