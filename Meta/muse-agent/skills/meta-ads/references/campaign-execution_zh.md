# 活动审核与执行

仅在投放策略和创意获得批准后，或在部分创意修复过程中阅读本节。重新检查一致性；若素材出现偏差，需回溯至最早受影响的策划阶段。最终审核仅授权未更改的已暂停层级结构，且绝不允许发布。

## 确保可执行请求的准确性

在最终审核前，通过每项选定工具的一次 `describe-tool --input-only` 命令，获取 `ads_create_campaign`、`ads_create_ad_set`、`ads_create_creative` 和 `ads_create_ad` 的实时输入 Schema。除非因失败或能力更新导致过时，否则应复用当前创意阶段已获取的 Schema。当需上传新素材时，也应同时获取上传 Schema。仅使用对话中当前精简发现结果中存在的名称。

严格按照这些 Schema 构建每个预期的参数对象。在最终审核前，将 `campaign-delivery-compatibility.md` 中的预写门控规则应用于精确的层级结构和参数，包括实时字段描述中的每一个条件或互斥规则，而不仅限于各 Schema 的 `required` 列表。绝不可猜测任何字段、枚举值、条件要求、目标 URL、身份标识或素材引用，也绝不能借助写入或验证失败来推断接口契约。若某字段未出现在所选 Schema 中，则该计划不支持此字段。可选字段默认为缺失状态。已知的值并不意味着可以使用所有可能承载该值的可选字段；仅包含经审核设置所映射的字段，或 Schema 要求的依赖项。

切勿仅因某字段在其他 Ads 工具中常见就将其沿用至当前工具。现有对象的读取响应无法证明创建 Schema 中的字段为可选；若当前读取与实时创建契约存在冲突，应在该契约缺口处停止，而不应尝试写入或进一步探查。若所需值无法从广告主处或成功的读取操作中获得，则应在请求最终批准之前回溯至最早的待定决策点。

字段名和枚举值必须完全照抄自实时 Schema，切勿将人类标签翻译成猜测的提供方值。标识符并非 URL。除非实时 Schema 明确定义了这种转换，否则不得根据 ID 构造 URL 模式；此外，若广告组的 `destination_type` 为 `MESSENGER`、`WHATSAPP` 或 `INSTAGRAM_DIRECT`，则应按照 `campaign-creative.md` 提供的链接处理。

仅当该工具的 Schema 暴露 `advertiser_request` 时，才使用 `SKILL.md` 所要求的广告主当前完整的多轮表述；切勿添加由助手编写的重构内容。

所有活动决策与执行状态均应保留在对话上下文中。不得调用记忆工具，也不得将活动设置、ID、素材引用、尝试或失败记录持久化至 `MEMORY.md` 或其他持久化存储中。

活动、广告组和广告的创建工具会在服务器端强制设置为 `PAUSED` 状态；创意本身并无投放状态。应严格遵循每个实时 Schema，不在未暴露的字段上添加 `status` 字段。保留每项已审核数值与其将用于创建的精确参数之间的私有映射关系，其中包括：

- 账户、主页及可选的 Instagram 身份；
- 目标、优化目标、投放目的地、定向、版位，以及必需的特殊广告类别声明和投放国家/地区，包括住房、就业或金融产品与服务类活动中每个广告组的 `targeting_as_signal: 0`（原因参见 `references/writes.md` 中的“特殊广告类别”章节）；
- 层级结构、预算、货币及投放时间安排；
- 创意格式、来源、文案、行动号召及披露信息；以及
- 所有将来自成功结果的父级/引用依赖项。在每个预算或出价相关的写入操作中，如果其模式暴露了 `account_currency`，
请传递为所选账户返回的确切币种。切勿根据地理位置推断币种，也勿擅自转换金额。预算应仅在一个层级上进行设置：当活动本身承载预算时，省略广告组的预算字段；当广告组承载预算时，省略活动的预算字段。

`render-campaign-summary --summary-json` 仅接受以下字段：`campaign_name`、`goal`、`optimization`、`destination`、`structure`（包含 `ad_set_count` 和 `ad_count`）、`budget`、`schedule`、`audience_and_geography`、`audience_description` 以及 `placements`。Schedule 字段需明确指定“发布后开始”或计划开始时间，以及“无结束”或计划结束时间，其中计划边界仅指定具体时间。Placements 字段只能选择一种模式：“automatic”、“platform_restricted”（并列出平台）或“manual”（并列出版位）。其取值必须准确反映预期的创建参数，不得借助渲染器来添加或省略任何实质性设置。创意、类别及暂停状态已在其他环节审核过，因此不在摘要行中显示。

请使用此 JSON 格式，仅替换其中的值：

```json
{"campaign_name":"假日工作坊","goal":"品牌认知度","optimization":"展示次数","destination":"https://example.com/workshop","structure":{"ad_set_count":1,"ad_count":1},"budget":"活动层级，每日$10","schedule":{"start":"计划开始","start_time":"2026年12月1日","end":"计划结束","end_time":"2026年12月23日"},"audience_and_geography":"美国","audience_description":"广泛的优势人群","placements":{"mode":"automatic"}}
```

## 渲染最终审核
使用这些已确定的完整参数，调用一次 `meta-ads-cli render-campaign-summary`，然后将其生成的精简小部件 `kind` 和 `data` 原封不动地传递给 `widget.create`。  
通过 `muse.create_options` 创建以下确切选项：

- “是，创建暂停的活动”
- “否，修改”

在最终响应中，先放置审核令牌，再提出问题：“是否继续创建该活动？它将以暂停状态创建。成功后我会提供一个直接指向 Ads Manager 的链接。”随后放置选项令牌。不得重复显示摘要或提出第二个问题。只有明确的肯定选项，或以清晰方式表达的指令要求创建未经更改的已审核层级结构，方可视为最终确认；不得将对其他决定的同意视作最终批准。

## 审批后创建
在获得上述肯定答复后，仅按已审核的参数执行以下步骤：

1. 使用 `ads_creative_upload_media` 上传每项已批准的新素材，并仅保留其返回的账户所有素材引用。已有素材无需再次上传。在首次写入 Ads 对象之前，务必完成并验证所有必传素材的上传；素材准备是关键门槛，不应与活动创建并行处理。
2. 调用一次 `ads_create_campaign`，并保留其返回的活动 ID。
3. 使用该活动 ID，为每个已审核的广告组调用一次 `ads_create_ad_set`；同时，使用已批准的素材标识/素材，为每个已审核的创意调用一次 `ads_create_creative`。仅允许并行执行彼此独立的调用。
4. 在配对的广告组和创意 ID 都已存在的情况下，为每个已审核的广告调用一次 `ads_create_ad`。

当每个预期的广告系列、广告组和广告创建结果都返回其ID和状态为“PAUSED”（已暂停），且每个创意创建都返回其ID时，创建即告成功。这些成功的创建结果就是验证依据；在一次干净的创建之后，不要重新读取层级结构。切勿从已暂停的父级对象推断子级的安全状态：每个对象的结果必须显示“PAUSED”。如果结果为“DRAFT”（草稿），则表示处于暂存状态而非已创建，并会在“references/writes.md”中报告。若出现意外的“ACTIVE”（已启用）创建结果，则应立即停止：一旦有公开的更新机会，就将其暂停，然后进行对账并报告，而不再创建任何子级。当一个报告成功的结果缺少ID或状态时，应使用实时读取工具对该对象进行一次新的读取，并先获取其架构；此次读取属于对账，而非重试。若在该读取后仍发现对象缺失或状态非“PAUSED”，则会阻止成功卡片及发布选项。

请将每项Ads操作作为独立的`exec`调用执行。切勿仅因缺少输出而重试创建。若在审批后参数或关键决策发生变更，应立即停止，仅更新受影响的部分，必要时重新定价，并生成新的最终审核界面。

`render-campaign-success --success-json`仅接受`campaign_name`、`ad_set_count`、`ad_count`以及可选的`ads_manager_url`。在确认成功后，调用该接口，将其返回的列表组件原样传递给`widget.create`，随后展示一个`muse.create_options`菜单。首先放置“发布以使其按预算和时间表开始投放”的选项，并根据已发现的工具与前提条件，最多添加三项当前可执行的已暂停编辑。不得提供“保持暂停”的选项；若菜单未作修改，则默认保持暂停状态。在最终响应中，用一句简短且有据可依的陈述说明创建已完成，层级仍处于暂停状态且尚未开始投放，随后依次嵌入Ads Manager卡片与选项菜单。在选项之后结束，不得重复设置、层级数量、ID、链接或选项标签。使用诸如“广告系列层级”之类的集合性表述，而非拼接返回的名称与类型标签。类似“随时提问”、“告诉我”或“开口说”的散文式邀请语绝不能替代选项。

## 失败与恢复

发生失败时，应在决定是否可以再次写入之前，先对当前Ads状态进行对账。仅报告已被证实存在的对象及其经验证的状态，以及首个未完成的阶段。若本地或生成的素材存在，但没有任何广告系列、广告组、创意或广告被创建，则应表述为“未创建任何Ads对象”，而非“什么都没创建”。

描述返回的失败时，不得擅自归因于未证实的服务提供商、宕机或基础设施问题。应说明对账发生的时间，而非声称每次尝试都经过了验证。即使没有创建任何投放对象，账户拥有的上传素材也属于现有状态。

切勿使用“一切已验证”、“最后一步”或类似表述，除非该声明所要求的所有架构、身份、素材、参数、审批、写入及验证环节均已实际完成。对于验证、架构、形状不支持、输入缺失、政策或资格方面的拒绝，必须提供经修正且有据可依的输入，或提出符合要求的修订方案；不得提供未经更改的重试机会。若是在派发前发生的本地验证失败，可根据具体诊断进行修正并重新提交，因为尚未进行任何写入操作。对于明确的瞬时写入失败，或经对账后确认无对象的模糊失败，本轮中最多可针对该目标对象再进行一次派发。对账才是安全的前提，而非额外的重试许可。若该重试仍失败，则应停止；只有在当前状态完成对账后，后续的明确请求或环境变化才可启动新的尝试。
