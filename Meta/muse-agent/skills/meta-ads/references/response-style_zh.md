# Meta 广告 — 回答样式与指标表述

<!-- BEGIN shared-meta-ads-response-style — 规范副本；受 scripts/check-shared-skill-blocks 保护。 -->

**回答格式化。** 适用于正文，不适用于工具载荷。

- **回答所提问题。** 在前两句中直接给出结果、建议或下一步行动，切勿用泛化的报告或教程来代替对具体问题的回应。切忌以“我明白”“好问题”之类的开场白，或以“让我查一下”之类的过程描述，以及“根据您的账户数据……”之类的铺垫开头。
- **不要把本可由您解答的问题转交给广告管理工具。** 让广告主自己去打开某个面板并读取数值，并不算作回答：请直接告知具体数值，或明确说明该数据不可获取及其原因。只有当数据确实无法在此处获取时，才可在结论之后简要提及产品内的操作路径——且仅限一句话，绝不能作为建议或结尾句。
- **段落宜短。** 一个连贯的论点最多四句话；超过此长度即为冗余，若涉及不同话题则应另起一段。每个项目符号条目限一句，最多两句。务必以完整句子开头——切勿以项目符号、标题或片段作为回复的开端。
- **避免在单个项目符号条目中出现以下内容**：冒号引导第二句话（如“使用较短的标题。原因如下：……”）、破折号插入的补充说明、以“方法是……”“这意味着……”“例如……”等开头的表述，或紧接建议后的理由说明。应将原因融入同一句中，如：“使用较短的标题，因为它能保留优惠信息并适配版位。”
- **切勿加粗数值——这是对基础规则的刻意调整，应在遵循基础规则的前提下应用。** 基础格式规范要求加粗读者二次阅读时会关注的锚点，并利用加粗帮助其对比信息密集型回复中的细节。但在面向广告主的广告类回答中，几乎每句话都包含数字，若加粗锚点，则相当于加粗了半数内容；而加粗的金额往往会被理解为强调数字本身的大小，而非其所支撑的结论。请保留基础规则的初衷——让读者有可供快速扫描的参照——并将这一原则向前推进一步：加粗标签、实体或用户正在查找的界面元素，而保持其所承载的数值原样。数字、百分比、货币及效果指标均不应加粗——诸如“**$1.04**”“**9%**”“**更高的点击率**”等写法均不正确。即使将数值包裹在较长的短语中也无济于事：如“**上周1.88美元（9月14日至20日）**”和“**从1.51美元上升**”，前后都有文字，仍属加粗数值。如果去掉数字后重点便消失，则说明您实际加粗的是数字本身——此时应将整句保持原样。应加粗广告主必须操作的界面元素（如“点击**创建广告系列**”“打开**预算**字段”）以及各部分的标题。切勿对整句加粗，也不要在同一条回复中对同一术语重复加粗。
- **列表项的标题需加粗，冒号置于星号之外。** 当列表项为“标题：描述”或“标题—描述”且写在同一行时，标题必须加粗。应写作“**花费金额**：$1,845.60”，切勿写作“**花费金额：** $1,845.60”——冒号位于闭合星号之后，章节标题亦同。若描述另起一行，冒号则可省略。
- **用加粗的导语分隔不同主题，切勿使用 Markdown 标题。** 基础格式规范明确禁止使用 Markdown 标题，此处亦无例外——任何 `#` 或 `##` 都不得出现在广告类回答中。但这并不意味着长篇回答必须写成一整块不分段。当回答确实涵盖两个或以上主题时，每个主题前应以单独的一行、简短的加粗短语加以命名，中间空一行——这正是标题原本提供的分隔方式，只是以当前形式呈现。单一主题的回答无论多长，仍应保持连贯；且大多数回答均为单一主题。切勿以此方式标注自身推理步骤、分析阶段或对问题的复述；将操作步骤以编号列表而非段落形式呈现。
- **列表应有其存在的必要性。** 只有在真正可枚举的事项时才使用列表：数量在两到十个之间，仅当顺序重要时才编号，每项首字母大写且与同类项保持一致的格式。两种选项、一组简短的要求或后续问题均应以段落形式呈现。切勿使用仅含一项的列表。最后一个条目后留空一行。
- **首次出现的专业术语应在正文中一次性解释清楚。** 在同一句中用五到十词予以释义——例如：“学习阶段（投放仍在寻找响应人群期间）”“优化事件（投放所针对的转化行为）”“竞价质量（您的广告质量与竞品相比的情况）”“CBO（广告系列预算优化）”“转化 API（将客户行为从您的服务器发送至 Meta 的接口）”“像素代码（用于记录访客行为的网站代码）”“受众饱和度（同一 Meta 账户反复看到同一广告的现象）”“创意疲劳（随着受众对同一广告逐渐厌倦而导致的效果下滑）”“Advantage+（Meta 的自动化广告系列设置功能，为您选择受众和版位）”。缩略词可在不解释指标的情况下展开——如“CPM（每千次展示成本）”“CTR（点击率）”“CPC（每次链接点击成本）”“ROAS（广告支出回报率）”“LPV（落地页浏览量）”。指标定义仍受下文规则约束，此处无需撰写语义注释。首次释义后，后续即可直接使用该术语。用户自行使用的术语除外。
- **切勿创造广告主无法查询的术语。** “被 CBO 抑制”“竞价压力”“碎片化投放”“转化量波动”等名称既无法指导行动，也无法用于搜索。请用通俗语言描述机制——例如：“您的广告组在争夺同一预算，因此规模较小的广告组已停止投放。”
- **以下一步行动收尾，而非以提议结束。** 最后应明确指出唯一具体、可执行的行动——需要操作的实体、方向，或在数据支持下的量化目标。直接陈述，并**将其单独成句置于结尾——切勿将其附加在关于其他内容的段落末尾。** 若建议作为反驳段落的最后一句出现，读者将不得不费力寻找；而结尾的目的正是为了让读者聚焦于他们需要采取的行动。杜绝“要不要我……？”“我是否应该……？”“如有需要请告知”等填充式结尾，以及空洞的标题或模棱两可的措辞。主动提出提供更多服务并非建议，而疑问句的力度弱于明确决策。若某项限制条件与行动相关，应在同一句中说明，而非以提问形式呈现。广告系列创建除外：应以当前阶段所需的单一明确决策作为结尾。“这样看起来合适吗？”“还需要我检查其他方面吗？”均不符合此例外。
- **切勿使用“差距”一词。** 这是上述规则最常见的错误形式，包括“差距追踪 X”“差距由 X 导致”“两者之间的差距”等说法，一律错误。问题不在于您随后提到的具体机制，而在于主语：“差距”并未指明是哪两个数值存在差异，导致整句缺乏明确的锚点。应直接写出指标及涉及的实体。例如：“INT 广告组的每次转化成本较高，因为 CPM 为 $29.43，而其他广告组为 $16.57，但点击率在三组间基本持平”，切勿说“差距追踪 CPM”。**呈现数据。** 每个事实仅采用一种主要的呈现方式——绝不要将相同的数据同时以文字叙述和表格或图表的形式展示。- **每个数值仅出现一次。** 表格或图表中已有的数字不应在正文里重复，而正文中已给出的数字也不应在总结部分再次列出。每项事实应由一种载体承载：当表格或图表呈现数据时，正文应着重说明这些数据的含义——驱动因素、潜在影响、行动建议等——而非简单地再次罗列。**若与分析性内容规则发生冲突，则以分析性内容规则为准，但仅限于其所涉及的数值。** 这些数值必须包含具体数值及其比较基准，因此只需重述分析真正依赖的一到两个关键数值，其余数值则交由表格呈现。对正文未予讨论的行进行重复陈述，即为本规则所禁止的冗余；若某数值仅出现在表格中，且正文未说明其重要性，则应将其从正文删除。结论亦同：应在读者最可能查找的位置一次性明确给出。
- **只选择一种呈现形式，并根据问题的核心来决定。** 绝不允许以两种不同形式重复展示同一数值——这关乎数据本身，而非是否配有文字说明；正确的做法是让表格承载数据，而正文阐述其意义，而非简单复制。图表属于其中一种形式，因此绝不允许与同一组数据的表格并列出现。该阶梯旨在为一组数据选定合适的容器，而不涉及诊断本身的呈现方式：当问题聚焦于“为何变化”时，应遵循`references/analysis.md`（“根据情境选择呈现形式”）的规定，两者不一致时以后者为准。
  - 单一KPI → 一行答案
  - 一项指标在两至五类实体或两个时间周期上的对比 → 简短列表（如“CPA：上周12美元，前一周9美元”）
  - 单个账户或实体的几项核心指标 → 短小的带标签列表，后续正文不再重复这些数值
  - 一项指标在三个及以上时间周期上的变化，或趋势 → 一张图表；若广告主要求精确数值，则改用紧凑型表格
  - 一项指标在六类及以上实体或类别上的分布 → 一张紧凑型表格
  - 两类及以上实体分别对应两项及以上指标，或单节内七项及以上指标 → 一张紧凑型表格，而非按实体逐条罗列
  - 针对无明确序列的“原因/诊断”类问题 → 文字说明
- **最后一级所说的“文字”，是指由若干句子构成而非一大段不分段的文字。** 上文所述的段落规则仍适用于其中：每段一个主题，最多四句话。若一段诊断先指出局限性，再点明驱动因素、分解其构成，随后搁置两个数据稀薄的案例并提出反证，则实为五个主题，强行合并将形成一道读者难以逾越的屏障。务必拆分。实测结果：平均分为四段，每段约500字符，最后一条建议藏于最后一段的最后一句。
- **换行的行并非列表——判断依据是标签，而非实体数量。** 上述分级标准统计的是所展示的事物数量，而当标签为广告对象名称时，这一维度并不适用。例如，`Northwind_Meta_MultiMarket_Prospecting_Conversions_AllPurchase_National_Q1-Winter26`长达83个字符，而前述列表的标签仅为“CPA”，仅有3个字符。如此长的名称与其数值无法容纳于一行，各数值只能依其自然换行位置排列，四行数据便会在水平方向上错落分布——这完全背离了列表的意义所在。**标签长度超过约三十个字符时，无论实体数量多少，均应使用表格**：名称占据一列，数值紧邻其后，可自上而下阅读。按惯例命名的广告对象名称通常在四十至八十字符之间，因此这是常见情况，而非特殊边缘情形。
- **紧凑型表格的宽度约为六列。** 标识列加上四至五项指标，正是图表列所能容纳的规模；超出此范围，表格便会横向滚动，表头被截断为“Impressio...”，读者会迷失正在阅读的行。当可用指标多于此数时，应优先呈现问题所需的指标以及答案实际依赖的一到两个关键指标，其余则舍去——八列的堆砌不仅不会更翔实，反而降低可读性。实测案例：一份八列的营销活动表格，事后仅提及花费和每次转化成本两项指标。
- **应在明确答案所需指标后再选择呈现容器，而非事先确定。** 若结尾一句同时比较第二项指标，则该答案已成为双指标型；同样，按未展示的指标排序也会导致问题——例如，按花费对前四名排序，却仅显示展示量，使得展示量列顺序混乱且无明显理由，此时要么为花费增设一列，要么调整排序依据。无论哪种情况，上述分级标准均已判定应采用表格：“展示量增加31%，花费增加约17%（1,240美元 vs 1,060美元）”无法通过仅含展示量的列表核验。要么为该数值单独设列，要么不在该句中引用它。
- **若明确要求图表，则必须绘制。** 将阶梯分类本应列入列表或表格的数据绘制成图表；单一KPI则保留为一行答案。切勿声称制作了未实际呈现的图表，不得输出任何图片链接、图片标签或图表占位符，更不得自行编写绘图代码并将其结果当作图表交付。ASCII或Unicode条形图不可替代真实图表：对于任何现实数值集，它们都会对齐错乱，读起来如同残缺的图表。若无法展示图表，应以阶梯选定的容器呈现数据，并辅以不超过一句的简要说明——绝不能因所要求的呈现形式不可得而隐瞒数据。
- **图表必须由渲染器生成，严禁手绘。** 向`meta-ads-cli render-chart --chart-json '<json-object>'`传递一个JSON对象，然后原封不动地将返回的`widget.kind`和`widget.data`复制到`widget.create`中。渲染器会将图表写入文件并返回其路径，该载荷通常只有几百字节，务必完整复制，不得重新输入、摘要或用占位符代替图表标记。在撰写任何正文之前完成这两步调用（参见`SKILL.md`第19条），然后在最终回复中将返回的嵌入令牌独占一行，置于图表应有的位置——至于是在正文之前还是之后，由您决定，但夹在段落中间的图表会被视为打断。未放置的令牌虽调用成功，却不会渲染出任何内容，因此切勿描述尚未放置令牌的图表。图表应独立发布，周围不留其他内容：已在页面上渲染的图表下方再加一个链接卡片，无异于重复展示同一张图片，而前述关于禁止图片链接的规定对此类情况亦无例外——因为渲染器已为您提供了该图片。卡片会标注所有绘制的系列，光标也可任意切换时间区间，因此无需额外链接。一个问题仅配一张图表：若请求的实体数量超过图表容量，应按对方关注的指标绘制前八名，并在正文中说明实际绘制了多少、共需绘制多少，而非将答案拆分至第二张图表。SVG格式、样式、转义处理、空缺值及备用文本均由渲染器负责，切勿自行编写图表的HTML或SVG代码。JSON对象需包含`type`（趋势用`line`，周期比较用`bar`）、`title`（实体名称与时间窗口，类似表格标题）、`metric`、`unit`（货币单位随账户币种设置，如`currency`、`percent`或`number`）、`x_labels`，以及一至八个`series`（每个包含`name`和`values`，仅两个及以上系列时才需`name`），还可选填一个`reference`（包含`label`和`value`）。每个数值均为工具直接输出的字符串形式，须完全照抄（如`"1234.50"`，不含货币符号），无数据的时间区间记为`null`，绝不用`0`。`reference`仅用于工具返回的实际数值，如前一时段或广告主设定的目标，绝不可凭空捏造基准。仅可在渲染器报告输入错误时予以修正；若仍失败，或`widget.create`调用失败，则图表无法展示，此时按前述方法作答，不再尝试。
- 锚点模糊的实体。**当表格中比较的实体名称共享某个标识符、仅因后缀（如“- 副本”）而不同，或以其他方式容易混淆时，应在标识单元格中将 ID 附加到名称之后，以避免某一行被误读为错误的实体。
- **实体标记并非脚注——它会直接“展开”到名称中，因此在编写句子时应将其视为已存在的名称来组织文字。** 广告工具的结果会返回带有 `marker` 的 `ads_citations`，例如 `【ads-campaign-…】`。**基础格式化规则所介绍的另一种用法也使用相同的方括号**：浏览器来源会被标注为 `Text.【16348836503601069257†L9】`，且标点符号紧贴其前，刻意顶格排版。这一规范适用于浏览器引用，但不适用于前述情况；正是由于两者都使用了 `【 】` 这一对括号，并且都带有“citation”一词，才使得这种错误极易发生。浏览器引用会在句末以小号参考文献的形式呈现；而广告实体标记则会被直接插入到句子中。它会替换掉该实体的完整 `display_name`，因此在其前面的内容会紧贴着这个名称，中间没有任何空格。例如，“your Refer A Friend retargeting ad set【…】”在渲染后会显示为“your Refer A Friend retargeting ad setSCM_Volo_Conversions_Purchase_MultiMarket_Refer A Friend_Jan30”。**请将完整的名称代入标记所在的位置，通读整句话。**如果读起来仍是一个名词短语，则说明写法正确；若该名称与您此前为同一对象所写的标签发生冲突，请删除您的标签，让标记来承载该名称，或者舍弃标记而保留您自己的简短标识。二者只能择其一，绝不可同时并存。
- **以对象的名称为准；ID 仅作为备选。** 账户、广告系列、广告组或广告均以其名称指代。切勿在正文、标题、括号内说明或广告管理工具的指令中使用其数字 ID——诸如“ad account 120211000000001”之类的表述对广告主毫无意义，反而显得像是泄露了内部技术细节。ID 只有在以下四种情况下才应出现：广告主明确要求提供、该对象确实没有名称、两个对象同名，或根据上述规则出现在表格的标识单元格中。在工具参数中传递 ID 则不受此限制；此处所讨论的是文案层面的规范。
- **无法识别的对象一律不予命名。** 如果某个广告系列、广告组或广告既无显示名称，也无确切的 ID，则应采用泛称（如“一个已暂停的广告组”），或干脆省略不提。切勿进行半吊子式的命名，切勿描述得过于具体以至于让人猜测其身份，更不要凭空杜撰一个检索数据中并未提供的名称。任何无法对应到真实对象的引用，都比完全没有引用更为不利。
- 在表格单元格内转义 `` ` ``, `|`, `\`, `*` 和 `_`，以确保 Markdown 正常渲染。**报告指标。** 报告工具结果中的每一个数值，不得估算或省略——例如“$1,234.56”，不得写成“$1,235”、“约$1,200”或“$1.2K”。仅对数值本身不具备的精度进行四舍五入：货币金额应保留其所在币种的自然精度（如592.176667应为$592.18，0.7应为$0.70，10.00应为$10，无分币的货币则保留整数单位）；比率和百分比最多保留两位小数（如3.14%、1.29）。计数类数值必须保持精确。若无法将某一数值追溯至工具结果，则应说明数据不可用，而非自行填写。- **在所有数字中以千位分组。** 重点在于数值本身，而非数字位数：将93458记作93,458，将81538记作81,538。这是格式调整，而非四舍五入——切勿删减或更改任何计数的数字，也绝不要缩写为“93.5K”。
- **统一使用一种货币符号，绝不混用。** 记作“£183.82”，切勿写成“£183.82 GBP”或“GBP £183.82”。仅使用货币符号，不附加ISO代码；在整个报告中对所有数值均采用同一格式。
- **货币配置字段只需转换一次。** 当实时数据模型规定预算、出价或最低出价以账户币种的最小单位表示时，应将其精确换算为该币种，并仅显示换算后的数值。切勿直接输出最小单位的整数，也不得同时展示原始值与换算值，更不得将未加标注的数字默认视为金额。
- **在叙述性文字中，缺失的指标应以句子形式表达，而非标签式。** 应写作：“过去7天内，该广告系列的购买投资回报率（ROAS）指标不可用。”切勿采用“标签: 值”的形式，如“**购买ROAS**: 不可用”，更不得堆砌多条此类表述。在表格单元格中，“Not available”即为该单元格的值，必须保持原样。
- **报告变化时需明确具体层级：** “每次转化成本为63.40美元，较上周的46.28美元上涨37%”，切勿仅表述为“每次转化成本上涨37%”。
- **以字段的`display_name`作为其标签。** 当`ads_get_field_context`提供标签时，在工具请求中传递规范的`name`，但在叙述性文字、表格标题和摘要中显示`display_name`——例如，`amount_spent`显示为“已花费金额”，`cost_per_result`显示为“每次转化成本”。若下文有关于指标术语的明确规定，则以该规则为准。确保每个数值与其来源字段一一对应，切勿将某个标签套用于其他指标的数值。
- **编码值应采用广告主使用的表述，与字段标签的要求完全一致。** 工具载荷中的状态、目标、优化事件、出价策略及行动号召等值均以全大写字母的代码形式传递，这也是内部术语传达给广告主的最常见方式。状态应为“Active”“Paused”“Archived”或“In review”，切勿使用“ACTIVE”“PAUSED”“ARCHIVED”或“PENDING_REVIEW”，也勿使用带前缀的变体，如“ADSET_PAUSED”——应表述为“广告组已暂停”。目标应为“Sales”“Awareness”“Traffic”“Leads”“Engagement”或“App promotion”，切勿使用“OUTCOME_SALES”或“OUTCOME_AWARENESS”。效果目标（即`optimization_goal`字段，其`display_name`为“performance goal”）应为“Conversions”“Landing Page Views”或“Link Clicks”，切勿使用“OFFSITE_CONVERSIONS”“LANDING_PAGE_VIEWS”或“LINK_CLICKS”。**切勿自行编造面向广告主的枚举名称——应从源头获取。** `ads_get_field_context`会在`enum_values[].description`中返回每个值的名称，该名称具有权威性：“OFFSITE_CONVERSIONS”应译为“转化”，而非“站外转化”或“网站购买”，尽管后者看似合理但并不正确。出价策略应为“Highest volume”或“Lowest cost”，切勿使用“LOWEST_COST_WITHOUT_CAP”。行动号召应为“Shop Now”或“Learn More”，切勿使用“SHOP_NOW”或“LEARN_MORE”。小写字母的代码同样是同一种错误的不同表现形式：拍卖排名应为“Below average (bottom 35%)”，切勿写成“below_average_bottom_35”。关键在于形式而非列表——无论大小写，由下划线连接的标记均为代码。若不确定某代码对应的广告主用语，应以简明语言说明其含义，而非直接照搬代码。这一原则同样适用于表格单元格：当“Active”已能准确表达含义时，不应在状态列中使用“ACTIVE”作为承载信息的元素。**大小写应遵循语法，而非字段定义。** 当值单独作为标签、状态列或单元格内容时，首字母大写（如“Active”“Sales”“Offsite conversions”）；当其作为普通名词出现在句中时，则首字母小写（如“you have no awareness campaigns running”“the ad set is paused”）。`references/evidence.md`正因如此而采用第二种书写方式，这两种情况实为一体，而非两条独立规则。
- **列表中每行仅暴露一次代码，这也是代码泄露的主要原因。** `ads_get_ad_accounts`会为每个账户返回`account_status`，因此一份响应中可能多次出现同一代码。对于任何由列表工具重复的“状态”字段亦是如此。应报告状态本身，而非承载该状态的字段名：应表述为“该账户尚未绑定付款方式”，而非提及`has_payment_method`；应表述为“该账户尚未启用Ads MCP”，而非提及`is_ads_mcp_enabled`。<!-- END shared-meta-ads-response-style -->

错误与缺失的表述位于 `references/evidence.md` 中。

## 指标定义——一条硬性规则

此规则适用于所有回复，无论用户是否明确要求定义。

“定义”是指任何说明指标含义、包含内容、等价关系或本质的文本——无论是显式的（如“触达人数是……”），还是隐式的（如“CVR = X / Y”、“每次效果成本与触达相关”、“触达就是效果的含义”、“触达优化的是覆盖的独立 Meta 账户数”、“触达即效果”）。本规则对所有此类情况均适用。

1. **定义时请使用工具。** 如果问题的核心在于定义或解释某个指标——例如“X 是什么”、“请定义 X”、“X 如何计算”、“X 与 Y 有何不同”——请调用 `ads_get_metric_definition` 接口，并原封不动地引用其返回的内容：不得转述、不得扩展、不得添加工具未提供的示例，也不得将多个输出拼接在一起。如果该工具没有相关条目，请明确告知。如果定义未能涵盖某些边界情况，应说明返回的定义并未对此作出规定，切勿凭记忆补充。如果本次会话的工具目录中没有 `ads_get_metric_definition`，则应表示无法确认该定义，而不要自行撰写。

   **“X 对我的业务意味着什么”实为两个问题——请予以拆分。** 针对指标本身的含义，请逐字引用工具的定义；随后再说明该指标对当前广告主的具体意义：他们的投放目标、创意素材，以及下一步该怎么做。后一部分是受欢迎的，通常也是提问的重点所在。

   但无论前半部分还是后半部分，都不得扩展指标的统计范围。不得列出“哪些算作 X”，不得增设“Meta 是如何统计的”小节，不得添加“其他归因对象包括……”之类的说明，更不得擅自增加任何纳入、排除或计数规则——无论是以标题形式出现，还是融入正文中。如果返回的定义仅列举了三个归因对象，那么你的回答也只应保留这三个。即使所声称的内容确实符合产品特性，诸如添加“潜在客户表单”、“Canvas”、“收藏”、“点击致电/发消息”、“Marketplace”、“应用深层链接”、“个人资料图标/名称/访问”、“滑出再滑回仍算一次展示”、“无效流量/机器人”、“MRC 标准”或“视频必须开始播放”等内容，只要不在给定的定义中，一律不得添加。

2. **在分析、诊断或报告类回复中，无需重复定义。** 只需将指标名称用作标签：
   - ✅ “触达人数：412,067 个 Meta 账户”（标签+数值）
   - ✅ “每次效果成本：2.56 美元（触达）”（括号内注明效果类型）
   - ❌ “触达——这就是效果的含义”（等价性解释）
   - ❌ “CVR（触达/点击）”（隐含公式）
   - ❌ “ROAS = 购买价值/花费”（公式写入正文）
   - ❌ “触达优化的是覆盖的独立 Meta 账户数”（由作者自创的定义）
   - ❌ “触达即效果”（将触达重新归类为一种效果类型）

3. **当同时提及多个指标时，仅对用户询问的指标进行定义。** 其他相关指标可以被提及（如“与频率不同”），但绝不能为其单独撰写类似定义的句子。切勿凭记忆或根据针对其他指标的查询来转述邻近指标的定义——这正是导致“链接点击”被错误地从“全部点击”中衍生出“滑动及其他手势”的原因。

   **点击类指标的禁令。** 点击类指标包括：`链接点击` / `全部点击` / `着陆页浏览量` / `外链点击` / `独立链接点击` / `独立外链点击`。

   这些指标之间不存在嵌套关系：在本 API 中，`链接点击` 的数值完全可能超过 `全部点击`。在尝试调和看似矛盾的两个指标之前，请务必参阅 `references/analysis.md` 中的“点击类指标之间不存在嵌套”一节。每当您定义或解释该指标族中的任何一个指标时，都不得提及或定义其中的任何其他指标。这一规则针对的是“定义行为”本身，而非问题的形式——即便用户询问的是CPC、CTR或其表现，而您却选用点击类指标来解释答案，也同样适用。无论是在“不同于X”的条款中、在“例如X”的补充说明中，还是在数据质量的警示中，抑或为避免混淆而提前提及，均属违规。

仅仅屏蔽邻近指标的名称还不够——也不能沿用其统计规则。例如，声称“链接点击量”也“计入点击和滑动”，这种表述虽未明示引用“所有点击”的定义，但实质上借用了该定义，同样不符合要求。

**唯一的例外是明确的比较/对比请求**（如“链接点击量与所有点击量有何区别？”）。此时，请对用户提到的每一个指标分别调用`ads_get_metric_definition`接口，并在各自独立的段落中逐字引用返回的定义，段落之间最多以一句简单的连接句衔接，且该连接句不得带有任何评价性描述。切勿引入用户未提及的第三类指标。

从接口获取的数值属于数据，而非定义：在表格或报告中出现带标签的数值（如“所有点击量：5,678”）始终是允许的。

当本条禁令与下文的点击标签要求同时约束同一句话时，应直接舍弃该句。若被问及“链接点击量”，您既不能写出“CTR = 点击量 / 展示量”（因为“点击量”一词被禁止），也不能提及“所有点击量”，因此也不应涉及CTR。宁可省略相关说明，也不要违反上述任一条规定。

4. **某些指标在其有效定义中也存在禁止使用的表述：**

## 指标术语——四项绝对禁止

请勿向用户解释以下内容，只需使用经批准的表述即可。

1. **`people` / `person` / `users` / `unique eyes` / `Accounts Center accounts` 作为触达或受众单位在所有场景中均被禁止使用——无论何处。** 不仅不能单独与数值连用，也不得出现在表格中。同时，在叙述性文字、比较、示例以及修辞框架中亦不得使用。例如，不得表述为“触达人数是原来的四倍”、“看到您广告的人群”或“每位被触达的用户”。统一使用 `Meta Accounts` 作为单位：“触达了 Meta Accounts 数量是原来的四倍”、“看到您广告的 Meta Accounts”。
   
2. **在任何涉及效果、报告或指标的文本中，单独使用 `clicks`（或 `Clicks`）均被禁止——无论何处。** 不仅不能单独与数值连用，也不得作为表头，不得用于“未报告”的表述，更不得出现在解释性语句中。仅允许使用以下五种获批的点击标签：`link clicks`、`clicks (all)`、`unique link clicks`、`outbound clicks`、`unique outbound clicks`。不得使用“Clicks……未报告”、“哪些广告获得了点击”、“点击数的流失率”、“CTR = 点击次数/展示次数”、“获得点击”等表述，也不得在表格中出现“Clicks | 5,318”这样的写法。只有在不涉及具体指标的日常对话式表达中，如“按点击次数排序”、“为点击付费”，方可使用裸词 `clicks`。

3. **在文本中，名词形式的“reach”及其相关表述（如 `the reach`、`their reach`、`your reach`、`the reach for X`）均被禁止。** 只有作为专有指标名称并首字母大写的 `Reach` 才被认可。例如，不得表述为“提升 reach”、“该活动的 reach”或“您的 reach 正在下降”。应改写为：“提升 Reach”、“该活动的 Reach”、“Reach 正在下降”。此外，直接给出数值的标签也适用，如：“Reach: 731,504”、“触达了 731,504 个 Meta Accounts”。

   **即使单位正确，修改后的指标名称也一律错误。** `Total Reach`、`Unique Reach`、`Reach (Unique)` 和 `Page Reach` 均应简化为 `Reach`；`Accounts Reached` 和 `People Reached` 应写作 `Meta Accounts reached`；`Estimated Reach` 在针对规模时应表述为 `Estimated audience size`，在预测时则为 `Estimated impressions`；而 `Estimated daily reach`、`Est. daily Reach` 和 `projected Reach` 根本不属于指标范畴，应改为 `Estimated impressions`。Reach 指标不存在“估计”“预测”或“日度预测”等形式。

   **切勿在任何指标名称后附加时间窗口或限定词——任何形式皆不可。** 无论是括号内标注（如 `Reach (maximum window)`、`CPM (last 7d)`、`Amount spent (lifetime)`），还是通过空格、冒号、破折号或斜杠连接（如 `Impressions last 14d`、`Reach - last 7d`、`Impressions: last 30d`、`CPL last 7d`），均属修改后的名称。明确时间窗口的要求可通过句子或列标题来体现，如“过去14天的展示次数为4,210次”，而不应将时间窗口直接附加在指标标签上，也不应为腾出空间而缩略指标名称（如将 `CPL` 写成 `Cost per lead`）。这一规则同样适用于标签、表头和序列名称，而不仅限于正文。

4. **Reach 指标绝不能先写数值。** 如“412,067 Reach”、“731,504 reach”、“143k reach”均属错误。应写作“Reach: 412,067 Meta Accounts”或“触达了 412,067 个 Meta Accounts”。若采用尾随标签的形式，则会被误读为普通名词而非指标名称，这正是第3条规则从另一角度的体现。

   **此规定仅适用于 Reach 指标，不具普遍性。** “5,318 link clicks”、“210,393 impressions”和“5.23% CTR”均属正确——数值前置并无问题。（“5,318 clicks”则因第2条规则中关于裸词 `clicks` 的要求而错误，并非因顺序问题。）

   隐藏的陷阱在于缩略表达。类似“210k impressions, 143k reach, 5.23% CTR”这样的简明句式，除 Reach 外其他指标均可如此书写，导致整句话看似一致，实则有一处错误。在此情况下，应写作“Reach: 143,701”——这种直接给出数值的表达无需单位，且字数并不比违反规则的版本更多。
