# 活动交接

仅在广告主选择创建后投放状态或编辑操作之后阅读本节。初始的成功交接由 `campaign-execution.md` 负责。

## 显示成功创建

在管理读写流程验证当前状态后进行的后续重新渲染中，使用审核后的活动名称、整数形式的广告组/广告数量，以及在可用时的确切返回 HTTPS Ads Manager URL，运行 `meta-ads-cli render-campaign-success --success-json`。将其小部件的 `kind` 和 `data` 不做任何修改地传递给 `widget.create`。处于暂存或草稿状态的结果不属于成功创建，因此在此交接之前停止，并将其报告为暂存状态。如果 URL 被拒绝，则省略该 URL，以便渲染器使用规范链接。任何呈现失败都不应导致重试写入操作。

请使用以下 JSON 格式，仅替换其中的值：

```json
{"campaign_name":"Holiday workshop","ad_set_count":1,"ad_count":1,"ads_manager_url":"https://adsmanager.facebook.com/adsmanager/manage/campaigns"}
```

卡片显示正常时，切勿添加 Markdown 或纯文本链接、通用的 `external_link`、ID、签名 URL、设置摘要、创意预览或相关素材。原生卡片没有标题，只有一行链接：“在 Ads Manager 中打开”。渲染器仅负责此链接卡片；而外围响应则包含简短的状态说明句。

在任何已验证的编辑、发布/激活或暂停操作之后，最终响应必须按顺序包含：一句简短且有据可依的句子，说明已完成的内容及当前的投放/花费状态；Ads Manager 卡片；以及一个 `muse.create_options` 菜单，列出当前可执行的下一步操作。保持卡片与选项紧邻，并在选项之后结束。切勿以“随时提问”、“告诉我”或“开口就好”之类的文字代替选项。应使用“活动层级”等集合性表述，而非将返回的名称和类型标签拼接成重复的“广告组 广告组”等形式。

## 暂停期间

紧接卡片下方，显示一个 `muse.create_options` 菜单。首先列出：

- “发布以按 <预算和时间安排> 开始投放”

最多再添加三项当前可执行且有实时工具支持、满足前置条件的操作：修改创意/文案、调整预算/时间安排，或添加经单独审核的广告。不得提供推测性操作或“继续保持暂停”选项；若菜单保持不变，则表示继续暂停。此菜单在成功暂停后以及对已暂停的层级进行编辑后均属必填。状态说明句必须明确指出层级已暂停且未在投放。不得重复设置、层级数量、ID、链接或选项标签。

暂停期间的编辑选项仅用于记录意图，并遵循常规的策划、创意及写入审批流程。每次成功暂停更新后，应在唯一的一句状态说明中注明已完成的变更，随后再次显示卡片和当前菜单；务必在撰写该句之前先调用两次小部件接口。

发布即为新的投放请求。在其下一次处理时，应用 `writes.md` 及实时激活模式，在原生审批界面中说明状态对象及投放后果，并让 Sentinel 对每次写入进行拦截。结果为 ACTIVE 或 PUBLISHING 仅证明提交成功，而非实际投放；只有在后续读取确认活动、广告组及广告均已有效投放后，方可称其为“已上线/正在投放”。切勿将日预算描述为严格的一日上限。

## 发布之后在未确认已上线、触达用户、开始投放或产生消耗之前，仅陈述已验证的发布状态；待后续读取结果证实该状态后再进行渲染。随后呈现广告管理器卡片，并显示一个包含两到四个支持操作的 `muse.create_options` 菜单，建议按优先级排序：检查审核与投放状态、在数据可用时查看投放效果、结合投放数据重新调整预算、暂停投放，或准备另一则已通过审核的创意/广告。若回读结果仅显示“活动处于激活状态”，则使用一句简短说明，例如：“发布已完成，广告系列层级已激活；投放与消耗尚未得到确认。” 请勿再次提供“发布”选项。所选操作不触发任何写入操作，而将在后续轮次中依据其自身的读写规则执行；切勿在激活后直接串联其他操作。除非广告主另行提出并配置，否则不得主动承诺未来的监测服务。
