# 广告系列预算

请在估算器和广告主约束所需的非预算输入已稳定后阅读本节。未解决的地理区域限制会影响定价。

现有广告系列的预算诊断属于 `tool-routing.md` 的范畴。

对于广告系列规划，这是一个定价子步骤，同样需要在 `campaign-planning.md` 中定义的可执行目标；即使请求侧重于预算、效果或学习，也应将决策权交还给该控制器。只有纯粹针对价格或预算说明的请求才属于纯定价场景，此时无需提供与执行绑定的 URL 或对象标识。

## 对一个稳定的方案进行单次定价

在经过精简的发现流程确认了 `ads_budget_estimate` 后，请使用 `describe-tool --input-only` 读取其实时 Schema。利用其中当前的目标、优化方式和结果枚举，然后通过以下类型化命令对方案进行一次测算：

```sh
/opt/hatch/bin/meta-ads-cli estimate-budget \
  --account-id <ACCOUNT_ID> \
  --advertiser-request '<COMPLETE_REQUEST>' \
  --campaign campaign_1 '<CAMPAIGN_NAME>' <OBJECTIVE> <OPTIMIZATION> CBO \
  --ad-set campaign_1 ad_set_1 '<AD_SET_NAME>' \
  --country <COUNTRY_CODE> \
  --target-country ad_set_1 <COUNTRY_CODE> \
  --advantage-audience ad_set_1 on
```

该类型化命令负责 JSON 序列化、请求关联以及最终的实时 Schema 校验。请勿使用 `call-tool`、CLI 帮助、源码检查或试运行来构建请求。将 `yield_ms` 设置为 120000 毫秒。如果执行仍在后台运行，请等待其自动返回结果；正在运行的命令并不算失败，也不得重复调用。

- 使用 `--campaign KEY NAME OBJECTIVE OPTIMIZATION CBO|ABO` 添加每个广告系列，并使用 `--ad-set CAMPAIGN_KEY KEY NAME` 添加每个广告组。
- 默认为潜在客户开发模式。仅当现有证据明确支持再营销时，才添加 `--campaign-stage KEY retargeting`。
- 在调用前比较每个广告组的最终定向设置。若所有广告组的定向完全相同，则以 `--country` 提供计划上下文，为每个广告组指定单一地理范围（使用 `--target-country`、`--city-key` 或 `--region-key`），并添加返回的 `--interest-id`、`--custom-audience-id`、`--locale-id`、`--age-range KEY MIN MAX`、`--gender KEY all|men|women` 以及 `--advantage-audience KEY on|off` 等参数。
- 使用 `--ad-set-start KEY ISO_8601` 和 `--ad-set-end KEY ISO_8601` 添加有时间范围的投放计划。

对于已确定的城市定向，保留 `--country` 作为上下文，用返回的城市键替换原有的国家键，并仅追加返回的兴趣 ID。

估算器会为每个广告系列输出一份基于定向的费用估算。若任一广告组的定向存在差异，则首次调用时仅允许使用广告系列层级的 `--country` 参数，其余定向相关标志均应省略。保持可执行受众不变，并将估算结果标注为“按国家级别”，而非“按受众级别”。切勿尝试测试被拒绝的差异化定向、合并受众或将受众范围扩大以使定价成功。

预算及约束相关的标志均为计划级别的数值参数，而非广告系列或广告组的键值：
- `--daily-budget AMOUNT` 或 `--lifetime-budget AMOUNT`
- `--max-daily AMOUNT` 或 `--max-lifetime AMOUNT`
- `--max-cost-per-result AMOUNT`
- `--min-roas NUMBER`

若预算未定，则省略每日及总预算标志，切勿自行设定初始值。若广告主已承诺具体金额，请通过 `--currency` 传递。总预算必须同时指定投放周期或结束日期。最大成本、每效果成本及 ROAS 约束仅在广告主提供时使用。

仅当目标事件与所测价的优化事件一致时，才通过 `--goal-value`、`--goal-result-type` 以及可选的 `--goal-period day|week|month|total` 传递广告主设定的效果目标。切勿在未验证转化率的情况下，将购买、线索、预订等实际转化数转换为浏览量、点击量或互动次数；此类数据仅作为业务背景信息保留。使用 `SKILL.md` 所要求的完整、当前的多轮对话 `advertiser_request`。当投放节奏或货币单位存在歧义时，应在定价前进行确认。切勿自行提供成本或 CPA；估算器会据此推导得出。

在为包含 Instagram 的广告位定价之前，需先确定一个兼容的 Instagram 身份标识。若不存在，则应排除 Instagram 并说明这一限制。

请将 `total_budget` 用于整个方案预算，而用 `per_campaign[]` 进行各子活动的预算分配。优先使用格式化数值或以大单位表示的数值，并在返回转换结果时保留两种货币。针对方案校验预算模式、各项假设及警告信息。如出现不一致，仅允许进行一次基于 schema 的修正；否则应保持定价状态为未解决。

## 解读返回的证据

金额依据说明了为何选择了该预算。成本来源、置信度、样本量、回退原因及附加说明则解释了其预测结果的依据。但仅凭其中任何一项都无法证明广告主应投入的具体金额。

| 依据 | 对广告主的意义 |
| --- | --- |
| `budget_honored` | 广告主所选预算及其对应的预测结果 |
| `target_derived` | 与广告主目标及时间框架相匹配的预算；仅为目标适配，并非强制要求或必然可承受 |
| `account_history` | 观察到的账户历史行为中与之相符的部分；需明确证据来源及样本范围 |
| `learning_floor` | 每个广告组在近七天内平均约 50 次优化事件所需的预估花费；可用于快速退出学习期，但并非最低限额或保证值 |
| `account_minimum` | 接受的最低预算；不代表实际有效投放量 |
| `delivery_floor` | 支持的最低投放计划；不代表可行或盈利 |
| `mixed` | 需分别说明各主要组成部分 |

将 `account_history` 视为仅针对兼容的返回样本计算得出的结果。将 `peer_benchmark` 和 `forecast` 标注为估算值。将 `hardcode` 视为低置信度的静态回退值；其成本及推导出的金额仅供参考。所有预期结果均为预测值。

`fallback_reason` 说明了为何更有力的依据被放弃。`cost_caveat` 则对所选依据加以限定。例如，`cost_not_split_by_stage` 表示账户证据同时包含了获客与再营销数据，但这并不意味着该证据是合成的。

保留返回的不足提示、警告信息、可行性评估及支持的操作建议。切勿擅自提高预算、重新分配资金或删除任一广告活动。估算器不接受具体的广告位输入，因此切勿按广告位调用其估算结果。

使用返回的格式化数值。否则，应按货币的常规小数位精度显示金额，且不得将显示四舍五入的结果用于后续计算。将机器元数据翻译成面向广告主的语言，不得暴露枚举标记、蛇形命名、空值或内部状态。对投放量的解读仅限于返回的预测结果、来源与置信度，以及适用的基准参考；稳定性、效果及实用性等指标除非另有说明，否则不予评价。

## 对预算决策进行分类

根据依据、金额、预测结果、学习阶段关系及关键约束条件，返回 `settled` 或 `open` 状态：

| 输入与结果 | 状态与交接 |
| --- | --- |
| 承认并采用所提供的预算金额 | 返回 `settled`，并保留该金额及其预测结果 |
| 提供的预算低于学习门槛 | 预算仍为 `settled`，但开启可行性选项，并优先给出支持的建议 |
| 提供的预算达到门槛，或学习阶段不适用 | 返回 `settled`，除非其他返回的约束导致需要分叉处理 |
| 无预算，但有兼容的历史数据建议 | 返回 `settled`，并附上相关证据及样本 |
| 无预算，但有基于目标推算的金额 | 返回 `open`，因为目标成本已知，但是否可承受尚不确定 |
| 既无预算也无目标，仅有学习门槛 | 返回 `open`，并予以说明但不采纳该门槛作为最终方案 |
| 仅有账户最低预算或投放门槛 | 返回 `open`，并询问可持续的预算规模或期望达成的效果目标 |
| 可行性与既定限制或目标冲突 | 保留用户提供的决策，并返回冲突详情及可供选择的支持路径所提供的金额不会因等于最低值或存在更高价值的替代方案而被视为已确定。目标推导出的金额无论低于、等于还是高于学习下限时，都将保持未确定状态，因为广告主尚未认可其可承受性。当既未提供预算也未设定目标时，优先参考兼容的账户历史数据；否则，绝不凭空臆造一个面向中小企业的通用范围，也不应默认采用过大的学习基准。

切勿将仅满足最低要求的结果视为可行、有效，或作为初始预算。

针对预算约束，向控制器返回以下选项族：

- 所提供的金额低于下限：若上游事件经验证且为推荐方案，则优先展示该事件；否则，优先展示“维持<所提供金额>”。其他适用路径包括“维持<所提供金额>”、“使用<学习下限金额>”以及“调整预算”。
- 目标推导出的金额：若上游事件经验证且为推荐方案，则优先展示该事件；否则，优先展示“使用<与目标匹配的金额>”。其他适用路径包括“使用<与目标匹配的金额>”、在展示精度上显著不同时“使用<学习下限金额>”，以及“选择其他预算”。
- 无预算、无目标、无历史数据：返回时优先展示“使用<学习下限金额>”，其次为“设定预算”和“设定效果目标”。

每条路径仅列出一次。仅在可行时添加经验证的上游事件。支出选项应选用与说明中所示格式一致的金额及投放节奏。仅账户最低限额或投放下限本身绝不能作为“使用<金额>”选项；仅提供“设定预算”和“设定效果目标”。

在全面调研规划中，按如下流程执行控制器终端：对于开放预算或存在实质性可行性分歧的情况，先调用`muse.create_options`并传入适用的选项族，随后在最终响应中撰写说明与问题，并在其嵌入的标记处停止；对于已确定预算且无其他约束的情形，则继续生成完整方案，并呈现“批准此策略”/“否，需修改”组件。

在引导模式下，所有成功结果均应返回至`campaign-guided.md`；即使金额已确定，也必须包含预算或可行性的引导信息。切勿以文字形式的问题或占位符代替。

## 学习与分配的保障措施

直接使用返回的学习下限。若未返回货币下限，但某个广告组有每周事件预估，则将其与近七日平均约50次事件进行比较，而不应凭空推算货币下限。

- 当预估值达到或高于下限时，可说明该预估值有望支持快速退出学习阶段所需的量级；但切勿承诺一定能够退出。
- 当预估值低于下限时，可说明计划仍可运行并针对该事件进行优化，但预计量级低于基准。在此止步：诸如“学习可能较慢”或“投放稳定性较差”等表述，即便以可能性形式提出，亦不予支持。
- 除非明确返回相关信息，否则不得预测“学习受限”、退出日期、学习速度放缓、投放不稳定或成本上升等情况。
- 缺乏下限并不意味着不存在学习过程。若有权威结果表明学习不适用，则应说明该基准不适用。
- 学习是针对每个广告组的。仅使用返回的各广告组量级；若缺失，则充足性无法判定。在建议增加投放前，应先合并不具备独立投放机制的广告组。
- 广告系列级预算为统筹资金，可能被不均衡地分配。切勿将其或其结果按广告组数量进行分割。面向广告主的响应中应省略“预期每日份额”；该指标属于估算模型，并非实际分配结果。广告组下限并不能保证实际投放量。

## 事件可行性评估

事件的可用性应基于追踪数据或原生转化归因的证据。估算器认可的事件仅证明其可被定价。

如果所请求的事件无法衡量，则不应为其定价。将跟踪约束和已验证的可执行路径返回至 `campaign-planning.md`。如果该事件可衡量但量级低于其学习基准，且有证据支持时，应优先推荐最接近的、已验证的高频率事件，作为更为可行的方案。同时，将所请求的事件以当前预算或目标匹配预算保留为明确的备选方案，切勿将其悄然替换。若无上游事件的支持，则应以所请求的事件为主导。

上游事件优化的是该行动本身，而非原始结果。不得将原始数值目标带入其估算，也不得将预测的上游事件等同于最终结果。在未提供相应证据的情况下，不得承诺后续的再营销、投放时机、CPM、成本或销售提升。

变更优化目标会使估算失效。应将首次结果视为可行性依据，且仅对选定的最终结构进行一次定价。只有当被取代的金额能切实解释变化原因时，方可予以保留。

将决策返回至 `campaign-planning.md`，由其负责处理下一个问题、选项组件或完整评审。对于营销活动规划请求，不得在此定价子步骤中结束流程。引导模式将返回至 `campaign-guided.md`。

## 故障处理

若因确定性参数或架构错误导致预算未能解决，则在输入或界面发生变更之前，预算将保持未定状态。仅当故障被明确标识为暂时性时，才可对未更改的请求重试一次。若成功响应中缺失必要的定价字段，则视为不完整，不应因此查阅 CLI 帮助或重复调用。
