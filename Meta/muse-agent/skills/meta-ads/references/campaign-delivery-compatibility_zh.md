# 营销活动投放兼容性

在选择投放方式时以及在最终审核前的创建参数中，请再次使用此检查机制。它可防止某个看似合理的设置在与其他设置组合时变为无效的营销活动。

将每个广告组的业务结果、营销活动目标、优化目标、投放位置、所需信号或推广对象以及计费事件视为一个整体决策。只有当所有要素都达成一致时，才确定该组合：

- 目标必须支持所选的优化目标；
- 投放位置必须能够产生用于优化的事件；
- 为所选账户返回的所有必要主页、表单、消息发送身份、数据集/像素及事件，均属于预期的角色。由于任何工具都不会列出账户的应用，因此应用ID和商店URL应来自广告主或现有广告组的推广对象，切勿自行编造；
- 推广对象的结构必须包含优化目标和投放位置所要求的全部字段；
- 计费事件与预算/出价层级必须由同一设置支持。

计划必须准确描述其实际优化的目标。计划不能承诺购买量却优化访问量，也不能将网站访问误称为“广告内潜在客户”，或将主页点赞误称为“流量”结果。上游事件属于不同的投放路径，应如实呈现并作为独立路径处理，而非重新定义广告主的结果。

## 常见推荐类型

对于常规推荐，请使用以下类型。代码为内部规划值，回复时应使用面向广告主的名称。

| 预期结果       | 兼容的投放类型         |
|----------------|------------------------|
| 品牌认知或触达 | `OUTCOME_AWARENESS`，搭配 `REACH`、`IMPRESSIONS` 或其他受支持的认知类目标 |
| 网站访问       | `OUTCOME_TRAFFIC`，搭配 `LANDING_PAGE_VIEWS` 或 `LINK_CLICKS`，提供经验证的网站URL，并仅使用该目标支持的追踪字段 |
| 网站购买或转化价值 | `OUTCOME_SALES`，搭配 `OFFSITE_CONVERSIONS` 或 `VALUE`，指定网站作为投放位置，并提供已返回的符合条件的转化来源及受支持的事件 |
| 网站潜在客户转化 | `OUTCOME_LEADS`，搭配 `OFFSITE_CONVERSIONS`，指定网站作为投放位置，并提供已返回的符合条件的转化来源及所选的潜在客户事件 |
| 表单潜在客户   | `OUTCOME_LEADS`，搭配 `LEAD_GENERATION` 或 `QUALITY_LEAD`，指定广告内投放位置，并提供已返回的主页和表单 |
| 消息对话       | 使用与声明结果匹配的目标，搭配 `CONVERSATIONS`，指定 Messenger、WhatsApp 或 Instagram Direct 作为投放位置，并提供其已返回的身份；创意需按照 `campaign-creative.md` 的要求使用相应渠道的消息按钮和标准链接，不得使用广告主提供的URL |
| 主页点赞       | `OUTCOME_ENGAGEMENT`，搭配 `PAGE_LIKES`，指定主页作为投放位置，并提供已返回的主页；应使用受支持的计费事件，通常为展示次数 |
| 帖子互动       | `OUTCOME_ENGAGEMENT`，搭配 `POST_ENGAGEMENT`，指定帖内投放位置，并提供已返回的主页/帖子或受支持的新广告格式 |
| 个人资料访问   | `OUTCOME_TRAFFIC`，搭配 `VISIT_INSTAGRAM_PROFILE` 或 `PROFILE_VISIT`，并提供与之匹配的已返回的个人资料投放位置 |
| 视频观看       | `OUTCOME_AWARENESS` 或 `OUTCOME_ENGAGEMENT`，搭配受支持的视频观看类目标及投放位置 |
| 应用安装或应用事件 | `OUTCOME_APP_PROMOTION`，搭配应用类目标、应用投放位置，并提供广告主提供的应用ID和商店URL，或应用事件身份 |
| 电话拨打       | 使用与目标匹配的业务目标，搭配受支持的电话拨打类目标、电话号码投放位置，并提供已返回的主页/号码信息 |

这些是推荐类型，而非当前工具接口的替代方案。只有在现有工具证据充分证明整个组合及其所需输入的情况下，才能确认账户受限或未公开的组合。仅凭某个字段存在于架构中，并不能证明使用该字段的每种组合都是有效的。

## 组合通过了各项字段检查但仍被拒绝的情况- **每个最低成本的广告系列预算对应一个优化目标。** 当某个广告系列采用最低成本出价策略时，其下的所有广告组（包括后续新增的广告组）都将使用相同的优化目标。在添加新的广告组之前，请先查看现有广告组的优化目标；如果目标不同，则需要创建单独的广告系列。
- **生命周期预算必须设置结束时间。** 如果广告组或其所属广告系列的预算为生命周期预算，则该广告组必须设置一个在开始后24小时以上的结束时间。在将广告组添加到现有广告系列之前，请先检查其所属广告系列的预算设置；如果没有设置结束日期，应要求设置，切勿自行将广告主的生命周期预算改为每日预算（参见 `references/writes.md` 中关于预算频率的说明）。
- **应用类广告应针对相应平台定向。** 当推广对象为某款应用时，定向范围应仅限于该应用的操作系统：App Store 上的应用为 iOS，Google Play 上的应用为 Android。若未指定操作系统，系统会判定为不匹配并予以拒绝。相关值应取自实时架构或定向搜索结果，切勿凭猜测填写。
- **iOS 14 及以上版本的归因需配合 iOS 14 及以上版本的广告系列。** 仅当广告系列是在本次沟通中以 `is_skadnetwork_attribution: true` 创建，或由广告主明确声明为 iOS 14 及以上版本的广告系列时，才可为广告组设置 `campaign_attribution` 属性（`SKAN` 或 `AEM`）。对于现有广告系列，无法读取该设置，因此在其他情况下应省略此项。字段名称应以实时架构为准。

## 在定价前解决不兼容问题

当传入的参数涉及多个功能族时，应将每项意图作为约束条件保留，并在可行的执行路径之间给出一个明确的选择。例如，若请求为“以主页赞为目标优化的网站流量”，则应在“网站访问”和“主页赞”之间做出选择；两者均不应被静默覆盖。同样地，若缺少必要的转化信号，也应在恢复该指标与接受上游明确指定的投放路径之间作出选择。
在参数组合完全兼容之前，应保持开放状态，不得进行定价、制定完整策略、据此规划创意、进行最终审核，也不得调用广告创建工具。

## 再次核对完整的创建参数

在获取选定的实时创建架构后，应将其包含的条件约束及互斥规则（而不仅仅是 `required` 数组）应用于具体参数。逐一核对每个广告组的优化目标、投放目标、推广对象、计费事件及出价字段，确保与广告系列的目标和预算归属一致；随后再核对定向/版位设置，以及某一创意类型的所有身份/素材/链接要求，并确认广告组与创意的引用关系。
若实时描述与当前约定存在差异，则以实时描述为准。应追溯至最早受影响的规划决策，重新取得审批；切勿依赖创建时的默认值或自动修正，也不得将创建失败作为发现兼容性的依据。
