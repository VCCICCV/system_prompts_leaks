# 幻灯片制作规范

如何编写每张幻灯片的 HTML，使整个演示文稿读起来像精心设计的作品，而不是模板化的产物。每张幻灯片都应写成一个自包含的 `section.slide`，图片以内嵌 `data:` URI 的形式插入，并通过 `render_audit.mjs` 进行校验。请结合阅读 `design-system.md`（CSS 令牌、画布、主视觉/标识与布局框架）和 `image-directive.md`（指导 `media.generate_image` 的艺术创作）。

当你收到一份“风格方案”时，它已经为你选定了原型、主题、配色、字体、每张幻灯片的布局，以及整套演示文稿的标识组合；请直接应用，不要重新挑选颜色或字体。如果没有提供风格方案，请以同样的严谨态度应用你在工作流程中设定的设计系统。

## 内容策略

- 先确定幻灯片“说什么”，再考虑它的外观；内容决定版式。
- 每张幻灯片只传达一个核心信息。将该信息作为标题中的**主张**而非话题（例如：“提案阶段推动增长”，而非“销售漏斗概览”），并让幻灯片上最大的元素来佐证它。如果无法提炼出唯一的要点，这张幻灯片就不算完成。
- 标题应简短，不含任何数据指标。先点明“所以呢”：文字负责阐释，视觉负责呈现证据。
- 每个事实只在一个地方出现。如果图表已展示各项数值，就不要再用统计卡片、柱状图标签或图例重复这些数据。
- 最多突出显示 3 个关键指标，且这些指标应共同支撑最终结论。
- 留白透气：内容页最多包含约 5 个要点（每条 1–2 行）或 3–4 张卡片。若内容过多，应删减或拆分到多张幻灯片，切勿强行塞满。
- 只使用来自所提供资料的真实、可验证的数据；绝不能虚构数字、日期、引用或来源名称。真实来源最多引用一次，并以小号、浅色标注；绝不可引用自己刚生成的图表。

## 简洁与克制

- **幻灯片上严格禁止出现以下元素：** 圆角标签、副标题、摘要行、顶部装饰、引言、徽章、芯片、标签、说明文字。请全部移除。也不要为它们编写 CSS：即使只是定义了一个从不使用的 `.kicker` 规则，或者仅仅用于隐藏该类名的规则，也属于每个演示文稿中的无用代码。
- 每个元素都必须服务于表达的核心观点，且不得重复信息。信息应按逻辑顺序线性呈现。
- 封面仅保留标题叠加在主视觉背景之上：不得添加副标题、标语、日期/来源行、图标、卡片或统计框。细节留待内容页呈现。

## 版式与构图

- 采用统一的全画布布局，并在不同幻灯片之间调整版式结构（封面和结尾页除外）。通过字体排印和间距引导观众的注意力。
- 使用 CSS Grid 构建多元素布局，为每个网格单元明确指定 `grid-column` 和 `grid-row`，确保各元素互不重叠且不依赖自动定位。主容器中不得使用 `position: absolute`，并保持容器对齐。
- 内容区块之间至少留出 16px 的间距，内容与每条幻灯片边距之间至少留出 48px。任何元素的边界框均不得与其他元素相交；文字绝不能覆盖在图片的复杂区域上。
- 通过将内容整体居中填充画布（在网格布局中使用 `align-content: center`，在弹性盒子列布局中使用 `justify-content: center`），使剩余空间均匀分布在上下两侧的外边距中。不要为了填满垂直空间而拉伸卡片，也不要把多余的空间集中在底部。如果版面高度远低于 720px，可放大图片、提升字号比例，或减少列数。
- 文本段落最多设置两栏并排显示（每栏约 460px，每行容纳 8–14 个词）。若内容似乎需要三栏或更多，应改为两栏，将整行内容堆叠在标题下方，或直接删减。只有简短的数据组合（一个数字加一个约 3 个词的标签）才适合三栏布局，切勿用于句子或项目符号列表。
- 编号、排序或序列型列表应以左对齐的垂直列表形式呈现（每行一项，编号/标签靠左，标题左对齐置于上方）。切勿将排序序列排成居中块状或 2×2 的网格。居中对齐仅适用于单句陈述页或结尾页；切勿对多项目列表或内容页的标题使用居中对齐。
- 若内容超出版面空间，应精简内容（减少项目符号、缩短文本），而非将字体缩小至层级规范的最小值以下。内容被裁剪绝不允许。

## 字体与色彩- 内容布局采用以下尺寸：标题使用 `var(--slide-font-display)`，48–64px，粗体，颜色为 `var(--slide-fg)`；正文使用 `var(--slide-font-body)`，16–18px，行高1.4–1.5；数值使用 `var(--slide-font-display)`，48–72px，粗体，颜色为 `var(--slide-primary)`；数值标签使用 `var(--slide-font-body)`，11–13px，首字母大写。数值组合时，将数值置于标签上方，左对齐，相邻组合之间间距≥24px。
- 两个相邻元素绝不会共用同一字号；每一层级的字体大小都应有明显区分。
- **所有文本均采用句子大小写**（包括数值标签）。切勿对任何文本使用 `text-transform:uppercase` 或 `letter-spacing`。
- **所有颜色和字体均需使用 CSS 变量，切勿硬编码十六进制色值或字体族名称。** 背景使用 `var(--slide-bg)`，主文本使用 `var(--slide-fg)`，强调色（如标题、关键数据、边框、图标）慎用 `var(--slide-primary)`，辅助色使用 `var(--slide-accent)`，标题使用 `var(--slide-font-display)`，正文使用 `var(--slide-font-body)`。对于半透明叠加层，使用 `color-mix`（例如：`color-mix(in srgb, var(--slide-primary) 20%, transparent)`）。每张幻灯片的颜色方案控制在2–3种以内。主题变量均由 StylePlan 中的 `:root` 块定义，不得重复定义。
- **在幻灯片文件中，出现 `#` 颜色或 `rgb(` 均属错误。** 仅有两种例外情况，除此之外一律禁止。一是该幻灯片自身的 `--hero-scrim-color:`，其颜色取自该幻灯片的图片；二是封面标题覆盖照片时，背景遮罩上仍保留 `#fff` 或固定深色值。其他所有场景的颜色必须是 `var(--slide-*)`，或通过 `color-mix(in srgb, var(--slide-*) N%, transparent)` 来生成浅色调。若需某色更深或更浅，则使用 `color-mix(in srgb, var(--slide-fg) 90%, black)`，或以 `white` 代替 `black`。覆盖图像的色块应使用渐变中的 `var(--slide-bg)`，而非对其各通道分别设置 `rgba()`。上述规则适用于 `style=` 属性、幻灯片自身的 `<style>` 块、渐变停点、阴影以及 SVG 的 `fill`。也适用于徽章、边框、状态标识，以及按层级或风险等级进行颜色编码的集合。在 `deck.css` 中，`#` 仅允许出现在唯一的 `:root` 块中，以及用于 `html, body` 的背景色和 `var(--hero-scrim-color, #1a1a2e)` 的回退色。反色卡片无需新增颜色，因为深色背景搭配浅色文字可直接使用 `background:var(--slide-fg)` 和 `color:var(--slide-bg)`。硬编码的原始值当下可能看起来无误，但当周围环境的主题发生变化时，它将保持原样，无法同步更新。
```html
  <!-- 错误：这些样式在主题变更时都会保持不变 -->
  <strong style="color:#008694">                                        <!-- 复制的色值 -->
  <div style="border:1px solid rgba(0,134,148,0.12)">                    <!-- 色值以rgba通道形式存在 -->
  <div style="background:#FAF7F2">                                       <!-- 纸张颜色，完整写出 -->
  <div style="background:color-mix(in srgb, #11181F 70%, transparent)">  <!-- 复制到函数内部 -->

  <!-- 右侧 -->
  <strong style="color:var(--slide-primary)">
  <div style="border:1px solid color-mix(in srgb, var(--slide-primary) 12%, transparent)">
  <div style="background:var(--slide-bg)">
  ```
- **内联 SVG 的颜色通过 CSS 而非属性来设置。** 表现属性无法可靠地解析 `var()`，因此不要写 `fill="var(--slide-primary)"`，而应写成 `style="fill:var(--slide-primary)"`，或者将样式规则放在 `deck.css` 中。如果图表的 `fill` 和 `stroke` 属性使用十六进制值，则在任何主题切换时都能保持这些颜色。通常，图表是幻灯片上最大的彩色元素。
- 每张幻灯片都会为 `section.slide` 设置一个不透明的背景（即主题变量 `--slide-bg`，或全幅覆盖图片）。未设置背景时，页面会显示灰色，看起来像是出错。不要为封面或结束页设置不同的纯色背景；它们的视觉效果应来自全幅图片或版式设计，而不是单纯更换纸张颜色。
- 所有可读文本与紧邻其后的背景之间的对比度需达到 ≥4.5:1（对于 ≥24px 或粗体 ≥19px 的文本则为 ≥3:1）。**切勿通过 `opacity` 或低透明度的 `rgba`/`hsla` 来制造层级或弱化文字**：因为这些会与背景混合，导致对比度悄然低于 AA 标准；请改用 `var(--slide-muted)`。加粗的标签及其后跟随的破折号或冒号后的内容应保持相同的正文层级和完整对比度，不要将其灰化。
- 不要在任何地方使用 `padding-bottom`；垂直间距请使用 `padding-top`。

## 图片

- 默认情况下，每个演示文稿都需要配图：可通过图像搜索技能获取真实拍摄对象（如标志、产品、地点或人物），或使用 `media.generate_image` 生成概念性素材。如果确实无法获取或生成图片，或者项目需求明确要求无图演示，则另当别论；否则，仅靠纯文字排版或以 CSS 渐变和内联 SVG 填充空间的做法并不理想。图表承载数据，图片传递概念。若项目要求禁止使用合成图片，并不意味着完全排除生成途径，而是限制了来源途径，因此仍需通过图像搜索技能获取真实素材。
- 每个可通过视觉呈现的重要部分或概念都应配有一张能真实反映该内容的图片。**切勿**在仅包含数字、统计或陈述的单元格中放置装饰性图片，也不要在网格单元格中仅仅为了填充或凑数而加入图片（非说明性的图片比空白更糟糕）。整套演示文稿中至少应包含两幅说明性图片，根据各自的主题分别获取或生成，且仅用于辅助说明内容。
- **封面必须配有主图**：若主图主体为真实事物（如公司、产品、地点或人物），则通过图像搜索技能获取；否则，使用 `media.generate_image` 生成。纯文字封面属于错误；CSS 渐变、纯色或内联 SVG 都不能替代真正的主图，除非因无法获取图片或项目明确要求无图时作为经文档记录的备选方案。
- 除全幅主图及分屏图外，其他图片均应添加圆角（大图 16–24px，缩略图 12px）；全幅主图和分屏图则应贴边无圆角（参见 `design-system.md`）。
- 用于填充单元格的图片应使用 `width:100%; height:100%; object-fit:cover`，使其完整填充单元格而不留白边。**切勿**在弹性轨道（`1fr` / `height:100%` / `flex:1`）中为这类图片设置固定高度或 `max-height`：固定高度的子元素无法填满弹性父容器，会导致出现白色条带。请按单元格的宽高比请求图片尺寸（高单元格用竖图，宽单元格用横图）。仅当图片内含文字或为不可裁剪的示意图时，才使用 `object-fit:contain`（叠加在 `var(--slide-bg)` 背景之上）。
- 在验证前，将所有图片以内联 `data:` URI 形式嵌入到展示该图片的幻灯片文件中，使每张幻灯片都能独立运行。概念性图片通过 `image-directive.md` 规定的 `media.generate_image` 生成，真实照片和标志则通过图像搜索技能获取；两类资源均存放于 `.src/media/` 目录下。整个演示文稿**不得**包含任何外部引用，包括字体：主题使用的字体族应在 `deck.css` 的 `:root` 令牌中声明，然后由 `embed_deck_fonts.mjs` 将这些字体以 `@font-face` 规则的形式写入 `deck.css`，直接嵌入字体字节。任何文件中都不得出现 `fonts.googleapis.com` 或 `fonts.gstatic.com` 的 URL。图片和 CSS 中的 `url(...)` 也应始终为 `data:` URI。幻灯片文件中绝不能保留任何其他 `http(s)://`、`file://` 或相对路径的 `.src/media` 引用。
- 若找不到合适的图片，宁可省略，也不要重复使用不匹配的图片。
- 主图文字的可读性：建议将图片置于单独的面板，文字置于另一块纯色的 `var(--slide-bg)` 面板上（无需遮罩）。若文字必须置于照片之上，则应在文字区域下方添加渐变遮罩（而非全幅遮罩）、使用磨砂玻璃卡片，或叠加文字阴影。切勿将未经样式的文字直接置于照片之上。
- 内容页上的图片边缘应保持平直或圆角矩形，切勿用斜线 `clip-path` 或倾斜边切割文字栏（倾斜边缘会使标题看起来偏移）；对角分割仅适用于封面（参见 `design-system.md`）。
- 并排的两个面板宽度之和不得超过 100%，且不得重叠。

## 图表与示意图

- 当幻灯片需要绘制数据时，请先阅读 `/opt/hatch/skills/artifacts/references/charts.md`：其中详细说明了数据来源、如何为演示文稿绘制图表，以及通用的编码规范。
- 切勿将图表或图片与其文字垂直堆叠，应并排摆放。

## 溢出与卡片尺寸

- `section.slide` 的尺寸为 `1280px × 720px`，`overflow:hidden`，`box-sizing:border-box`。超出 720px 的内容会被**无声截断**，不会显示。作者在编写时无法看到溢出情况，因此应在前期规划时确保内容在合理范围内，并依赖 `render_audit` 的 `overflow` 和 `fill` 检查（参见 `workflow.md` 第 8 步）来发现潜在问题。
- 编写前应预留可用高度 ≈620px（720 减去边距）。一张幻灯片大致可容纳一个标题加上 10–12 行正文/列表项；最多约 5 个项目符号或 3–4 个卡片，均为硬性上限而非目标。文字栏旁若配有图片，则可占据全部 720px 高度，但实际只能容纳约一个标题加 3–4 行短文；若在此处放入较长的引言段落或超过 4 行内容，则会发生溢出。
- 文本卡和数据卡**会自动适应内容高度**（`height:auto` 或 `min-height`）；切勿为统计卡、提示框、便当式单元格或对比区块设置固定高度或行数限制，也切勿在文本中间进行截断。
- 对于卡片网格，应使用 `align-items:stretch` 配合自动行高（`grid-auto-rows:auto`），使同一行中的所有卡片都拉伸至最高者高度，避免被裁剪。保持 `min-width:0`；文本卡不要设置 `min-height:0`，不要使用 `align-items:start`，也不要使用固定高度或占满 720px 的 `1fr` 轨道。若最高的卡片可能超过 720px，则应减少卡片数量或缩短文本长度。
- **便当式布局**应呈现均衡的网格效果：相邻单元格高度一致（`align-items:stretch`），较高的功能区或图片单元格可跨两行，或占用两列（`grid-column: span 2`），整体居中排列（`align-content:center`）。文本单元格按内容自适应高度，只有图片单元格通过 `object-fit:cover` 进行填充。

## 版式与组合设计

- 每张幻灯片在样式规划的 `layout_plan` 中都分配有一个版式类（`cover`、`closing`，或八种内容版式之一，详见 `design-system.md`）。将其视为默认选项，但应以内容为导向进行选择：当幻灯片内容较为空白时，优先采用更简洁的版式，而非密集的网格；切勿为填充指定网格而刻意添加卡片元素。
- **结束页** 应为居中对齐的文本，背景为单一均匀色块或一张跨全幅720px画布的满版图片，绝不能使用高度不足的面板或色带，以免形成双色调条带。
- 当幻灯片同时包含文本和图像时，应选用演示文稿中预设的两种 **组合样式** 之一（`StylePlan.lockups`，取自 L1/L2/L4，详见 `design-system.md`）；确保组合样式中的图像区域紧贴边框，使图像或文本下方不露出任何空白背景带。切勿自行设计新的图文排布方式。
