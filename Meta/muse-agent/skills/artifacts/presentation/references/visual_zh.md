# 演示文稿视觉指南

用户在`verbatim_request`或上一轮对话中提供的视觉指示具有权威性。在进行样式设计之前，先按照通用默认设置过一遍：每项视觉选择都应基于其是否适合该交付物，而非因为它是最简单的模板（到处都是一个强调色、单一字体承担所有任务、标题与正文之间没有层级关系、用表情符号充当图标）。

- 在创作新幻灯片之前，先确定 StylePlan。首先根据 `workflow.md` 中的规则确定幻灯片数量，然后从规划的内容中为每张幻灯片推导出一个稳定的 kebab-case 格式的 ID（以原始请求和发起对话提供的内容为依据），其中 `cover` 为第一张，`closing` 为最后一张。将严格格式的 JSON 写入 `project_dir/.src/style-plan-input.json`，包含 `title`、`brief` 和 `slide_ids`。其中，`brief` 是原始请求加上来自上一级对话的任何明确视觉指示。
- 使用您写入的确切输入文件路径作为参数，运行 `/opt/hatch/bin/hatch-slide-style plan --input`。切勿在 shell 参数中传递标题或简述。该命令的 JSON 输出即为整个幻灯片的 `style_plan`；将其原样写入 `project_dir/.src/style_plan.json`。必须生成 StylePlan：如果解析失败，应报告构建失败，而非自行编造替代方案。
- 对于已有的幻灯片编辑，除非用户要求重新设计主题，否则保留现有的 `.src/style_plan.json`。若需重新设计主题，则使用现有幻灯片标题、用户指定的设计方向以及现有幻灯片 ID 运行相同命令，并用命令的 JSON 输出替换保存的主题方案。
- 解析后的 `style_plan` 是唯一的样式权威。所有颜色、字体、布局和标识组合均应源自该计划；不得直接根据请求文本、上一级对话内容或已保存的文档主题对幻灯片进行重新设计。
- 优先采用以图片为主的版式，强调清晰的层次结构，并保持文字简洁。每张幻灯片最多包含约 5 个项目符号或 3–4 个卡片；避免出现段落密集的幻灯片。
- 避免使用通用的企业风格幻灯片、千篇一律的构图、装饰性填充元素，以及重复的“标题+项目符号”布局。
- 幻灯片上不得添加任何辅助性元素：如标签、副标题、摘要行、眉标、引语、徽章、芯片、标签和说明文字等。不要在标题上方放置小型标签或小标题（如“3 — 问题”一行）；应将要点直接写入标题中。
- 封面仅由幻灯片标题叠加主视觉图像构成，不得添加副标题、标语、日期或来源行、引语、标签、统计框或按钮。其余细节留待内容页呈现。
- 切勿通过缩小文字来勉强容纳内容。正文、项目符号和卡片文字始终保持 16–18px，且不得小于 14px；只有短小的统计标签可设为 11–13px。若内容在此字号下仍无法完全容纳，应删减内容或将信息拆分到多张幻灯片上，而非缩小文字或压缩间距。
- 整个幻灯片统一使用一种主题：所有颜色均应取自 StylePlan 的 `--slide-*` 变量（如 `--slide-bg`、`--slide-fg`、`--slide-primary`、`--slide-accent`、`--slide-muted`），而非直接使用十六进制色值；并为每张幻灯片设置相同的背景。整个幻灯片应呈现出统一的设计体系感，而非多种主题混杂。
- 每张幻灯片只表达一个核心观点，宁可删减也不可过度堆砌。将幻灯片的核心论点写入标题作为主张，重点突出不超过 3 项指标，每张内容页控制在约 5 个项目符号或 3–4 个卡片以内。每个事实只需一处呈现（不要将图表中的数据同时以统计卡片形式重复展示；图表归 `/opt/hatch/skills/artifacts/references/charts.md` 管理）。当原始资料超出全尺寸容纳范围时，应舍弃大部分内容；内容较少的幻灯片观感更佳，也让文字更有呼吸空间。
- 切勿将未加样式的文字直接叠加在照片上。应使用遮罩、面板或分屏布局来形成对比。
- 确保文字在演示距离下依然清晰易读。建立明确的层级关系：标题、正文、统计数字、统计标签。不存在单独的小节标签层级；小节的核心观点应体现在其标题中。
- **全文采用句子大小写**（包括统计标签）。切勿对任何文字使用 `text-transform:uppercase` 或调整字距。
- 防止文字重叠与裁切。优先减少内容，而非一味缩小字体。
- 每套幻灯片均需配有真实图片，封面使用主视觉图，内容页也需配图；不得出现空白图片框或“此处插入图片”的占位符，除非需求说明明确要求无图片（步骤 6）。
- 图片必须与相邻的论点紧密相关；若找不到合适的图片，宁可省略，也不要使用不相关的图片。
- 不得凭空捏造事实、日期、指标、引用或来源名称；所有论点均应基于原始请求及发起对话中用户陈述的事实。
- 有关详细的视觉规范，请参阅 `authoring.md`、`design-system.md` 和 `image-directive.md`。幻灯片的工作流程与编辑指南则涵盖了规划、校验及导出的相关机制。如果交付的演示文稿报告了视觉问题，请将受影响的页面重新渲染为 PNG 格式并读取，然后再修改源文件。在没有视觉证据的情况下，不要臆测布局或样式缺陷。
