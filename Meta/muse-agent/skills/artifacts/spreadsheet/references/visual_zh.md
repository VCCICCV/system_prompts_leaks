# 电子表格视觉指南

用户在 `verbatim_request` 或上一级对话中提供的视觉指示具有最高权威性。在进行样式设置之前，应先按照通用默认规则进行一轮处理：每项视觉选择都必须基于其与当前交付物的契合度，而非出于模板最简便的考虑（例如：处处使用同一强调色、仅用一种字体承担全部任务、标题与正文之间缺乏层级关系、用表情符号充当图标等）。

- 除非用户明确要求样式化，否则不得应用已保存的 PDF 主题。
- 应使用醒目的标题、清晰的层级结构、一致的间距，并适度使用颜色。表格需具备可读的表头、稳定的对齐方式，以及与其数据相匹配的数字格式。
- 图表、绘图及其他事实性图形应根据其源数据以确定性方式生成。

## 验证

在返回工作簿的链接之前，先读取该工作簿：

```sh
# 您的构建任务名为 `project_dir`。请使用它，而不是硬编码的 `your_files`
# 路径：在某个目标下构建的工件位于该目标的 `files/` 目录中。
# `project_dir` 来自您的构建任务。将其开头的 `~/` 写成 `$JARVIS_HOME/`：因为 shell 会在引号内保留波浪号的字面意义，所以 `"~/workspace/..."` 会被解析为一个名为 `~` 的目录。
DIR="$JARVIS_HOME/<来自构建任务的 project_dir，去掉开头的 ~/>"
python3 "/opt/hatch/skills/artifacts/scripts/validate_xlsx.py" \
  "$DIR/<file_name>.xlsx" --json-out "$DIR/.src/validate/xlsx.json"
```

- 如果文件不是有效的工作簿、是损坏的归档文件，或者所有工作表均为空，则退出时返回非零状态码。请先修复后再重新运行；在检查失败时不要提供链接。当请求的是空白模板时，请使用 `--allow-empty` 参数。
- 在摘要中列出其工作表、单元格和公式的数量。`csv` 输出将不进行读取器校验。

## 财务模型约定

除非用户另有说明或现有文件已采用其他设置，否则模型和计算器的默认设置如下：

- 按角色进行颜色编码：蓝色文本用于硬编码输入和情景调节变量，黑色用于公式，绿色用于指向其他工作表的链接，红色用于指向其他文件的链接，黄色底色用于关键假设及用户需填写的单元格。
- 数字格式：货币格式为 `$#,##0`，并在标题中注明单位（如 `Revenue ($mm)`）；负数用括号表示，零值显示为短横线（`$#,##0;($#,##0);-`）；百分比格式为 `0.0%`，以小数形式存储（`0.15` 显示为 15.0%，而存储 `15` 则显示为 1500.0%）；估值倍数格式为 `0.0x`；年份以文本格式显示，确保 `2024` 不会被错误地显示为 `2,024`。
- 结构：每个假设均置于单独的带标签单元格中，并由引用它的公式调用（如 `=B5*(1+$B$6)`，而非直接使用 `=B5*1.05`）；公式在各预测期间保持一致，因为行中仅有一个手动编辑的单元格是最常见的隐性错误来源；对可能为零的分母进行保护性处理。
- 全文采用专业默认字体（单元格预装 Liberation Sans 和 Liberation Serif，作为 Arial 和 Times 的替代字体）。
