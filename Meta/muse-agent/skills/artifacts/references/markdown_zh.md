# 用于构件文件的 Markdown 格式规范

这些规则适用于构件的 Markdown 文件（`.md` 格式的交付物、报告，以及任何可能导出为 PDF 或 Word 的构件内容）。

**表格：**
- 单元格内容尽量控制在约 25 个字符以内。若内容过长，可使用缩写或将详细信息移至表格下方的脚注。
- 单元格内不使用完整句子，仅使用简短短语、关键词或数值。
- 表格单元格中不得包含 URL。链接应置于“来源”部分或表格下方的脚注中。
- 最多使用 3–4 列。若需更多列，可拆分为多个表格，或改用定义列表。
- 数值列右对齐，并使用 `---:` 以方便快速浏览。

**列表：**
- 当每个条目包含子描述或长度超过几个词时，顶级条目之间空一行。
- 子条目之间不留空行，紧贴其父条目。
- **加粗首句**，后接描述：`**事项**：此处说明`。
- 嵌套层级不超过 2 层。若需第三层，请重新组织为带标题的章节。

**表情符号：**
- 在可导出文档（即用于转换为 PDF/Word 的 `.md` 文件）中禁止使用表情符号。大多数 PDF 渲染引擎会将其显示为方框或缺失字形。
- 请使用文本标记代替：用 `**注意：**` 表示提示，用 `-->` 表示流程，用普通 `*` 作为项目符号，用 `---` 作为分隔线。
- `.md` 文件中的章节标题应使用纯文本（如 `## 设计`），而非表情符号前缀（如 `## 🎨 设计`）。

**通用建议：**
- 在各主要部分之间使用 `---` 水平线，以增加视觉上的留白空间。
- 在 GitHub 上使用 `> [!NOTE]` / `> [!WARNING]` / `> [!TIP]` 来标注提示信息。若需跨平台输出，请使用 `**注意：**` 等加粗前缀。
- 标题采用句子大小写（如 `## 关键发现`），除非是专有名词标题，否则不使用标题大小写。
