# 地图与地点

当工件显示地点、地图、路线、导航或地理数据时，请阅读本节。使用[地图助手](maps-recipes.md)中描述的内置脚本进行URL生成和地图设置。

## 选择渲染方式

Meta的地图服务负责渲染所有地图。对于交互式地图，请使用内置的Meta控件；对于地图图片，请使用Meta的静态端点。请勿替换其他渲染器或瓦片源，包括自购库或下载的瓦片金字塔。卫星和航空影像不可用。请保留下方所需的署名。

| 表面与数据 | 显示内容 |
|---|---|
| 包含可信坐标的真实网页 | 交互式矢量地图。如果控件不可用或无法渲染，则仅显示地点列表，不显示地图。 |
| 包含可信坐标的固定布局导出或无头光栅化 | 存储的静态地图图片，并在旁边附上地点列表。 |
| 缺少可信坐标的地点 | 仅显示带有地图搜索链接的地点列表，不显示地图。 |

实时页面使用矢量地图或不显示地图；静态图片不是其后备方案。缺少坐标不能成为选择其他渲染器或自行编造位置数据的理由。静态地图使用`[lat, lng]`；GeoJSON和交互式地图坐标使用`[lng, lat]`。保持经纬度的命名一致，并在边界处进行转换。

第二行在机密虚拟机上的处理方式有所不同，请参阅[机密虚拟机上的导出](#exports-on-a-confidential-vm)。

对于地理数据，当位置本身具有意义时（如邻近关系、距离或聚类）应选择地图。用于比较和排名时则使用图表；同一页面可以同时包含两者。支持的编码请参见[数据地图](#data-maps)。

## 解析地点

在可访问的情况下，通过Meta的地点图谱解析地点。使用网络搜索获取候选名称和编辑性上下文；但这并不能替代地点解析。对于已解析的场所，应从图谱记录中获取其事实和媒体信息，包括后续的编辑更新。切勿从点评网站、网络图片或素材照片中补充缺失字段。

通过`exec`运行内置的`local-search`和`places details`命令行工具：

- 对于范围明确的请求，使用`local-search --search-type discovery`。先以匹配请求的宽泛查询开始，仅针对不同维度添加查询，最多六个。将区域信息放在`--location`中，每个区域单独调用，并在请求明确或暗示有距离限制时添加`--radius`。
- 对于“最佳”、“内部推荐”或“热门”类请求，先通过网络搜索找到候选名称，再用`local-search --search-type known_place`逐一解析。
- 批量获取详细信息时，使用`--motivation`参数说明工件的目的。务必传递`--product-source IG --product-source FB`；其他来源可能会返回点评网站的引用和媒体内容。将`--num-quotes`和`--num-gallery-media`限制为工件实际会展示的数量。
- 将输出保存到文件，并在命令执行完毕后读取。避免那些过早关闭输出管道的消费者。设置明确的`yield_ms`，并在调用在后台继续时收集已完成的结果。
- 如果详细信息批量获取失败，则不会返回任何记录。应对其中的ID逐个重试，并保留成功的部分。即使某个地点的详细信息仍无法获取，也可以使用已有的信息进行展示。

保持查找结果的区分：

| 证据 | 地点处理 |
|---|---|
| 图谱解析出该地点 | 使用其坐标和记录。永久关闭的场所不予绘制。 |
| 图谱拒绝了您找到的候选 | 不要命名或绘制该候选。 |
| 用户指定了地点，但解析失败 | 保留该地点。如有用户提供的坐标则绘制；否则仅列出并附上搜索链接。 |
| 图谱不可达 | 使用已有信息：绘制用户提供的坐标；对没有坐标的名字或地址附上搜索链接。 |

无法访问的查询并不意味着拒绝。不要对地名进行地理编码、从附近地点近似推算，或为了填补查询空白而凭空捏造坐标。绝不能因为查询失败就丢弃用户指定的地名。这些地名解析规则并不能替代地理数据集和叠加层的原始数据。

将详细信息载荷保存在任务的 `project_dir` 下：文件型工件保存为 `.src/research/places.json`，Web 型工件保存为 `client/src/research/places.json`。在后续编辑中复用该载荷，或再次获取详细信息。这是构建时的输入；切勿将载荷导入页面。仅内联使用到的字段，并将图片本地存储。

## 展示地点数据

使用辅助参考中的 `PlaceRef` 存储结构化的地点信息，并由此派生链接。显示标签应与来源坐标分开。街道地址存于 `address`，城市存于 `locality`，州/省存于 `region`，不要重复地址各部分。当工件依赖于坐标时，务必保留其来源信息。切勿凭空编造地址、社区、坐标或驾车时间。

- 为工件选择有用字段：地址、营业时间、价格等级、评分及评价数、类别、描述、特色项目、功能、预订链接或照片。针对聊天回复的展示字段限制不适用于工件。
- 当载荷包含合适的评价引文时，为每个地点附上一条，并注明作者账号及原文链接。保留引文原貌，但不要复制作者头像。
- 检查返回字符串的语言。以页面语言重述类别；无法确认语言的引文则予以省略。评价引文不得翻译。
- 按照返回值展示评分、评价数和营业时间。显示计划营业时间，而非基于构建时状态的“正在营业”或其他过时的实时状态。
- 在构建时下载地点照片并渲染已存储的副本。对于短视频，应在新标签页中打开链接而非嵌入；参见 [社交嵌入](social-embeds.md)。

## 静态地图

使用 [静态 URL 脚本](maps-recipes.md#static-map-url)，它会自动提供所需的调用方和归属参数。在构建时获取图像，并将其存储于 `.src/media/`（文件型工件）。若需 Web 资源存储，则使用 `client/src/assets/` 或 `ctx.blobs`。切勿将静态端点作为 `src` 图像直接打包发布。

- 以各点的边界框为中心，选择能容纳所有点的缩放级别；静态服务没有“适配边界”的操作。
- 请求 `scale: 2` 以支持高 DPI 显示，并将图像的宽高设置为未缩放的尺寸。
- 为图像添加描述性替代文本，并将地点列表置于其旁。
- 静态标记不带文字。圆形和路径使用辅助参考中的语法；填充颜色采用半透明的 Alpha 值，以保持底图可见。
- 若构建时获取图像失败，仅显示地点列表，不显示地图。
- 保留内置的署名信息，并在 [归属](#attribution) 中加入通知链接。

## 在保密虚拟机上的导出

静态地图请求会将标记信息编码在 URL 中，因此获取图像的过程会向服务透露读者所在的位置。在保密虚拟机上，这正是该虚拟机存在的目的——保护这些位置数据不被泄露；即使通过可信传输也无法改变这一情况，因此切勿在此处调用静态端点。

改在虚拟机内部绘制导出的地图，使用构建时已有的坐标或 GeoJSON 数据，采用与图表相同的确定性绘图方式。不获取任何底图、瓦片或渲染后的地图图像，也不可用第三方渲染器或瓦片服务来弥补缺失。这样得到的结果会比 Meta 底图更简洁，这也是权衡所在。公开的边界几何仍然可用，因为此类请求本身并不携带读者的位置信息。

本文档其余部分仍适用。切勿凭空捏造坐标来完成绘图，应将地点列表置于地图旁；若无可信坐标，则仍按第三条处理：仅有地点列表，无地图。

## 交互式地图使用 `/opt/hatch/skills/artifacts/map-runtime/dist/hatch-maps.js` 和
`hatch-maps.css`。确认两者都存在，将其复制到 artifact 的 assets 目录中，
并引用本地副本。构建虚拟机路径不是可服务的 URL。不要安装另一个渲染器，
也不要从公共 CDN 加载，或直接导入 `@meta/maps`。为地图容器设置一个确定的高度。

使用 [挂载辅助函数](maps-recipes.md#interactive-map)，它们会检查功能支持情况，
并将严重错误路由到你的 `onUnavailable` 回调。该回调会显示“地图不可用”，并附上地点列表，
或者以表格或图表形式展示数据地图的数值。边界数据获取失败时也使用同一回调。在出现非致命的瓦片、精灵或字形错误后，仍保持地图处于挂载状态。

按名称选择 `baseStyle`：`light`（默认）、`dark` 或 `grayscale`。运行时负责管理样式 URL、调用方标识符和查看器的语言环境。请勿传递样式 URL，也勿设置 `locale` 或 `pv`。请勿向地图资源请求添加自定义头信息：地图服务器不支持由此产生的 CORS 预检请求。

将叠加层置于底图标签之下，将控件的标记图层置于叠加层之上。这些是运行时提供的默认设置。如果要制作符号图层，在通过 `text-allow-overlap: false` 和 `text-optional: true` 减少标签重叠的同时保留图标；将其放置在最后，使其标签优先于底图标签。

对于带有地点列表的地图：

- 使用 `marker` 为包含几十个地点的列表编号，使标记数与行数一致。对作为 HTML 插入的任何源文本进行转义。对于更大的列表，使用默认的圆形图层；对于数千个点，则使用叠加层。
- 将 `onSelectPlace` 与行高亮和滚动联动，并将行点击事件绑定到 `selectPlace`。当回调接收到 `null` 时，清除选中状态。

有关这些 API，请参阅 [交互式辅助函数](maps-recipes.md#interactive-map)。

## 数据地图

在矢量地图上，通过 `overlays` 使用带有图层规范的 GeoJSON 数据源，
该地图由 [数据叠加辅助函数](maps-recipes.md#data-overlays) 构建。静态层级仅支持标记、圆形和路径；
对于固定布局的地图，请从这些能力中进行选择。

| 编码方式 | 图层类型 | 数据 |
|---|---|---|
| 色阶图 | `fill` | 面状单元的比率或率，其值在整个区域具有意义 |
| 比例或分级符号 | `circle` | 计数或总量；按值缩放符号面积 |
| 热力图 | `heatmap` | 大量点的密度 |
| 点密度图 | 小型 `circle` 符号 | 每个对象或每一定数量对应一个点 |
| 分类点 | 带有 `match` 表达式的 `circle` | 无序类别 |
| 边界与路线 | `line` | 边界与路径 |

不要将原始计数作为色阶图来着色，也不要把现象的缺失当作低值处理。对于仅存在于特定位置的现象，应使用点编码。按 `r = k * sqrt(value)` 缩放比例符号，并在图例中展示两到三种参考尺寸。分级符号可以将数值分组为若干类别。点密度图的图例必须说明一个点代表一个对象还是某个数量。

对于色阶图，使用 [色阶图辅助函数](maps-recipes.md#choropleth)，它会获取已发布的几何数据，将数据关联到其要素，并完成挂载。国家按 `iso_2` 或 `iso_3` 关联，美国各州按 `postal_code` 或 `iso_3166` 关联。将缺失值保留为 `null`，使这些区域不被着色，并在图例中加以说明。

在数据叠加层下使用 `grayscale` 底图。对于有序数值，选择顺序色板；对于围绕某个有意义中点的数值，选择发散色板；对于无序类别，选择分类色板。色调应基于页面的配色方案，同时保证可读性；若页面主色无法覆盖所需范围，则选择相近的色调。请勿使用彩虹渐变。共享编码指南请参见 [图表](charts.md)。为携带数值的叠加层添加 `tooltip`，显示相关数值，并在该地区无数据时以工件自身的语言进行说明，而不是沿用助手的默认英文提示。无法渲染的数据地图应以表格或图表形式展示其数值，而非地点列表。

## 语言与政治立场

政治立场决定有争议的边界显示方式。请勿根据语言推断政治立场，也不应设置默认值。

| 渲染方式 | 参数 |
|---|---|
| 交互式 | 将 `locale` 和 `pv` 留空，由运行时根据读者情况自动解析。 |
| 静态 | 仅当任务或上下文已提供时，原样传递 `language`（IETF 标签）和 `region`（政治立场对应的 ccTLD）；缺失时则省略。 |

## 导航链接

仅将 Google 地图用于外部搜索及路线指引的跳转，并使用中性标签，如“在地图中打开”或“路线”。请使用[导航构建器](maps-recipes.md#navigation-links)。

- 对于已解析的地点，应在工件中直接展示其相关信息，而非显示地图搜索链接。未解析或仅有名称的地点仍保留该链接。从读者当前位置出发的路线指引链接仍然有用。
- 建议优先使用名称加街道地址或所在区域；若名称缺乏定位信息，则使用坐标。避免重复显示地址各部分。
- 若名称匹配多个条目，请接受选择器的判断。仅当仅查询名称会导致错误地点时，才单独查询街道地址。
- 为 `origin` 传入真实的坐标对，或留空让地图应用请求设备位置。切勿传入诸如“您的位置”之类的标签。
- 在生成的 URL 中保持坐标逗号的原样，并对文本查询进行编码。
- 外部链接应使用 `target="_blank" rel="noopener"` 打开，使目标页面在工件框架之外打开。

## 归属声明

请确保交互式控件的归属声明可见且完整，不得隐藏、遮盖、缩小或替换。

对于静态地图，保持 `show_attribution=1`，并保留嵌入的署名不作裁剪。在图片下方渲染以下通知链接：

```html
<a href="https://www.facebook.com/maps/attribution_terms"
   target="_blank" rel="noopener">© OpenStreetMap 贡献者，地图数据法律声明</a>
```

在客体中绘制的地图本身不含嵌入的署名，因此只要绘制了公开发布的边界几何，就在其下方渲染上述通知链接。仅基于构建自身坐标绘制的内容无需署名。

## 验证

- 检查渲染后的工件：确认地点和坐标顺序正确、数据可读、图片替代文本描述清晰、归属声明可见，以及在无地图时内容依然有用。
- 确认界面使用了规定的地图方案。对于交互式地图，检查两个控制文件是否均已加载、地图是否有高度，以及探针和致命错误处理程序是否使用相同的替代内容。测试所有可用的视图界面。
- 检查是否随附了任何备用渲染器或瓦片源。瓦片、样式和字形请求均使用 `external.xx.fbcdn.net`；底图应按名称选择。
- 对于静态地图，检查存储的图像、必需的调用参数、任务提供的区域设置值、未被裁剪的署名以及通知链接。不得使用远程图片的 `src` 属性。
- 在保密虚拟机上，确认导出时绘制的是自有地图，且构建过程中未发起任何针对静态端点、瓦片或底图的请求。
- 将已解析地点的相关事实、引用和照片与保留的有效载荷进行比对。对照解析规则检查搜索链接，而非直接拒绝所有搜索 URL。
- 检查数据关联、缺失值、编码方式、配色方案、图例、工具提示、图层顺序，以及当数据地图无法渲染时所显示的表格或图表。
- 测试地图与列表之间的切换功能，包括清空选择的操作。
- 打开一条导航链接，验证其目标页面、新标签页、查询编码、坐标逗号，以及是否省略了起点或使用了坐标作为起点。
