# 文档制品中的正文

## 范围检查

当文档制品的值为其文本内容时，请阅读本文件：无论是PDF、Word文档，还是其他形式，包括报告、简报或信函。对于幻灯片文稿（其文案规则和计划文件位于演示技能中）以及电子表格（无正文内容可遵循），则无需阅读。

以下两条例外情况优先于所有规则：

- **用户有明确要求。** 即使本规则有所限制，也应按用户要求提供结论、要点式条目、特定语气或其他内容。
- **这是一次编辑。** 保留文档中原有的语气，仅修改用户提出的问题部分。对所修改的内容进行回读检查；若发现某些部分并非用户要求改动，则在最终回复中说明，而不予重写。

## 先撰写大纲

在正文第一行之前，先在`project_dir/.src/OUTLINE.md`中编写大纲，每节一条，格式如下：

```text
章节：试点项目停滞的原因
论点：采用率下降是因为入职培训耗时三周，而非价格问题。
来源：数据负载第4至11行（每周新增注册用户数），用户关于定价的留言。
```

大纲即为文档的论证主线，因此每节都应包含一个论点。若无法提炼出论点，则删去该节；若两节表达相同论点，则将其合并。正文将分段撰写，若无大纲指引，各部分内容易相互脱节。

“来源”仅为供您参考的工作注释，不会出现在正式文档中。

撰写完成后请保留大纲。回读环节会依据大纲对文档进行校验，下一次修订也将以此为基础展开。

## 将论点置于标题中

陈述发现，而非主题。例如，应写“漏斗流失点在于入职培训”，而非“入职培训分析”；应写“三家供应商报价低于预算”，而非“供应商报价”。读者仅阅读标题，也应能把握全文主旨。

对于参考性文档，则使用简洁的描述性标题。手册、目录、发票、表格、术语表或简历等通常用于查阅而非通读，且读者已明确所需信息。

- 每个标题都应在正文中得到支撑。若正文无法证明标题所述，则该标题不如平淡无奇。
- 在标题、小标题或图注中合理组织信息，切勿简单重复需求：“面向非技术读者的家用储能简报”是任务提示，而非标题。
- 不要以重述全文内容的章节结尾。如能在开头以摘要形式列出主要发现，则属佳作。

## 根据格式调整语气

- 默认采用专业语体，因为文档通常会被归档、转发或交由他人审阅。若需求明确要求创意、活泼或个人化语体，则遵照执行。
- 使用需求指定的既定格式语体。旅游宣传册应呈现旅游宣传册的风格，事故复盘报告应体现事故复盘报告的风格。若用户提供参考文档或特定风格，则应与其保持一致。
- 针对需求中指明的读者群体写作，该读者往往并非提出需求的人。例如，某人转发给其领导层的简报，应针对该领导层撰写。
- 整篇文档使用一种语言，即需求所指定的语言，除非用户明确要求多语言文档。
- 正文须以完整句子书写，仅标签、表格单元格及自带语法的列表项可使用片段。
- 每种语言首次出现缩略语时均需展开全称，之后方可自由使用缩略形式。
- 采用连贯的叙述性文字，而非堆砌关键词。“两居室公寓，阿尔法玛区，月租1,400，无电梯”是表格中的一行；在段落中应写成一句完整的句子。
- 对于毫无实质内容的段落予以删除，但保留读者理解所需的冠词、连接词及解释性说明。要点式简写、省略冠词及未加解释的缩略语并非精炼，反而会在面向非专业人士的文档中造成困扰。

## 不予发布的部分

仅引用读者可查证的内容：页码、出版物、文档。
切勿引用工具、端点、您执行的查询或框架字段。
在格式允许添加链接的情况下，对来源进行超链接。自我佐证应遵循系统提示中的内容完整性规则；请严格遵守这些规则。
以下内容一律不得出现在文档中：
- 文档的组装方式、您遵循的指令、早期草稿的内容、您排除的部分，以及您对自身核查结果的信心程度。
- 工具名称、文件路径、用户输入的原始提示，以及属于其他任务的图片或材料。
- 延缓进入正题的“铺垫式”表述：“本节将探讨……”“值得注意的是……”“总而言之……”
- 不承载任何信息的装饰性标签：不可点击的标签、填充用的芯片、状态标识，以及每个部分上方的装饰性分隔线。
- 在内容缺失处以看似合理的文字进行填补。这是最隐蔽且代价最高的缺陷，因为它往往显得最为完整。请明确说明某项事实缺失，或直接留空该处。

## 回读正文
在内容定稿后、提交链接前，与格式的视觉校验同步进行回读。对于 PDF 文件，直接阅读已栅格化的渲染页面；对于 Word 文档，则回读其导出的纯文本。
对照 `.src/OUTLINE.md` 检查文档：
- 每个列出的章节均存在，且准确落实了其承诺的观点。
- 不存在超出大纲范围的主张，且任何论点均有可靠依据支撑。
- 各章节之间不出现用不同措辞重复同一观点的情况。
- 各标题按顺序单独阅读时，能够清晰地传达整体论证脉络。
- 全文的语体风格自始至终保持一致，并符合用户需求。若文档分段撰写，极易在中途出现风格漂移——或过于正式、或过于口语化，甚至压缩成笔记式表达。
- 与您的工作流程、核查过程、草稿版本或所用工具相关的信息均未出现在最终文档中。

针对发现的问题予以修正，重新渲染并再次回读。若某项修正需要您尚未掌握的原始资料，请在最终回复中如实说明，切勿试图通过文字掩盖。
