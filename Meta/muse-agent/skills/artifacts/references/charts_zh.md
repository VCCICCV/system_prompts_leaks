# 图表

在任何平台上绘制任何图表之前，请先阅读本节。首先明确一点：该图表是放置在固定页面上的渲染图像，还是页面中会随内容流动而重新布局的动态元素？这一选择将决定您应采用下文中的哪种技术方案。数据和编码规则适用于所有场景。

## 数字的来源

- 如果数据已经存在（用户提供的文件、您刚刚生成的文档、工作区中的电子表格），请直接读取并基于这些数据进行构建。切勿重新生成您已产出的数据：两代“相同”的数据不会完全一致，用户也无法判断哪一个是正确的。
- 除非您从一个数据源读取并据此构建了另一个数据源，否则不要声称两个产物显示的是同一组数据。
- 只使用来自原始来源的真实且可验证的数据。切勿捏造数值、日期、引用或来源名称，也切勿将您生成的图表作为引用来源。
- 如果某个数据源的摘要与其明细行不一致，请根据明细行重新计算，并在产物中注明这一点。
- 已发布的产物中不得包含随机性：`Math.random()` 会导致每次加载的结果都不相同。如果必须合成示例数据，请一次性生成并将其持久化到文件中，然后让每个产物都从该文件中读取。

**所有显示的数字均应由所绘制的数据计算得出。** 这包括标题、副标题、统计卡片、注释和汇总行；诸如“峰值”、“最高”、“增长最快”之类的最高值，应通过序列中的 argmax 计算得出，绝不能凭记忆给出；以文字表述的比较和计数（如“增长40%”、“超出阈值8个”）；以及差值，其两端数值都必须存在于数据集中。若在文本中直接输入一个数值，一旦数据发生变化，该数值就会出现偏差。切勿对显示的统计值进行向下取整或向上取整：`max(22, computed)` 只能保证是一个数字，而非事实。切勿声称完成了您并未实际计算过的校验。
  
总计与占比：应根据其旁显示的各部分来计算总计，绝不能使用与各部分不同的数据源。百分比应共享同一个分母，且各部分之和必须等于整体；若各部分之和仅为90%，则说明有部分缺失或总计错误，产物中应明确指出是哪一部分缺失或总计有误。只有当计数与您所绘制的内容一致时才予以标注。为剩余部分命名；未标注的扇区将难以辨识。

## 数据如何映射至图形标记

以下规则适用于所有平台。如果您手动绘制图表，这些规则就是您即将编写的计算逻辑；如果由库来完成映射，则务必检查其输出，因为库的默认设置可能会绘制出被截断的基线或裁剪数据的坐标轴。

坐标轴：

- 域应由数据推导得出，切勿硬编码限制。硬设的最大值终将小于实际数据，超出该范围的数据点会被无声地裁剪掉。请确保所有绘制的数值都位于您设定的范围内。
- 柱状图和面积图的基线必须从零开始：长度表示大小，截断基线会误导读者。如果变化仅在截断尺度上才能显现，请改用折线图。当截断不可避免时，应在图表本身上明确标示（例如可见的轴断裂），而不是在旁边的说明文字中提及，因为后者无法随截图一起传播。
- 范围应与问题相匹配：若坐标轴过宽，导致有意义的差异在视觉上表现为相同的条形；或过窄，使噪声看起来像山脉，则都会造成误报。
- 每种编码方式对应一个带标签的刻度。不同单位的两条序列需要两个带标签的坐标轴或两张图表；通过常数缩放一条序列使其共用一个坐标轴的做法，本质上仍是同样的问题，只是多了一道步骤。
- 每个坐标轴都应提供可读的刻度，仅有数值标签并不构成完整的刻度。

标签：

- 切勿在代码中截断标签文本：被截断的标签会被误认为是数据的一部分（如“Utiliti”）。可通过旋转、换行、缩小字体或减少刻度数量等方式调整，但在做出选择前，务必测量最长标签与可用空间的关系。
- 标签的省略应保持一致，要么全部保留，要么全部省略；只裁剪最长的标签会隐藏最大值。
- 检查文本与容器（卡片、绘图区域、饼图空心部分）的适配性，而不仅仅是视口，并避免标签之间或标签与图形标记之间的重叠。

图例与注释：

- 每个已绘制的序列都会出现在图例中，每个色块都基于渲染器使用的相同值生成；两个序列绝不能映射为同一种颜色。
- 参考线或注释位于其对应的统计量位置：标注为“中位数”的线应位于中位数处。
- 装饰性标记必须保持比例关系，否则就不是标记。

数据形态：

- 缺失数据应以空白表示。切勿在空缺处进行插值；读者无法区分数据缺失与数值为零。
- 不等间距的数据需要使用真实的刻度：例如，2021、2023 和 2026 若被当作三个等距的类别，则会误导读者认为间隔相等。
- 部分时段应明确标注为“部分”，否则会被误读为数据骤降。
- 整体与部分的关系图应展示所有部分；即使对某一部分进行了合并处理，剩余部分仍需命名并计入总数。
- 切勿将数值截断至区间上限：若将最大值设为100%，则108%和166%将被视为完全相同。

## 按呈现载体划分的技术规范

### 幻灯片演示文稿

- 使用确定性的 Python 工具（如 matplotlib）从真实数据生成图表图像。切勿使用 CSS 形状、渐变、带样式的 div、内联 SVG 或 Mermaid 来伪造图表，也切勿使用 `media.generate_image` 来生成图表：生成的图像适用于概念性内容，而图表承载的是实际数据。
- 使用幻灯片主题色系进行配色：将 `--slide-primary`、`--slide-accent`、`--slide-fg` 和 `--slide-muted` 传递给图表脚本。
- 使用 `object-fit: contain` 来放置图表，切勿使用 `cover`，因为后者会裁剪坐标轴和标签。这会覆盖单元格默认的 `cover` 设置。
- 图表库会自动计算刻度、刻度线和图例，但仍需对照上述编码规则进行检查；matplotlib 很可能会截断基线。
- 幻灯片的布局及“一事一归”原则应遵循 `slides/authoring.md` 中的规定。

### PDF 或印刷文档

- 使用 Python 脚本（如 matplotlib、plotly 或 seaborn）构建图表。切勿使用 `media.generate_image` 或任何其他媒体生成工具来制作数据可视化。
- 页面排版（包括 `object-fit`、`max-height` 以及可能裁剪坐标轴的 `cover` 设置，即便验证通过）由 PDF 技能的 `workflow.md` 文件负责。如果图表过小以至于难以辨认，请提高其 `max-height` 或将其移除。

### 无需构建步骤的自包含页面

适用于 `runtime: static` 环境以及任何不依赖打包工具的实时页面。

- 手动编写内联 SVG 来绘制图表，而非在运行时从 CDN 加载图表库；这样可将图表的正确性直接写入文件，而不依赖于必须先解析才能渲染的外部依赖。
- 由于没有库来计算刻度、刻度线、标签或图例，因此“数据如何映射为图形元素”中的每一条规则都需要您手动算出。在绘图之前，务必确定数据范围、基线、标签策略、图例以及注释的位置。
- 将数据以字面数组的形式内联一次；该数组是图形、标签、图例以及任何显示的总计值的唯一来源。
- 页面支持滚动，因此卡片应根据内容自适应高度（`align-items: start`），切勿为了匹配更高卡片而拉伸图表卡片。请为绘图区域保留足够的高度：若强行挤入一个宽而矮的容器，序列会变得扁平。
- 提示框的位置应基于其所应用的坐标空间来设定：在 SVG 的 `viewBox` 中计算的值若直接作为 CSS 像素设置，在 SVG 缩放后会显示错误；此外，容器上设置的 `overflow: hidden` 还会在提示框出现的边缘将其裁掉。
- 本节仅针对图表部分。页面的其他资源（字体、图片、允许的 CDN 标签、地图等）应遵循您现有说明中的资源管理规则；切勿为了满足此处的要求而移除任何已被允许的资源。

### TypeScript 运行时下的 Web 资产

- 将图表绑定到源文档已读取的数据文件。通常，网络制品会紧随文档之后，而其数据集的手动誊写版本则构成了第二份数据集：两者必然存在差异，且两份制品都会声称使用的是同一组数值。如果尚未有源文件，请先生成一份，并让两者都读取该文件。
- 使用 Recharts 构建真正的 DOM 图表。不要使用 Matplotlib 生成的 PNG（它们无法自适应布局、对辅助技术不可见，且缩放时会模糊）；不要使用样式化的 div 或 Mermaid 模拟的图表；也不要使用基于 canvas 的库（如 Chart.js、uPlot，以及 ECharts 的默认渲染器——这些会导致图表变成页面无法检查或样式的位图）；除非图表确实需要高度定制，否则也不应使用 D3/visx，因为它们会重新提供本参考旨在避免的刻度和坐标轴计算逻辑。
- 首先检查制品自身的 `package.json`：新搭建的项目会固定 `"recharts": "2.15.3"`，而旧版制品可能没有这一项；若未安装该依赖直接导入，构建将会失败。请添加脚手架中确切的版本号（而非版本范围），并在构建前运行 `bun install`：自动安装功能已关闭，仅靠入口文件不会将模块下载到磁盘。
- Recharts 会根据数据系列推导出刻度、图例条目和工具提示的位置，而这三者往往是错误最多的部分。它有两个不会自动处理的地方：一是不会自动缩放，因此对于柱状图和面积图，请自行设置零值域；二是不会阻止您在一个坐标轴上绘制两种不同单位的数据。
- 让卡片在滚动网格中根据内容自适应大小（`align-items: start`）；拉伸效果更适合用于固定幻灯片。确保文本在制品实际呈现的宽度下都能完整显示，包括较窄的宽度；水平滚动的表格会隐藏右侧列，通常是合计列。
- 页面或回复中提到的每个控件都会重新渲染其所影响的每个面板。请将控件状态与显示状态统一管理，并使导出内容反映当前视图。

## 交付之前

从源数据重新推导每个关键数字，并与制品所展示的内容进行比对：总值、百分比、特定极端值、任何增长指标，以及您声明的各类计数。凡是无法从数据中复现的数字都是错误的，正确的做法是修正数字本身，而不是修改说明文字。然后以读者的视角阅读制品，从首次加载且无任何交互的状态开始：只有在点击后才会出现的图表并未真正交付。
