# PDF 视觉指南

用户在 `verbatim_request` 或上一轮对话中提供的视觉指示具有权威性。在进行样式设计之前，先根据通用默认值进行一次检查：每项视觉选择都应基于其与当前交付物的契合度，而非因为它是最简单的模板（到处都是一个强调色、单一字体包办一切、标题与正文之间没有层级关系、用表情符号充当图标）。

- 在创作之前确定文档的主题。阅读 `~/workspace/themes/` 及其可选的 `_default.json` 文件，其中的 `default` 字段指定了首选主题文件（不带 `.json` 后缀）。如果请求中提供了完整主题，则使用该主题；若携带了视觉指示，则匹配已保存的主题，或据此推导出合适的系统。如果没有明确指示，且存在已保存的默认主题，则使用该默认主题；否则，选择一个符合文档特点的独特系统。除非用户要求，否则不要将新推导出的系统保存为可复用的主题。
- 已确定主题中的 `ui` 块控制排版、颜色、间距、形状和层级；`visual` 块则控制生成的或主视觉图像。
- 将所有请求的字体映射到通过 `fc-list` 验证过的本地已安装字体族。PDF 渲染不得依赖 Google Fonts 或 Microsoft 字体。
- 在每一页上保持一致的设计系统：相同的字体、相同的间距比例、相同类型的元素采用相同的处理方式。读者翻阅时不应能分辨出你在哪里停止、又从哪里开始。应使用可读的对比度、精心规划的留白以及克制的层级结构，而非通用卡片或装饰性填充。留白也是系统的一部分：在空间紧张时，宁可删减内容，也不要压缩间距。
- 根据文档的类型进行设计，而非套用通用报告模板。表单、发票、简历、手册、学术论文、宣传册和图片画廊各有其既定的规范，读者对此有所预期；请遵循与需求相符的那一套。
- 页面背景也是这些规范之一：在设置背景之前，先确定该类型文档通常使用何种底色。发票、表单和学术论文一般为纯白色，以此作为默认，只有在有充分理由时才做例外。
- 装饰性点缀也需遵循同样的原则：在添加任何装饰色之前，先判断该类型是否通常带有此类元素。发票、表单、数据表格和学术论文通常没有彩色顶部条带或侧边条纹；它们的结构主要依靠排版和对齐，必要时辅以细而中性的分隔线。只有在品牌化是核心目的的类型中，才保留点缀色带和条纹。
- 除非用户另有要求，否则使用标准的纵向页面尺寸，并设置适合打印的页边距。任何承载信息的内容都应位于内边距之内。
- 在内容密集的页面上使用标题和项目符号，并确保同一层级始终呈现一致的样式。若页面信息量较少，则无需使用这些元素。
- 页面上的每个元素都应有其存在的理由。图表或示意图的存在必须是因为它承载了文字无法传达的信息。照片则遵循构建合同中的图像指引：关于日常生活的文档（旅行、美食、生活方式）若缺少所提及地点和事物的真实照片，则会显得不够完整；而数据密集型及实用类文档则更适合无图呈现。
- 若发现页面留白过多，应将其视为布局问题来解决，而非随意添加卡片、标签或素材图。
- 只有在有意作为封面时才使用跨页满幅图像。实用报告、指南、手册以及数据密集型文档应使用常规的内页图片，避免与内容产生冲突。
- 关于 HTML 的编写、分页、渲染及视觉校验的具体操作，请参阅与本文同目录下的 `workflow.md` 文件。文档的主题解析遵循上述 `~/workspace/themes/` 规则；演示技能中的 StylePlan 系统仅适用于幻灯片，此处不适用。如果交付的 PDF 存在已报告的视觉问题，请将受影响的页面重新渲染为 PNG 格式并读取，然后再修改源文件。在没有视觉证据的情况下，不要臆测布局或样式缺陷。
