# 叠加层规范 — 确定性气泡渲染器

`../cmm/overlay.py` 是所有以下数值的实现与事实依据；该文件解释了每项设计的意图及决策缘由。若代码与文档存在不一致，以代码为准——请同步更新此文件。

为所有气泡质量提供单一的防漂移实现。请勿在其他线程中重新实现气泡 UI。

## 内部机制（维护者参考 — 非代理使用说明）

`MessageOverlayRenderer.render_frame(t, active_blocks)` 返回一个 RGBA 图层；其唯一调用方是 `cmm/compose.py`，负责将其与创作者视频合成并编码输出。作为代理，您无需直接构造该图层：整个管线通过 `./mm render` 运行，由其自动驱动合成流程。请勿针对此类编写独立的驱动脚本。

## 画布缩放

以下所有数值均基于 720×1280 的基准校准。渲染画布可以是任意 9:16 尺寸（通过 `./mm render --size` 指定；默认情况下，画布尺寸根据源素材确定，宽度限制在 1080–1440 像素之间）：`overlay.px()` 在渲染时会将各常量按 W/720 进行缩放，因此无论何种分辨率，视觉效果的比例都保持一致，且在 720p 下比特完全相同。新增常量应以 720p 为基准值，并通过 `px()` 方法应用缩放。

## 锁定的内容及其原因

**字体大小。** Muse 和 You 均为 36px。既非 32px（显得过小），也非 46px（过于突兀）。在 720p 下，该字号约占可用宽度的 90%，从而确保在信息流中清晰可读。此锁定所防范的原始问题：字体加载器曾无声回退至 10px 字体，导致气泡宽度仅为 192px，而正确宽度约为 589px。

**字体随技能一同分发。** `load_font` 仅从 `assets/fonts/` 加载产品自带的 Optimistic AI 变量字体，绝不搜索系统路径，遇到缺失时会抛出 `FontUnavailableError` 而非降级显示。不存在无声回退机制。系统字体不可替代打包字体：不同的字形度量会导致换行点和气泡宽度偏移，从而使锁定的视觉效果依赖于宿主环境，而这并非预期行为。字体粗细沿变量轴变化（正文 500、粗体 700——400 在视频上显得过细）。

**产品气泡样式。** 渲染器绘制的气泡样式即为官方的 Muse 主题：Muse（代理）气泡为白色 (#FFFFFF)，文字为深灰 (#111112)；You（用户）气泡为浅蓝 (#CBE5FF)，文字为深灰；半径固定为 22 个产品单位，最大不超过屏幕高度的一半（短消息显示为胶囊形）；纯色填充，无描边。绝不允许为每条消息单独定制样式——线程内的作者身份仅通过气泡颜色区分，与应用端完全一致。请勿添加额外的身份标识。

**作者归属。** 在线程内仅通过气泡颜色区分作者。渲染器会在开场动画中呈现真实头像，将其标题固定于轨道上方，并在结束画面播放“笑声”音效；若“笑声”不可用，则改用 `milestone_level_up`。结束画面持续一整轮反应动画，并冻结最后一帧。请对照创作者面部检查叠加区域的定位是否准确。

**舞台与安全区。** 将最新内容固定于画面高度约 84% 处。文本应位于两侧各 14% 的内边距范围内，媒体则置于更宽的卡片区域内。较早的内容随新消息推进沿弧线向后移动，其缩放与透明度随深度变化。请对照创作者面部检查内容的远近关系。

底部的点击放大区域始终位于固定的下部舞台上，请确保人脸留有足够的空间。

**弹出与方向音效。** 每个气泡均以整体方式弹出，伴随短暂的缓入缓出过渡——禁止逐字显示；消息的呈现方式应与真实文本一致（逐字显现已废弃，Lucas，2026-09-02）。音效具有 iMessage 式的方向感，由 `render_sfx_wav` 根据实际时间生成：用户发送时为上升的“滑动”声，Muse 消息及卡片为较低的“叮”声，反应则为“滴答”声——这些音效被低调地混入语音之下（峰值远低于人声，且绝不会被拉平至与语音同级）。切勿复用其他视频中的时间戳。

**换行处理。** `wrap_text` 使用 `getbbox` 测量文本，并在字符级别断开过长单词。此前的实现采用 `len * 0.6` 估算宽度，导致每行仅容纳一个单词。

## 线程堆栈的物理效果

一个新的区块在0.30秒内进入，并在0.85秒内推动先前的内容沿着弯曲的透视轨道移动。先前的内容会随着深度增加而缩小并变得更透明。内容在`end`之后仍保留在轨道上，只是其预设的动画停止。输入光标会在`end`处停止，其占位区域会在离开布局前经过0.85秒的收缩过程。渲染器在整个深度变化过程中持续更新其缓存图层。

## 浏览器会话

`browser`区块是一等公民：渲染器负责管理浏览器的外壳（包括Mac风格的圆点和地址栏胶囊）、页面图像、导航光标、点击反馈环以及加载时的页面切换特效——这些动画的时间跨度贯穿整个节拍周期（5至20秒）。因此，在整个旅程中始终只有一个浏览器实例存在于舞台上，而非每页一张卡片。页面被重新构建为站点视口：每个`pages[i]`的HTML都会渲染成一个固定尺寸为1240×640的桌面视口（`render_browser_page`），并且每个非最终页的`click`选择器都会在其自身渲染后的页面上进行测量，以确保光标准确落在目标组件上；如果选择器缺失或目标位于视口下方，则会因未找到对应选择器而渲染失败。渲染后的页面会同时适配线程和点击阶段的尺寸，并将测量得到的点击位置转换为各自视口坐标系下的值（`clicks_t` / `clicks_s`）；区块默认按点击触发，而模态则以舞台分辨率实时绘制画面。点击播放的视频也是如此：帧率会根据点击阶段的适配尺寸提取，线程视图则在此基础上进一步缩放。
