# 以视觉方式编排故事

在确定场景的容器之前，先选定每个场景的主题。对于结果使用实物图，对于关系使用空间示意图，对于交互使用气泡图。让焦点元素占据卡片的大部分空间。标题应简短，并去除那些与画面内容重复的标签。

遵循 `/opt/hatch/skills/magic-moment/reference/design.md` 中的产品配色方案和“乐观”字体风格。在整个视频中保持一致的圆角半径和内边距节奏。当主题发生变化时，调整构图。针对技术机制或关键指标，若能强化叙事，可选用刻意加深的背景色卡片。辅助文本的视觉权重应低于焦点元素。切勿对所有主题都采用完全相同的“标题+两行文字”版式。

在适合的情况下使用以下构图：

- 日历：展示小型周视图网格或时间轴，并按实际位置标注相关事件。仅在有依据时高亮显示可用时段或已规划的活动。仅当有明确日期和时间来源时才标注具体日期与时刻；若叙述支持周期性规律但无确切时间表，则使用无日期的时间节奏示意图。
- 路线：为路线线条及端点留出足够的可读空间。只有在有明确坐标来源时才绘制真实地图；若无坐标，则在标注路线名称、距离或时长的同时，采用明显抽象化的路径示意，省略地图瓦片、街道名称、方向标识及虚假的位置标记。
- 进度：仅当数值有据可依时才使用图表。通过实心与空心标记以及简短的状态标签，区分已完成事项与待办建议。切勿将预期进展误作实际成效。
- 同步或自动化：展示源端、连接路径及目标端。若源端确有已完成的传输动作，则动画呈现一次传输过程；对于虽已构建但尚未见执行证据的功能，仅揭示连接关系，不添加成功标志或虚构的活动数据。
- 实物：完整呈现实物的大块区域，按相关内容裁剪画面，而非强行将整页桌面内容塞入缩略图。让实物自身的视觉语言主导场景。当叙述从过往记录转向即将开展的工作时，可再进行一次裁剪。

参照 `/opt/hatch/skills/magic-moment/reference/design-system/story-compositions.html` 中的 HTML 示例，用于布局与动效设计。其示例内容应基于事实证据进行调整。这些仅为说明性示意图，而非产品界面的复刻。主组件库中的控件应保持可识别的产品特征。

对叙述中的变化只做一次动画过渡，随后保持结果画面足够长时间以便阅读。若有依据，可绘制路径、高亮时段或显现已记录条目。观众阅读时，装饰性动效应保持静止。入场、出场及点击动效由渲染器统一处理，无需在整张 HTML 卡片上额外添加弹跳效果。

按“场景—来源—焦点元素—动效—停留”的顺序规划整个序列。使用 `/opt/hatch/skills/magic-moment/mm preview <screenplay.json>` 预览效果，并以其返回的手机尺寸查看初始、中间与最终三态。在正式渲染前，修正层级薄弱、文字被截或实物细节过小等问题。最终编码后的视频需单独审核，因为独立预览无法验证画面清晰度、转场间距及音频时序是否准确。
