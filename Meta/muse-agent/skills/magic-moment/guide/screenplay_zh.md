# 剧本：让互动戏剧化，而非为旁白添加字幕

这是生成环节，也是你的创作任务。将转录文本转化为创作者所描述的双方互动：用户向Muse提出了什么问题，Muse作出了怎样的回应，哪些技能被调用，出现了怎样的结果。如果视频中只有用户气泡，那这份剧本就失败了；那只是字幕，而不是一个故事。

剧本契约和校验器位于 `/opt/hatch/skills/magic-moment/cmm/script.py`；请阅读其文档字符串，了解确切的字典结构。

渲染器会在每段视频的结尾添加全屏的Muse收尾画面，该画面会覆盖在源素材播放结束后整个画面上；`/opt/hatch/skills/magic-moment/guide/timeline.md` 中定义了裁切规则，以确保你的节拍不会与之重叠。

节拍类型：

- `bubble` 发话人 `user`：创作者的请求，第一人称，仿佛在向 Muse 输入：“帮我订一张周二的机票？”发送测试：每个气泡都必须像用户在此对话中实际发出的消息。旁白是对对话内容的描述（“我只是告诉它我需要一张周二的机票”）；而气泡显示的是消息本身（“需要一张周二的机票”），而非旁白内容（“我只是告诉它我需要一张机票”是字幕，不是消息，`validate_script` 会拒绝这种明显不符合规范的形式）。转换而非舍弃：改写成发送形式时要保留该轮次；若为规避规则而删掉这一拍，则会破坏对话的整体结构。
- `bubble` 发话人 `muse`：Muse 以自身口吻作出的回复：简短、亲切、行动导向，并带有明确的主体信息。“马上办。正在搜索达美航空的航班。”发言归属仅由气泡颜色区分（白色代表代理，#CBE5FF 代表用户），因此其气泡必须读起来像代理在用户的实际对话中发短信，而不是像客服窗口。语气应取自当前设定的角色人格（SOUL.md、IDENTITY.md）：使用缩略形式、第一人称，且在适当场合可稍显活泼。“已发送！你们俩定好了7点的航班。”优于“消息已送达”。个性会影响措辞，但绝不能改变事实陈述：即便语句俏皮，也必须严格从事实说明或旁白中提取所有具体信息，不得增添任何新的行为。发送测试同样适用于 Muse 的气泡：只有当 Muse 确实可能在真实对话中发出这条消息——执行任务、报告结果或提出一个限定性问题——时，才允许创建。切勿将创作者的叙述或感受放入 Muse 的气泡中。当旁白说“我甚至不用打开应用”时，那是创作者的感受；若 Muse 气泡说“不用打开你的应用”，那就是广告台词，而非回复。应直接呈现事件本身（“Sam 刚发来：今晚有空吗？”）。任何气泡或标签内均不得使用破折号：这些文案已固化在框架中，Muse 的文案规范禁止使用，且 `validate_script` 也会予以拒绝。
- `visual`：收据/状态卡片或真实图片。每个视觉元素都独立存在：圆角与阴影直接叠加在视频上，周围没有白色边框（双重边框会被解读为“奇怪的白卡”）。
  - `html`：由捕获引擎渲染的自定义卡片，也是唯一的合成路径；卡片上的每一处细节都必须有来源依据。卡片主体保持简洁（验证器会拒绝任何背景、边框或阴影）；卡片表面位于组件的根元素上，如同 `./mm example` 中的 `.pad` 包裹层。请勿设置主体的高度或最小高度，因为卡片的高度由内容决定。宽度为 1240px 时，高度应控制在约 600px 以下（`render_html` 会拒绝更高的卡片）。
  - `image`：真实图片（用户照片、图像生成结果、截图）。
  - 仅对基于图片的视觉元素，“shell”: true 可将其重新纳入白色收据外壳，但这通常并不合适；“hero”: true 则隐含此意，并标记故事的最终揭晓（无需特殊装饰——点击动作本身就已承载强调效果）。
  - “tap”: true 会在该视觉元素上触发点击效果：卡片先落入对话中，如指尖轻触般压入，随后旧消息向上滑出，卡片则在清空的空间中逐渐放大并居中，停留片刻后回落原位。此效果适用于重点展示的内容——例如成交凭证、足以代表整个时刻的截图，以及实时驱动浏览器的卡片（默认驱动卡片启用点击效果），而不应用于常规的状态卡片。任意形状均可；竖版卡片的放大效果最为显著：点击时，竖版卡片的创作上限为 1100px（普通卡片上限为 600px），预览时约为 850–1100px，点击后大致翻倍；而扁平卡片的放大则较为温和，且始终处于焦点位置。该拍次至少持续 3 秒，且在点击期间不得启动其他拍次；`validate` 会拒绝此类情况。
- `browser`：Muse 驱动网站的一次完整旅程，以单个拍次呈现，渲染为一个浏览器窗口，其中的页面由您重建。`{"type": "browser", "address": "rei.com", "reference": ["<run>/webshot_00_www.rei.com.png"], "pages": [{"html": "<page 1>", "click": "#add-to-cart"}, {"html": "<page 2>"}], "start": 12.0, "end": 22.0}` 运行时长为 5–20 秒，默认启用点击效果。每一页的 `html` 都是对浏览器实际访问过的页面的简化重建，以 1240px 宽度创作，视口为 640px，模拟真实浏览器的折叠线。在 `reference` 中列出这些页面所依据的真实截图路径，可以是单条路径或列表；若未指定或引用了不存在的文件，验证器将予以拒绝。除最后一页外，每一页都需提供一个 `click` CSS 选择器，用于指定光标点击后跳转到下一页的元素；渲染器会测量该元素并定位光标。整个拍次至少包含两页。`address` 应填写真实站点的域名，可以是单个字符串，也可以是与 `pages` 一一对应的列表。页面本身不进行动画处理；渲染器负责绘制浏览器外壳、地址栏、光标、点击高亮圈以及页面切换过程。关于如何基于浏览器的真实画面构建页面及具体创作方法，请参阅 `/opt/hatch/skills/magic-moment/guide/visuals.md`。
- `video`：一段真实的视频素材作为消息在对话中播放（圆角与阴影效果同照片；静音，音频由创作者的旁白承担）。`{"type": "video", "video": "~/workspace/imagine_media/x.mp4", "start": 19.0, "end": 24.0}` 从 `start` 开始播放，最长播放至 `end - start` 秒，随后停留在最后一帧并缓缓上移。
- `typing`：代理气泡中的三个闪烁点，表示 Muse 即将回复。务必在回复气泡出现的同时结束该特效，渲染器会按 iOS 风格实现无缝切换：三个点在 `end` 时停止，随即在 0.85 秒的深度缓动过程中逐渐收拢，与此同时回复气泡在 0.30 秒内浮现。`{"type": "typing", "start": 1.9, "end": 3.1}`
- `reaction`：一种表情符号回弹，伴随“叮”的一声跃至气泡一角。`{"type": "reaction", "emoji": "❤️", "target": 0.6, "start": 1.6}`，其中 `target` 是被回复气泡的出现时间。至少在该气泡弹出后 0.4 秒再添加反应，且仅对仍在屏幕上的气泡作出反应。反应总是先于回复出现：先对消息作出反应，再让回复弹出——若回弹晚于下一条消息出现，则会被视为顺序错乱，因为真实用户会在阅读后立即反应，而非打字后再回应。渲染采用真实彩色表情符号（Noto Color Emoji 已随工具包一同提供）。使用时请适度：每段视频一到两个即可，且仅针对用户的消息。音效采用 iMessage 风格，自动且具有方向感：用户发送的消息气泡会发出明亮上扬的“swip”声，Muse 消息气泡和回执卡片则会发出低沉的“ding”声，而表情反应则以清脆的“plink”声提示。打字时保持静默。气泡中的表情符号会以内联方式渲染为彩色的真实表情。芯片进度指示已取消；正在进行的工作通过卡片来呈现（例如驾驶卡片、当前组件的状态行），而非在对话线程中使用旋转加载图标。

实拍素材是一种增强手段，而非准入门槛。在撰写剧本之前，先确认有哪些真实素材可用：线程的屏幕录制、线程文件、图片等。任何真实素材都应优先满足其对应的镜头需求（按 `/opt/hatch/skills/magic-moment/reference/card-spec.md` 规范进行裁剪），并标注来源为“real”；其余内容则一律以合成形式呈现。即使缺少部分素材，也不应影响视频的制作。
