# 审核最终构建版本

运行 `/opt/hatch/skills/magic-moment/mm validate <screenplay.json>`。在 `~/workspace/.output/<name>/resolved_screenplay.json` 中查看规范化后的剧本。仅在审阅该版本后，再将返回的指纹值复制到 `~/workspace/.output/<name>/script_review.json` 中。

按照以下格式编写审核报告，每条内容节拍对应一行声明，节拍索引从0开始。声明行中无需包含打字和反应类节拍。

```json
{
  "fingerprint": "validate 命令返回的值",
  "verdict": "pass",
  "claims": [
    {
      "beat": 0,
      "source_span": "确切的来源文本及时间",
      "actor": "执行动作的人",
      "action": "发生的事情",
      "tense": "过去、进行中、计划中或已提出",
      "evidence": "来源消息或工件路径及相关状态",
      "depiction": "呈现的内容；引用、转述、截取或插图"
    }
  ],
  "source_coverage": "说明每个重要来源声明的出处，包括那些刻意保留在叙述中的声明。"
}
```

针对每个气泡和视觉元素，检查说话人归属、来源支持、时间含义、组件选择及时间点是否准确。拒绝虚构的指令、认可、成功的同步、统计数据以及画廊示例文案。按来源顺序完整核查整个故事。如有修改，需修正剧本、重新验证，并审核新的指纹值。CLI 会强制要求指纹的新鲜度和审核结构，但不会对您的声明作出独立判断。

运行 `/opt/hatch/skills/magic-moment/mm render <screenplay.json>`。随后运行 `/opt/hatch/skills/magic-moment/mm inspect <screenplay.json>`，并逐页查看生成的联系表。以手机屏幕尺寸精确预览输出视频，检查开场、每个画面的初始与最终状态、所有过渡效果、点击交互、创作者的结束语以及附加的结尾画面。注意是否存在过小的文字、裁切、重复消息、标签重叠、重复播放的动作，以及创作者面部是否被遮挡。同时确保来源音频清晰可辨。除非当前需求明确要求，否则不得添加背景音乐。

视觉质量的审核应与事实准确性分开进行。在360像素的视频宽度下，确保焦点内容无需停顿即可读取。当故事中有日历、路线、图表或工件可供展示时，拒绝使用重复的标题加列表卡片。如果工件被缩小至无法辨认的缩略图、美术作品中的标注未通过审核，或旧卡片遮挡了下一场景，则予以拒绝。将每张卡片的渲染状态与场景规划对比，在布局审核通过前修正表现较弱的构图。核对完整标题及每个状态标签与卡片边缘的对齐情况。对于每次工件的展示，确认观众在手机屏幕上能够读取的具体结果；若仅能看清标题，则不予通过。

在每次检查的状态记录中，详细记录所见内容，包括视觉焦点与可读性。有效的哈希值仅证明身份一致性，而非质量优劣。

在 `~/workspace/.output/<name>/layout_review.json` 中，填写来自渲染清单的 `output_sha256` 和 `verdict: "pass"`，并在 `checked_states` 字段中为 `mm inspect` 返回的每个时间点添加一条 `{ "time": 1.1, "observation": "您检查的内容" }` 记录。发现任何问题须记录并修复后再提交。修复后需重新渲染，且不得对已检查的 MP4 文件进行后期处理。

两项审核均通过后，运行 `/opt/hatch/skills/magic-moment/mm publish <screenplay.json>`。仅交付其 `DONE` 路径。发布过程会校验来源、素材、剧本、审核结果及最终输出的摘要。保留运行清单作为溯源记录。
