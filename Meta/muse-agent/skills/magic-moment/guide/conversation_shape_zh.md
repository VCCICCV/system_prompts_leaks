# 对话与节奏

展示引用的讯息时，应忠实呈现其原文；仅当原文传达的是含义而非确切语句时，方可使用忠实的转述。无论采用哪种方式，都应保留发言者、意图、时态及结果。在评审的描述字段中注明每个气泡所采用的形式。

仅展示源文本中实际存在的用户请求与决策，不得因已有结果而凭空捏造请求或同意。切勿将事后回顾的故事改写成新的实时交互。对于持续性的协助，若源文本已给出，则只需在首次出现时展示一次该请求，后续可通过其他内容来支撑叙述，无需再次强制要求用户提出请求并作出回应。

只有在确有对话交流时才使用气泡；若虚构对话会扭曲故事原意，则让相关素材单独呈现即可。切勿将创作者的赞扬转化为“缪斯”消息，也不得将本应发给第三方的消息置于本线程的用户侧。

在确定主张及其证据之后再选择组件。当叙述再次涉及同一素材时，可重复使用该素材，但调整其裁剪或状态。将每周运行日志作为运行日志呈现，而非作为计划任务设置；将渐进式建议作为建议呈现，而非作为已完成目标的复选框。组件的多样性是可选项，且不得改变原意。

文案长度应便于在手机屏幕上阅读。内容型气泡的显示时长按每三字约一秒钟加一秒钟计算。若文案过长无法在规定时间内读完，应精简内容或将支持性观点拆分。视觉元素的数量应根据故事需要决定，而非为了凑数。避免在同一气泡和相邻卡片中重复同一主张。

构建场景序列时，每次只突出一个焦点视觉元素。仅保留那些能为叙述增添额外意义的对话。为每张新卡片的出现设定与其叙述节奏相匹配的时间点。随着新卡片的进入，让渲染器自动将先前的卡片移至背景。章节之间的画面留白应适当，预留足够的呼吸空间。切勿添加重复创作者结论的结尾气泡。
