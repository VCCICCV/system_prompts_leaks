# 保留原始故事

在选择视觉素材之前，请先阅读当前的请求及其明确的修改说明。以提供的素材作为原始来源。除非用户明确要求缩短剪辑，否则请完整保留旁白内容。不得从以往作品中引入无关的音乐、风格偏好、功能实现或示例文案。

使用 `/opt/hatch/skills/magic-moment/mm transcribe` 进行转写。阅读转写文本，并与用户提供的文字进行比对。务必保留自动语音识别（ASR）的记录。当用户提出修改时，在剧本中加入 `transcript_correction: {"text": "修正后的转写文本", "source": "提供该修改的用户消息或文档"}`。被修正的词语不会自动进行字幕时间轴对齐，需通过检查视频片段来确定其出现的时间点。

在进行版面布局之前，请将所有源自原始素材的陈述汇总至 `~/workspace/.output/<name>/script_review.json` 文件中。记录每条陈述的原文区间、涉及角色、动作、时态、证据以及预期的呈现方式。区分“提议”“计划”“正在进行的工作”和“已完成的结果”。例如，“过去几个月一直在规划跑步活动”并不意味着“未来两个月也会继续规划跑步活动”。

收集故事中提及的真实消息与相关文件。如有可用的父级对话记录，请通过 `chat.read_messages` 查阅。同时检查 `~/workspace/your_files/` 目录下的现有文件，以及源素材所在的目录。将观察到的细节及其来源记录在剧本的 `facts` 对象中。切勿为凑齐某个环节而凭空捏造名称、数据、路线、审批、交易或结果。也不得将作者撰写的事实说明书视为独立的证据。

仅在原始素材缺失时，才使用合成界面来辅助说明经验证的陈述，并在审查记录中注明其来源。切勿将其当作真实的历史截图呈现。对于缺乏支持的细节，请直接省略，由旁白加以说明。切勿为了制造凭证而刻意操作应用、更改计划、发送消息或重新生成用户数据。

机器校验仅用于检查结构与时间节奏。语义层面的审核需人工完成：每一项被呈现的陈述都必须有来源支撑；每一项重要的口述陈述也都必须配有相应的画面呈现，或明确决定将其保留在旁白中。切勿将机器校验的结果视为故事忠实度的证明。
