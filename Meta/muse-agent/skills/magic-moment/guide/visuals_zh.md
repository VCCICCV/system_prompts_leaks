# 从证据中选择视觉素材

阅读 `/opt/hatch/skills/magic-moment/SKILL.md` 中的组件索引，以及 `/opt/hatch/skills/magic-moment/reference/design-system/muse-moments-kit.html` 中的相关组件。选择一个能够呈现所支持的操作与状态的组件。将所有图库名称、数值及示例文案仅视为示例，而非证据。当多个叙事片段描述同一实物的不同部分时，请复用该实物的真实素材。

优先选用原始媒体及真实实物的拍摄画面。为每个基于文件的视觉素材或视频记录 `provenance: {"kind": "original-media|historical-capture|current-capture|reconstructed-ui|synthetic-illustration", "source": "来源路径或事件及显示状态"}`。仅凭文件路径既不能证明真实性，也无法确定其历史状态。

将出处信息保留在剧本和审查文件中。切勿在视频上添加诸如“真实实物”、“历史副本”或测试虚拟机状态之类的验证标签。应展示实物本身的名称与内容，并按产品原貌书写可见文案。删除解释视频制作或审核过程的语句，让画面构图与简洁的状态标签来体现这些差异。当时间点对论点至关重要时，使用相关日期或简明状态，如“计划中”。除非源素材确实支持该状态，否则不要添加“实时”字样、同步成功标志或完成动画；对于无法证实的主张，应直接省略，而非以技术性免责声明掩盖。

在创作前请先阅读 `/opt/hatch/skills/magic-moment/reference/visual-storytelling.md`。为每个叙事节点拟定简要场景方案，明确其视觉焦点、所用组件、素材来源及动态效果。运行 `/opt/hatch/skills/magic-moment/mm preview <screenplay.json>`，并在决定正式渲染之前预览每张卡片生成的样片。按目标视频宽度（360px）检查每张卡片在初始、中间及最终状态下的动画表现，包括点击展开后的状态。在再次渲染之前，修正文字被截断、标题过于拥挤或实物呈现不够清晰等问题。

当源素材以纯文本为主时，应围绕其核心内容设计一份具有明确重点与可读辅助信息的演示文稿，并在拍摄前将其保存为独立素材。保留原始事实，并在出处信息中记录这一改编过程。切勿将整页文字压缩进一张卡片，也不得为使图表看起来更吸引人而捏造数据。

使用 `/opt/hatch/skills/magic-moment/mm webshots` 查找浏览器截图。在使用前，务必核对截图中的任务、网址及时间是否与叙述路径一致。存在无关截图并不意味着该故事曾使用过该浏览器。只有在有确凿证据表明发生了一系列浏览器操作时，才使用浏览器相关的镜头。

使用 `/opt/hatch/skills/magic-moment/mm snap <document-or-url> --run <name>` 进行当前状态的屏幕截图。此命令会开启一个全新的浏览器环境，不含产品的Cookie、本地存储或状态缓存。仔细检查显示的内容。若素材需要实时状态，请使用产品官方支持的浏览器访问路径，切勿将默认的本地HTML页面视作用户数据。如果新环境显示为空的计数器或示例状态，应裁剪掉这些区域，选取包含完整有效内容的区块进行拍摄，或根据已保存的记录重建所需状态，并在出处信息中予以注明。切勿通过点击交互控件来填充截图内容。使用 `--viewport-height <pixels>` 指定明确的视口高度，或在页面超出尺寸限制时截取完整的有意义区块；渲染器不会默许无提示的截断行为。

有关裁剪规则，请参阅 `/opt/hatch/skills/magic-moment/reference/card-spec.md`；有关套件的设计规范，请参阅 `/opt/hatch/skills/magic-moment/reference/design.md`。确保在手机尺寸下源内容仍清晰可读。每张卡片仅保留一个核心内容焦点，并移除不支持的字段。请使用套件自带的 Optimistic 字体。作者创作的卡片应保持自包含，宽度为 1240px，至少留出 32px 的可见文字区域，主文字行高为 56px。在 `/opt/hatch/skills/magic-moment/reference/design.md` 中规定的单面规则下，保留有意义的内部结构。对于支持且适合放大的展开效果，请使用 `tap: true`；普通卡片的高度预算为 600px，而点击展开的卡片为 1100px。

仅编写 HTML 和 CSS，不得内嵌脚本、事件处理程序、iframe 或任何网络依赖。本地媒体资源需使用绝对的 `file://` 路径引用。作者创作的捕获模式会禁用页面脚本并拦截网络请求；而在真实应用的快照模式下则明确允许使用脚本。请勿将作者编写的 HTML 与 `shell` 或 `hero` 混合使用；其根元素负责提供显示表面。
  
通过设置 `box-sizing: border-box`，使内边距和边框计入卡片的声明宽度。当标题和状态标签无法在同一行显示时，允许它们自动换行或堆叠。在渲染预览中检查其完整文本，切勿通过隐藏溢出来让过大的布局勉强通过视觉检查。
  
为 CSS 动画设置明确的持续时间，确保在节拍周期内完成。捕获运行于单一单调的时间线上，直至节拍结束，因此有限时长的动画只执行一次，而环境类的循环动画则会持续进行。请勿让已完成的动画再次循环。仔细检查过渡过程中的中间状态，避免出现意外的重叠；最终状态正确并不意味着过渡过程也一定正常。
  
请保留自动的头像入场、固定页眉以及结束时的庆祝动画。仅当故事本身与该头像的生成相关时，才在卡片中添加额外的头像素材。在最终画面中务必保留创作者的面部。渲染器采用固定的叠加区域，因此请通过视觉确认面部是否重叠，而不要依赖自动人脸检测。
