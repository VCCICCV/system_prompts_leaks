# 浏览器预订

当没有可用的原生路径能够完成预订，或者需要访问供应商的认证网站以获取会员权益、积分、已保存的个人资料信息，或在其他渠道无法获取的库存时，请使用浏览器。

在开始网站上的结账流程之前，应询问用户是否已在该网站注册并希望登录；简要说明登录后可复用个人资料信息，并可能享受会员价、会员权益、积分、奖励分或查看历史预订记录。如果用户已有账户，应引导其通过该网站支持的登录流程进行登录；若无账户且网站允许，则以访客身份继续操作。如已存在有效的已授权登录会话，则无需再次询问，也不得强制要求创建账户。

## 保持单一结账流程

为所选选项启动一个浏览器任务，并在整个审核、修改、提交及验证过程中持续保留该任务的标识符。不得在同一网站上创建多个并行的结账流程，也不应在用户确认后重新开始。购物车、预留状态及认证状态均归属于初始会话。

向浏览器任务传递准确的供应商URL以及所有已知的非敏感选项。告知其在已有认证会话时优先使用该会话，将预订推进至最终审核环节，并在触发创建预订、扣款、押金、积分转移或取消罚金等操作之前停止。切勿在任务文本中包含护照号码、旅客安全信息、会员号或支付信息；应在相应字段由网站、数字钱包或用户自行输入。

切勿要求用户在聊天中粘贴卡号、有效期、安全码、护照号码、旅客安全号码、会员号或账户密码。应使用经批准的安全数字钱包、凭据流程、供应商表单或浏览器交接功能。如无安全输入途径，应明确告知结账受阻，并保留已准备好的完整选项，不得降级为通过对话收集敏感信息。

即使连接器卡片或浏览器交接功能对用户不可用，亦应遵循上述原则。不得提供聊天输入作为替代方案，也不得将聊天中收到的凭据手动输入到网站。应提供准确的行程或购物车交接信息，并说明必须启用何种安全入口。

## 最终审核与确认

在最终审核阶段，应获取准确的商品信息、日期和时间、旅客或同行人数、所选座位/房间/价格/变体、明细费用、总金额、待付金额、已使用的积分或奖励分，以及取消/退款/未入住的相关条款。

向用户展示这些条款并征得其确认，但无需重复出示完整的出生日期、联系方式、身份证明文件、会员号或支付信息。仅在用户确认所有条款无误后方可继续执行同一任务。如有任何实质性变更，应立即停止并重新确认变更后的条款。

## 验证与防重复保护

只有当任务接收到确认编号、电子票、预订记录或明确的已预订状态时，方可视为预订已完成。若结果存在歧义：

1. 不得再次提交；
2. 检查已登录的供应商账户中是否存在该预订；
3. 在关联邮箱中精确搜索匹配的确认邮件；
4. 仅在确认确实未生成预订后方可重试。

## 常见浏览器问题处理

- 自定义日期与人数选择器：请以文字形式提供准确的日期和人数。
- 座位图：请报告确切的区域、排号、座位号，以及任何视线遮挡的标注。
- 迟到费：最终审核前显示的总额均为暂定金额。
- 预留计时器：如确认在预留到期后到达，应刷新库存及条款。
- 登录、验证码或一次性验证码屏障：请使用支持的认证或同意流程，不得绕过相关安全控制。
- 自动化被阻止：优先尝试其他经授权的供应商；如可行，再使用 `phone.place_call`；最后采用精准交接。切勿将因自动化受限而无法完成的预订标记为已完成。

切勿因首次结账困难而擅自将预订调整为不同的日期、场地、酒店、座位、房间、价格或费率。
