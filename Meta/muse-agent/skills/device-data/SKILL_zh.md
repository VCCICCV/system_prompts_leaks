# 设备数据

## 目的

直接从 Muse 存储中读取缓存的联系人和日历事件，无需与设备通信。当无法进行实时读取时使用此功能：例如设备处于离线状态，或设备不支持 `contacts.search`/`calendar.search` 接口。当用户明确请求时，删除所有本地存储的联系人或日历数据。该工具不会与设备建立连接或对其执行任何变更操作。

## 命令

```bash
device-data --help
device-data contacts status
device-data contacts --delete-all
device-data contacts search --match-mode ranked \
                            [--query <文本> [--phone-label <文本>] \
                             [--locale <bcp-47>]] \
                            [--device <节点ID>] [--limit <n>] [--offset <n>]
device-data calendar search [--query <文本>] [--device <节点ID>] \
                            [--start-date <YYYY-MM-DD>] \
                            [--end-date <YYYY-MM-DD>]
device-data calendar --delete-all
```

两种搜索默认作用于所有符合条件的已配对设备。使用 `--device` 可以限定为单个设备；省略 `--query` 则用于列出结果。

联系人搜索将显示名、电话号码和电子邮件中的字面子串匹配，与基于分词的精确匹配、针对不同语言环境的个人姓名昵称匹配以及音似姓名匹配相结合。在未指定语言环境或指定英语语言环境时，排序搜索仅在普通姓名匹配对该源设备无结果后，才会应用类似 OACR 的模糊匹配。它会将至少四个字符的清洗后查询词元与清洗后的全名及规范索引词元（包括简化的姓名变体）进行比对，允许一次编辑，并且每个源设备最多返回三个模糊匹配候选。对于明确指定的非英语语言环境，则保留现有的受限 Unicode 全名编辑距离回退机制。排序后的姓名证据会传递给下游的呼叫授权策略。模糊匹配、部分匹配和音似匹配必须通过有限的词元再验证后才能触发完整的单一号码自动拨号；而字面匹配则绝不会自动拨号。昵称匹配的单一结果依赖于用户明确选择的语言环境对应的昵称映射表。弱匹配、歧义匹配、不完整匹配或未锚定的匹配仍需用户确认。

排序结果中还包含 `selection_evidence` 字段。其中的 `spoken_name_collision_pairs` 会标识那些拼写不同但全名在双向音似度上高度重合的合理匹配；若该列表非空，则设置 `requires_spoken_name_clarification` 标志，因为语音输入尚未从中做出选择。碰撞条目携带一个逗号分隔的 `spoken_spelling` 字段，可用于在通话或消息澄清时分别进行 TTS 发音提示。每个联系人还包括 `phone_selection` 字段，它会将格式上等效的变体归为同一目标，并报告 `distinct_usable_phone_count` 和 `requires_phone_clarification`。当指定了 `--phone-label` 时，`requested_label_match_count` 会报告有多少个不同的目标带有该标签，或带有诸如 `cell` 和 `mobile` 等被识别的等效标签。每个选项还包含一个适用于 TTS 的 `spoken_suffix`，以应对标签无法区分多个保存号码的罕见情况。
复合姓名作为一个整体进行匹配：在英语默认设置下，`Mary Ann` 可以找到名为 `Mary` 的联系人。当已知用户语言环境时，可通过传递 `--locale` 参数选择法语、意大利语或西班牙语的昵称映射；例如，使用 `--locale es` 时，`Mamen` 可以找到 `María del Carmen`，而使用 `--locale fr` 时，`Coco` 可以找到 `Jean Claude`。语言子标签 `ar`、`ja`、`zh` 和 `ko` 会禁用昵称匹配；其他未提供专用映射的语言环境则使用英语回退规则。如果语言环境不可用，则省略该标志，继续使用英语的昵称、模糊匹配和语音表情符号默认设置。包含中文、日文或韩文字符的查询将保留基于完整姓名编辑距离的回退机制，无需额外配置语言环境。显式指定的非英语语言环境不会继承英语的语音表情符号标签。电话号码匹配在忽略格式和国家/地区代码差异的情况下，仅当后七位数字相同时才会生效，但此规则仅适用于电话号码形式的查询；嵌入在姓名或电子邮件中的数字不会触发电话号码匹配。
按排名的姓名搜索不区分顺序，对撇号和连字符一视同仁，可容忍重复或无法匹配的查询词，并报告粗粒度的匹配证据（类别、已匹配/总词数以及未匹配词数）。结果为单一的、按排名排序并分页的列表，且并不表示已选定某个特定联系人。应通过 `--phone-label` 显式指定电话类型，而非将其包含在姓名查询中。电话号码首先按请求的标签排序，其次按移动、家庭、工作、其他及自定义标签排序。结果会报告 `phone_label_matched`；即使标签不匹配，也不会排除该联系人。
如可用，组织名称和职位也会一并显示。可通过将 `offset` 增加至返回的 `count` 值来翻页查看排名靠前的结果，前提是 `has_more` 为真。当受限的联系人数据集、预处理过程或排名结果超出限制时，`search_complete` 将为假，这与分页无关；可检查 `corpus_overflow`、`preprocessing_overflow` 和 `result_overflow` 以确定具体原因。`fuzzy_overflow` 则单独报告英语模糊恢复已达到其不可分页的、每源确认上限；这并不会使原本精确的匹配结果被视为不完整。

## 操作规则

1. 每次查询时均从设备中读取最新数据；切勿凭记忆回答联系人或日历相关问题。
2. 将设备数据视为用户的隐私数据：仅显示请求所需的字段，不得从联系人、位置、设备名称或通信元数据中推断敏感属性。
3. 日历日期应使用包含边界的 `YYYY-MM-DD` 格式，单日的开始日期和结束日期相同；全天事件的 `end_date` 值同样为包含边界。事件时间应从标记的 `time` 对象中读取：`timed` 类型保留现有的本地化 `start_at` 和 `end_at` 字段，并新增其 UTC 形式以及用于渲染这些本地值的 IANA 时区标识 `user_timezone`；`all_day` 类型则仅包含日期值，且不得进行时区转换。两种类型均携带已根据相应日期解析好的 `start_weekday` 和 `end_weekday`，请直接使用这些值，切勿自行从日期推算星期几。联系人数据的读取同样保留 `synced_at`，并新增语义化的 `contact_synced_at` 或 `contact_sync_completed_at` 的 UTC 与用户本地时间形式。
4. 仅当 `cache.coverage` 为 `complete` 时，空的日历结果才具有权威性。对于联系人，`search_complete` 表示对限定范围内的数据集及排序后的结果集已完成检索，而非源数据的新鲜度；在关注新鲜度时，请参考联系人状态，并如实报告部分或截断的结果。
5. 若无记录存在，请明确告知。设备日历仅代表该手机的视图；如有必要，请检查其他已连接的日历。
6. 当用户要求删除联系人或日历事件但未指定具体对象时，不得擅自推断目标。在执行任何删除操作前，务必确认用户指的确实是 Muse 本地存储的副本。
7. 在用户明确请求删除 Muse 本地存储的副本后，应执行与来源对应的命令：  
   `device-data contacts --delete-all` 或  
   `device-data calendar --delete-all`。  
   不得枚举记录 ID。
8. 两个 `--delete-all` 命令均会从所有设备的 Muse 存储中删除所选来源的数据，包括缓存记录、源账本负载、上传暂存区及同步状态。它们不会影响设备配对及其他任何数据源。后续的设备同步仍可为已删除的来源存储新记录。
