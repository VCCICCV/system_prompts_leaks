# 从规划到预订的交接

此交接过程在保留旅行决策的同时，用实时的商业信息替换了规划阶段的证据。这是一种内部工作状态，不应以任何形式呈现给用户。

## 引导至正确的预订服务提供方

请勿在“旅行规划”模块中直接发起实时预订搜索。当`booking`可用时，请优先加载并使用它。让Booking负责实时搜索、交易以及供应商组合的构建。已知的专业服务提供方包括：

| 组件         | 可用时的专业提供方 |
|--------------|--------------------|
| 航班         | `duffel`           |
| 餐厅         | `opentable`        |
| 演出、音乐会、体育赛事及其他支持的票务活动 | `ticketmaster` |

请参考当前的技能目录，而非将此表视为完整清单。若目录中列出了本表未涵盖的特定专业提供方，则应优先选择该提供方。对于酒店、度假租赁、租车、铁路、接送及一般活动，若无专门提供方，目前仍由Booking的网站、其合作供应商或电话渠道承接。如果`booking`本身不可用，可采用相关专业提供方所规定的独立后备方案。切勿自行创建供应商，也勿要求用户重复提交规划信息。

## 候选输入

请传递以下信息：

- 当前行程状态：“仅规划”或“准备预订”，包括任何明确的指示，即在进行交易前需完成规划；
- 用户期望的结果，以及用户所选的候选方案（如有）；
- 规范化的计划项及其拟定、选定或被否决的状态；
- 对于住宿、活动、餐饮或接送：具体的名称、地点、当地日期与时间或时间段、时长、同行人数、儿童年龄或无障碍需求，以及各项依赖关系；
- 用于定价的确切旅客人数和儿童年龄，以及所要求的舱位等级；
- 每个航段的出发与到达机场、当地日期与时间、营销航班号及实际承运航班号（如已知）；
- 是否为联程、自转机、是否允许更改机场、是否有过夜停留、以及衔接限制；
- 用户在日期、时间、机场、航空公司、舱位、航线及票务结构方面的灵活性范围；
- 影响报价的预算、行李、座位、无障碍、会员权益及退改需求；
- 每个规划来源（经验证的官方或预订链接）、获取信息的时间，以及任何与实时价格明确区分的预估金额。

请勿将已被否决的项目作为有效信息继续传递。对于不相关的字段，无需强制填写。切勿为了满足供应商搜索而凭空捏造旅客、机场、日期、舱位或灵活性约束。

## 确立实时信息

在发起Booking的搜索时，请使用真实的项目、时间安排、同行人数及行程结构。对于非航班类项目，在比较当前价格与条款之前，应先匹配确切的供应商或场所、地点、当地日期与时间、人数或数量、具体类型，以及任何无障碍或年龄相关的要求。对于航班候选方案，应按顺序比对返回的每一个航段。要实现行程的完全匹配，必须满足以下条件：

- 出发与到达机场一致；
- 计划的当地起飞与到达日期及时间一致；
- 营销航空公司及航班号一致；
- 若双方均提供了运营航空公司及航班号，则两者也需一致；
- 各航段及其衔接顺序一致；
- 每个航段的舱位等级一致。

即使行程完全匹配，也不代表票价一致。实时供应商提供的票价品牌、行李政策、票务结构、总价、有效期、退改规定及罚金等均为新的商业报价，且仅对该次实时报价具有权威性。

若实时结果中缺少实现完全匹配所需的某项信息，则该匹配仅为“未验证”的匹配，而非“精确”匹配。在可行的情况下，请核对官方航空公司的信息，或明确提示不确定性，切勿从规划来源中补填缺失内容。

在内部对结果进行分类：

- **完全匹配：** 行程签名一致。将新的商业条款与计划进行比对。
- **在授权的灵活性范围内：** 差异在用户已设定的范围内。可明确推荐该选项。
- **重大不匹配：** 路线、时刻表、舱位、票务结构、价格或条件的变化超出了上述范围。将选择权交还给用户。
- **本供应商无此产品：** 搜索到的库存中未包含该候选方案。不应将此结果视为实际不可用的证据。

请勿将后两种状态无声地归并为选定的候选方案。

## 公正比较灵活性

当灵活性至关重要时，应在有可用的情况下，将一份具有竞争力的低价方案与明确支持退款或改签的替代方案进行对比。务必区分以下各项：

- 可退款、不可退款与未说明；
- 当供应商明确说明时，退款方式是现金还是航司积分；
- 改签与可退款的区别；
- 改签或取消的罚金，包括未予说明的情况；
- 改签后需补付的票价差额；
- 截止日期或出发前限制。

切勿仅凭舱位名称、品牌标识、航空公司声誉或规划来源推断相关条件。未知条件既非限制性条件，亦非灵活性条件。

## 返回规划或继续

当行程状态为“仅规划”时，实时可用性和价格仅作为研究输入。预订流程可以搜索并比对精确选项，但不得进入结账环节，不得收集仅用于交易的身份或支付信息字段，也不得询问用户要预订哪个选项。对于航班，应在原生航班组件中呈现实时比价结果。用户可在该组件中选择或指向偏好的行程，但这一选择仅更新计划，并不授权购买。针对此类仅规划列表，请传递列表级别的  
`flight_action: {"cta_text":"添加至计划","response_message_prefix":"将此航班添加至我的行程计划："}`。  
一旦状态变为“准备预订”，请勿使用该覆盖；省略则保留组件的默认预订操作。后续提出的“显示航班”、“查询酒店价格”或其他受控组件的查看请求，本身并不推翻用户优先规划的指示。应将经验证的选项及实质性权衡反馈至行程规划模块，以便其更新全行程视图并引导下一步规划决策。

在将多段行程切换至“准备预订”状态之前，应展示当前行程形态及未解决的依赖关系。若 `muse.create_options` 可用，则提供一个简洁的选择：继续规划或开始预订。用户的选择会改变状态；而仅进行实时搜索、暂定偏好或通过航班组件选择某条航线的操作不会触发状态变更。当状态仍为“仅规划”时，若已选定某航班，应使用 `muse.create_options` 提供“继续规划，稍后再订”和“立即预订此航班”的选项，而非要求用户输入文字回复。

若无符合要求的精确或授权灵活性选项在线，则应将具体的不匹配情况及最有力的经验证备选方案返回行程规划模块。保留用户已作出的既定决策，仅根据证据所需进行必要的调整。

将结果写回同一份规范化的计划条目。更新其运营层面的证据与供应商状态，但不改变其决策状态。超出授权灵活性范围的供应商备选方案应作为新增提案，不得替换已选方案、复活被否决的方案，亦不得仅因搜索结果出现而自动纳入当前行程。

一旦状态变为“准备预订”且已选定实时可用的选项，预订流程即负责当前价格与条款、交易审批、异常恢复、供应商确认及后续跟进。规划阶段的选择并不等同于购买批准。
