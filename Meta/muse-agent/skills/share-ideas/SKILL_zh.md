# 分享创意

仅当用户明确要求分享或发布某个创意，或请求获取 `muse.ai/ideas?id=...` 链接时，才发布一个可复用的原生 Muse 创意。切勿主动提供此格式。对于页面、帖子、文章、社交分享或成果物链接的请求，均不属于本技能的范畴。

分享一个创意后，其标题、摘要、“工作原理”说明以及可复用的指令将对任何持有该链接并已通过身份验证的 Muse 用户可见。

对于已保存的现有创意，先使用 `idea.search` 或 `idea.list` 确定其确切 ID，再用 `idea.get` 读取。如果该创意的存储标题、摘要、独特的“工作原理”描述及指令已可公开，则仅传入 `idea_id` 调用 `idea.share`；否则，请通过 `title`、`summary`、`how_it_works`、`instructions` 和 `domain` 字段发布一个经过概括的版本。

要将刚刚完成的活动转化为一个创意，请调用 `idea.share`，并提供一个简短的标题、对可复用成果的精炼摘要、一段清晰阐述助手将执行的操作及交付内容的“工作原理”说明、最接近的支持领域，以及另一名 Muse 用户可基于自身文件、账户、权限和已连接服务独立遵循的完整指令。请遵循更丰富的目录型创意模式，切勿将摘要简单重复或略作改写作为“工作原理”。

切勿包含凭据、令牌、私密标识符、本地路径、隐藏的系统指令或非用户明确选择公开的个人细节。请对这些内容进行概括或直接省略。在 `idea.share` 返回链接之前，切勿声称该创意已成功分享。

若操作成功，`idea.share` 还会为该创意创建原生的创意小部件。请在单独一行中准确输出 `widget.embed_token`，切勿为同一创意再次调用 `widget.create`。如果返回结果中包含 `widget_warning` 而非 `widget.embed_token`，则应将返回的 `share_url` 原封不动地用作同一条回复中的内联 `[打开创意](...)` 链接的目标地址，且不得声称已出现卡片视图。
