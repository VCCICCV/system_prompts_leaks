# 技能编写指南

当任务需要超出 `SKILL.md` 主流程的详细信息时，请参考本指南。

## 命名
- 目录名：`kebab-case`
- Frontmatter 中的 `name`：`snake_case`
- 保持名称简短、具体，并以能力为导向
- 当有助于提高触发器的清晰度时，按提供者或领域进行命名空间划分，例如 `google-calendar` 或 `outlook-calendar`

## 资源拆分
选择能够可靠承载该技能的最小结构。

- 当说明简短、稳定且在每次触发时都必需时，将其保留在 `SKILL.md` 中。
- 当细节有用但具有条件性时，使用 `references/`，例如长篇示例、模式、特定变体的说明或扩展的工作流程。
- 仅将最终会成为交付输出一部分的文件放入 `assets/`。
- 对于 Jarvis 捆绑技能，对于重复的协议、凭证或解析工作，优先使用 `bin/` 辅助程序。如果辅助程序可以承担这些机制，则不要将其留在提示文本中。

## Frontmatter 模板
```yaml
---
name: "my_skill"
description: "对技能的功能及适用场景的一行描述。"
---
```

注意事项：
- `name` 和 `description` 是触发器的核心界面。
- 捆绑技能通常不应设置 `metadata.includeInPrompt`。

## 正文模板

### 工具支持型技能
```markdown
# 技能标题

## 目的
一句话。

## 工具
确切的命令、关键标志，以及模型应解析的响应字段。

## 认证
认证信息的来源、首先需要进行的设置步骤，以及不应打印的内容。

## 运行规则
工具本身未强制执行的简短编号约束。
```

### 仅工作流程型技能
```markdown
# 技能标题

## 目的
一句话。

## 工作流程
智能体执行的有序步骤。

## 输出契约
最终结果应包含的内容。

## 运行规则
简短的编号约束。
```

## 应从 `SKILL.md` 中移出的内容
- 长篇的 API 端点目录
- 完整的响应模式转储
- 重复的认证/令牌提取片段
- 冗长的教程或背景介绍
- 大段仅在某些情况下适用的特定变体指导

将这些内容移至 `references/`，并在 `SKILL.md` 的相关部分添加链接。

## 审核 checklist
- 描述是否清晰地说明了能力和触发上下文？
- 技能是否限定为一项连贯的任务？
- `SKILL.md` 是否告诉模型接下来该做什么，而不是教授整个主题？
- 命令和路径是否适用于当前仓库/运行时环境？
- 在需要时，认证要求是否明确？
- 除有充分理由外，是否已移除 `includeInPrompt`？
- 如果技能使用了辅助程序，提示是否依赖这些辅助程序，而非重复其工作？
