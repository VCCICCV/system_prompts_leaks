# 忘记文物清单

请将此用作必需的路由检查清单，而非移除所有列出表面的许可。仅记录包含所请求主题或能够重现该主题的表面。对于每个匹配项，需明确其所有者、确切定位、与来源的关系、拟采取的行动、前置条件、可逆性及验证方式。

## 1. 对话与实时执行

检查当前及之前的公开或私聊事件、仅限上下文的消息、压缩摘要、子代理历史、工具调用及其输出、溢出的工具输出文件、重启检查点，以及对话范围内的待办事项快照。应将对话标题、列表预览、回复预览、活动卡片及其他由转录生成的展示投影，与其生成的事件行分开核查。

纳入消息附件、反应、原生频道副本、审批请求或决定，以及任何可能重新插入相关内容的待处理交接。检查仍在持有或处理相关信息的活跃子代理、浏览器任务、工作流、Shell 进程、调用及其他 RuntimeWork。

私下利用对话历史查找记忆、摘要、待处理工作及其他下游材料。可见的聊天本身并非清理目标或完成障碍，不得将其持续可见或保留视为限制。防止新的压缩摘要、记忆刷新、检查点及未来生产者再次陈述该主题。

## 2. 源文件与常驻上下文

检查以下位置中的精确匹配及语义重述：

- `~/MEMORY.md` 及其下的相关文件，包括日期化的源日志；
- `~/USER.md`；
- 当信息涉及人格、身份或承载目标背景时，还包括 `~/SOUL.md`、`~/IDENTITY.md` 以及遗留的 `~/GOALS.md`；
- 当信息成为签到话题、时间或频率偏好，或反映用户对主动联系的容忍度时，还包括持久保存的会话跟进偏好输入 `~/FEEDBACK.md`；
- 人物与群组页面及其索引，位于 `~/memory/people/` 和 `~/memory/groups/` 下；
- 购物档案 `~/memory/shopping/PROFILE.md`，该文件可由用户编辑，不纳入记忆摄取，并由购物流程直接读取；
- 当信息成为指令、常规检查或环境说明时，还包括 `~/HEARTBEAT.md`、`~/AGENTS.md` 和 `~/TOOLS.md`；
- 目标、学习、梦想、反馈、工作空间及用户自创技能文件；
- 工作空间下的附件、生成媒体及工具输出溢出文件。

此外，当工作空间为版本库时，还应检查可恢复的回收站、临时文件或编辑器备份、导出与下载归档，以及版本控制的提交、暂存或远程分支。删除工作副本并不会抹去这些历史记录。

不得使用可恢复的回收站进行批准的清理。在重新确认目标后，使用 `rm -- <exact-path>` 永久删除精确的独立文件。切勿使用 `rm -r`、其他递归式 Shell 删除命令、通配符或主目录/根目录路径。对混合内容文件应就地编辑，并通过所属产品的操作进行目录清理。已进入回收站的精确匹配独立文件墓碑也应永久清除，包括由所属产品在取消计划或工作流时创建的墓碑。若仅剩目录归档且无所属产品的永久删除操作，则应报告这一限制，而非对其进行递归删除。

保留混合文件中与主题无关的内容。每日日志是历史资料，而非一次性草稿空间：删除或修订其中一项内容时，必须同步调整其搜索条目及所有下游投影。

## 3. 内存检索与衍生投影Markdown 语料被索引至 PostgreSQL 的 `memory.entries`、`runtime.search_documents` 和 `memory.embeddings` 中。在索引之外，还存在一个声明主干 `memory.claims`：每条已验证的声明对应一行，包含其 ID、支撑该声明的引用及对话句柄、状态，以及旧信念与其替代声明之间的取代关系链。`memory_explain` 可展示某声明 ID、`memory://` URI 或 `path#L<line>` 引用背后的具体行；而 `memory_search` 结果的元数据中也携带声明 ID。撤回一条声明时，必须触及该链条上所有与其相连的声明，因此请记录下所移除内容的 ID 及确切行号；执行者会将其暂存于 `~/workspace/memory/forget/pending.json`，运行时则会在重新索引前先行撤回整条链条。衍生记忆还包括：

- `~/memory/bank/{world,experience,opinions}.md`；
- 个人与群组页面及其索引；
- 个性化投影；
- 简洁版 `MEMORY.md` 以及 `USER.md` 中的个人档案投影；
- 提示上下文缓存与已组装的会话上下文；
- 虚拟机中由中心发布的用户记忆嵌入。

若未同步稀疏搜索、向量搜索、提示缓存及中心发布便直接删除文本，将导致仍有活跃副本残留。应优先使用归属记忆的重建/发布 API。成功的 `forget.confirm` 执行完成后，运行时会先对记忆进行一次重新索引，再传递结果；切勿启动第二次索引。执行期间，请核验源文件及归属 API 的状态；语义搜索命中可能仍来自清理前的索引，但这本身并不意味着清理失败。运行时主导的重新索引会在结果传递前关闭这一检索面。若远程发布缺乏删除或替换证明，请报告该限制。

## 4. 自我提升产出

审查已完成及正在进行中的运行，其证据窗口涵盖目标对象：

- 记忆声明、对账暂存、降级记录、收据、运行/步骤状态，以及 `~/workspace/memory/` 下的相关文件；
- 关系页面、排名及关系运行记录；
- 对齐状态、综合成果、进展历史、修复线程、证据、归档，以及 `~/dreams/` 下的每日梦境；
- 目标管理提案及已应用的追踪变更；
- 购物档案运行、暂存的 `shopping/PROFILE.md` 文件、收据、排队或正在运行的档案生成器，以及持久化的 `~/memory/shopping/PROFILE.md` 档案；
- 学习计划、目标简报、建议、进展势头，以及 `~/workspace/objectives/goals/STUDYING.md`；
- 创意、创意来源、嵌入、卡片、已采纳的构建，以及由此衍生的 Feed 提示或单元；
- 发现池或其他社区卡片，以及从这些创意发布的预览；
- 技能提升提案、暂存的产物、已安装的用户技能变更、学习成果及后续跟进；
- 对话跟进尝试、持久化的选择器决策与 `feedback_note` 值，以及从近期公开聊天或 `~/FEEDBACK.md` 中筛选出的候选；
- 队列式学习与 Feed 发布的待发箱、中心发布的课程、收据，以及源自相关信息的未消费远程记录。

仅移除最终投影是不够的，因为某个目标运行或其暂存产物仍可能重新应用它。对于 `~/memory/shopping/PROFILE.md` 而言，仅撤回声明并重新索引也不足：需直接编辑或移除匹配的档案条目，从全新状态验证该文件，并确保没有任何排队、运行中、暂存或已排期的购物档案运行能够恢复这些内容。首先应暂停正在进行的生成器。即便保留了运行收据，也可能仅保有空内容的溯源信息；但任何模型可读的证据或包含目标对象的生成提案，都需明确处置。

## 5. 目标、日程与未来生产者检查用户目标、助手跟踪项、条目、关联关系、建议、简报以及已保存的提示快照。检查所有 Cron 定义与主体、归属的提醒事项、心跳指令、事件钩子、钩子脚本及其日志、工作流定义与已保存的运行记录、待发送的发件箱行、待通知的有效载荷、渠道发送的有效载荷，以及已受理的工作者。

将六小时对话跟进选择器视为一个生产者。它会读取 `~/FEEDBACK.md` 文件，以及最多 48 小时内可见的公开聊天记录；如果存在未完成的待处理尝试，该选择器在重试时可能会追加其已选定的 `feedback_note`。编辑该文件前，请先暂停或确认当前正在进行的尝试；仅移除与偏好设置相匹配的条目，并确保没有待处理的决策会重新写入这些条目，也不会就该主题发出后续跟进。可私下利用近期聊天记录寻找已得出的候选内容或决策，但不要将保留的可见对话列为清理的限制条件。

如果在该 48 小时回溯范围内，该主题仍符合资格，且不存在任何阻止选择器使用的排除规则，则此生产者尚未完全关闭。在回溯期结束或确证存在排除规则之前，应将该对话跟进类别标记为“待处理”，但不应以可见对话本身作为限制依据。

在具备当前运行时控制的主机上，成功的确认操作即为相应的排除规则：选择器会收到一条无主题的指令，要求其不得使用、应在后续偏好中保留，或不得暴露相关话题；而在更早的确认生效之前，任何尚未完成的决策都将被抑制，无法写入或发送。请确认该控制机制可用；若不可用，则仍按上述规则将该生产者保持为“待处理”状态。

使用归属的目标、跟踪、Cron、钩子及工作流工具。判断该主题是否仅为需要改写的附带文本，还是整个义务都必须删除。删除目标可能会级联影响其拥有的计划任务；相关方案必须明确展示这一后果。在清理其输出之前，应先禁用或取消已批准的生产者，以免其与清理过程发生竞争。

## 6. 资产与共享

搜索文件资产、网页资产及其 `app.db` 记录、媒体、附件、小部件、个人资料、创意构建、简报、导出文件以及生成的报告。涵盖空间及其提案或共享内容、项目、播客节目及其远程音频、封面和 RSS 对象、信息流帖子或单元、媒体描述与元数据、提取的 OCR 或转录文本，以及头像或个人资料的投影。检查是否存在与之匹配的资产已被共享、发布、通过渠道发送、附加到邮件，或复制至外部服务。

对资产自有数据使用相应的资产操作。本地删除并不撤销共享链接，也不会撤回消息。解除共享、删除外部副本，或联系他人，均属独立的外部行为，如未包含在已确认的计划中，则需另行审批。

## 7. 已连接与缓存的来源

相同的信息可能仍存在于电子邮件、日历、通讯录、设备缓存、健康或传感器记录、通话记录、频道历史、浏览器会话及其页面、截屏、DOM、下载内容或无障碍缓存、采集/原始信号记录、连接器，或其他外部账户中。需确定 Muse 是仅读取了该信息、将其缓存，还是由其创建。仅凭遗忘请求本身，并不能授权更改源服务。

如果某个未变更的已连接项目仍可被再次采集，则方案中需包含针对该来源的排除规则，或明确的限制条件。验证过程中，切勿持续从外部服务中重复发现该主题。

## 8. 运营与保留的副本计入运行时事件、推理/提供者跟踪、Pariscope 或 Scuba 的遥测数据、journald 日志、数据库 WAL、快照、备份、移动通知、提示渲染结果、缓存的请求或汇总行，以及受保留策略管控的服务副本。这些并非普通的代理内存，虚拟机子代理可能无法将其清除。

对于每一种已知类型，请明确说明其是已被删除、被替换、从活跃模型的使用中排除，还是仍被保留直至外部策略到期。未经权威确认，切勿声称备份或服务遥测数据已被物理擦除。

## 9. 验证闭环
最终验证必须证明：

1. 该代理不再持有任何经批准的权威来源；
2. 精确检索和语义检索均不再返回可用的副本；
3. 常驻提示上下文、新的压缩摘要、内存刷新、重启检查点以及购物档案均未保留或重新呈现该内容；
4. 任何活跃的、暂存的、排队中的或已调度的生产者（包括购物档案的执行）均无法重建该内容；
5. 经批准的工件和共享均已按要求处置；
6. 剩余的外部副本或受保留策略管控的副本均已明确报告。

若在验证过程中出现将敏感文本重新引入正常聊天、记忆条目、待办事项、文件名或报告的情形，则视为验证失败。应在私有计划中保存详细的匹配证据，仅向用户公开精简的计数与分类信息。最终的限制报告中不得包含原始可见对话的内容。
