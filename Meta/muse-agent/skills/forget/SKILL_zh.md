# 忘记

将“忘记”视为在 Muse 中的全局清理，而非仅编辑某一条记忆笔记。
相关信息也可能存在于对话历史、其他笔记、偏好设置、目标、已安排的工作、已创建的项目、搜索结果或能够将其重新写入的正在进行的工作中。

与用户交流时使用日常语言，不要暴露内部机制。应使用“记忆”“提醒”“已创建的项目”“共享项目”“日志”或“备份”等术语，而非文件名、数据库表、索引、投影、遥测系统、工具名称、代理类型或运行时机制。将确切的定位符和技术细节保留在私有工作空间内。只有在用户提出要求或明确询问清理的具体方式时，才提供技术细节。

## 制定计划

首次调用 `forget.plan` 时传入空对象 `{}`。该操作会启动一个普通的、无类型的子代理，并使用标准工具目录，其主题由当前对话推导得出，因此请勿在工具参数中重复敏感文本。等待其移交结果，而非轮询或同时进行其他搜索。Muse 会将此子代理固定在 muse-special 空间，或在保密虚拟机上的私有 Avocado 空间中运行，且不受当前模型选择的影响。

规划器会读取 [references/artifact-inventory.md](references/artifact-inventory.md)，保持只读状态，并检查以下内容：

- 原始位置及具有相同含义的副本；
- 记忆、搜索结果、对话上下文及其摘要；
- 提醒、已安排或正在进行的工作，以及能够重新生成该信息的外部来源；
- 共享或已发布的副本，以及 Muse 无法删除的任何内容。

它会返回一份简洁的计划，说明发现的内容、需要变更的部分、清理的验证方式，以及已知的限制。移交时应保持隐秘，避免将信息复制到新的记忆、待办事项、文件名或报告中，而应以“那些信息”代指。可通过私下对话查找下游副本和后续活动，但不要将聊天本身的持续可见性或保留情况作为清理的限制条件。

## 征求同意，再执行

向用户展示计划的范围、不可逆的操作及重要限制，并将其转化为上述日常术语，然后提出一个直接的确认问题。沉默、含糊不清、部分认可或范围变更均不构成确认。

在用户明确同意后，调用 `forget.confirm` 并传入空对象 `{}`。该操作会启动一个新的普通无类型子代理，沿用相同的模型策略，并从继承的对话中读取最新的计划和确认信息。无需保存或传递任何规划代理的标识。

执行者若无法识别出一条明确的最新计划及其确认，则必须停止操作，不得进行任何更改。否则，它需重新验证当前状态，在移除输出之前停止所有已批准的工作，使用各项目的归属工具，保留无关内容，刷新所有依赖于已变更内容的衍生项，并从全新状态进行验证。例如，对于购物偏好，应直接检查 `~/memory/shopping/PROFILE.md`，编辑或删除匹配条目，并确保没有任何暂存、排队、运行中或已安排的购物偏好任务能够恢复这些数据。如果情况已发生重大变化，或不存在安全的清理方式，则应制定修订计划，而非扩大清理范围。

切勿将已批准的清理目标送入可恢复的回收站。对于必须彻底消失的精确本地文件，请通过 `exec` 调用 `rm -- <exact-path>`，切勿使用 `rm -r` 或其他递归式 shell 删除命令。在删除前立即再次验证路径，切勿使用通配符或宽泛的目标，对于混合内容的文件应进行编辑而非直接删除。清理目录时应通过其所属的产品操作来完成；若不存在安全的归属操作，则应制定修订计划。如果某个产品操作在其清理过程中将定义归档至回收站，则应永久删除与其完全匹配的独立文件墓碑。计划必须在用户批准前明确说明永久删除为不可逆操作。

在执行结束前，执行器会暂存其从内存中移除的内容，以便运行时能够撤销与之匹配的内存声明及其派生内容：它将写入 `~/workspace/memory/forget/pending.json` 文件，内容为 `{"claims":[...],"citations":[...]}`，列出在 `memory_explain` 或 `memory_search` 元数据中看到的声明 ID，以及被移除或重写的精确定位符，如 `MEMORY.md#L<line>` 或 `memory/<date>.md#L<line>`。文件中仅记录 ID 和定位符，绝不包含被遗忘的文本；即使两个列表均为空，该文件也会被写入。

执行器成功完成后，Muse 会撤销已暂存的声明并刷新内存搜索，并在两者都完成后再传递结果。若刷新失败，则应报告清理未完成，而不能声称相关信息已无法检索。清理工作应在本执行器中直接完成，而非交由其他子代理处理。如果执行器结束时仍有委托任务尚未落实，Muse 应报告清理未完成，以防止后续变更抢先于刷新操作。执行器仍需核查其他受影响的位置，但无需再次刷新内存搜索。

若任一工具失败，切勿转为未经计划的手动删除，亦不得擅自宣称任务成功。应说明失败原因；若用户仍希望继续，则制定新计划。

## 如实汇报

向用户说明哪些类别已完成清理、哪些提醒或其他未来活动已被终止，以及尚有哪些内容未处理。切勿重复被遗忘的信息。

只有在经再次核实确认不存在任何可使信息恢复的活跃记忆、派生副本或未来活动时，方可使用“已遗忘”一词。外部服务、共享或已发布的条目、日志、备份及其他保留的副本可能仍然存在；请明确指出属于日常类别的内容，并说明 Muse 是否能将其排除在当前使用之外。

切勿告知用户其原始消息可能仍会在聊天中可见，也不得将其表述为 Muse 未能清除的部分。可见的对话文本并非清理目标，亦不构成完成的障碍。仅可在私下检查这些内容，以查找并清理其中涉及的记忆、派生物或曾利用它们的未来活动。

本次请求并未授权删除外部电子邮件、日历数据、设备记录、共享出版物或他人持有的副本。此类操作需另行获得用户许可。
