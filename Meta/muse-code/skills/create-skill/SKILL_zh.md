# 创建技能

创建一个全新的 Muse 技能。此技能仅用于明确的技能创建请求，不得用于普通技能使用、代码变更、基准测试任务或第三方技能/插件系统。

有两种作用域（ADR 8975）：

- **项目作用域（默认）**：技能位于当前工作区的 `.agents/skills/<skill-id>/` 目录下。
- **个人作用域**（当用户请求“个人”、“用户”或“跨项目”技能时）：技能存放在受管理的个人根目录 `$CONFIG_DIR/skills/<skill-id>` 中（若未设置，则为 `$XDG_CONFIG_HOME/muse`，否则为 `$HOME/.config/muse`）。您需在工作区中暂存并验证草稿，然后向用户提供一条 `muse skills install` 命令——由技能仓库执行受管理的安装操作（包括文件及来源信息），从而确保后续的 `skills update` 和 `skills uninstall` 命令仍能正常运行。

切勿向其他环境的技能根目录（如 `~/.codex/skills`、`~/.claude/skills`）或 `$HOME/.agents/skills` 写入内容——这些仅为导入源，绝非写入目标。也切勿直接向 `$CONFIG_DIR/skills` 写入：该目录的写入权限归技能仓库所有，需通过下方的安装命令完成。

## 作用域

- 只创建一个目录：`.agents/skills/<skill-id>/`（项目作用域）或暂存目录 `.agents/skill-drafts/<skill-id>/`（个人作用域——刻意置于 `.agents/skills/` 外，以避免草稿被加载为项目技能）。
- 只创建一个必选文件：`<该目录>/SKILL.md`。
- 不得创建插件、安装插件、启用技能、信任插件、执行生成的技能、获取远程内容，也不得在当前工作区之外进行任何写入操作。
- 除非用户明确要求且目标始终位于新技能目录内，否则不得添加脚本、资源、引用或其他额外文件。

## 输入

在写入文件之前，需明确以下内容：

- `scope`：项目作用域（默认）或个人作用域——仅当用户明确请求个人、用户或跨项目技能时才选择个人作用域。
- `skill-id`：用于目录和 Frontmatter 中 `name` 字段的可移植小写标识符。
- `description`：一段清晰的句子，用于 Frontmatter。
- `body`：简洁的说明，使生成的技能能够独立发挥作用。

如果用户提供的信息不足以确定安全的 `skill-id` 和有用的行为，请提出简短的澄清问题。

## 安全检查

在写入前拒绝请求的情形包括：

- 目标路径不在当前工作区的 `.agents/skills/`（项目作用域）或 `.agents/skill-drafts/`（个人暂存）之下；
- 请求的最终目标是其他环境的技能根目录（如 `~/.codex/skills`、`~/.claude/skills`）、`$HOME/.agents/skills`，或任何超出两个指定根目录及个人暂存目标（即工作区的 `.agents/skills/` 目录树、`$CONFIG_DIR/skills/<skill-id>` 和 `.agents/skill-drafts/<skill-id>`）的绝对路径——此时应说明合法的路径；
- ID 为空、为 `.` 或 `..`，包含 `/` 或 `\`，以 `-` 开头，或包含除 ASCII 小写字母、数字、连字符或下划线之外的任何字符；
- ID 是 Windows 系统保留的名称，如 `con`、`prn`、`aux`、`nul`、`com1`、`com2`、`com3`、`com4`、`com5`、`com6`、`com7`、`com8`、`com9`、`lpt1`、`lpt2`、`lpt3`、`lpt4`、`lpt5`、`lpt6`、`lpt7`、`lpt8` 或 `lpt9`；
- 目标路径已存在、为符号链接，或其任意父目录解析后超出当前工作区范围。

## 创建步骤

以当前工作区为基准，使用常规的文件和 Shell 工具。下文中的 `<dir>` 指 `.agents/skills/<skill-id>`（项目作用域）或 `.agents/skill-drafts/<skill-id>`（个人作用域）。

1. 检查 `<dir>` 是否不存在。
2. 如有必要，创建其父目录（`.agents/skills` 或 `.agents/skill-drafts`）。
3. 使用不可覆盖的操作预留叶目录。若有其他进程先于您完成预留，则停止操作并报告为未完成。
4. 再次确认预留的目录位于当前工作区内且不是符号链接。
5. 写入 `<dir>/SKILL.md`。
6. 执行以下命令：

   ```sh
   muse skills validate <dir> --json
   ```7. 仅当验证器成功、返回 `valid: true` 并且未报告任何诊断或警告时，才将草稿视为已完成。
8. 如果验证失败，请修正同一份草稿并重新验证。经过三次修正后停止，并将剩余的验证器输出报告为“未完成”。

## 生成的 `SKILL.md`

使用以下格式：

```markdown
---
name: <技能ID>
description: <一句话描述>
---

# <易读的技能名称>

<关于何时以及如何使用该技能的说明。>
```

生成的说明应简洁明了、自成一体，仅包含用户所要求的行为或使技能正常运行所必需的内容。

## 完成报告

成功时，报告：

- 创建的目录的规范路径；
- 验证命令及其干净的结果；
- 未执行任何安装、启用、信任或执行步骤；
- **仅限个人范围**：完成向个人根目录管理式安装的唯一命令——由用户执行，以便技能存储能够自行记录安装来源：

  ```sh
  muse skills install .agents/skill-drafts/<技能ID>
  ```

  以及在安装成功后可删除暂存目录。

失败时，报告：

- 哪个操作失败了；
- 如果目标位置已被预留，则报告其位置；
- 剩余的诊断信息或工具错误；
- 哪些检查未完成。
