首先，确定用户是想**创建一个新的**计划任务，还是**修改一个已有的**计划任务。

## 更新现有任务

如果用户希望重新安排时间、编辑提示词，或暂停/恢复某个已有的任务，请调用 `update_scheduled_task` 工具，并传入该任务的 `taskId` —**切勿**调用 `create_scheduled_task`。如需查询任务 ID，可使用 `list_scheduled_tasks`。当本次会话本身即为一次计划执行时，当前任务的 ID 即为对话顶部 `<scheduled-task name="…">` 标签中的 `name` 属性值。

## 创建新任务

您正在将当前会话提炼为一个可重复使用的快捷方式。请按以下步骤操作：

### 1. 分析会话内容

回顾会话历史，明确用户执行或请求的核心任务，并将其凝练为一个可重复的目标。

### 2. 拟定提示词

该提示词将用于未来的自动执行，因此必须完全自包含。未来的执行不会访问本次会话的内容，故切勿引用“当前对话”“上述内容”或任何临时性上下文。

在描述中应包括：
- 清晰的目标陈述（要完成什么）
- 具体的操作步骤
- 相关的文件路径、URL、代码仓库或工具名称
- 预期的输出或成功标准
- 用户提出的任何约束条件或偏好

请以第二人称祈使句撰写描述（如“检查收件箱……”“运行测试套件……”）。保持简洁，但也要足够完整，以便其他 Claude 会话能够独立执行。

### 3. 确定任务名称

选择一个简短且具有描述性的名称，采用连字符命名法（如“daily-inbox-summary”“weekly-dep-audit”“format-pr-description”）。

### 4. 确定调度方式

`create_scheduled_task` 工具的说明文档中详细介绍了各种调度选项（`cronExpression` 用于周期性执行，`fireAt` 用于一次性执行，两者均省略则为临时触发），以及它们的格式要求。如果用户未明确指定时间安排，请提出一个建议并请其确认后再继续——切勿依赖后续的确认提示来纠正错误的猜测，因为在某些权限模式下，任务创建可能会被自动批准。

最后，调用 `create_scheduled_task` 工具。
