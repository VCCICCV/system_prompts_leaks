# 降本搜索：如何构建流程

针对以**降低成本**（在质量不降低或更优的前提下）为核心的、由评估驱动的搜索流程的指导——通常用于从旧模型和提示迁移至当前模型的场景。这是爬山循环（`eval-hillclimb.md`）在用户第一步目标为成本时所遵循的流程，它假定存在一个用于衡量质量的评估指标。若无该评估指标，则应改用 `shared/cost-optimization.md` 中的无评估清单（缓存 → 输入裁剪 → 代理循环优化 → 输出 → 批处理 → 算力 → 模型优先）。各环节的顺序刻意如此安排：有了评估，就能“发现”在更低算力下使用更强模型才是更经济的选择，因此在此将模型与算力的组合探索前置；而若无评估，则模型切换的风险最高，应置于最后。本文中出现的具体数值，均基于代表性基准评估的实测结果，除非另有注明为从业者报告，以便您预判结果趋势；但务必在用户的实际评估上重新测量。

## 搜索顺序

请按以下顺序逐一调整各参数。每一步的先后次序都有其合理性，若顺序颠倒，会干扰或浪费此前已执行的步骤。

**第0步 — 缓存健康检查：首先进⾏，并在每次调整参数后重新验证。**  
缓存属于配置范畴，而非搜索参数本身——其健康状况直接决定了后续所有成本测量的准确性，且其最常见的故障模式是静默失效。快速健康检查：缓存断点已正确设置；缓存前缀不含动态内容；响应中的 `cache_read_input_tokens` 不为零。此处不再赘述缓存设计细节，请参考技能的提示缓存指南（随包提供的 `shared/prompt-caching.md`），重点掌握以下实践要点：每次变更后都需重新验证缓存健康，而不仅限于初始设置；熟悉健康缓存在实际使用中的表现；当读取量下降时，要迅速定位并消除导致失效的具体原因。但在下面每一步进行模型或算力调整后，都必须再次执行此健康检查。此外，以下各步骤还需注意两点：缓存是按模型隔离的，且在 Messages API 上，算力会参与提示缓存键的生成——在对话中途切换算力会导致整个前缀被重写一次（经对当前顶级模型的原生 API 实测：3 次算力切换均按完整前缀计费，而 9 次相同算力的续写则未重复计费）。来自第一方产品界面的报告称算力切换不会导致缓存失效，这一结论并不适用于 API 客户——两者的服务路径不同，请以 API 测评为准。综上所述，任何参数变更都可能使原本健康的缓存悄然转变为看似由模型行为引起的成本上升，因此在完成模型与算力组合探索的每一步（第2步）后，都必须重新验证缓存健康，而不仅仅是在初始设置时检查一次。**步骤 1 - 审核现有提示与请求配置。**
过时的提示内容和遗留的请求参数会破坏后续的所有比较：在一次难度较高的迁移中（使用了严重过时且扩展过的提示），仅升级模型几乎未带来任何准确率的提升；而对同一提示进行审核后，却能弥补超过十倍的差距。在同一迁移中，较为温和的一侧（仅掺入少量冗余）测得约2倍的差距，这充分说明了提示过时程度的不同会带来多大的影响。一种人为引入的旧版思维配置（即过时的 token 预算设定）被明确拒绝——在当前所有模型上均如此，经探针验证——必须重新编写后才能进行任何比较；而符合时代要求的正确形式虽然不会导致崩溃，却会额外增加成本，这反而更糟，因为没有任何机制会提醒你注意到这一点。较新的模型对旧版框架的遵循更为“字面化”，因此在过时提示下进行的模型对比可能会导致模型排序错误，甚至还会进一步推高成本。审核的成本很低，只需执行一次，此后便能有效去除干扰。在进行任何需要保留的测量之前，请先运行 `prompt-audit`（该流程以 shared/prompt-audit.md 的形式提供），并对照当前 API 表面检查请求参数（参见模型迁移指南）。

**步骤 2 - 模型 × 质量目标：沿阶梯式路径搜索，而非遍历全网格。**
最经济的配置往往是“更强的模型搭配更低的质量目标”：较强的模型在完成相同任务时往往消耗更少的 token（这是一个普遍趋势，而非固定幅度），因此在成本和得分两方面都能占据优势。然而，任何先固定模型为默认质量目标、再调整质量目标的流程都会忽视这一配置；而完整的全因子网格则必须为每个单元付费，其中大部分都位于昂贵的角落。应将模型与质量目标视为一个整体表面，并采用“阶梯式搜索”来探索它：将模型层级沿一个轴排列，质量目标沿另一个轴排列。在每一行内，成本随质量目标的提高而上升；而在不同层级之间，测得的成本区间可能存在重叠（详见下文的例外情况）；同时，质量在两个维度上均呈弱增长趋势，因此那些达到预先设定的质量底线的单元会聚集在右上方区域，而最经济的可接受单元则位于该区域的左下边界附近。从左上角开始沿单调路径行走，只需经过大约（层级数 + 质量目标档位数）个单元即可勾勒出这条边界，而非遍历（层级数 × 质量目标档位数）个单元——那些被跳过的单元正是那些昂贵的角落。（在低成本评估中，这种阶梯式搜索带来的更多是可预注册的规范性约束，而非直接的费用节省：某项实测程序的完整网格成本总计约为 20 美元。）补充说明：“更强的模型搭配更低的质量目标”这一规律是在标准规模的任务上按列表价格测得的，且依赖于具体的基准测试；该搜索方法会在用户自己的评估中加以验证，而非直接假设其成立。
*搭建搜索网格。* 行代表按能力排序的模型层级；列代表质量目标档位（由低到高）。有两项规律支撑着这种搜索方式，其中之一更是制定计划时必须明确的前提假设：在同一条水平线上，成本随质量目标的提高而上升（本指南背后的两个项目中的每一行均已证实）；而在质量目标固定的情况下，质量随模型层级的提升而提高（在所有已测的组合中均成立——一旦出现反常，搜索就会误删候选，这也是注册确认机制存在的原因之一）。沿着“质量目标”这一轴，质量的增长趋势较弱——在某个实测案例中，最高档位在单次运行的指标上甚至低于最低档位（在约 ±6% 的噪声范围内打平，但 token 消耗却是前者的 1.7 倍）。因此，在搜索过程中绝不能依赖这一维度。位于默认顶层之上的前沿层级（如有）则作为扩展部分置于网格之外：它曾多次定价高于顶层的中等档位（在某次实测迁移中，其价格是最终胜出方案的约 7 倍），因此应将其视为质量探测点，而非成本候选——是否纳入考虑，需通过下文所述的成本可行性筛选来判定。

*第0轮诊断（在网格尚未分配任何资源之前）。* 从为噪声基准已执行的重复测试中，读取转录本中的两项指标：输出标记占比和每任务回合数。第三项指标——努力敏感度——会在*旧*模型上以另一种努力水平消耗一到两个廉价单元。若任务输出量大、多回合且对努力敏感，则预期胜出者位于顶部几行的低单元，并在此处安排预算重复测试；若任务输入量大、单次完成且努力影响不显著，则属于例外类别，此时按标记计价占主导地位；入门单元相同，但应迅速向下调整，并为底部几行安排预算重复测试。诊断结果决定重复测试的投放位置，绝不在行走路径的入口处。

*成本合理性筛查（何谓“成本合理”）。* 根据匹配努力水平下的计费结构，推算每个候选层级的最低单元价格——即该层级的标记单价乘以低努力水平的计费结构；而第0轮诊断已在旧模型上获取了这一低努力水平的计费结构；若仅有基准自身的努力水平计费结构，则在应用基准前先按实测的第0轮努力比进行折减。（这是规则4中努力匹配要求在筛查阶段的具体体现：在不同努力水平下，某一配置的最低单元价格会大致按努力比被高估，而在筛查时，这种高估会被判定为不予纳入。）只有当证据充分确凿时，某一层级才会被移至网格上方的扩展区域：即在既定误差范围内，没有任何推算能使该层级的最低单元价格低于其下一层级的中等单元价格——仅凭点估计无法断言“不可能”；已测得的推算误差既有约2倍的乐观偏差，也有约2.8倍的悲观偏差——并且，在当前工作负载环境下，既无实测也无报告的标记经济性证据表明该层级能够弥补这一差距（更高效的层级确实能减少每任务的标记消耗，但具体幅度取决于特定配置与任务组合，而迄今所测的经济性数据均为单次观测值，应将其视为方向而非量化数值）。筛查的设计是单向的：如有疑问，该层级仍留在网格内，因为纳入错误的成本较低（入门探测即为该层级最廉价的单元，失败则可直接剔除整列），而排除错误则不会被察觉（唯有失败后的扩展触发机制才能发现此类错误）。将筛查结果及其依据记录于预注册信息中。

*在低努力水平下，进入最高层次且成本合理的全新一代层级。* 原因有三：唯有左上角能提供明确的决策路径——通过即沿一个方向推进，失败则沿另一个方向推进；而从左下角出发，失败后仍有两条向上延伸的路径，且在未同时探测两者之前无法作出选择。入门探测采用顶层中最廉价的单元，因此预算可控。此外，这一步亦兼具制度检验的功能：若顶层整体未能达到最低门槛，则评估结果处于或高于各模型的能力边界——此时升级关乎质量而非成本；应停止寻找降本空间，并明确指出这一点。（一个客观成本：顶层在首次通过前尚无既定配置，因此其右侧的探索路径在设计上成本不受限，而这正是制度探测所付出的代价。）

*行走路径。*- **在（层级k，努力e）处通过：** 将该单元格记为当前优胜者，其成本为c*；删除第k行余下部分，并向下移动一层——此后仅进入那些投影成本不超过c*的单元格。这一行的剪枝无需任何质量假设：在通过点右侧的每个单元格成本均高于该通过点，因此无论是否达到门槛，它们都无法击败当前优胜者。这使得规则对努力程度的非单调性具有鲁棒性。
- **在（层级k，努力e）处失败：** 假设在同一努力水平下，所有更低层级也均未通过（基于前述层级单调性假设），并向右移动一步。一旦出现当前优胜者，后续仅进入投影成本不超过c*的单元格，并将向右搜索的范围限制在一到两个位置——因为努力与质量之间的单调性较弱，不宜继续深入。
- **重叠探测：** 在层级k上先失败后通过的情况下，层级k-1中投影成本不超过c*的单元格仍可能被探测。这种重叠——即较小模型全力运行而较优模型几乎不尝试——是整个搜索过程中唯一发生分支的地方。
- **扩展触发（唯一的向上移动）：** 如果最顶层的最低单元格失败，且该行中通过的单元格价格接近网格上方的扩展层级，则在停止前先探测扩展层级的最低单元格。这也是对筛选时错误排除某层级的唯一补救途径——按相同努力水平对其进行投影（规则4）。
- **停止条件：** 当无未探测单元格的投影成本低于c*，且扩展触发未被激活时，当前优胜者即为最终答案。

一句话概括：从最高成本合理的全新一代层级、以较低努力水平开始；通过则向下走，失败则向右走；按当前优胜者的成本进行剪枝；最前沿层级的最低单元格是网格上方的扩展层级，而低努力的老模型则是其下方的首轮诊断依据。

*搜索过程不可或缺的决策机制：*
1. **门槛在第一轮之前预先确定**——例如，以基准测试的最佳重复结果为准并说明理由，而非事后取基准的平均值。在一次实测迁移中，注册的门槛被设定在基准平均值之上，正是因为一个恰好等于或略低于该平均值的单次得分，既有可能低于基准，也可能等于基准——这样的读数不能作为等效性的有效证据。
2. **晋升需在门槛附近至少有n≥2次合格。** 任何即将成为当前优胜者的单元格，若其超出门槛的幅度处于噪声范围内，则在c*变动之前会再进行一次测试。误差具有不对称性，且代价更高的错误是假“通过”：一次侥幸通过会锁定c*并剪掉真正的优胜者；而更低层级的失败并不能说明其上方的通过是否真实；最终确认只能在被剪掉的单元格已消失后才发现这一错误。（实测案例：一名在首次重复中以20次中的11次通过的优胜者，在后续使用完全相同的配置时仅得6次。）而假“失败”只会使搜索向右推进一格——代价更低，且下一条规则可予以覆盖。
3. **位于门槛噪声范围内的失败结果，在向右移动之前需重新测试。**
4. **剪枝是校准后的暂缓，而非删除。** 根据计费特征预测单元格的成本——即该层级的单位价格乘以与候选人努力水平相匹配的实测单位用量分布（低努力的候选人应基于低努力单元格的存量特征进行预测；若以不同努力水平下的当前优胜者特征来估算，则会因努力差异而高估约相应比例——实测案例显示，按较高努力水平的当前优胜者估算时高出2.8倍，而按实际努力水平重新估算后，结论变为低于当前优胜者）。切勿仅凭先验信息进行预测：在一项实测项目中，早期预测曾偏乐观约两倍，而过于乐观的预测会导致过度剪枝。被剪枝的单元格只是暂缓处理；若预测结果得以修正，则应将其重新纳入考虑。*在真实评估中，这一“步进”过程是怎样的。* 重现本指南所依据的两次实测迁移：在普通工作负载评估中，“步进”仅用两格便抵达最终胜者——入口格以低优先级通过，其下一层格在提示条件满足（即残留冗余被清理）后也以低优先级通过（在此前的存活冗余条件下该格曾失败，后由第4步的重新探测予以挽救——参见该步骤的注意事项）；随后，“步进”会提出实际程序从未发出的一个问题，即再下一层格的问题；而该程序实际执行过的前沿层格则在下方扮演了既定的质量探测角色。在前沿难度评估中，入口格未能达到最低门槛，同一层的中优先级格却通过了——仅高出门槛1分，处于噪声区间内，而这正是上述规则2所针对的情形：它会在晋升为现任者之前再进行一次运行。（后续对该相同配置的确认测试所得的11、6、11这一组数值便是例证——一次重复中仅1分之差，到下一次可能就变成6分。）接着，“步进”向下移动至中间层的低优先级格——这是实际程序从未触发的一次探测（其成本预估低于程序实际调用的那些格）；若该格失败，“步进”便会直接进入中间层的中优先级格，而这一格正是程序实际调用了的：它的成本低于现任者的基准，但质量表现却明显不及。至此，“步进”停止，不再运行中间层的高优先级格，而实际程序为此支付了真金白银，才得知该格的价格高于现任者。（该程序的胜者在全新运行的均值上，较同一型号的高设置低46%，较旧型号基准低43%；而在单次最便宜的选择环节中，相应对比分别为低50%和48%。报告时应采用全新运行的均值，绝不能取某一波动区间的有利端点。两条路径均按内部计页方式计费；在公开断点计费模式下，降幅会略小一些——与基准对比约为-40%——且无论哪种计费方式，两条路径的比较都保持同口径。）前沿难度案例同时也是警示性的一面：胜者的预先登记确认测试未能通过稳定性条款——同一配置在选择环节中抽样得分为20中的11，而在三次全新的确认测试中则分别为11、6和11。因此，如实的结论是：“成本削减明确，平均质量在噪声范围内相当，但比基准更不稳定”，而标题必须采用确认测试的结果，而非选择环节的数据。你所处的制度环境决定了升级究竟是成本杠杆还是质量杠杆；而入口格正是通过一次有限的探测为你指明这一点。

*各格诚实性规则（适用于“步进”过程中的每一次探测）：*

- **单次运行的得分只是及格/不及格的依据，而非排名。** 单次评估就可能仅因采样差异而使结果波动数个百分点（实录的小样本示例：约8分，重复实验中的波动范围为±6分）。真正可信的单次运行指标是遥测数据——即每个案例的实际思考步数、输出token数以及工具调用次数，而非微小的分数差异。在开始搜索之前先测量噪声水平（对当前配置进行多次重复运行，或对已有结果文件按k值取样），以便为保底阈值和晋升规则提供可参考的数值。
- **在认定向右调整有效之前，务必确认努力调节旋钮仍具实效。** 努力曲线因模型家族而异，且并不总是单调的：曾有案例显示中等努力反而优于高努力，也有评分曲线存在末端采样无法捕捉的拐点。若向右调整后实际思考步数未发生变化，则说明该家族的努力调节已失效——后续更高的设置不过是同一单元以更高代价的重复，因此应视该行已穷尽。
- **成本探测读数是在缓存冷启动状态下的结果。** 各单元之间不会共享缓存——缓存是按模型划分的，且努力程度会参与缓存键的构建（步骤0）。因此，生产环境下的实际成本通常会比探测时的成本低，降幅取决于缓存命中率；要么预先对每个单元进行预热，要么在报告中明确标注这一情况。在测量某次会话的成本时，请保持努力程度不变，否则缓存失效带来的噪声会混入努力相关的数据中。
- **明确各单元的计费基准。** 评估框架的计费路径可能与API客户的实际支付不同——某些内部路径按固定大小的页面计费，而公开API则按断点处的实际token数精确计费；同一次运行在不同路径下报告的成本可能相差甚远。报价绝对成本前请确认账单所走的路径；同一路径下各单元之间的相对比例比绝对值更为可靠。

*必须设置一个质量探针，否则上限将无法被测量。* 按照设计，搜索过程不会触及最昂贵的角落，因此提前通过的迁移方案永远无法得知高努力下的顶级配置究竟能带来怎样的效果。如果确实需要这个数值——通常在首次探索时会有此需求——请单独运行右上角的单元，或网格之外的低努力前沿层级，并在计划中标明其作为唯一指定的质量参照单元。预算紧张时可酌情省略。
  
*从底部切入也是合理的两种情形：* （1）稳态调优——已在当前代际模型上使用经过调优的提示词，只需小幅优化：从当前位置向下扫描努力程度，但务必加入“下一档位的低努力”探针。这样可以弥补一个盲区：自下而上的扫描若发现较低档位的质量尚可而成本偏高，便不会再向上推进，从而导致更低一档、更便宜且性能更好的单元从未被测试。之所以不能省略此探针，是因为实际计费存在重叠：在某个项目中，顶层的低努力单元在两次运行中的成本分别低于和高于中间层的中等努力单元（分别为后者的约0.8倍和1.5倍），且在两次运行中都解决了更多问题——相邻档位的实测成本区间存在重叠，因此不能单纯依赖档位顺序来判断成本高低（上述现象只是证明了风险的存在，并非该盲区已被触发的实例：在该项目中，中间层的单元也未能达到保底要求，因此即便是自下而上的扫描也会终止）。（2）总预算仅够覆盖一两个单元，外加一轮用于诊断的初始探测：“异常类别”——直接跳到同档位的低努力替代方案，并承担错过反转效应的风险。

（关于努力调节旋钮的作用及其何时能体现其价值，请参阅该技能的努力等级指南——该指南尚待更新，尚未纳入正式发布版本；本节旨在说明如何对其进行搜索。）**步骤3——在冻结的模型上进行提示优化（Prompt-Hillclimb）。**
提示优化带来的收益无法跨模型迁移——在两个不同的模型族中分别测得+30和+15个点的提升，但这些收益均具有模型特异性；而且，某个较新模型的失效模式甚至完全无法通过调整提示来解决。在模型冻结之前就对提示进行梯度上升优化，会浪费宝贵的优化空间。请按照梯度上升指南执行循环，并遵循以下针对成本的具体规则。

不要假设成本问题就出在提示上。步骤1的审计能告诉你提示“哪里”出了问题；只有通过测量才能确定这些问题“造成了多少”成本。在一次实测案例中，一个过时的开场白充斥着增加回合开销的仪式性要求（强制提交计划文件、每次编辑后重读、每次变更后跑完整测试套件），经审计被认为是一个明显的成本优化点——然而清理后的开场白却未能节省任何成本：两个清理后的评估单元都落在了其预先登记的80%成本区间之上（清理后的单元的成本预测值仅降低了约32%），并且位于后续测得的现有配置相同设置下的成本分布范围内（因此，“成本更高”可能只是噪声所致；更确切的结论是“完全偏离了预先登记的成本区间”）。参与度统计（见下文）显示，在20次运行中，强制推理的仪式性要求被完全忽略，而计划文件的指示却有17次被真正执行；然而，即便将这些内容全部删除也未带来任何节省，因为每轮的成本主要由回合数和上下文增长决定，而非开场白文本本身。这比“模型会忽略无效文本”的说法更为精确：即便是那些被遵守的辅助性内容，也并非成本的来源所在。在清理环节之前先预注册一个否定条件——“如果清理后的提示未能降至指定的成本阈值之下，则提示这一优化手段已到极限，应如实记录”——这样，当优化无果时，就能以正式的结论关闭该优化方向，而不是在同样的无效瓶颈处继续进行新一轮的修改。

**步骤4——提示优化完成后，向下左方重新探测一个单元。**
降低一个努力等级，或在刚刚通过的努力层级再降一级。清理可能会使原本不达标的单元变得可行，因此在提示发生变化时，此前对该单元的判断即告失效：在一次实测迁移中，中级层级的低单元在旧提示下为0.64，而在基于转录文本的清理后，在冻结的模型上则变为0.98。需要坦诚说明的是，这一“拯救”效果来自第三轮基于转录文本的清理；至于仅靠前期的机械式审计（步骤1）是否也能恢复此类单元，尚未经过验证——早期项目的轨迹表明，它确实能弥补相当一部分差距（在同一评估中，经审计的单元得分远高于仅做交换的单元），但对于本次特定的重新探测，仍应将其视为一种推测，而非实测结果。只探测一个单元，而非重新开启搜索：如果该单元在现有配置下的成本达标，则将其作为最终确认的配置；否则，维持现有配置不变。

**步骤5——最后一次努力范围内的重新采样＝注册的联合确认。**
在完成提示优化（以及步骤4的重新探测，若其选定了一个更优的单元）之后，在所选点附近以n≥3的样本量重新采样，并以此运行预先登记的、针对完整配置（模型、提示、努力）的确认测试——即下面提到的三个采纳门槛，在触发前即予以登记，并在有保留案例的情况下应用于这些案例。最终报告的数值即为此处的结果。（提示的最佳选择是在更早的努力层级上确定的；提示与努力之间的直接交互尚未被测量，因此在高思考深度下调优的提示未必能在较低努力层级下同样奏效——联合确认即是对此的保障。）**步骤6——多模型拓扑仅在任务型预检之后使用——通常几乎不会。**
在所有经过测量的对比中，只需投入适当的努力，一款强大的模型就能在成本-得分平面上击败所有团队结构：低成本模型通过“替代”来节省开销（由低成本模型代为完成工作），而绝非通过“叠加”（即在强大主力模型之外再加一个辅助模型）——强大的主力模型大约会以自身消耗约一个数量级的token为代价来利用廉价的辅助。任何拓扑候选方案的门槛，就是步骤2所确定的模型×努力前沿（“这是否优于仅靠调整努力就能免费获得的效果？”）。值得进行预检的已记录例外情况包括：执行器被限制为必须是低成本或非Claude模型（此时由强模型一次性发出一条计划调用，过程中无需任何交互即可实现成本节约）；执行器确实较弱（顾问模型的费用低于主力模型的层级，并设有下限）；或者任务存在可观察、可验证的中间产物（如验证性转移；能力本身则不符合此条件）。

## 采纳门槛——首轮前须注册
一项候选变更（提示编辑、努力削减、模型替换）只有在以下三个预先注册的门槛全部通过时才会被采纳：
1. **质量区间**——留出的测试集得分需落在与当前方案相同的一个指定区间内（运行前须明确该区间）。
2. **成本优势**——在既定计费基准下，成本必须严格低于预先注册的最低优势幅度。
3. **机制验证**——预测的机制必须在实测结果中得到体现（例如，“此项编辑消除了重复查询”应表现为工具调用次数减少，而不仅仅是账单金额降低）。若机制正确但成本持平，或机制错误却成本更低，均视为不通过：前者说明编辑未产生实际效果，后者则意味着存在无法解释的混杂因素，上线后难以持续。

最终的联合确认（搜索流程的步骤5）仍依据上述三个门槛进行评估；由于三次连续筛选均基于各自选定的数据，单独报告每轮的得分会夸大整体收益，因此应以确认环节的结果数字作为最终结论，而非各轮的单独得分。

## 测量规范- **先测噪声基线。** 在第一轮开始前，针对“delta 至少要多大才能被认为有效？”这一问题，给出一个数值，该数值应基于对未变更配置的多次重复运行得出。相同的基线重复结果将作为模型与投入度探索（步骤2）中第0轮诊断的依据：从其输出日志中读取输出token占比和每项任务的迭代次数，并同时测量噪声基线。如果调优后的产物本身是随机生成的（例如构建的索引或维基，而非固定提示），则在评估任何修改之前，需通过一次不作更改的重建来衡量其“构建”方差。
- **选择集≠验证集。** 每轮由其得分决定胜负的数据划分是“选择集”，即便指南将其称为“测试集”。对于关键指标，应提前注册确认运行，并预期训练集到验证集之间会出现性能衰减。
- **定价基准须明确且统一。** 事先锁定并明确定价基准（使用哪张价目表、是否考虑缓存调整、促销价与标准价的区别）。同一运行在不同基准下的成本报告可能相差数倍——缓存输入的计费仅为新鲜输入的十分之一，因此在高缓存率下，经缓存调整与按原价核算的结果会迅速拉开差距。支出前务必对照价目表进行纸面测算，因为某些配置可能因无评测运行而被完全排除。
- **在目标中纳入成本考量。** 优化器只会优化已明确的目标：在一项实测搜索中，仅追求质量的优化导致每个交付成果的成本上升了75%。若目标是兼顾质量与成本，则上述各项约束条件即为目标本身——应在计划审批时将其写入。
- **每轮只动一个变量，其余保持不变。** 每轮仅调整一个维度，以便准确归因于每次改进或退步。
- **让优化器先预测，再实测。** 要求在每轮的方案中，对每个单元格都给出点估计值及80%置信区间——包括评分与成本两方面——并明确列出可证伪的条件（“若发生X，则该变量无效；请注明）。每轮结束后将实际结果与区间对比，并根据偏差调整下一回合的区间范围，使其适当放宽。如此一来，每一轮都成为对优化器自身预测的修正；在一项实测搜索中，优化器第二轮的各单元格预测值均落在已解区间之下，它主动进行了重新校准，而其为第三轮设定的可证伪条件则精准地识别出了提示词变量无效的情况。
- **在确信某个变量有效之前，先验证服务身份与配置正确性。** 记录来自*响应*中的模型ID，而非配置信息；逐例确认必要的用量字段是否存在；在能报告这些字段的评测环境中运行；禁用任何会在两次尝试中传递任一结果的自动重试机制。缺乏配置记录的结果不能作为证据。
- **在认定持续性失败前，先核查评分者。** 在一项实测案例中，重新评分后，原本宣称的+9分优势被压缩至+3分。当某个案例每轮都失败时，应先怀疑评分者的可靠性，而非一味调整提示内容。
- **路由策略仅在全流量场景下评估其成本效益。** 若仅在困难子集上评估难度路由，会导致自我失效（所有请求都被路由到大模型，白白承担路由开销）；其节省效果只有在全量分布下才存在，且在预测器经过验证之前，这些节省只是理论上的。

## 影响提示成本的因素（实测机制）

- **成本随额外触发的操作数增加，而非提示长度。** 在一项实测分解中，仅增加一轮工具调用便使每例成本约上升三分之一，而较长但未被激活的提示文本在缓存时几乎不产生额外费用。
- **裁剪前先评估参与度。** 在调整框架指令之前，统计现有记录中每条指令所引入的开销（计划文件写入、强制推理块、受限或重复读取、每次编辑的套件执行、叙述性短语等），并从中减去提示本身对这些标记或伪装成参与度的静态文本的引用次数。修正后的计数接近零，说明模型忽略了该段文本：这部分内容在缓存时几乎免费，删除也不会降低成本。结果往往参差不齐——在实测案例中，强制推理仪式在所有测试中均未被触发，而一条计划文件指令在20次运行中有17次被激活。进行一个两组对比实验（仅清理开头部分 vs. 清理开头并保留仪式）成本低廉，可判断可疑模块是否真正起作用：在此例中，两组的成本差异不到2%，且在既定质量指标上完全持平（部分得分指标有所波动，提醒我们“持平”是相对特定指标而言的）——在本次测试的规模下，该仪式被视为无效开销。
- **最昂贵的模式是会触发操作的指令。** “验证两次”（通过重复查找和重新 deliberation 使每例成本上升48%）与“力求极致细致”（通过不必要的工具调用使成本上升39%）两项合计，其成本约为其他所有增本模式总和的两倍。裁剪文本前，应先排查那些会引发冗余操作的指令。
- **为每次提示修改按实际缓存调整后的价格计入其自身的 token 开销。** 每次请求都必须携带的一条固定指令，其净收益必须高于自身带来的 token 开销：一项实测显示，一条650字符的指令确实产生了预期的行为变化，但最终成本仍与基准持平，因为其每次请求的 token 开销抵消了节省的部分。
- **精简能通过缩短回复长度来节约成本**——但这是一种需要向用户明确告知的回复质量权衡，并非无成本的收益。在报告成本节约的同时，也应标注回复长度的中位数变化。
- **输出 token 也是影响延迟的关键因素。** 对于延迟敏感的产品，减少输出 token 的策略优先级提升：某客户自报，在质量保持不变甚至提升的情况下，输出 token 减少了约11%（此为实践者反馈，非基准测试数据）；此外，流式传输的 token 会直接被感知为延迟。
  
## 停止规则

- **提示迭代轮次：** 改进主要集中在第1—2轮；当连续两版未能显著优于当前方案，超出噪声范围时即停止；每种模型的迭代次数控制在3—4轮左右。
- **努力程度：** 成本节约呈阶梯式饱和（每降低一级，节省幅度递减，同时波动增大）。应在噪声范围内停止。需注意，降低努力并不意味着固定用例不再失败——失败会在不同运行间转移（“思考深度不足时，任何细微的边际都会导致失败”），因此削减努力的决策应基于多轮运行的整体表现，而非单次结果。
- **模型×努力程度的探索路径：** 该路径会自行终止——当所有未测试的组合预测成本都不低于当前方案，且扩展信号趋于平稳时，当前方案即为最优解。切勿为了“确保万无一失”而继续试探；已确认的质量基准才是获取信息的合规途径。
- **总体原则：** 当联合验证通过各项指标时即可上线；若未通过，则应如实报告通过验证的最优配置，而不应在验证数据上反复搜索。
