# PPTX 的创建、编辑与分析

如果本会话提供了专门的幻灯片文稿制品类型或独立的幻灯片技能，且用户既未要求生成 PowerPoint/.pptx 文件，也未提供用于编辑、填充或转换的 .pptx/.potx 文件，则应使用该类型或技能来构建文稿。仅作为素材或新文稿示例（“制作一个与此类似的文稿”）提供的 .pptx/.potx 文件不视为已提供的文件：应先用本技能读取该文件，再使用相应类型或技能构建新文稿。本技能仍然是生成 .pptx 文件以及读取、编辑、模板化或转换现有 .pptx/.potx 文件的合适工具。

`.pptx` 是一个由 XML 文件组成的 ZIP 压缩包。请根据具体任务选择合适的方法：

| 任务 | 方法 |
|---|---|
| **创建** 新文稿 | 编写 `pptxgenjs` 脚本——参见下文注意事项 |
| **编辑** 现有文稿，或基于模板构建 | 解压 → 编辑 `ppt/slides/slideN.xml` → 重新压缩 |
| **读取** 内容 | 使用 `markitdown deck.pptx`（每张幻灯片以 `<!-- Slide number: N -->` 标记分隔为一个块）；可视化网格：`python scripts/thumbnail.py deck.pptx` |

## 脚本

路径均相对于本技能的目录。其余部分均为原生 Python、Node.js 或 Shell 脚本。

| 脚本 | 功能 |
|---|---|
| `scripts/thumbnail.py deck.pptx [prefix]` | 生成每张幻灯片的带标签网格，便于选取模板布局。仅支持 `.pptx` 格式。可指定 `prefix` 参数，默认为 `thumbnails`，这会覆盖同一目录下其他文稿的网格文件 |
| `scripts/add_slide.py unpacked/ slide2.xml [--after slideN.xml]` | 复制一张幻灯片（或一个 `slideLayoutN.xml`），并保留所有相关元数据。也可直接传入 `.pptx` 文件，并通过 `-o out.pptx` 指定输出文件 |
| `scripts/clean.py unpacked/` | 删除不再被引用的幻灯片、媒体及关系文件。应在 `<p:sldIdLst>` 最终确定后运行 |
| `scripts/office/validate.py deck.pptx [--original src.pptx]` | 执行模式、关系、内容类型、图表及幻灯片检查；每次失败都会提示修复方法。对于源自模板的文稿，请使用 `--original` 参数——它会以模板为基准进行模式检查，从而避免将模板自身的 XSD 错误误判为你方的问题 |
| `scripts/office/soffice.py --headless --convert-to pdf deck.pptx` | LibreOffice 封装脚本——在本沙盒中直接调用 `soffice` 可能会挂起 |

## 使用 pptxgenjs 创建时的注意事项

`pptxgenjs` 已预安装，请勿先执行 `npm install`，而是直接编写脚本并 `require('pptxgenjs')`。只有当 `require` 失败时才执行 `npm install pptxgenjs`。模型熟悉该 API，以下是常见的陷阱：

- **在添加幻灯片之前设置 `pres.layout`。** 默认画布为 `LAYOUT_16x9`，即 **10英寸 × 5.625英寸**，而非13.3英寸宽。超出边界的坐标会被写入，但不会被裁剪——只是形状不会显示在幻灯片上。（`LAYOUT_WIDE` 的尺寸为13.3英寸 × 7.5英寸。）
- **十六进制颜色：不要使用 `#`，也不要使用8位格式。** 使用 `color: "FF0000"`。无论是 `"#FF0000"` 还是将透明度烘焙到十六进制中（如 `"00000020"`），都会 **损坏文件**。若需半透明效果：填充和图片使用 `transparency: 0–100`，阴影使用 `opacity: 0.0–1.0`——两者在对方上均会被静默忽略。
- **pptxgenjs 会就地修改选项对象**（首次使用时将值转换为 EMU）。切勿在两次 `add*` 调用之间共享同一个 `shadow` 或选项对象——每次调用都应新建一个对象。
- **阴影的 `offset` 必须 ≥ 0**——负偏移会导致文件损坏。若要让阴影向上投射，请使用 `angle: 270` 并配合正偏移。
- **`letterSpacing` 会被静默忽略**——正确的选项是 `charSpacing`。
- **列表：** 每个项目都应设置 `bullet: true`，切勿直接使用字符 `•`（否则会渲染出双层项目符号）。除最后一个数组项外，其余每一项都应设置 `breakLine: true`。使用 `paraSpaceAfter` 来分隔带项目符号的段落，而不是使用 `lineSpacing`（后者会导致巨大间距）。
- **每个输出文件对应一个 `new pptxgen()` 实例**——切勿复用同一实例。
- **`rectRadius` 仅对 `ROUNDED_RECTANGLE` 有效**，对 `RECTANGLE` 无效。
- **不支持渐变填充**——请改用渐变图像作为背景。
- **每次调用 `addText` 都需要设置 `isTextBox: true`**——否则形状缺少 `txBox="1"` 属性，屏幕阅读器会将文本识别为“图形”而非文本框。视觉上无任何变化。
- **文本框自带内边距**——当文本必须与同一水平位置的形状、线条或图标对齐时，请将 `margin` 设置为 0。
- **演讲者备注应写入 `slide.addNotes("...")`**（纯文本，每张幻灯片仅一次），切勿将其放入幻灯片上的文本框。
- **尽量保持图表的原生特性。** 对于 PowerPoint 支持的所有图表类型，请使用 `addChart()`（对于组合图，传入 `{type, data, options}` 数组）。对于库未暴露的 PowerPoint 原生功能（如趋势线、误差线），请自行计算额外的数据系列，或在生成后对 OOXML 进行后期处理——切勿退而求其次，使用渲染后的图片。只有 PowerPoint 本身没有原生实现的图表类型（如桑基图、网络图、弦图）才应以图片形式插入。
- **默认图表的渲染效果较为简陋**——无标题、无数据标签、配色方案过时。请设置 `showTitle + title`、`showValue: true + dataLabelPosition`、从您的配色方案中指定 `chartColors: [...]`，并适当弱化图表边框元素（如 `catAxisLabelColor`/`valAxisLabelColor`、`valGridLine: { color, size }`、`catGridLine: { style: "none" }`），以及针对单系列图表关闭图例（`showLegend: false`）。
- **对于堆叠条形图或柱状图，`dataLabelPosition` 必须设置为 `ctr`、`inEnd` 或 `inBase`。** 设置为 `outEnd` 会 **损坏文件**。
- **使用 `secondaryValAxis` 或 `secondaryCatAxis` 的组合系列，必须在图表选项中同时指定两个数值轴和两个分类轴，并各填写两条记录。** 否则，pptxgenjs 会写出它从未声明过的轴 ID，PowerPoint 会 **丢弃该图表** 并将文件标记为损坏。仅提供数值轴是不够的。
- **调用 `writeFile()` 后，请运行 `python scripts/office/validate.py deck.pptx`。** 该脚本会报告上述两种图表问题，以及 PowerPoint 拒绝打开的幻灯片 XML 缺陷，并给出相应的修复方法。请在生成器中进行修复，不要手动编辑打包后的 XML。
- **切勿重新排序 `<p:presentation>` 的子元素。** pptxgenjs 会在 `<p:sldIdLst>` 之后紧接写入 `<p:notesMasterIdLst>`，并将两个母版都指向同一个主题部分。PowerPoint 可以正常读取这种结构——但如果移动该元素，同一份演示文稿就会无法打开。
- **图标：** 将 `react-icons` 渲染为 SVG（使用 `ReactDOMServer.renderToStaticMarkup`），再用 `sharp` 以不低于 256px 的分辨率栅格化，然后通过 `addImage({ data: "image/png;base64," + buf.toString("base64") })` 插入——其中 `image/png;base64,` 前缀是必需的（`react-icons`、`react`、`react-dom` 和 `sharp` 已预装——只有在 `require` 失败时才需执行 `npm install react-icons react react-dom sharp`）。

## 编辑现有牌组和模板

首先选择版式：`python scripts/thumbnail.py template.pptx template-thumbs` 会生成每一张幻灯片的带标签网格，并输出它创建的文件——`template-thumbs.jpg`，当幻灯片超过12张时会被拆分为 `template-thumbs-N.jpg`。**务必传递这个第二个参数，其名称应与演示文稿一致。** 默认值为 `thumbnails`，因此如果在同一目录下对两份演示文稿生成缩略图，它们的网格会互相覆盖——第一份演示文稿的网格将被彻底删除（仅用于模板分析；视觉质量检查需要从[转换为图片](#converting-to-images)步骤中获取的全分辨率渲染结果；该工具只接受 `.pptx` 格式，因此请先将 `.potx` 文件复制并重命名为 `.pptx`）。结合 `markitdown` 使用，可以将每个内容区块映射到模板幻灯片上，并灵活调整版式——不要把所有区块都放在同一张标题加项目符号的幻灯片上。

```bash
python3 -c "import sys,zipfile; zipfile.ZipFile(sys.argv[1]).extractall('unpacked')" deck.pptx
python scripts/add_slide.py unpacked/ slide2.xml --after slide2.xml   # 复制一张幻灯片（或 slideLayoutN.xml）；输出新幻灯片的路径
# 重新排序或删除幻灯片 = 编辑 ppt/presentation.xml 中的 <p:sldIdLst>
python scripts/clean.py unpacked/                                     # 删除后：移除孤立的幻灯片、媒体和关系文件
# 在 ppt/slides/slideN.xml 中编辑幻灯片内容
(cd unpacked && rm -f ../out.pptx && zip -Xr ../out.pptx .)           # 从目录内部打包；先删除，否则已删除的部分仍会保留
python scripts/office/validate.py out.pptx --original deck.pptx
```

- **在编辑任何幻灯片内容之前，完成所有结构上的操作——添加、删除、重新排序。** `add_slide.py` 会逐字复制幻灯片文件，因此在编辑后再复制会克隆已编辑的内容；而 `clean.py` 会删除 `<p:sldIdLst>` 中缺失的任何幻灯片，包括你刚刚新建的那一张。
- **切勿手动复制幻灯片文件**——`add_slide.py` 会自动完成新幻灯片所需的所有注册工作，并报告其创建情况（“从 slide2.xml 创建了 ppt/slides/slide17.xml”）。它也可以直接作用于文件：`add_slide.py deck.pptx slide2.xml -o out.pptx`——**务必指定 `-o`，否则会原地覆盖输入的演示文稿。** 复制的幻灯片仍然*引用*源幻灯片中的图表、SmartArt 或嵌入对象部分，而不是将其克隆，因此编辑其中一张幻灯片的图表会影响另一张。
- **如果你使用 `python-pptx`**，有三件事它是无法做到的：复制一张幻灯片（其唯一入口是 `add_slide(layout)`），通过 `text_frame.text = "..."` 保留格式（这会将段落压缩为一个无样式文本块——应改为设置 `run.text`），以及读取大多数模板素材使用的 SVG/EMF 格式（调用 `add_picture` 会抛出 `UnidentifiedImageError`）。
- 旧版 `.ppt` 文件必须先转换：`python scripts/office/soffice.py --headless --convert-to pptx file.ppt`。`.potx` 模板的解包与打包过程相同——输出时请保留 `.potx` 扩展名。
- 若要复用模板中的图标或图片，可复制一张已包含该元素的幻灯片或版式。

填充模板时：

- 如果编写 XML 转换脚本，请使用 `defusedxml.minidom` 解析——通过 `xml.etree.ElementTree` 对 OOXML 进行往返处理会重写命名空间前缀，导致演示文稿损坏。
- **模板占位符 ≠ 源内容。** 如果模板显示 4 名团队成员而你只有 3 名，请删除第 4 名成员的整个组（包括图片和文本框），而不仅仅是文本——然后在质量检查中确认是否存在孤立的视觉元素。
- 每个列表项对应一个 `<a:p>`——切勿将多个项目合并为一个段落。复制同级的 `<a:pPr>` 以保留间距，并在标题、章节标题及内联标签（如“状态：”、“负责人：”）的 `<a:rPr>` 上设置 `b="1"`。
- 让项目符号继承自版式；仅在需要覆盖时才添加 `<a:buChar>`、`<a:buAutoNum>`（编号）或 `<a:buNone>`——切勿在文本中直接输入字符 `•`。
- 带有前后空格的文本，其 `<a:t>` 需设置 `xml:space="preserve"`。

## 设计思路

**不要制作乏味的幻灯片。** 纯白背景上的普通项目符号不会给人留下深刻印象。为每张幻灯片考虑以下建议中的创意。

### 开始之前- **选择大胆且贴合内容的配色方案**：配色应与主题高度契合。如果将你的颜色换到另一份完全不同的演示文稿中仍然“适用”，那就说明你的选择还不够具体。
- **主次分明，避免平均用力**：一种颜色应占据主导地位（视觉权重60%-70%），搭配1-2种辅助色，再加一个鲜明的强调色。切勿让所有颜色权重均等。
- **明暗对比**：标题页和总结页使用深色背景，内容页使用浅色（“三明治”结构）。或者全程采用深色，营造高端质感。
- **确立统一的视觉符号**：选定一个独特的视觉元素并贯穿始终——例如圆角图片框、彩色圆圈中的图标等，并在每一页上重复运用。**切勿将色条或强调色带作为主要视觉符号**（详见“避免事项”列表）。

### 配色方案

请根据主题选择合适的颜色，不要一味沿用通用的蓝色。以下配色可供参考：

### 每页幻灯片设计要点

**每页都需加入视觉元素**——图片、图表、图标或形状。纯文字页容易被遗忘。

**布局建议：**
- 两栏式（左侧文字，右侧插图）
- 图标+文字行（图标置于彩色圆圈内，粗体标题，下方附说明）
- 2×2或2×3网格（一侧为图片，另一侧为内容区块组成的网格）
- 半幅出血图（占满左侧或右侧），叠加内容文字

**数据呈现方式：**
- 大型数据突出显示（数字字号60-72pt，下方配小标签）
- 对比柱状图（前后对比、优缺点对比、并列选项对比）
- 时间轴或流程图（编号步骤，箭头连接）

**视觉细节优化：**
- 在各部分标题旁添加置于小彩圈内的图标
- 关键数据或标语可使用斜体字加以强调

### 字体排版

**你在PPT文件中指定的字体名称，最终由用户本地PowerPoint软件渲染，而非本环境。** 我们的视觉校验使用LibreOffice进行预览，而LibreOffice会自动替换其未安装的字体；某些字体的替代版本宽度不同，因此校验预览可能出现文本溢出或恰好合适的情况，但实际演示时效果可能有所差异。为确保校验结果准确可靠，请注意以下事项：- **安全字体**（在 QA 中能精确呈现宽度，且随 Office 一起发布）：**Arial、Calibri、Cambria、Times New Roman、Courier New、Bookman Old Style、Century Schoolbook**。请将这些字体用于正文字体以及任何对排版空间有要求的场景。
- **无 QA 风险的个性标题**：将安全列表中的衬线标题字体（如 Cambria、Bookman Old Style、Century Schoolbook）与安全列表中的无衬线正文字体（如 Calibri 或 Arial）搭配使用。这样既能实现视觉对比，又不会影响可靠的溢出检查。
- **如果用户要求使用安全列表之外的字体**（如 Georgia 或 Trebuchet MS）：可在用户指定的位置使用该字体，但需为相关容器预留额外空间（约 10%），并且不要依赖针对这些元素的 QA 文字适配检查——预览时该字体的显示效果仅为近似值。若用户未指定，则正文字体应优先选用安全列表中的字体。
- **QA 不可靠的字体**（替换后字宽不同，可能导致溢出检查错误）：Georgia、Trebuchet MS、Impact、Arial Black、Garamond、Consolas、Palatino Linotype。Calibri Light 的替换行为因环境而异，视为 QA 不可靠。此类字体适合作为标题或点缀使用，但需留足空间；切勿依赖其 QA 文字适配结果。
- **切勿默认使用 Aptos**——Office 2023 后版本的默认字体在此处没有度量兼容的替代方案，且旧版 Office 中也缺失，因此两端均不可靠。

| 元素         | 大小       |
|--------------|------------|
| 幻灯片标题   | 36–44pt 粗体 |
| 节标题       | 20–24pt 粗体 |
| 正文         | 14–16pt    |
| 图注         | 10–12pt 柔色 |

### 间距

- 至少 0.5 英寸的页边距
- 内容块之间间距 0.3–0.5 英寸
- 留白充足，避免每寸都填满内容

### 避免常见错误

- **不要重复使用同一版式**——在不同幻灯片中变换列布局、卡片样式和标注位置。
- **正文不要居中对齐**——段落和列表左对齐，仅标题居中。
- **不要吝啬字号对比**——标题至少 36pt 才能从 14–16pt 的正文中脱颖而出。
- **不要默认使用蓝色**——选择能体现主题特色的颜色。
- **不要随意混用间距**——统一采用 0.3 英寸或 0.5 英寸的间隔，并保持一致。
- **不要只设计一张幻灯片而其余保持原样**——要么整体精心设计，要么全程保持简洁。
- **不要制作纯文本幻灯片**——添加图片、图标、图表或其他视觉元素，避免仅有标题加项目符号的单调形式。
- **别忘了文本框的内边距**——当需要使线条或形状与文本边缘对齐时，可将文本框的 `margin` 设置为 0，或通过偏移形状来补偿内边距的影响。
- **不要使用低对比度元素**——图标和文字都必须与背景形成足够对比；避免浅色文字配浅色背景，或深色文字配深色背景。
- **切勿在标题下方添加强调线**——这是 AI 生成幻灯片的典型特征，建议改用留白或背景色来突出。
- **切勿添加装饰性色条或强调条**——包括：横跨整张幻灯片的页眉/页脚条、沿幻灯片一侧的竖向边栏条、卡片或内容块一侧的细窄强调条，以及矩形的单侧边框。这些都会显得像 AI 自动生成的填充内容。若要让某个卡片更显突出，可使用柔和的背景色、阴影或图标，而非边缘条纹。
- **不要默认使用米色/奶油色背景**——未指定背景时，应使用白色（`FFFFFF`）或用户的品牌色系；避免使用暖色调中性色作为默认，如 `F5F5DC`、`FAF0E6`、`FAEBD7`、`FFF8E1` 等。
- **切勿提交文字溢出的幻灯片**——若文字无法完全容纳，应缩小字号、拆分到多张幻灯片，或扩大容器尺寸；绝不能让内容被截断或超出边界。

## QA（必做）

初次渲染通常会发现一些实际问题——重叠、溢出、对齐错位等。请逐一排查并修正，仅重新渲染已修改的幻灯片，然后停止。

### 内容 QA

```bash
markitdown output.pptx
```

检查是否有内容缺失、拼写错误或顺序不当。

**使用模板时，请检查是否残留占位符文本：**

```bash
markitdown output.pptx | grep -iE "\bx{3,}\b|lorem|ipsum|\bTODO|\[insert|this.*(page|slide).*layout"
```

若 grep 命令返回结果，请务必先修复后再确认完成。

### 文件质量检查（必选）

```bash
python scripts/office/validate.py output.pptx                      # 从零开始构建
python scripts/office/validate.py output.pptx --original src.pptx  # 基于模板构建
```

**如果演示文稿源自模板，请务必使用 `--original` 参数。** 模板本身可能包含 XSD 不接受的部分，因此仅运行验证可能会报告一些并非您引入的错误——而真正的回归问题则可能隐藏在其中。`--original` 参数会以模板为基准进行模式和幻灯片检查，从而屏蔽模板已存在的错误。至于关系、内容类型、图表等结构性检查，则不依赖于 `--original` 参数，无论是否指定该参数都会报告模板继承的问题，因此请单独查看这些检查结果。

pptxgenjs 会输出 PowerPoint 无法打开但其他工具都能接受的图表 XML：python-pptx 可以打开此类文件，LibreOffice 能正确渲染，XSD 验证也能通过。每项失败都会给出修复建议，请在生成器中修正并重新构建。

### 视觉质量检查

将幻灯片转换为图片（参见[转换为图片](#converting-to-images)），并对每一张进行仔细检查。由于长时间盯着生成代码，人容易看到自己预期的内容而非实际渲染效果，因此请以“新鲜”的视角查看图片（如有子代理协助则更佳）。需重点关注以下用户可见的缺陷：

- **文本溢出或被框线、幻灯片边界裁剪——务必优先检查此项。** 这是最常见的缺陷，且始终会对用户造成影响。（对于预览器在排版方面表现不稳定的文字，预览仅供参考：请相信您预留的大约 10% 空间，而非其显示的适配情况。）
- 元素重叠（文字穿过了形状、线条穿过文字、元素堆叠）
- 来源标注或页脚与上方内容发生冲突
- 元素间距过小（间隙小于 0.3 英寸）或卡片/分区几乎贴合
- 间隙不均匀（一处留白过大，另一处过于拥挤）
- 幻灯片边缘留白不足（小于 0.5 英寸）
- 多列或其他类似元素未保持一致对齐
- 文字对比度不足（例如浅灰色文字置于米色背景上）
- 替换文字后模板装饰位置错位——例如标题下划线原本适用于单行，但替换后的标题却换成了两行
- 图标对比度不足（例如深色图标置于深色背景上，且未添加对比色圆圈）
- 文本框过窄导致过度换行
- 残留占位符内容

## 转换为图片

将演示文稿逐页转换为图片，以便进行视觉检查：

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 150 output.pdf slide
ls -1 "$PWD"/slide-*.jpg
```

**请直接将上述命令输出的绝对路径传递给查看工具。** `rm` 命令用于清除上一次运行遗留的旧图片。`pdftoppm` 会根据页数自动补零命名：少于 10 页时为 `slide-1.jpg`，10 至 99 页时为 `slide-01.jpg`，100 页及以上时为 `slide-001.jpg`。

**修复后，请重新执行以上四条命令**——必须先用修改后的 `.pptx` 文件重新生成 PDF，`pdftoppm` 才能反映您的更改。
