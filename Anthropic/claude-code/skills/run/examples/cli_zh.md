# 示例：命令行工具

命令行工具是最简单的情形——通常没有需要管理的后台进程，也没有端口或生命周期。该技能重点在于**安装**、**典型用例的调用示例**和**测试**。

## 重要事项

- **如何将二进制文件置于 `PATH` 中。** 是全局安装？通过 `npx`/`uv run` 运行？还是构建到 `./target/release/foo`？请明确说明。
- **两到三个示例调用**，覆盖主要使用场景。附上预期输出，以便读者确认运行成功。
- **退出码**（如果有意义，例如 linter 在发现错误时返回 1）。
- **标准输入行为**（如果工具会从标准输入读取）。

## 示例片段

> ---
> 名称: run-mytool
> 描述: 构建、安装并运行 mytool。在需要运行 mytool、测试或验证其是否正确安装时使用。
> ---
>
> ## 准备工作
>
> ```bash
> pip install -e .
> ```
>
> 这会将 `mytool` 放入 `PATH`。验证：
>
> ```bash
> mytool --version
> # -> mytool 0.3.1
> ```
>
> ## 运行
>
> 处理单个文件：
>
> ```bash
> mytool process input.json
> # -> 已处理 42 条记录，已写入 output.json
> ```
>
> 从标准输入读取，写入标准输出：
>
> ```bash
> cat input.json | mytool process -
> ```
>
> 检查一个目录（发现问题时退出码非零）：
>
> ```bash
> mytool lint ./src
> echo $?  # 如果无问题则为 0，有问题则为 1
> ```
>
> ## 测试
>
> ```bash
> pytest
> ```
>
## 保持简洁

命令行工具的运行技能可以非常精简。不要把所有选项都罗列出来——这些内容已在 `--help` 输出中涵盖。只需展示足够信息，让代理能够：(a) 构建工具，(b) 确认其正常工作，(c) 运行测试。
