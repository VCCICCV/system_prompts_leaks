# 数据可视化

图表是**由人阅读、由你实现**的。这项技能将“让它看起来美观”转化为一套带有检验步骤的流程，因此结果是通过规范而非凭感觉得出的。

**此处的方法与具体的设计系统无关。** 流程、形态启发式、六项检查以及标记规范中没有任何内容是针对某一特定产品的。设计系统仅提供一组*参数*（其色阶、分类顺序、发散色对、状态色板、纹理、表面样式、筛选组件）；该方法原封不动地使用这些参数。一个**经过验证的默认色板**是参考实例，在`references/palette.md`中已完整说明。若要适配你的品牌，请参照该文件的结构并替换其中的值——其他部分无需改动。

> 最重要的习惯是：**颜色部分是可以计算的，所以请务必计算。** 切勿凭肉眼判断色板是否适合色盲用户——请运行`scripts/validate_palette.js`脚本。

## 操作流程——按顺序执行

颜色应放在最后。大多数糟糕的图表都是先选颜色的。

1. **选择图表形态。** 数据的用途是什么——表示大小、标识、极性、单一标题，还是随时间的变化？用途决定了图表类型，有时答案甚至可能是“非图表”（如统计卡片或核心数字）。→ `references/choosing-a-form.md`
2. **根据用途分配颜色。** 分类色（标识）、顺序色（大小）、发散色（极性）或状态色（状态）——每种用途都有明确的规则。分类色需按固定顺序分配，切勿循环使用。→ `references/color-formula.md`
3. **验证色板——运行脚本，不要凭直觉判断Delta E值。** 运行命令：`node scripts/validate_palette.js "<hex,hex,...>" --mode light`（在本技能的根目录下执行，或将其作为`<script type="module">`加载到图表所在页面，从`<body>`读取`data-palette`属性并输出`console.table`报告）。脚本会针对明度范围、饱和度下限、相邻色对的色盲分离度、正常视力下的最低要求以及对比度进行检测并给出通过/未通过的结果。任何未通过的项目都必须修复后再继续。对于暗模式，请使用`--mode dark`选项，并以暗模式对应的背景色为基准重新运行。
4. **应用标记规范与间距。** 使用细线标记，数据端点圆角设为4px并锚定基线，线条宽度2px，标记直径≥8px，填充区域之间（包括堆叠条和相邻柱状图）留出2px的间隙，重叠标记外侧再加2px的边距，并适当添加直接标签。→ `references/marks-and-anatomy.md`
5. **默认添加悬停层。** HTML/SVG图表本身即具备交互性；线图/面积图应显示十字准线与工具提示，柱状图/散点图/单元格则应为每个标记单独提供悬停提示。唯一例外是不含图形的纯统计卡片。悬停目标应大于标记本身；筛选控件应置于图表上方一行。→ `references/interaction.md`
6. **最终的可访问性检查。** 对于两条及以上系列，始终显示图例；少于四条系列时还应直接标注各系列名称（单系列无需图例框，标题即可标明）。标识信息绝不能仅依赖颜色；应提供表格视图；暗模式需**主动启用**——其配色基于同一色阶，并针对暗色背景进行验证，而非简单地自动反转；同时应提供适用于色盲、打印或强制色彩模式的纹理方案。
7. **渲染并目视检查。** 验证器仅检查颜色，不检查布局——打开或截屏查看最终效果，目测是否存在标签重叠、几何问题或溢出，确认无误后方可完成。

最后，对照**`references/anti-patterns.md`**检查结果——这是常见错误的清单。若你的图表与其中某项相符，则说明它存在问题。

## 不可妥协的原则（适用于所有设计系统）- **按固定顺序分配分类色相，绝不循环使用。** 第9个系列绝不会被赋予自动生成的色相——它会被归入“其他”、小多图或复合编码。
- **单轴。** 绝不使用双轴图表（两个y轴刻度）。不同量级的两个度量应采用两张图表、小多图，或以共同基准进行指数化。（这是图表设计中最常见的错误——参见反模式。）
- **颜色跟随实体，而非其排名。** 能改变系列数量的筛选器不得重新着色剩余的系列。
- **顺序型：单一色相，由浅至深；发散型：两种色相加一个中性灰作为中间点。** 绝不使用彩虹色系；发散型中间点绝不能使用色相。
- **在任何分类调色板上线前运行验证程序。** CVD Delta E ≥ 8 是目标值（OKLab ×100）；6–8 是最低要求，且仅在辅以次级编码时方可接受。对于正常视力用户，低于15即为硬性不合格——全彩读者无法区分该对色；应在相邻色对表中重新调整配色（次级编码不能免除这一要求）；若在 `--pairs all` 检查中仍不达标，则应减少系列数或改用分面图——参见检查4。对比度警告必须通过可见标签或表格视图来弥补，不可忽视。
- **标记细而简洁；当系列数≥2时始终显示图例（单系列则不显示），并选择性地添加直接标注（绝不给每个数据点都标数字）；网格线和坐标轴应尽量淡化。**
- **文本使用文字标记，而非系列颜色**——数值、标签和图例均采用主色/辅色/弱化墨色；与其搭配的彩色标记用于标识身份。
- **状态色保留专用**（良好/警告/严重/危急），绝不挪作“第4系列”之用；状态色需同时配备图标和标签，绝不用纯颜色表示。

## 接入设计系统

方法保持不变，仅以下参数会随系统而异。参考实例——所有参数均已填妥——位于 `references/palette.md`。
| 参数 | 系统提供的内容 |
|---|---|
| **色阶** | 调色板所基于的色相渐变（命名步长） |
| **分类主题** | 固定的色相顺序（命名主题）；默认及备选方案 |
| **顺序型色相** | 表示大小的默认单色相 |
| **发散型色对** | 一暖一冷两极加一个中性灰中间点 |
| **状态调色板** | 良好/警告/严重/危急——与分类色相区分开来的步长 |
| **纹理填充** | 单向手绘填充，角度分别为45°和135° |
| **背景色** | 浅色与深色图表背景色（验证程序需要这些） |
| **筛选控件** | 日期范围与维度筛选控件（行为规范详见 `interaction.md`） |

接入新系统时：填写上述各栏，将系统的色阶输入验证程序，让其自动将每个位置匹配到最接近的合格色阶。结构与规则保持原样。
