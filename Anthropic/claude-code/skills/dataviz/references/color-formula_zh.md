# 颜色公式

颜色**并非手工挑选**。每种图表颜色仅承担四项任务中的一项，且只有通过六项检验的配色方案才是合法的。这些检验是核心——它们确保配色方案可以安全地变更，并使同一种方法能够在任何设计系统的渐变中运行。

## 四项任务

| 任务 | 编码内容 | 结构 |
|---|---|---|
| **分类** | 标识（属于哪个系列） | 8种色相，固定顺序，按序分配，从不循环 |
| **序数** | 在序列中的位置（漏斗阶段、层级、分桶） | 单一色相，明度单调递增；亮端在表面上仍需 ≥ 2:1 对比度 |
| **顺序** | 大小（多少） | 单一色相，从 100 到 700 的明度阶梯，由浅至深；暗色模式下锚点反转 |
| **发散** | 极性（基准线的哪一侧） | 两种色相加一个中性灰色中间点；两侧步长相等 |
| **状态** | 状态（良好→严重） | 小型固定比例尺，含义固定，始终图标+标签 |

**分类还是序数？** 如果调换类别顺序会改变含义——例如漏斗阶段、尺寸等级（S/M/L）、年龄组、队列分桶——则为**序数**，采用单色相渐变，以便读者从颜色中看出顺序。如果调换不会改变含义——例如产品名称、团队、地区、端点——则为**名义分类**，每个条形使用相同的第 1 色相（单个系列，无需图例框——标题已命名），或在有 N 个独立系列时依次使用第 1 至第 N 色相。切勿根据数值给名义类别的条形着色：这会占用标识通道，重复表达条形长度已显示的信息。

## 六项检验

每种分类颜色——无论是现有还是拟议的——都必须全部通过。

1. **固定色相锚点。** 八大色系按固定顺序排列。此顺序是色觉障碍安全性机制，永不更改。（结构要求——强制执行，而非测量）
2. **各模式下的明度区间。** OKLCH 明度 L 约为 0.43–0.77（亮色模式）；约 0.48–0.67（暗色模式）。（验证器）
3. **饱和度下限。** OKLCH 饱和度 C ≥ 约 0.10——低于此值，色相将呈现为灰色，无法发挥标识作用。（验证器）
4. **色觉障碍区分度。** 此方法中及所有场景下的 Delta E 均以 OKLab 空间中欧氏距离 ×100 计算。目标值 ≥ 8，最低门槛 ≥ 6（仅在存在辅助编码时允许放宽）。在模拟 1.0 强度的原色盲与绿色盲条件下（基于 Machado-Oliveira-Fernandes 2009 模型），阈值已针对该模型校准，因此该模型是标准的一部分，而非实现细节。同时设有**正常视觉下限**，用于未模拟情况下的同组对比：最差对比对 Delta E ≥ 15，确保全色觉用户也能轻松区分相邻色相。此下限为硬性门槛——即使有辅助编码亦不得放宽。（正是这一下限促使 2026 年 7 月对既定默认配色方案进行了首次重新排序——色相与步长相同，仅调整顺序；当前默认方案在亮色模式下为 19.6，在暗色模式下为 19.3——参见 `palette.md`。）对于堆叠/条形/折线图，仅相邻色相对之间需满足要求（只允许相邻接触——分配绝不跳过）；而对于散点、气泡、区域热力图及小多图，任意两个标记都可能并排出现，因此必须通过 `--pairs all` 检验，否则潜在的混淆将被隐藏。全对检验更为严格，也限制了此类图表可承载的系列数量：既定默认方案在两套模式下均仅能通过前三个色相的全对检验，而八个色相无论如何排序都无法全部通过（全对色相列表与顺序无关）。若全对形式超过三个系列，则应减少系列数量（归入“其他”）或改用分面图——而非调整配色方案。（验证器）
5. **与背景的对比度。** 标记与背景对比度 ≥ 3:1；当数值可通过其他方式（如可见标签或表格视图）读取时，可有条件放宽。（验证器）
6. **仅使用文档化配色方案。** 每个色位必须来自实例文件（`palette.md` 或其等效文件）——严禁目测取值。（结构要求；对于客户定制的渐变，可就近取值——详见下文）

## 执行检验——切勿凭目测判断
```
node scripts/validate_palette.js \
  "#2a78d6,#eb6834,#1baf7a,#eda100,#e87ba4,#008300,#4a3aa7,#e34948" --mode light
```

（`scripts/` 是相对于该技能根目录的，根目录路径显示在提示框顶部。）

（或者在图表所在页面中以 `<script type="module">` 的形式加载——它会从 `<body>` 上读取 `data-palette` 属性，并输出一份 `console.table` 格式的报告。）

对于每项可计算的检查（2～5），报告结果为 PASS、WARN 或 FAIL，并指出最差的一对 CVD 颜色组合。退出码 0 表示没有硬性 FAIL（WARN 级别的情况——如地板带 CVD 值在 6～8 之间，以及低于 3:1 的对比度缓解——仍视为退出码 0，但需要辅以二次编码）；只要出现任何 FAIL，包括正常视力下的对比度地板低于 15 的情况（这是硬性门槛），则退出码为 1。每个模式下需运行一次（例如 `--mode dark --surface "#1a1a19"`），对于散点图、气泡图、地图或小多图等图表（其中任意两个标记都可能相邻），还需添加 `--pairs all` 参数——默认的相邻检查可能会掩盖颜色坍缩问题。如果是**序数型**渐变，请使用 `--ordinal` 参数——此时将切换到渐变专用的检查标准（亮度单调递增、相邻亮度差 ΔL ≥ 0.06、亮端对比度 ≥ 2.0:1、单一色相），而非分类六项的检查。只有同时提供二次编码（直接标签、间隔或纹理）时，CVD 地板值在 6～8 之间的 WARN 才是合法的；而正常视力下的地板 FAIL 则意味着全色读者难以区分被标记出的邻近颜色。在“相邻”配对列表中，若发现某一对不符合要求，应调整其中一个颜色的阶调；二次编码不能作为此问题的免责理由。当使用 `--pairs all` 时，如果多个系列均因地板值不达标而 FAIL，则说明系列数量过多，必须限制系列数、进行分面处理或更换图表类型——因为在当前地板值下，仅靠重新排序或调整阶调无法使八种颜色两两区分。对比度方面的 WARN 也**不可忽视**——必须增加缓解通道（如可见的直接标签或表格视图）；若填充色低于 3:1 对比度且未采取任何缓解措施，则判定为 FAIL。

**范围——校验器覆盖与不覆盖的内容。** 这六项检查针对的是**分类**调色板（用于区分系列）。它们**不**适用于单个状态色或文本色，也不适用于顺序渐变。对于单一的状态色或文本色，应执行 WCAG 的*文本*对比度检查（普通文本 4.5:1，大号文本 3:1）——`validate_palette.js` 导出了 `contrast(a, b)` 函数，专门用于此类场景。对于顺序或发散渐变，检查重点是整个渐变的亮度单调性，而非相邻颜色的 CVD——将分类校验器用于顺序渐变**必然会导致 FAIL**（因为渐变跨越了整个色域，各阶调间距较近），这属于预期行为，而非真正的失败；切勿为迎合校验器而“修复”一个本就合格的渐变。

## 拍齐至通过（适用于任何设计系统）
给定客户提供的渐变和期望的顺序：
1. 对于每个位置，选择其 OKLCH 亮度 L 落在对应模式色域范围内且饱和度 C 达到最低要求的颜色。
2. 运行校验器。若发现任意相邻颜色对的 Delta E 低于目标值 8，则微调其中一个位置的颜色阶调（保持色相不变，调整亮度），并重新运行校验。
3. 重复上述步骤，直至最差的相邻颜色对满足最低要求。功能保持不变，客户的色相得以保留。

## 主题
颜色的位置**顺序**是一个可分离、可命名的选择——即“主题”，它基于相同的色相和相同的六项检查。每个设计系统都会定义默认顺序及若干备选方案；切换主题可在不改变方法的前提下调节视觉氛围。界面应采用一种主题并固定下来，切勿在同一仪表盘中混用不同主题。（参见 `palette.md`。）

**当系统尚无主题时如何推导顺序：** 不要凭猜测。枚举系统色相的所有候选排列，分别运行校验器，选出能使“最小相邻”CVD Delta E 最大的那一个。（先根据色系类比选取一个已知良好的初始顺序，再在此基础上优化也是可行的——`palette.md` 中的默认顺序正是通过这种枚举得出的，在所有满足各项约束的排列中名列前茅，最终因其开篇效果而被选定。）

## 状态色是固定的状态值从不遵循分类体系——它是一个固定的小尺度等级（良好 → 警告 → 严重 → 致命），并具有预定义的语义，其各级之间的间隔经过刻意区分，以确保状态颜色不会冒充分类序列，并且始终与图标和标签搭配使用（在浅色背景上，按照设计，警告和严重级别的对比度低于3:1——这种搭配起到了视觉缓解的作用）。（具体分级详见 `palette.md`。）冲突规则如下：当某个序列本身即表示优劣（如错误率、通过/失败）时，应使用状态标记；而当其仅作为“序列4”这类标识时，则应使用分类标记——同一张图表中二者不可同时出现。
