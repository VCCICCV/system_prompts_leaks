# XLSX 文件的创建、编辑与分析

| 任务 | 方法 |
|---|---|
| 使用公式/格式**创建**或**编辑** | `openpyxl` — 请参阅下方注意事项 |
| 大量数据的**导入**或**导出** | `pandas`（`read_excel`、`to_excel`） |
| 快速查看某个工作表 | `markitdown file.xlsx` — 每个工作表以 `## 工作表名` 标记；也支持 `.xlsm` 文件。不显示单元格坐标，因此不适合用于编辑 |
| 读取模型（公式*和*数值） | 需要两次调用 `load_workbook` — 请参阅注意事项 |

> `openpyxl`、`pandas` 和 `markitdown` 已预装，请勿先运行 `pip install`；直接编写脚本并导入即可。仅当导入失败（或缺少 `markitdown` 命令）时，再使用 `pip install` 安装缺失的包。

> 下文中的脚本路径均相对于本技能的目录。

## 所有输出的通用要求

- 全文使用**专业字体**（Arial 或 Times New Roman），除非用户另有要求。
- **杜绝公式错误。** 在 `recalc.py` 报告“errors_found”时绝不能交付。若认为错误并非由您引入，请通过将原始文件以 `data_only=True` 加载并检查该单元格来证明：您引入的错误与继承来的错误表现完全一致。
- **使用公式，绝不使用硬编码结果。** 应写入 `sheet['B10'] = '=SUM(B2:B9)'`，而非由 Python 计算得出的总值。当输入发生变化时，工作表必须能够重新计算。
- **严格遵照用户规范。** 包括准确的工作表名称、列标题以及用户明确指定的公式。即使设计更优，只要计算内容不同，即视为不合格。
- **在读者可见的位置注明所有假设和硬编码数值**——例如单元格批注，或表格末尾的相邻单元格。若有真实来源，请注明出处（如：“来源：公司 2024 财年 10-K 报告，第 45 页，收入附注，[SEC EDGAR URL]”）；若数值来自用户，则应明确说明。
- **若您为他人创建需填写的工作簿**，须附简短说明，标明可编辑的单元格，并提供一行符合预期格式的真实示例数据。切勿在受托编辑的文件中添加此类示例行。
- **编辑现有文件时：务必完全遵循其原有规范。** 此处的所有指南均服从于现有文件的约定。首先确定其指定的输入单元格——通常以特殊字体颜色、填充或底纹标识——仅在此类单元格内进行修改，并保持所有现有公式不变。

## 重新计算（文件包含公式时必做）

`openpyxl` 会将公式以字符串形式写入，且**不缓存任何数值**。在未执行重新计算之前，任何读取缓存值的操作（如 `pandas`、`load_workbook(data_only=True)` 以及大多数预览工具）都会将公式单元格读作 `None`。

```bash
python scripts/recalc.py output.xlsx [超时秒数]   # 默认 30 秒
```

LibreOffice 会重新计算所有公式，并**原地覆盖保存文件**，同时输出 JSON 格式的结果：包括 `status`（`success` 或 `errors_found`）、`total_formulas`、`total_errors`，以及按错误类型列出最多 100 个单元格的 `error_summary`（`locations_truncated` 表示被截断的数量——请以 `total_errors` 的总数为准，而非列表长度）。修正其中列出的问题后再次运行。**若 JSON 中出现 `error` 键而非 `status` 键，则表示未进行任何重新计算**，且只有这种情况才会返回非零退出码——而 `errors_found` 返回 0，因此切勿将干净的退出状态等同于无误的工作簿。

**重新计算成功仅能证明您的公式能够正常求值，但无法保证其结果正确。** 即使是范围错了一格或引用了错误的行，也可能得到一份看似整洁、无错误但数值却错误的文件。在构建完整表格前，请先编写 2–3 个公式并验证它们是否获取了预期的值。

**如果使用 openpyxl 重新保存并随后进行重算，链接到其他文件的工作簿会丢失这些链接。** 此类公式的形式为 `='[1]Returns Analysis'!$B$2`——其中的 `[1]` 是工作簿外部引用列表中的索引，指向磁盘上的*单独文件*，而非某个工作表。由于该文件在此处通常不存在，单元格中仅保留了其缓存值。openpyxl 在保存时会清除该值；LibreOffice 随后必须真正解析该引用，但会失败，写入 `#NAME?`，并删除所有链接。在这种状态下，`recalc.py` 将拒绝运行——请在覆盖保存之前将这些单元格的值从原文件中复制出来（使用 `--force` 可以绕过此限制，并接受数据丢失）。

## 如何选择能够通过验证的公式

LibreOffice 支持的函数少于 Excel，而任何它无法计算的函数都会以字面量 `#NAME?` 的形式固化在您交付的文件中。

- **优先使用 Excel 2007 年代的函数**——如 `SUMIFS`、`INDEX`、`MATCH`、`IFERROR`、`SUMPRODUCT`——这些函数无需前缀。
- **六个 2007 年之后的函数可以使用，但必须加上 `_xlfn.` 前缀**，因为 openpyxl 会原样将您的公式写入 XML 文件，而 Excel 会将 2007 年之后的函数名存储为带前缀的形式（其用户界面会隐藏该前缀）：`_xlfn.TEXTJOIN`、`_xlfn.CONCAT`、`_xlfn.IFS`、`_xlfn.SWITCH`、`_xlfn.MAXIFS`、`_xlfn.MINIFS`。若不加前缀，每个函数都会返回 `#NAME?`。
- **切勿使用 `XLOOKUP`、`XMATCH`、`SORT`、`FILTER`、`UNIQUE` 或 `SEQUENCE`。** 运行时的 LibreOffice 在任何前缀下都无法计算这些函数。较新的版本确实可以计算它们，但这些都是溢出数组函数，而由 openpyxl 写入的文件没有溢出元数据，因此只有区域的左上角单元格会获得一个值——且 `recalc.py` 对这种被截断的结果报告 `total_errors: 0`。对于查找操作，请使用 `INDEX`/`MATCH`；排序、筛选和去重应在 Python 中完成后再写入单元格。
- LibreOffice 无法解析的公式会被**小写**写回——这是判断是否出现 `#NAME?` 的一个快速标志。

## openpyxl 的一些陷阱

- **读取模型需要两次加载。** 使用 `data_only=True` 会得到已计算的值，但公式已被移除；默认设置则返回公式字符串，但无计算结果。一次遍历无法同时获取两者。
- **使用 `data_only=True` 后再保存是具有破坏性的。** 此时工作簿中已无公式，保存时会将所有公式替换为字面量——且不可恢复。
- **对 openpyxl 刚刚写入的文件使用 `data_only=True` 会导致所有单元格返回 `None`**——请先运行 `recalc.py`。（结果为 `""` 的公式也会被读回为 `None`。）
- **合并单元格：仅写入左上角的锚点。** 范围内的其他单元格均为 `MergedCell`，其 `.value` 属性为只读。
- **`.xlsm` 文件除非在调用 `load_workbook` 时传入 `keep_vba=True`，否则会丢失宏代码。**
- **包含空格的工作表名称在跨工作表引用中必须加引号**——例如：`='Assumptions Inputs'!$B$5`。若未加引号，则会返回 `#VALUE!`。

## 财务模型

除非用户另有要求，或现有文件已经采用了其他约定。

**颜色：** 硬编码输入和情景控制项使用蓝色文字（`0,0,255`）；公式使用黑色；链接到其他工作表的单元格使用绿色（`0,128,0`）；链接到其他文件的单元格使用红色（`255,0,0`）；关键假设及用户需填写的单元格使用黄色填充（`255,255,0`）。

**数字格式：** 货币采用 `$#,##0` 格式，单位在标题中注明（如“Revenue ($mm)”）；零值显示为 `-`，包括百分比（`$#,##0;($#,##0);-`）；负数用括号表示；百分比采用 `0.0%` 格式，**以分数形式存储**（`0.15` 显示为 `15.0%`；若存储为 `15`，则显示为 `1500.0%`）；估值倍数采用 `0.0x` 格式；年份以文本形式表示（如“2024”，绝不用 `2,024`）。

**结构：** 每个假设都置于独立的标注单元格中，由使用它的公式引用（如 `=B5*(1+$B$6)`，而非 `=B5*1.05`）；公式在每个预测期间保持一致，因为行中间单独编辑一个单元格是最常见的无声错误；对可能为零的分母要加以保护。
