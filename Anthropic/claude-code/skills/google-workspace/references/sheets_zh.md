# Google 表格参考

作为第一步，在创建或修改表格之前，您必须完整阅读以下电子表格设计规则。在这些规则之后，本文档将介绍 Sheets 连接器（`get_spreadsheet`、`get_values`、`update_values`、`update_formulas`、`insert_dimension` 和 `update_spreadsheet`）及其如何遵循这些设计规则。此处连接器的大部分行为已通过 Google Sheets API 进行了测试；其余部分则通过连接器进行了验证，另有少数规则尚未经过检验。

# 电子表格设计

当用户提出具体要求时，例如标签页名称、列标题、公式或数字格式，请严格按照其要求执行，不要以自己的设计替代；这些规则决定了用户未明确指定的部分应如何处理。编辑现有工作簿时，应优先遵循其原有规范（参见“编辑现有工作簿”）。关于工作表名称、标题、标签和备注的表述规则，请参阅“在工作簿中书写”。

读者评判一张电子表格的标准在于其中的数值是否正确，以及他们能否对这些数值进行核验。请确保点击任意数值时，要么显示可追溯的公式，要么显示可修改的带标签输入项。

## 公式，而非手动输入的结果

- **所有派生数值都应为公式**，并引用其来源单元格：总计、平均值、比率、增长率、查找等。应输入 `=SUM(B2:B9)`，而非自行计算出的总值。
- **这一原则同样适用于代码处理场景。** 使用代码读取、探索和重塑数据，但最终写入表格的结果必须是基于源单元格的公式。如果任务是“汇总这张包含 5,000 行的表格”，则汇总单元格中应填写 `=AVERAGE(Data!B2:B5001)` 和 `=SUMIFS(...)`，而不是在 pandas 中计算得出的数值。
- **手动输入的数值仅用于从外部引入的数据**，例如来自文件、查询或网页的行数据（事先进行排序、筛选或去重是可以的），以及“输入与硬编码值”中列出的输入项。若先在代码中计算出总和、平均值或比率，再将其粘贴到表格中，则属于硬编码结果。
- **将统计指标和分析结果置于带标签的单元格中。** 例如，`=CORREL(B2:B100, C2:C100)` 应放在一个标记为“价格与成交量的相关性”的单元格中。您报告的任何数值都应在文件中能够找到出处。
- **引用工作簿中已有的数据。** 不要将其复制到其他位置作为“干净”的副本，而应让公式直接指向原始数据源。
- **图表数据应为公式或对源数据的引用**，而非粘贴的一组数值。
- **公式覆盖了大多数分析需求：** 聚合（`SUM`、`SUMPRODUCT`）、条件判断（`SUMIFS`、`COUNTIFS`）、查找（`INDEX`/`MATCH`）以及统计函数（`CORREL`、`STDEV`、`SLOPE`）。Sheets 支持的较新函数详见下文“函数支持”。
- **语法基础：** 每个公式均以 `=` 开头。文本需用双引号括起（如 `=IF(A1="Yes",1,0)`）；若直接使用单词，则会显示 `#NAME?`。对包含文本的单元格进行算术运算则会返回 `#VALUE!`。

在完成前，请检查读者是否能点击分析中的任意数值，并查看其计算过程。将所有本应为公式的裸数值替换为公式。

## 输入与硬编码值

- **每个业务假设都放在单独的带标签单元格中**，公式直接引用该单元格：`=B5*(1+$B$6)`，其中B6被标记为“收入增长率”，而不是直接写成`=B5*1.05`。这适用于增长率、利润率、税率、估值倍数和各类阈值。在公式中添加注释来解释某个数值并不能解决问题；该数值仍应置于独立的单元格中。
- **不要：**
  - 重复工作簿中已有的数值：例如，当5%已存在于假设单元格中时，不应写成`=A1*1.05`；或当500,000已存在于另一单元格时，不应写成`=500000+B2`。
  - 输入自己计算出的数值，如在算出1,000,000 × 1.05后直接输入1,050,000。
  - 从其他工作表复制数值到公式中，而不通过引用（如`=Inputs!A5`）。
  - 用手动输入的数值覆盖公式以强行得到结果；应修正输入数据或其背后的逻辑。
- **以下硬编码值是允许的：**
  1. 明确指定的输入：位于带标签的输入或假设区域中的数值，供公式引用。
  2. 公式中的真正常量：如一年12个月、一周7天、将百分比转换为小数时使用的100等，无需加标签。
  3. 计算序列中的首个值，且没有更早的参考值时，例如第一年的收入，可放置在带标签的区域中。
  4. 结构性数值：如`OFFSET`函数中的行数、工作表索引号等，这些数值描述的是工作表本身而非业务。
  5. 小型查找表：位于带标签区域内的静态参考数据，如税率等级，供其他公式引用。
- **注明每个硬编码输入的来源**，可在单元格批注或相邻单元格中说明：“来源：[系统或文档]，[日期]，[具体出处]，[如有URL则附上]”，未掌握的部分可省略，例如“来源：公司2024财年10-K报告，第45页，收入注释，[SEC EDGAR URL]”。若数值来自用户，则注明：“来源：用户提供的假设”。“来源与引用”部分用于记录从外部引入的数据。
- **对输入项进行标注。** 在您构建的模型或为他人创建的待填写工作簿中，在顶部附近附上简短图例，说明哪些单元格是输入项及其标注方式。供他人填写的工作簿还应提供一行示例数据，展示预期的格式。切勿在受邀编辑的文件中添加示例行。

在输入数值之前，请先自问：这是业务假设吗？如果是，就将其放入带标签的单元格中。如果是推导得出的，请编写公式。如果它是没有工作簿内来源的输入，则为其加标签并注明其来源。

## 便于读者理解的公式- **使每个公式简短，便于一目了然地阅读。** 将包含多个条件或查找的逻辑拆分到带标签的辅助单元格或列中，以便逐项检查。
  - 好：在带标签的辅助单元格B6中计算税率，然后使用`=B5*(1-B6)`。
  - 差：`=B5*(1-IF(AND(B3>100000,B4="US"),0.21,IF(B4="UK",0.25,0.15)))`
  - 差：`=SUMPRODUCT((A2:A100="East")*(B2:B100>50)*(C2:C100))/SUMPRODUCT((A2:A100="East")*(B2:B100>50))`
- **编写可复制的公式。** 使用`$`锁定公式复制时不应改变的部分：`$A$1`同时锁定行和列，`$A1`在横向复制时保持A列不变，`A$1`在纵向复制时保持第1行不变，而`A1`则会随复制方向变化。
- **将维度标签置于表头，并用一个引用该标签的公式。** 在按月、季度、地区或产品进行汇总时，将标签写在表头行或列中，并使用一个引用这些标签的公式。
  - 差：E2是`=SUMIFS($D:$D,$B:$B,"Jan")`，F2是`=SUMIFS($D:$D,$B:$B,"Feb")`，依此类推，每个月都手动编辑一个公式。
  - 好：E1至P1依次为“Jan”到“Dec”；E2是`=SUMIFS($D:$D,$B:$B,E$1)`，并向下复制到F2:P2。
  - 如果源数据只有日期，应先添加一个辅助列（如`=TEXT(A2,"mmm")`），并引用该辅助列，而不是在`SUMIFS`的条件中直接计算期间。
  - 如果无法沿行复制公式而不做修改，则公式中的文字应放在表头单元格中。
- **在一行的每个期间使用相同的公式。** 行中间有一个被修改的单元格是最常见的错误来源，且不会产生错误值。
- **对分母可能为零的除法进行保护：** `=IF(C5=0,0,B5/C5)`，其中“财务模型”中的零格式会显示为短横线。此处应使用`IF`而非`IFERROR`，因为后者也会隐藏无效引用。
- **跨工作表引用使用`!`：** `=Assumptions!B5`。如果工作表名称包含空格或符号，需加单引号，并将其中的单引号加倍：`='Q3 Forecast'!B7`、`='Owner''s tab'!A1`。`=Assumptions.B5`（LibreOffice的表示法）、`=@Assumptions!B5`以及`[Book2]Sheet1!A1`（Excel对其他文件的引用）在Google Sheets中均不适用。

## 数据增长
- **用户会追加行的日志类公式必须包含新增行。** 这适用于交易清单、工时表及任何仅追加记录的场景。固定范围（如`=SUM(B2:B128)`，或针对1000行表格的`J2:J1001`）会遗漏新增的一行。首先明确数据是持续增长的日志还是固定快照；如果是快照，则可使用固定范围。
- **使用开放式范围**，如`=SUM(B2:B)`。Google Sheets中的表格（格式 > 转换为表格）也支持`=SUM(Sales[Amount])`，但`[@Amount]`、`[[#Totals],[Amount]]`及`@`运算符在Google Sheets中均为语法错误。对于逐行计算，应锁定列并向下填充公式（如`=$B2*$C2`）。命名范围不会自动扩展，因此不要将其用于增长型数据。`ARRAYFORMULA`可用一个公式计算整个增长列，但需防范空白行，例如`=ARRAYFORMULA(IF(LEN(B2:B), B2:B*C2:C, ))`，其中最后一个空参数会使未使用的行为空白（若使用`""`则会被`COUNTA`计入）。`ARRAYFORMULA`仅存在于Google Sheets中，若文件可能导出到Excel，则应改用普通公式向下填充。
- **为行设置带状效果，使其能延伸至新行：** 对超出最后一行的区域应用交替颜色（格式 > 交替颜色），或对列应用条件格式（如`=MOD(ROW(),2)=0`），同样要覆盖到新增行。手工填充的隔行颜色不会自动延伸到新行。

## 布局- **在开始之前，为多工作表的文档确定一种统一的样式**：包括页眉填充、字体、列宽和表格样式。在每张工作表上以相同的方式应用这些设置，并在完成前逐一核对。如果每张工作表都单独设置样式，就会导致各工作表之间风格不一致。
- **全文使用一种专业字体**，例如 Arial 或 Times New Roman，除非用户另有要求。
- **在单元格中使用用户的语言及其地区拼写规范**书写文本：包括标题、标签、备注和图表标题。如果工作簿已采用某种特定的语言变体，则应与之保持一致。切勿在同一工作簿中混用不同语言变体。
- **列宽设置**：调整行标签列的宽度，确保标签完整显示，不被截断。对于位于一组列上方的标题，应使用合并居中方式，而非通过加宽某一列来适应；在财务模型中，数字列应保持统一的宽度，并通过添加一个更窄的辅助列来实现缩进，而不是通过改变列宽来实现。
- **使用分组代替隐藏行或列**。除非用户明确要求，否则不要隐藏行或列。分组会显示一个“+”/“−”控件，提示读者该区域存在内容；而隐藏的行则容易被忽略，从而导致错误。在折叠分组之前，请检查是否有图表覆盖或基于这些行创建：折叠行会导致图表也被隐藏。应将图表的数据放置在不会因折叠明细行而受影响的位置，例如单独的区域或工作表。
  
## 在工作簿中撰写文本

您在工作簿中撰写的文本（工作表名称、标题、标签、备注、批注、文本单元格、图表标题）应当读起来像出自真人之手。一旦读者认为某段文字是由 AI 生成的，无论内容如何，他们都会将其视为粗制滥造并失去信任。他们会根据一系列常见特征做出这一判断，如下所述，因此请务必在写作中避免这些特征。本规则适用于您自行撰写的文本；若用户或其风格指南有特定要求，则应优先遵循用户的要求。除非用户明确要求，否则请勿为了符合这些规则而修改用户已有的文本。
- 陈述事实时，不要先否定其他内容。“收入增长12%，是美国增速的三倍”，而不是“这不是一个增长故事，而是一个市场份额的故事”。不要以“关键在于”或“真正的情况是”开头。
- 列点、举例和形容词的数量应与内容相匹配，而非固定为三个。如果有两个驱动因素就列两个；有五个就列五个。如果列表恰好只有三个（如“快速、可靠、可扩展”），往往意味着第三个只是为了语句节奏而添加，并非因为确实有三件事要说明，读者会将其视为填充内容。
- 在可以用直白词语表达的情况下，不要使用比喻。如果已有简洁的描述（如“同样的结构”“同样的模式”“放缓”“下降”），就直接使用。比喻适用于直白表述更冗长或不够精确的情形，而这在分析性写作中很少见。检验方法：如果比喻可以被一个普通词语替换且不损失原意，就应予以替换。比喻会让读者将其还原为直白表述，并承载你并未刻意选择的含义。常见比喻包括：“北极星”“推动进展”“双击”（意指深入查看）“拆解”“旅程”以及“格局”（指市场）。商务写作中常见的还有：“护城河”“逆风”“拖累”（指对业绩的成本影响）“安全网”“达标”以及“落地”（指完成或总额，如“比预算低4.4万美元”）。示例：
  - 不佳：“它拥有的都是同一种类。” 良好：“它拥有的遵循同样的模式。”
  - 不佳：“一次协调一致的支出暂停会立即显现。” 良好：“如果多家大型客户在同一季度削减资本开支，会在下一份指引中体现出来。”
  - 不佳：“架构转型在进入阶段压缩了利润率，在退出阶段又将其扩大。” 良好：“毛利率在Hopper向Blackwell过渡期间下降，待Blackwell批量出货后才恢复。”
  - 不佳：“解锁增长的杠杆。” 良好：“正是价格调整使目标得以实现。”
- 删除那些声称重要却未提供证据的词汇：“真正地”“确实”“实际上”“显然”“显著地”“稳健的”“杠杆”“深入探讨”“可操作的洞察”“经验教训”。若这些词只是用来替代某个事实，就直接写出该事实（如“利润率下降了4个百分点”，而非“利润率显著下降”）；否则请删除。当“杠杆”或“显著”具有其财务或统计学意义时（如“净杠杆率”“统计上显著”），则属于直白术语，应予保留。
- 正确使用句号、逗号，并在列举前使用冒号。工作簿中不得使用表情符号。
- 慎用破折号：每段最多一个，标题、页眉以及加粗标签与其后文字之间均不应使用。一段内出现多个破折号往往是读者识别机器生成文本的首要特征之一。遇到这种情况，可用逗号、冒号、括号或另起一句来替代，切勿使用一字线或带空格的连字符。
- 工作表名称和标题应反映内容本身（如“收入（百万美元）”“假设”），而非制作方式（如“新计算”“已修正”）。概括分析结果的文本行，例如汇总表的标题，应直接陈述结论（如“欧洲未达计划”，而非“分析结果”）。
- 避免在工作簿中记录对话：不要将标签命名为“汇总（修订版）”，也不要在单元格中写“根据您的反馈已更新”。若有多个版本并存，应按各自内容命名。下一个打开工作簿的人并未参与之前的沟通，因此这些文字对他们毫无意义。应在回复中说明变更内容，而非在工作簿中注明。数据来源注释和“数据来源”工作表用于记录数据出处，它们并非对话，因此请按照“来源与引用”的要求继续填写。
  
## 财务模型

除非用户另有要求或现有文件已有不同做法，否则请使用以下规范。**文本颜色：**
- 蓝色（`#0000FF`）：硬编码的输入值，以及用户在不同场景下需要修改的数值。
- 黑色（`#000000`）：所有公式和计算。
- 绿色（`#008000`）：指向同一工作簿中其他工作表的链接。
- 红色（`#FF0000`）：指向其他文件的链接。
- 黄色填充（`#FFFF00`）：需要重点关注的关键假设，以及用户应填写或更新的单元格。

**数字格式：**
- 年份采用文本格式：“2024”，而非2,024。
- 货币格式为“$#,##0;($#,##0);‘-’”，并在标题中注明单位，如“收入（百万美元）”。
- 负数用括号表示：(123)，而非-123。
- 零值显示为短横线，百分比亦然（`0.0%;(0.0%);‘-’`）。
- 百分比保留一位小数（`0.0%`），并以分数形式存储：0.15显示为15.0%，而15则显示为1500.0%。
- 估值倍数（如EV/EBITDA、P/E）采用“0.0×”格式，显示为12.5×。

**敏感性分析表：**
- 表格的行数和列数应为奇数，如5×5或7×7，使基准情形位于中心单元格，并对该单元格进行高亮（例如黄色填充）。对于WACC与终值增长率的分析表，应将当前WACC置于中间行，当前增长率置于中间列。
- 表格中的每个单元格均应设置为公式，根据其所在行和列的输入值重新计算输出结果。例如，在DCF模型中，每个单元格均以所在行的折现率对相同的现金流进行折现，并以所在列的增长率计算终值。

## 图表

- **将图表数据按单一区块布局。** 第一行的标题将成为系列名称，第一列的类别将成为坐标轴标签：

  |       | Q1  | Q2  | Q3  | Q4  |
  |-------|-----|-----|-----|-----|
  | 北部  | 100 | 120 | 110 | 130 |
  | 南部  | 90  | 95  | 100 | 105 |

- **某些图表类型需要特定的数据布局。** 饼图或甜甜圈图只需一列数值及对应的标签；散点图需将X值放在第一列，Y值放在其他列；蜡烛图则需包含最低价、开盘价、收盘价和最高价。
- **先汇总再绘图。** 若要对需要聚合的原始数据行绘制图表，应先构建汇总表，可以是数据透视表，也可以是使用`SUMIFS`公式的表格，然后基于该汇总区域绘制图表。基于数据透视表生成的图表会随数据透视表的变化而自动更新，因此应直接调整数据透视表，而非单独修改图表。
- **通过辅助列将日期分组为周期。** 当用户希望按月、季度或年统计总量，而数据为每日记录时，可新增一列，将每日期转换为其所属周期，例如使用`=EOMONTH(A2,-1)+1`获取当月的第一天（需将该列格式设置为日期，否则会显示序列号，如45413），或使用`=YEAR(A2)&"-Q"&ROUNDUP(MONTH(A2)/3,0)`获取所属季度。为该列添加标题，向下填充至所有行，然后按该列进行分组，而非直接按原始日期分组。

## 数据来源与引用
凡从外部引入本工作簿的数值，均应在无需询问的情况下可追溯其来源、传递路径及获取时间。- **这些无需注明出处**：用户手动输入或口述、且无后台系统支持的数据行，以及用户交给你编辑的现有工作簿中的原有内容。即便这是用户的假设，也需在“输入与硬编码值”中注明。
- **你单独查到并引用的数值**（如从网页、文档或仪表板中获取），应直接在该数值单元格上添加备注，而非其所在行标签或标题处。例如，若A8为“现金及现金等价物”，B8为179,172美元，则备注应标注在B8单元格上。采用“输入与硬编码值”中的出处格式，注明你实际查阅该数值的页面URL，而非起始的索引页：`来源：苹果投资者关系，https://investor.apple.com/sec-filings/annual-reports/2024`。这同样适用于你在对话前期已找到的数值。
- **整表引入的数据**只需在左上角标题单元格（如C4:F20表格的C4单元格）添加一条备注，而无需在各数值单元格或其他标题单元格上添加备注。这包括上传文件中的数据行、查询结果、用户粘贴的查询结果，以及你从文档中誊抄的表格，例如PDF中的财务报表。
  - 对于上传的文件或文档：`来源：[文件名]，[适用时注明页码或表格编号]，上传日期：[日期]`。
  - 对于查询结果：`来源：[系统]（[对象]），共[N]行，执行日期：[年月日 时分 时区]。获取方式：[说明]。完整查询见“数据源”工作表。` 其中N仅统计数据行数，不包含标题行。“获取方式”为：“由Claude执行”（当你自行运行查询时）；或“由用户粘贴至聊天，非Claude执行”（当结果由用户提供时）。切勿以自己执行了他人提供的查询为由进行备注。
- **查询结果还需在“数据源”工作表中占一行记录**，每组结果对应一行。将该工作表置于最后一页，并保持可见状态。其列顺序如下：写入位置（工作表!区域，含标题行）| 来源 | 对象（数据库.模式.表、端点、URL或文件名）| 获取途径 | 查询或请求内容（精确的查询语句，或未展示查询时用用户原话描述；切勿凭空编造）| 参数 | 执行时间 | 请求人（如知晓姓名则填写）| 行数 | 检索后变更（无变更，或注明所做操作：排序、筛选、透视、单位转换等）| 备注。若再次执行同一查询，应在旧记录的“备注”栏中注明“已替换”，而非直接覆盖；若删除某张表，则在该表的“备注”栏中注明“已移除”。
- “执行时间”应按工具或用户报告的实际拉取时间填写。将“昨天”等相对时间转换为具体日期，并以文本形式录入；切勿使用`NOW()`或`TODAY()`，因为它们会在每次打开文件时发生变化。
- **确保审计记录中不含机密信息及个人标识**。凭证、API令牌、密码和连接字符串一律不得出现在工作簿的任何位置。在查询文本、备注及“数据源”工作表中，凡作为字面值出现的个人标识均应替换为“[已遮盖]”：如政府身份证号、完整的银行账号或支付卡号、个人姓名或出生日期、家庭住址，以及个人电子邮箱或电话号码。表名、列名、公司与产品名称、内部记录键及非识别性筛选条件则予以保留，以便查询仍可被读取并重新执行。例如，“WHERE ssn = '123-45-6789' AND region = 'EMEA'”应改为“WHERE ssn = '[已遮盖]' AND region = 'EMEA'”。返回的行数据按用户要求写入工作表；此规则旨在避免将标识信息二次复制到记录中。

## 编辑现有工作簿- **其约定优先于这些规则：** 颜色、数字格式、字体、布局和 Tab 键顺序。首先找到它的输入单元格（通常会用独特的字体颜色、填充或底纹加以标记），除非需求另有要求，否则只在这些单元格中进行编辑；除非用户要求，否则不要动它已有的公式。
- **保留原有格式。** 新增行的格式应与上一行一致，新增列的格式应与相邻列一致。
- **汇总时保持与源数据相同的数字格式。** 货币列下方的合计应采用相同的货币格式。如果新单元格未设置格式，应明确设置格式，而不要仅显示纯数字。
- **在汇总区域内部插入行后，** 请检查总计和平均值是否已包含这些新行。通常，紧贴最后一行下方或最上面一行上方插入的行会被遗漏。
- **插入的行和列会继承相邻单元格的格式。** 在蓝色标题行下方插入的行也会显示为蓝色。请检查新单元格，并清除不适用的格式。

## 检查结果

- **检查读者将看到的内容。** 数字格式和区域设置决定了单元格的显示内容，因此在进行格式调整时，请检查显示文本，而不仅仅是存储的数值。
- **无错误值：** 不应出现 `#VALUE!`、`#REF!`、`#NAME?`、`#DIV/0!` 或 `#N/A` 等错误，也不应存在循环引用，以及任何未涵盖全部数据的范围。
- **无错误值并不意味着正确。** 请注意是否存在本应使用公式的地方却硬编码了数字，或者公式虽然今天给出了正确结果，但引用的却是错误的行。
- **逐张检查工作表。** 列出工作簿实际包含的所有工作表，而不是仅凭记忆创建的工作表，并确认每张工作表都有相应的内容。对于您添加的空标签页，请予以删除或完成内容。
- **核对来源。** 所有来自工作簿外部的数据都应附有“来源与引用”所要求的来源说明。
- **对照用户需求及上述约定检查格式。**

## 应用设计规则

- **颜色：** `sheets_helper.py format` 规则从上述设计规则中提取 `fg` 和 `bg` 的十六进制值，例如用于输入单元格的 `{"range": "B2:B8", "fg": "#0000FF"}`。
- **数字格式：** 辅助工具中的 `currency` 格式为上述设计规则中的 `$#,##0;($#,##0);"-"`，其 `multiple` 格式为 `0.0"x"`。其 `percent` 格式为简单的 `0.0%`，会将零显示为 0.0%；在财务模型中，应改用模式 `0.0%;(0.0%);"-"`。*尚未通过连接器测试。*
- **年份作为文本：** 使用前导单引号写入 `'2024`。若不加单引号，两种写入工具都会将其存储为数字 2024。
- **来源注释：** 通过 `updateCells` 请求可设置单元格的注释：`{"updateCells": {"rows": [{"values": [{"note": "Source: ..."}]}], "fields": "note", "start": {"sheetId": 0, "rowIndex": 3, "columnIndex": 2}}}` 将注释置于 C4 单元格。*尚未通过连接器测试。*
- **分组行或列：** `{"addDimensionGroup": {"range": {"sheetId": 0, "dimension": "ROWS", "startIndex": 4, "endIndex": 12}}}` 可将第 5 至 12 行分组；索引从 0 开始，且结束索引为非包含值，与网格范围的定义方式相同。*尚未通过连接器测试。*
- **隔行换色：** 使用 `addBanding` 并设置 `bandedRange`，其中的 `rowProperties` 可指定 `headerColor`、`firstBandColor` 和 `secondBandColor`。隔行换色效果会延伸至该范围内新增的行，因此请确保范围超出数据的最后一行。*尚未通过连接器测试。*

## 创建- **先创建空白表格，再分四次调用完成填充。** 适用于模型以及包含公式的任何内容。
  1. 调用 `create_file`，并指定 `contentMimeType: "application/vnd.google-apps.spreadsheet"`。新表格的第一个标签页默认为 `Sheet1`，其 `sheetId` 为 `0`，此时尚无数据可读。
  2. 一次 `update_formulas` 调用即可从左上角单元格开始写入整个表格：标题、表头、标签、数值和公式一并以二维数组形式传入，空单元格用 `null` 表示。两种写入工具的输入解析方式相同，因此无需分多次分别发送数值和公式。
  3. 一次 `update_spreadsheet` 调用即可完成其余操作：重命名标签页（通过 `updateSheetProperties` 并设置 `fields: "title"`）、格式设置、冻结行、合并单元格、条件格式，以及文本列的宽度调整（使用格式规范中的 `col_widths` 键，或发起 `autoResizeDimensions` 请求），以避免标签被截断。运行 `sheets_helper.py format spec.json --sheet-id 0` 即可在不读取元数据的情况下生成格式配置，并在其输出基础上追加其他请求。
  4. 最后对表格执行一次 `get_values` 进行校验。
- **上传：** 上传由 `xlsx` 技能生成的 CSV 或 `.xlsx` 文件，Drive 会自动将其转换为电子表格，随后可在原地编辑。由于文件的全部内容都需在工具调用中传递，上传过程较慢且容易失败：一个 20 KB 的编码文件可能需要约三分钟。请尽量保持上传文件较小；对于大型数据集，建议先创建空白表格，再通过 `update_values` 写入数据。

## 表格的引用方式

有两种坐标系统，每种工具使用其中一种。

| 工具 | 引用单元格的方式 | 示例 |
|---|---|---|
| `get_values`、`update_values`、`update_formulas` | 使用带标签页名称的 A1 表示法 | `'P&L Model'!B4:D10` |
| `update_spreadsheet`、`insert_dimension` | 使用数字 `sheetId` 加上基于 0 的索引；结束索引为开区间 | 标签页 1001 上的 B4:D10 表示为 `{"sheetId": 1001, "startRowIndex": 3, "endRowIndex": 10, "startColumnIndex": 1, "endColumnIndex": 4}` |

- 对于包含空格或特殊字符的标签页名称，请用单引号括起，并将内部的单引号转义为双引号：`'P&L Model'!F5`、`'Owner''s tab'!A1`。
- **`sheetId` 并非标签页名称或其位置序号。** 可通过 `get_spreadsheet` 获取（参见“读取”部分）。若要自行指定新标签页的 ID，可在 `addSheet` 中设置 `sheetId`，响应中会确认该值。
- **将计算交由辅助工具处理。** 运行 `sheets_helper.py range` 可将 A1 表示法转换为网格范围，包括开放范围如 `C:C`，并解析标签页名称：

```
python <skill>/scripts/sheets_helper.py range "'P&L Model'!B4:D10" --meta meta.json
{"sheetId": 1001, "startRowIndex": 3, "endRowIndex": 10, "startColumnIndex": 1, "endColumnIndex": 4}
```

`meta.json` 是下方元数据读取操作的（小型）输出结果，已写入文件中。

## 读取- **工作表和 ID：** 使用 `fields: ["sheets.properties"]` 调用 `get_spreadsheet`。它会返回每个工作表的 `title`、`sheetId` 和网格大小。务必保持请求简洁：切勿在未指定 `fields` 的情况下调用 `get_spreadsheet`。
- **字段掩码：每个数组项对应一个路径，不得使用括号。** 该连接器会拒绝将 `sheets.properties(sheetId,title)` 或 `"spreadsheetId,properties.title"` 作为单个项处理，尽管工具本身的说明似乎暗示了带括号的形式。请分别传递各个项：`["spreadsheetId", "properties.title", "sheets.properties"]`。
- **显示值：** `get_values` 返回 UI 中显示的内容，以字符串形式呈现（如 `"$125"`、`"25.0%"`、`"#DIV/0!"`）。它不提供获取公式或原始值的选项。空行会返回为 `[]`，末尾的空单元格和空行会被省略，而完全为空的区域则不会包含 `values` 键。
- **使用开放范围读取至数据末尾。** 在小型工作表中，`'Log'!A:F` 会返回标题行及所有已填充的行，且不会包含最后一行之后的内容，因此一次读取即可同时获取布局信息和数据的终止位置。切勿猜测固定范围（如 `A1:Z1000`）：超出工作表最后一行的范围可能会导致“超出网格限制”错误，且删除行会导致工作表变短。若要对某一列进行向下格式化，请在网格范围中省略 `endRowIndex`（`sheets_helper.py range "D2:D"` 即为此做法）。
- **公式、原始值和错误：** 改用读取网格的方式。请使用以下精确的调用，它既简洁又包含了辅助工具所需的所有信息：

```json
{"spreadsheetId": "...", "includeGridData": true, "ranges": ["'Model'!A1:H40"],
 "fields": ["sheets.properties.title", "sheets.data.startRow", "sheets.data.startColumn",
            "sheets.data.rowData.values.userEnteredValue",
            "sheets.data.rowData.values.formattedValue",
            "sheets.data.rowData.values.effectiveValue"]}
```

随后列出单元格，并将每个公式与其显示结果并列展示：

```
python <skill>/scripts/sheets_helper.py cells grid.json
Sheet1!D5   '=B5*(1+C5)'   -> '$125'
Sheet1!D7   '=D5/0'        -> '#DIV/0!'  <-- ERROR DIVIDE_BY_ZERO
errors: 1
```

添加 `--errors-only` 参数可仅列出包含错误的单元格。若需读取单元格格式，请在字段中加入 `sheets.data.rowData.values.userEnteredFormat`，并尽量缩小范围：网格读取的数据量会迅速增长。

## 写入值和公式

- **两种写入工具都按照表格界面的方式解析输入。** `update_values` 和 `update_formulas` 都会将 `"=A1+B1"` 转换为公式，将 `"0.25"` 转换为数字，将 `"3/14/2026"` 转换为日期，将 `"00123"` 转换为数字 123。`"1/2"` 会被识别为日期并仍显示为 1/2，对其使用 `SUM` 函数时会计算该日期的序列号，即一个五位数，如 46024。诸如 `"Jan 2027"`、`"2027-01"` 或 `"Jan 1"` 等时段标签也会被转换为日期；而单纯的月份缩写，如 `"Jan"`，则会保持为文本。由于两者采用相同的解析方式，一次调用 `update_formulas` 即可同时写入单元格中的标签、数字和公式。
- **通过在开头添加单引号来保留文本格式。** `"'00123"` 会存储文本 `00123`，`"'=not a formula"` 则会原样存储该文本。适用于 ID、邮政编码、账号以及任何看起来像数字、日期或公式的文本。预先设置为 `TEXT` 格式的单元格也会按文本保存输入；其他数字格式（如货币）则不会。
- **以数字形式发送数字，而非字符串。** 百分比应以小数形式存储，例如 25% 对应 `0.25`，并在格式中设置为百分比。
- **`null` 表示跳过该单元格；`""` 表示清空该单元格。** 布尔值会变为 `TRUE` / `FALSE`。
- **为每个计算型单元格写入公式。** 不要直接写入您自己计算的结果。公式能使表格在用户更改输入时保持动态更新。
- **范围应与数据相匹配。** 可指定完整区域（如 `'Model'!A4:D6` 表示 3 行 4 列），也可仅指定左上角单元格。若将二维数组写入较小的范围，会报错“请求写入的范围……”。
- **清除数值时会保留单元格的数字格式。** 曾存放日期的单元格，在下次写入时仍会按日期格式显示。在重复使用这些单元格前，请先用 `repeatCell` 重置其格式。
- **插入行或列时，公式会自动调整引用。** `insert_dimension`（或批量操作中的 `insertDimension`）会更新现有公式中的引用，因此在向插入位置下方的行写入前需重新读取数据。设置 `inheritFromBefore: true` 可复制上方行的格式。若是在标题行正下方插入，则传入 `false`：`true` 会复制标题行的格式。在最后一行求和结果与其总计行之间插入的行不会被纳入 `SUM` 计算，同样，在第一行求和行或其上方插入的行也不会被计入：因为求和范围会向下移动，越过该行。请在求和范围内插入，或将总计行改写为包含新行的公式，切勿用手动输入的数值替换。
  
## 批量更新：结构、格式、图表

`update_spreadsheet` 用于发送原始的 `spreadsheets.batchUpdate` 请求。本文件中的读取操作不返回 `revisionId`，因此在发送此类请求时无需提供 `writeControl`，并在依赖单元格位置的写入操作之前再次读取数据。
  
- **请求中的字段掩码遵循相同规则：** 使用逗号分隔的完整路径，不得使用括号。`"fields": "userEnteredFormat.numberFormat,userEnteredFormat.textFormat.foregroundColor"` 是有效的；而 `"userEnteredFormat(numberFormat,textFormat)"` 则会被拒绝。
- **颜色值以 `red`、`green`、`blue` 表示，范围为 0 到 1，而非十六进制。**
- **格式化：使用辅助工具。** 在简短的规范中描述格式要求，然后使用 `sheets_helper.py format` 构建请求，确保范围、颜色和字段掩码正确无误：

```json
{"sheet": "Model",
 "rules": [
   {"range": "A1:F1", "bold": true, "bg": "#1F3864", "fg": "#FFFFFF", "align": "center"},
   {"range": "B2:B8", "fg": "#0000FF"},
   {"range": "C2:F20", "number": "currency"},
   {"range": "G2:G20", "number": "percent"},
   {"range": "A1:G20", "borders": "#BFBFBF"}],
 "freeze": {"rows": 1, "columns": 1},
 "col_widths": {"A": 220, "B:G": 110},
 "row_heights": {"1": 30}}
```

```
python <skill>/scripts/sheets_helper.py format spec.json --meta meta.json
```

对于某个你已知其 `sheetId` 的标签页，例如新表中的 `0`，可传入 `--sheet-id 0` 而非 `--meta`，并在规范中省略 `sheet` 字段。输出结果为用于 `update_spreadsheet` 的完整 `requests` 列表。命名的数字格式包括：`currency`、`currency2`、`percent`、`multiple`、`integer`、`decimal`、`date`、`text`；其他任何字符串均被视为 Sheets 的自定义格式模式。规则键包括：`bold`、`italic`、`size`、`font`、`fg`、`bg`、`align`、`valign`、`wrap`、`number`、`borders`。

- **一条条件格式规则可覆盖多列。** `addConditionalFormatRule` 接受一个 `ranges` 列表。在第一个范围的左上单元格中编写 `CUSTOM_FORMULA`；对于其余单元格（包括其他范围内的单元格），Sheets 会自动调整相对引用。对于 D5:D15、F5:F15 和 H5:H15 这些范围，`=D5>C5` 会将每一行的实际值与其左侧计划列的值进行比较。若要固定某一列，可在公式中添加 `$` 符号，如 K5:L15 中的 `=$J5>$I5`，这样只需一次比较即可同时为该行的两个单元格设置颜色。
- **多列组的标题：** 如果“July”这样的未合并标题位于“Plan”和“Actual”两列上方，它会紧贴其起始单元格的左侧边缘，而下方的数字则右对齐。可通过 `mergeCells` 合并该组的标题单元格并居中显示，或直接删除该组所在的行，并分别为各列命名（如“Jul plan”、“Jul actual”）。
- **其他常见请求：** `addSheet`（含 `properties.sheetId` 和 `title`）、`updateSheetProperties`（通过 `fields: "title"` 更名；通过 `gridProperties.frozenRowCount` 冻结行数）、`deleteDimension`、`mergeCells`、`setDataValidation`（下拉列表、复选框）、`addConditionalFormatRule`、`sortRange`、`findReplace`、`autoResizeDimensions`。
- **图表可用。** `addChart` 会创建原生图表，响应中返回其 `chartId`，可用于在 Slides 中嵌入。以下是一个最简柱状图示例：

```json
{"addChart": {"chart": {
  "spec": {"title": "Revenue", "basicChart": {"chartType": "COLUMN",
    "domains": [{"domain": {"sourceRange": {"sources": [
      {"sheetId": 0, "startRowIndex": 0, "endRowIndex": 6, "startColumnIndex": 0, "endColumnIndex": 1}]}}}],
    "series": [{"series": {"sourceRange": {"sources": [
      {"sheetId": 0, "startRowIndex": 0, "endRowIndex": 6, "startColumnIndex": 1, "endColumnIndex": 2}]}},
      "targetAxis": "LEFT_AXIS"}],
    "headerCount": 1}},
  "position": {"overlayPosition": {"anchorCell": {"sheetId": 0, "rowIndex": 8, "columnIndex": 0}}}}}}
```

随时间变化的趋势使用 `LINE`，对比类图表使用 `BAR` 或 `COLUMN`，当首行为标签时应设置 `headerCount: 1`。

- **将嵌入到 Slides 演示文稿中的图表** 将遵循演示文稿现有的图表样式。如果演示文稿没有预设样式，则图表不应包含标题（因为幻灯片上已有标签），也不应有图例，且每个柱体上都应显示数值标签。为此，在 `spec` 中省略 `title`，在 `basicChart` 中设置 `"legendPosition": "NO_LEGEND"`，并在每个柱体或条形系列中添加 `"dataLabel": {"type": "DATA"}`。折线系列无需数据标签——折线上的少数几个点标签及其名称应以文本框形式置于幻灯片上。若要单独为某一根柱体着色，可使用系列的 `styleOverrides`（如 `[{"index": 3, "colorStyle": {"rgbColor": {...}}}]`）。*尚未通过连接器测试。*

## 验证

1. 使用 `get_values` 读取所有构建内容的显示值，检查是否存在 `#REF!`、`#DIV/0!`、`#NAME?`、`#VALUE!`、`#N/A` 和 `#ERROR!` 等错误，并确认合计与预期数值一致。
2. 对于模型，运行网格读取及 `sheets_helper.py cells --errors-only`，然后抽样检查计算单元是否包含公式（如 `'=...'`），而非手动输入的数值。
3. 上传后，通过编辑前的元数据读取确认标签页的名称和大小。

## 功能支持Sheets 支持 `XLOOKUP`、`FILTER`、`UNIQUE` 和 `SORT`，因此 LibreOffice 在 `xlsx` 导出时的限制在此并不适用。如果用户可能将文件导出到 Excel，请避免使用仅限 Sheets 的函数，如 `QUERY`、`ARRAYFORMULA`、`IMPORTRANGE` 和 `GOOGLEFINANCE`。那些从外部 URL 获取数据的公式（`IMAGE`、`IMPORTDATA`、`IMPORTXML`、`IMPORTHTML`、`IMPORTFEED`）会显示 `#REF!` 错误，直到有人在浏览器中打开该表格并点击“允许访问”为止，请告知用户这一点。

## Sheets 使用中的常见问题

| 症状 | 原因 | 解决方法 |
|---|---|---|
| `Invalid field: sheets.properties(sheetId,title)` | 连接器拒绝带括号的字段掩码 | 对每个数组项传递一个完整路径：`["sheets.properties"]`。 |
| `Invalid field: user_entered_format(number_format` | 请求的 `fields` 中存在括号 | 使用逗号分隔的完整路径。`sheets_helper.py format` 会自动处理这一点。 |
| 某些 ID 失去了前导零，或文本被识别为日期 | 两种写入工具都会像 UI 那样解析输入 | 在值前加上单引号 `'`。 |
| 公式显示为你手动输入的值 | 写入的是计算结果而非公式 | 公式字符串需以 `=` 开头。 |
| `get_values` 结果中没有 `values` 键 | 范围为空 | 将其视为空；这不是错误。 |
| 格式应用到了错误的行 | 行号按 1 开始计数却被当作 0 开始的索引，或结束索引包含在内 | 使用 `sheets_helper.py range` 构建范围。 |
| 格式应用到了错误的工作表 | 使用了工作表的位置或名称作为 `sheetId` | 读取 `sheets.properties`，使用其中的数字型 `sheetId`。 |
| 插入行后，公式引用了错误的行 | 写入行时使用了插入前的行位置 | 执行 `insertDimension` 后重新读取；Sheets 已经自动调整了现有公式。 |
| `Unable to parse range: <tab>!A1` | 通常是工作表名称不存在，而非 A1 引用格式错误 | 读取 `sheets.properties`，使用准确的工作表标题。 |
