# Google幻灯片参考

**在开始构建、重写或重新设计任何幻灯片之前，无论是在新演示文稿中还是现有演示文稿中，您都必须完整阅读以下设计规范。在添加或更改图表之前，请同时阅读 `references/charts.md` 文件。** 在规范之后，将介绍Slides连接器的工具以及如何使用这些工具来落实相关规范。

# 幻灯片设计

当用户提出具体要求时，例如幻灯片数量、确切措辞、颜色或布局，请严格遵照执行；对于用户未明确的部分，则按本规范处理。图表的设计规范请参见 [charts.md](charts.md)；幻灯片文字的设计规范则在下文“幻灯片文案撰写”部分说明。

您的幻灯片应与顶级战略咨询公司的演示文稿、投资银行的推介材料或商业版面头条文章相媲美，几乎难以区分。

## 演示文稿结构

- **每张幻灯片传达一个核心信息。** 演示文稿应按主题逐个展开，每个主题对应一条明确的信息。除非两者密切相关，否则不要将收入与留存率放在同一张幻灯片上，以免让读者需要同时理解两个要点。
- **标题应能讲述整个故事。** 仅阅读幻灯片标题的人也应能完整理解整份演示文稿的内容。
- **常见的结构是金字塔式：** 先呈现核心信息，接着是概述各部分内容的执行摘要，然后依次展开各章节，最后以结论收尾，通常会列出基于发现的后续行动。
- **根据演示文稿的篇幅调整结构。** 短小的演示文稿可能无需引言和结论；而篇幅较长的演示文稿则可能需要在不同主题之间加入分隔。
- **围绕演示文稿的目的进行设计：** 用于决策、达成共识、庆祝成果、化解分歧或开启讨论。
- **根据使用场景进行设计。** 现场演示文稿需配合讲解，并可能引发讨论；预读型文稿则必须独立承载全部叙事。现场会议中的高管观众通常偏好文字简洁、视觉效果突出的幻灯片。而对于专业领域专家或供离线阅读的文稿，详细且文字密集的幻灯片有时更为合适。分析报告则更多依赖图表和表格，标题承担主要的叙事功能。
- **根据演讲时长规划现场演示文稿的规模：** 每张幻灯片约1.5至2分钟，若预留提问时间，则相应缩短每张幻灯片的展示时长。

以下是一个示例大纲，标题的具体内容由演示文稿的主题决定：

1. 封面页：“Q3成本回顾：物流支出降低15%”，并注明主讲人、日期及听众（如已知）。
2. 执行摘要：物流成本同比增长22%，主要受三个可控因素驱动；解决这些问题每年可节省420万美元。简要概述演示文稿内容及建议。
3. “自Q1以来，物流支出增速为收入增速的三倍”：展示支出与收入的对比，并指出差距在Q2开始拉大。
4. “三大因素解释了80%的成本增长：承运商费率、加急配送及仓库加班”：按各因素分解成本增长情况。
5. “两家承运商费率上调18%，而货运量保持不变”：按承运商展示费率变化与货运量占比。
6. “加急订单翻倍，主要源于订单录入延迟而非客户需求”：分析加急订单激增的原因。
7. “加班主要集中在两家员工配置模式落后的站点”：按站点展示加班工时。
8. “三项改进措施，按节省金额与实施难度排序”：比较重新谈判、强化订单截止管理及人员配置调整的效果。
9. “建议：推进三项措施，优先开展承运商费率重谈以实现最快回报”：阐述节省金额及回报周期。
10. 后续步骤：明确负责人、关键里程碑，以及本月底前需由参会者作出的决策。

## 幻灯片设计流程

在制作每张幻灯片之前，请按以下顺序进行设计：确定信息、准备证据、规划布局。布局安排在最后，因为它取决于幻灯片需要承载的内容。

### 信息：标题

标题应准确传达幻灯片的核心信息，大多数幻灯片都需要标题。幻灯片标题有三种常见形式：1. **故事型标题**：用一句话向读者传达核心要点，例如：“2025年德国营收增长12%，是美国增速的三倍”。采用主动语态，明确主语，如有数字则直接写出，字数控制在十五字左右，不超过两行；在宽10英寸的幻灯片上，32号字体的两行约可容纳十二个字。不要使用“德国市场概览”或“我们分析了德国市场”这类表述。
2. **仅标签型标题**：概括幻灯片的总体主题，如“2025年德国营收”。
3. **标签加故事型标题**：第一行写“德国营收”，第二行写“2025年德国营收增长12%，是美国增速的三倍”。这样既点明主题，又突出核心结论。

按照上述方式为整个演示文稿中的每一页标题统一命名。若文稿已有既定规范，则沿用该规范；否则，默认内容页采用故事型标题。

结构性页面（如封面、目录、执行摘要、章节分隔页、后续步骤、附录等）均采用标签式标题，无论文稿整体采用何种规范。此类页面不承载单一结论，因此使用故事型标题会显得生硬，例如“我们将讨论以下四个主题”不如“目录”简洁明了。执行摘要的核心要点应置于正文而非标题中。

### 证据

内容的唯一作用是让读者信服标题所传达的观点。在选择版式之前，先确定用什么来支撑这一观点：文字、图形、图片、表格、图表、脚注，或多种元素的组合，并大致规划各类元素的占比。大多数幻灯片只需一个主要元素搭配少量辅助文字：
- 若标题为数字或对比，则主要元素为图表（参见[charts.md](charts.md)以确定图表类型）；
- 若标题描述结构或流程，则主要元素为示意图；
- 若标题提出一项主张并附带若干理由，则采用简短文字，或当各理由彼此平行时使用一排带标签的图标。

### 版式

遵循公司风格与品牌规范，参考母版、文稿中已有的成品幻灯片，以及用户的具体要求进行设计。新建幻灯片时应基于母版提供的版式，以便继承其字体、字号及元素位置。若无适合的设计版式，可从最接近的版式入手，使新幻灯片保留文稿的背景与字体，再在此基础上进一步调整。

在确定信息与证据后，选择能够有效呈现它们的版式。文字较多的幻灯片可选用简洁的标题加正文布局；高度视觉化的幻灯片则可能无需正文，仅以包含文字的图形呈现即可。常见版式包括：
- **大字标题**：仅含一条信息，别无他物。较为少见，适用于引用语句，或需要单独占页的重要信息/数字。
- **标题在上、内容在下，或标题在一侧、内容在另一侧**：适用于目录、执行摘要，或能自明且无需额外说明的关键图表。
- **标题在上、下方配图并辅以说明**：最常见的版式——左右分栏，一侧放置图形，另一侧撰写说明。图表至少占据60%的宽度；其他视觉元素可占一半或三分之二。

只要符合文稿的设计标准，其他版式亦可使用。若文稿提供多种版式供选择，凡含文字的幻灯片均应选用带有文本占位符的版式，以确保文字沿用母版的字体与字号；完全由视觉元素构成的幻灯片（如全幅图片或由形状拼成的示意图）则保留空白版式。除非有意组成系列，否则不应连续三页及以上采用同一版式，例如每位团队成员对应一页的情况。

## 从文稿设计出发

**已有模板或主题的文稿**：保持原有设计。新增内容应严格沿用主题色彩，新建幻灯片也应选用主题版式。若用户要求重新设计风格，则应修改主题与母版，而非逐页手动调整。主题变更不会影响那些自带固定颜色的文本与形状（多数实际文稿都存在此类元素），因此还需一并替换这些颜色。**基于默认主题逐张幻灯片进行样式设计的演示文稿。** 有人直接对每张幻灯片进行样式设置，从未修改母版。现有的幻灯片即为设计规范：不要新建或更改母版。仔细观察一张具有代表性的已完成幻灯片（背景、字体、字号、颜色以及形状的样式），然后按照现有幻灯片的方式，在新幻灯片上逐一应用相同的样式，因为母版中并无可供继承的内容。

**全新或空白的演示文稿。** 在添加任何幻灯片之前，先在母版中完成整体设计：设定主题颜色、标题字体和正文字体、背景、默认文本颜色，以及加粗的标题样式。文本颜色应在母版的文本样式中统一设置，而非逐个形状单独调整。让各幻灯片继承这些设置，以保持全篇风格一致，并便于日后统一修改。凡属每张幻灯片都应出现的内容，如背景或公司标志，一律置于母版，切勿逐页复制。若该演示文稿面向某家公司，请遵循其品牌规范；如品牌规范不明确，可查阅相关资料。否则，依用户提供的信息为准，并自行补充其余部分。除非下方所选配色方案另有说明：

- 使用无暖调的浅白色背景（如#FAFAFA）搭配近黑色的文本，而非纯白与纯黑；
- 选用一至两种亮度相近的强调色；
- 确保整体风格与本次演示的主题相契合：季度回顾、商业提案和工作坊演示的视觉效果不应雷同，即便连续制作的两份演示文稿亦然。

请勿默认采用深蓝色背景。请根据内容选择合适的配色方案：

- **企业中性风：** 白色或浅灰色背景，一种饱和度较高的强调色，留白充足。适用于报告与提案。
- **温暖编辑风：** 米色背景搭配赤陶色或橄榄色强调色。适用于案例分析与叙事型内容。
- **大胆创业风：** 近白色背景搭配一种高对比度的强调色。适用于产品发布与商业推介。
- **学术低调风：** 类似纸张的白色背景，钢蓝与低饱和度的绿色，衬线字体用于标题。适用于研究与教学。
- **活泼明亮风：** 温暖的浅色背景搭配多种饱和度较高的强调色。适用于活动与创意类内容。

米色或米黄色背景（如#F5F5DC、#FAF0E6、#FAEBD7 或 #FFF8E1）仅适用于“温暖编辑风”，切勿将其作为默认选项。深色背景则适合作为标题页及章节分隔页的背景。

**已完成的幻灯片与未定稿的幻灯片。** 并非每一张现有幻灯片都能作为样式参考。判断一张幻灯片是否“未定稿”的关键在于格式是否尚未完善，而非内容本身：例如，文本框留空，或使用了系统默认字体与字号而非本演示文稿的规范；用一个空方框代替图表；字体与颜色与整篇风格格格不入等。若标题仅为“草稿”、“进行中”、“待定”或“占位符”，或幻灯片上贴有便签（如“周五前更新数据”），这都是需要进一步核查的信号，而非判定依据。在已设计好的模板幻灯片上使用填充文本或留空占位符，并不意味着该幻灯片未定稿；同样，旨在呈现不同风格的标题页或分隔页也不属于未定稿。请从已完成的、经过精心设计且彼此协调的幻灯片中提取本演示文稿的设计规范。如果所有幻灯片均为未定稿，则不存在可供参照的风格：此时，若演示文稿有自己的母版而非默认母版，请从母版中获取字体与颜色；其余部分则按本指南执行，并向用户说明这一情况。

未定稿的幻灯片在接到需求时仍需补充或修正，只是它们并非可直接照搬的样式范例。

## 文本

幻灯片中的文字应尽量简明。若内容超过一句话，请使用项目符号列表。- **标题使用粗体**，采用标题字体，且字号大于幻灯片上除大数字外的所有其他文字。如果标题使用常规字重，就会被误认为正文，从而导致幻灯片失去层次感。
- **结构清晰易读**。保持平行结构（全部为短语或全部为完整句子）。将读者理解信息所需的关键词加粗。每条要点控制在两行以内。
- **直截了当**。删去冗余词语（如“为了”“关键的”“非常”）。
- **使用主动、具体的语言**。选用具体名词和简洁动词：“客户流失了”，而非“我们经历了客户流失”。每句话都要明确主语。
- **前后一致**。标题与内容必须相符；若不一致，则其中之一必有误。
- **不要重复视觉元素**。要点应补充视觉无法呈现的内容。如果要点中的所有信息都能从图表中直接读出，则应删除该要点。
- **提供数据背景**。每个独立数字都应附带对比：与前期、计划或竞争对手的比较。根据决策需求确定精确度（如420万美元，而非4,183,207美元），并用比率或倍数（如“翻了一番”“五分之一”）来直观展示变化幅度。每张幻灯片的格式、单位和缩写应保持统一。
- **论断须经得起推敲**。每个主张都必须追溯到可验证的数据点，或基于清晰、逻辑严密的推导。若无法找到直接证据支撑，则不应提出该论断。当用户要求提供你没有的数据（如“加入我们的财务数据”）时，请向其索取，切勿凭空捏造数据。

当一张幻灯片需要大量文字时，可通过标注或辅助图形将其拆解。

## 图表

精心选择的图表能一目了然地展现一段文字需要费时描述的结构：例如示意图、流程图、时间轴、流程地图、组织结构图、漏斗图、金字塔图、二乘二矩阵、维恩图、循环图、路线图、前后对比图，或图标加标签的布局。

- **让图表形态契合理念**。序列可用流程图或时间轴，层级关系可用金字塔或组织结构图，重叠类别可用维恩图，权衡取舍可用二乘二矩阵，周期性过程可用循环图。若理念本身无固有结构，则不必强行赋予其形式。
- **一张图表只表达一个核心观点**。若需用一段文字才能解释清楚，则应简化图表。删减元素，直至几秒钟内即可看出重点；细节可移至辅助文本或后续幻灯片。
- **直接标注各要素，而非使用图例**。将简短标签（2–5个词）置于要素本身或其旁。较长的说明则置于图表之外。
- **为每种颜色、形状和大小赋予唯一含义**，并在图表内部及整套演示文稿中保持一致。用颜色突出关键要素，而非用于装饰；其余部分均采用中性色调。
- **按从左到右或从上到下的顺序呈现信息流**。箭头仅用于表示关系（如顺序、因果、依赖），而非装饰，且所有流向应保持单一方向。
- **通过尺寸与间距体现要素的重要性**。同等重要的要素应采用相同尺寸并均匀分布，对齐也应精确，而非大致对齐。

## 图片

图片必须承载信息。通用的素材照片还不如留白。只有当图片本身就是证据时才应使用，例如产品实拍、屏幕截图、地点、人物或前后对比。否则请勿使用。

- 观众会跟随画面中人物的视线，因此照片中的人物应面向内容，而非幻灯片边缘。
- 照片可以充满画面并进行裁剪。而屏幕截图或示意图则应以原比例完整呈现，且不得在其上叠加文字。
- 叠加在照片上的文字应置于卡片或深色背景带上，以确保可读性。
- 具有透明背景的图片需搭配与内容形成对比的底色，以便清晰显示边缘。
- 切勿拉伸或压缩图片以适应版面；应对其进行裁剪，或在中性背景上添加黑边。

## 图标每个要点旁的小图标能让读者在阅读前快速扫视，也是解决原本满是文字的幻灯片最简单的方法。当一页幻灯片包含三到六个并列项目（功能、类别、步骤、风险、团队等），且内容本身无需图表或示意图时，可使用图标：一排带标签的图标，或图标卡片组成的网格，比四条项目符号更易一目了然。对于文本过多又无法删减的幻灯片，图标还能为每个文本块提供视觉锚点。

- 每个要点配一个图标，且图标应直接传达该要点的含义：盾牌代表安全，时钟代表时间，图表代表增长。若图标需搭配标签才能理解，则只是装饰，应舍弃。
- 幻灯片内及整套演示文稿中的所有图标应风格统一（全实心或全轮廓）、大小一致（与文字并列时30–50pt；仅用于单个主视觉图标的除外），并沿同一行或网格均匀排列，位于其标签左侧。
- 图标颜色采用演示文稿的强调色或中性色，确保与背景有足够的对比度；切勿为每个图标使用不同颜色。将图标置于强调色的小实心圆内效果尤佳。
- 每个图标旁配简短标签（2–5字）；图标不能替代标签。
- 图标应取自图标素材库，切勿使用表情符号，因其在不同平台上显示效果各异。如无可用图标库，可使用带有简单象征性图形或数字的实心圆，并遵循上述规则。

## 表格

当读者需要跨多个维度查找特定数值，或比较少量对象的多项属性时，表格是合适的选择。若核心是比较单一信息，则应使用图表而非表格。保持简洁的样式，以便数字优先被读取。

- **边框：** 细线（1pt或极细），采用演示文稿的浅色边框（如白色背景下的#E0E0E0），仅在行间设置，且在表头下方加一条下框。不设列边框。完整的网格看起来像电子表格，而非幻灯片。
- **表头行：** 文本加粗，无填充。仅此处理即可。多数幻灯片工具的默认表格样式会添加彩色表头栏，反而显得未做设计。
- **行标签（第一列）：** 加粗并左对齐。
- **对齐方式：** 文本列左对齐，数字列右对齐以使数字位数对齐。单位标注在每个数值后（如“$42M”、“61%”；纯计数如355则无需标注），而非置于行或列标题，与柱状图标签规则相同。每列采用一种数字格式，或在按时间段划分的指标表中每行为一种格式。
- **高亮：** 作为重点的行或列可略施演示文稿的强调色底纹，其余部分不做任何处理。热力图应采用由浅至深的单一色调，切勿使用红—黄—绿的默认配色。突出单个单元格即可。
- **密度：** 整页幻灯片最多容纳约六列八行；超出时应拆分表格或移至附录。若某个单元格需三句以上或超过约40字，则过于密集：应精简至一句，将细节移至脚注或文本框，或拆分表格。
- **字号：** 自行制作的表格中文本至少14pt；若使用现有密度过高的模板，则保留模板原定字号。行高应宽松，单行约28–32pt，双行约48–56pt，且不使用斑马纹。搭建前务必确认整个表格能完整容纳于页面底部边距之上；否则应跨多页拆分。
- 应按真实表格形式构建，切勿用文本框拼凑。

人们阅读表格和图表的方式不同。表格通常先横向逐行读取，再纵向浏览，因此适合每位观众查找自己所在行的情境，例如区域销售中每位读者查找自己的区域。但在现场演示中，表格容易让重点淹没在细节里。将完整表格置于附录，可满足预习与提问需求。图表则能更快传递核心信息，更适合高管受众。请根据需求选择：用图表传递信息，用表格提供参考。

## 脚注与来源

脚注承担两项功能。首先是引用来源。如果某个数据来自外部研究或内部数据集，应在相关表述后立即标注上标数字（如“…增长12%¹”），并在幻灯片底部以相同的数字开头添加脚注，且脚注内容应足够具体，以便读者找到原始出处。务必注明出版方和日期，因为2021年的市场规模与2025年的市场规模是不同的论断。请在参考文字后添加超链接，而非直接粘贴原始URL。每张幻灯片的编号均从1开始；若整个演示文稿设有“来源附录”，则应在各张幻灯片之间连续编号。

其次是方法论与注意事项：详细说明那些对主要结论并非必需、但在他人质疑分析时至关重要的信息，例如样本量、排除项、汇率，以及“活跃用户”等术语的具体定义。应先列出方法论与注意事项，再注明数据来源，并以“来源：”开头。

在整个演示文稿中保持引用格式一致。脚注置于幻灯片底部，字号为10–12磅，颜色应偏淡。若幻灯片上的所有内容均来自同一份报告，则可用一行“来源：[报告名称，年份]”替代逐项脚注。

仅引用您实际掌握的来源，无论是用户提供的还是您自行查阅的。除非用户特别要求，否则不要在标题页之外添加“编制单位”字样、保密声明或日期。未掌握的来源即为虚构引用；用户自行提供的数据图表则无需标注来源。

## 尺寸、间距与布局

**视觉层级与尺寸。**读者的目光应首先落在标题上，然后是主视觉或加粗文本，最后才是细节信息。尺寸与字重决定了这一阅读顺序。由于幻灯片通常在会议室后排观看，因此在网页上看起来合适的字号在此处往往过小。在标准16:9比例的幻灯片中：

| 元素         | 尺寸       |
|--------------|------------|
| 幻灯片标题   | 32–40磅加粗，至少为正文字体的1.75倍以上 |
| 节标题       | 24–28磅   |
| 正文字体     | 16–18磅   |
| 图表说明     | 14磅      |
| 脚注及来源行 | 10–12磅，颜色偏淡 |

脚注、来源行、图表标签的第二行、图表年份行（11磅）以及图表标注（11–12磅）是唯一可使用14磅以下字号的文本，但有一个例外：某些模板的正文本身就较小，这在银行和咨询行业的演示文稿中较为常见。此时应遵从模板设定，因为与其追求最小字号，不如保持整体一致性，但字号不应低于10磅。请明确设置字号，而非依赖默认值。

**文本适配。**若按上述字号仍无法容纳全部内容，则说明单张幻灯片承载的信息过多。切勿通过缩小您撰写的文本使其勉强适应版面，而应调整容器大小、删减文字或拆分幻灯片。用户提供的文本应保留原意，其字号可适当缩小，若最终低于10磅，需告知用户。切勿让文本溢出框外或被截断。

**充分利用版面。**每边留出约半英寸的空白。在您自行排版的幻灯片中，应尽量填满版面（约占70%以上），充分利用宽度，并尽量延伸至下方空白区域，而非仅集中在上方。短列表下方留有少量空白并无不可，但若整张幻灯片几乎全是空白，则属不当。编辑现有幻灯片时，请尊重用户的原有布局，切勿为填补空间而随意调整。

**间距。**各内容块之间应留出0.3–0.5英寸的间距，并在整个演示文稿中保持一致。

**标题区。**在放置标题下方的内容之前，应先测量标题的实际高度，因为不同模板的标题高度各异，且内容起始位置应至少位于标题下方10磅处。

**内缩。**置于形状或卡片上的文本，应距形状边缘内缩10–15磅。文本紧贴容器边缘是最常见的排版小问题。

**对齐。**正文应左对齐，而非居中，以使幻灯片边缘整齐。标题的对齐方式依布局而定：标题页和节标题居中，内容页左对齐。模板自身的标题对齐方式始终优先。

## 杂乱、强调与多样性**杂乱。** 幻灯片上的每个元素都会消耗观众的注意力。凡是贡献小于代价的内容，一律删去；切勿为填充空白而填充空白。

**当幻灯片必须密集时的突出处理。** 有时，一张幻灯片或一张图表确实需要包含较多信息。你仍可通过引导注意力来传递核心信息。若某部分内容需要特别突出，且图例尚未为其分配颜色，则可使用色彩加以强调。对比也能传达变化，例如在实际数据转为预测数据的区域添加阴影。你可以圈出相关元素，或为某个不易察觉的关键点添加标注；标注应采用简洁的方框加线条形式，因为常见的标注图形效果不佳（图表上的标注请参考 `references/charts.md` 中的“标注”部分，且不加方框）。对于文字较多的幻灯片，可将匆匆一瞥时所需的关键词加粗，让观众在必要时再细读完整句子。

**多样性。** 最常见的失败模式是整套演示文稿中每张幻灯片都只有标题和一堆项目符号。现场观众不会逐字阅读屏幕上的段落，而十二张形状雷同的幻灯片也会让人产生视觉疲劳、难以区分。项目符号应占少数。如果超过三分之一的幻灯片都是项目符号型，那么其中一些本该以图表呈现的数据或比较关系被强行塞进了文本，另一些则是两张内容被硬挤在同一张幻灯片上。每张幻灯片只承载一个核心信息；若是项目符号型幻灯片，也只需几行简短的文字，通常三到四行即可。若内容需要一段完整的文字说明，则该页应作为预读材料而非幻灯片：将其拆分，或将细节移至附录。刻意调整节奏：两幅图表之后插入一个大数字，各部分之间加入深色分隔线，用图片页开启新章节。灵活运用不同类型的幻灯片，并每次都以统一的方式构建每种类型。

## 撰写幻灯片文案

这些规则适用于所有出现在幻灯片上的文字：标题、项目符号、标签、标注及脚注。

幻灯片文案应当读起来像出自真人之手。一旦读者认为内容是由AI生成的，无论其实际质量如何，都会觉得粗糙并失去信任。他们会根据一系列常见特征做出判断，如下所述，因此务必格外注意避免这些特征出现在你的文字中。- 只陈述事实，不要先否定其他内容。“收入增长12%，是美国增速的三倍”，而不是“这不是一个增长故事，而是一个市场份额的故事”。标题或要点开头不要用“关键在于”或“真正的情况是”。当幻灯片旨在提出问题时，标题可以用问句；若幻灯片本身已给出答案，则标题即为答案。
- 要点、示例和形容词的数量应与内容相匹配，而非固定为三个。两个驱动因素就列两个要点；五个则列五个，或以表格呈现。如果列举恰好三项（“快速、可靠且可扩展”），往往意味着第三项只是为了节奏而添加，并非因为确实有三点要说明，读者会将其视为填充内容。
- 不要用比喻来替代直白的表达。若有明确的描述（“相同的结构”“同样的模式”“放缓了”“下降了”），就使用这些措辞。比喻适用于直白表述过长或不够精确的情况，而这在分析性写作中很少见。检验方法：若能用一个普通词语替换比喻而不损失原意，就应替换。比喻会让读者将之还原为直白说法，并承载你并未刻意选择的含义。常见比喻包括：“北极星”“推动进展”“双击”（意指深入查看）“拆解”“旅程”以及“格局”（指市场）。商务写作中常见的还有：“护城河”“逆风”“拖累”（指对业绩的成本影响）“安全网”“达标”以及“落地”（指完成或总额，如“比预算低4.4万美元”）。例如：
  - 错误：“它拥有的都是同一种类。” 正确：“它拥有的遵循同样的模式。”
  - 错误：“一次协调一致的支出暂停会立即显现出来。” 正确：“如果多个大客户在同一季度削减资本开支，会在下一份指引中体现。”
  - 错误：“架构转型在进入阶段压缩了利润率，在退出阶段又使其扩大。” 正确：“毛利率在Hopper向Blackwell过渡期间下降，待Blackwell批量出货后才恢复。”
  - 错误：“解锁增长的杠杆。” 正确：“正是价格调整让目标得以实现。”
- 删去那些声称重要却未提供证据的词汇：“真正地”“确实”“实际上”“显然”“显著地”“稳健的”“杠杆作用”“深入探讨”“可执行的洞察”“经验教训”。若这些词只是用来代替某个事实，就直接写出事实（“利润率下降了4个百分点”，而非“利润率显著下降”）；否则就删除。
- 使用句号和逗号，并在列表前使用冒号。幻灯片上不得使用表情符号。
- 尽量少用破折号：每段最多一个，标题、主标题以及加粗标签与其后的文字之间均不应使用。一段中出现多个破折号往往是读者识别机器生成文本的首要标志之一。遇到这种情况，可用逗号、冒号、括号或另起一句来替代，切勿使用一字线或带空格的连字符。
- 内容页的标题应写成结论式表述（参见上文“信息：标题”部分），而非过程描述：“欧洲未达计划，差额190万美元”，而非“我做了哪些调整”或“难点所在”。结构性页面（议程、执行摘要、下一步、附录）则保留简洁的标签。
- 避免在演示文稿中加入对话式的语气。当用户要求更简短或更正式的版本时，就直接精简或调整风格，不要将其命名为“执行摘要（精简版）”，也不要在开头写“根据您的反馈进行了更新”或“本精简版聚焦于……”。受众并未看到相关需求，因此这些语句对他们毫无意义。应在回复中说明改动，而非在文稿中注明。
- 按照文稿已使用的语言变体撰写（如美式英语或英式英语），或在文稿尚无文字时采用用户的语言；切勿在同一份文稿中混用不同变体。

## 常见错误- **标题下方的装饰线。** 这是AI生成幻灯片的典型特征；建议改用留白或背景色来替代。
- **装饰性彩色条或强调条：** 幻灯片顶部或底部的横条、一侧的竖条、卡片一侧的细条，以及矩形单侧边框等，这些元素容易显得多余。若要突出某个卡片，可使用浅色背景底纹、柔和阴影或图标。
- **低对比度。** 图标和文字应与背景形成鲜明对比：避免浅色文字配浅色背景，或深色文字配深色背景。
- **仅对一张幻灯片进行样式设计，其余保持简洁。** 应将设计统一应用于所有幻灯片，或者让每张幻灯片都保持简洁。

# Slides连接器

本节介绍Slides连接器的相关功能：`read_presentation`、`read_slide_page`、`read_slide_page_thumbnail`和`update_presentation`。其中大部分行为已通过Google Slides API进行了测试；其余部分则通过连接器观察所得，尚有少数规则尚未验证。

## 设计规则的应用

设计规则已在上文列出。以下内容专门针对使用`update_presentation`构建时的注意事项。

- **构建新幻灯片。** 使用 `update_presentation` 构建新幻灯片时，应分两到三次调用，而非为每张幻灯片单独调用一次。首次调用时，填充标题幻灯片的占位符 `i0` 和 `i1`（通过 `insertText` 添加到 `build` 的输出中），并使用 `build` 插入第一张内容幻灯片，以便用户能尽早看到内容；其余幻灯片可在后续一到两次调用中逐步添加。每次调用均将该批次的所有幻灯片内容一次性处理。在每次调用前（包括首次调用）都先读取当前幻灯片，并将读取所得的 `revisionId` 传递给 `build`，正如 SKILL.md 中所强调的“先读后写，保护写操作”；用于检查某次调用幻灯片的读取结果，也可作为下一次调用的 `revisionId`。
- **默认版面的标题。** 上述字号同样适用于默认的 10 英寸宽版面，在该版面上，标题行所能容纳的字数少于更宽的幻灯片。根据 `build` 的估算，一个 9 英寸宽的框内以 32 磅粗体显示一行文字约可容纳 38 个字符，因此两行约含 75 个字符，大致相当于十二个单词。两行标题在 32 磅时所需的高度约为 1.3 英寸；若超过两行，则应删减文字而非缩小字体。当标题所需的行数超出框高时，`build` 会发出警告。
- **版式。** `build` 会按照规范指定的预定义版式创建每一张新幻灯片（若未指定则使用 `BLANK` 版式），并自行绘制文本框，而不填充版式的占位符。对于包含标题和正文且已定义版式的幻灯片，请按“编辑配方”中的占位符配方创建幻灯片，使标题和正文字体沿用母版样式，随后再使用 `build` 并设置 `"existing": true` 来添加表格、卡片和形状。对于完全由视觉元素构成的幻灯片，请使用 `build` 的 `BLANK` 版式，如上文所述的版式规则所示。
- **母版。** 本参考文档尚未提供更改幻灯片母版或主题的经过验证的方案，因此请跳过“从现有设计入手”中的母版相关步骤。在新建幻灯片时，确保所有幻灯片上的新增元素采用相同的字体和颜色，并为需要背景或徽标的幻灯片逐一添加背景或徽标。若需重新设计风格，则直接修改每一张幻灯片，并告知用户母版未作变更。
- **警告。** `build` 会对小于 14 磅的文本发出警告，除非其为页脚行——即高度不超过 0.5 英寸且距离幻灯片底部不超过 0.8 英寸的文本框。设计规范允许部分其他小号文本：图表标签的第二行、图表中的年份行及标注、非页脚行的来源说明，以及与模板中较小字号匹配的文本。这些警告可保留；其余警告则需予以修正。
- **字体。** 请使用 Google 字体，例如 Arial、Roboto、Lato、Montserrat 或 Merriweather 等。
- **表格。** 设置 `"header": true` 可加粗表头行。请勿设置 `header_fill` 和 `header_color`，因为设计规范仅要求表头行加粗，不涉及其他格式；对于数值列，应将 `"col_align"` 设置为 `"END"`。可通过在 `build` 请求之后追加 `updateTextStyle` 和 `cellLocation`（参见“编辑配方”中的表格部分）来加粗第一列，因为 `build` 会将表头以外的所有单元格设为非粗体。本参考文档尚未提供设置设计规范要求的仅针对行边框的方法：`build` 默认不设置任何边框，且目前尚未通过连接器测试任何边框请求，因此新建表格将沿用主题的默认边框。
- **图表。** 链接的 Sheets 图表外观取决于源 Sheets 中的图表，因此应在 Sheets 中按标准进行制作，具体参照 `references/charts.md` 中的规定：若整个演示文稿的图表风格统一，则采用该风格；否则采用公司内部标准。按照公司标准，图表标题应省略，并将其标签放置在幻灯片上方的文本框中。本参考文档尚未提供在 Sheets 图表中仅标注特定数据点，或绘制线端名称、年份行、标注或增长箭头的方法，因此建议将这些元素以文本框和形状的形式添加到幻灯片上，并在最终渲染后的幻灯片上校验其位置。

## 创建
根据幻灯片类型选择相应流程。- **设计好的演示文稿**：加载 `pptx` 技能，用它构建一个 `.pptx` 文件，并按照该技能的 QA 流程进行检查。然后使用 Drive 的 `create_file` 接口上传文件，让 Drive 自动完成格式转换。由于整个文件内容都包含在工具调用中，因此上传过程可能会较慢，且对于大型演示文稿可能失败。这样可以利用 `pptx` 技能的设计工具和质量检测功能。不过，转换过程中可能会改变字体和间距，因此请对转换后的结果再执行下文的 QA 步骤。
- **少量幻灯片，或向现有演示文稿中添加幻灯片**：使用 Drive 的 `create_file` 方法并指定 `contentMimeType: "application/vnd.google-apps.presentation"` 创建一个空白演示文稿（或打开现有演示文稿），然后通过 `update_presentation` 接口，结合下方的 `slides_helper.py build` 脚本进行编辑。新建的演示文稿默认会包含一张标题幻灯片，其占位符分别为 `i0`（标题）和 `i1`（副标题）。您可以填充这些占位符，或者使用 `deleteObject` 删除该幻灯片。

## 幻灯片的定位方式

- **单位为 EMU**：每英寸 914,400 EMU，每磅 12,700 EMU。默认的 16:9 页面尺寸为 9,144,000 x 5,143,500 EMU（即 10 英寸 x 5.625 英寸）。在放置任何元素之前，请先读取 `pageSize` 属性；某些演示文稿可能是 4:3 或自定义尺寸。
- **元素的实际大小等于 `size` 乘以其变换缩放系数**。API 经常以 3,000,000 x 3,000,000 的基准尺寸存储，并通过缩放显示：例如，一个宽度显示为 9.32 英寸的标题，其 `size.width` 可能报告为 3,000,000 EMU（约 3.28 英寸），而 `scaleX` 为 2.84。位置由 `translateX` 和 `translateY` 表示，即左上角坐标。在进行布局相关计算时，请务必先进行缩放乘法。
- **表格的尺寸由其列宽和行高决定**。表格的 `size` 字段并非其实际渲染尺寸，应通过累加 `tableColumns[].columnWidth` 和 `tableRows[].rowHeight` 来获取。由于行高会根据内容自动调整，因此最终表格的高度可能超过预期。
- **对象 ID 由您自行指定**。创建幻灯片或元素时，请设置 `objectId`：长度为 5 至 50 个字符，在演示文稿内唯一，允许使用字母、数字、下划线 `_`、连字符 `-` 和冒号 `:`，且必须以字母、数字或下划线开头。建议按幻灯片编号和用途命名（如 `s4_title`、`s4_chart`），以便后续同一批次请求以及后续操作能够准确引用它们。
- **形状或表格单元格内的文本有独立的索引**，从 0 开始。`textRange: {"type": "ALL"}` 可覆盖整个文本，是应用样式时最安全的目标。若使用 `insertText` 而未指定 `insertionIndex`，则会在文本起始处插入内容；若要追加文本，请传入文本的 UTF-16 长度（不包括读取时显示的末尾换行符）。与 Docs 不同，Slides 在遇到表情符号（如 🙂）时不会报错：它会将插入点移至表情符号之后，并使删除范围扩展到整个表情符号。

## 读取操作

- **始终传递字段掩码**。未使用掩码的读取操作会返回所有版式和母版信息，仅三张幻灯片的演示文稿就可能达到 150 KB。以下掩码仅返回编辑和辅助工具所需的信息，同样三张幻灯片的文件大小约为 5 KB：

```json
["revisionId,pageSize,layouts(objectId,layoutProperties.name),slides(objectId,slideProperties.layoutObjectId,pageElements(objectId,size,transform,shape(shapeType,placeholder,text.textElements(textRun(content,style.fontSize,style.bold))),table(rows,columns,tableColumns,tableRows(rowHeight,tableCells(location,text.textElements.textRun.content))),image.contentUrl,sheetsChart(spreadsheetId,chartId),line.lineType,elementGroup.children.objectId))"]
```

与 Sheets 连接器不同，Slides 允许在掩码中使用括号。
- **单张幻灯片**：使用 `read_slide_page` 接口，传入 `pageId` 和以 `pageElements(...)` 开头的掩码。
- **仅提取文本**：如果只需了解演示文稿的内容，可使用 Drive 的 `read_file_content` 接口，以紧凑格式获取全部文本。
- **带真实几何信息的轮廓**：将带有掩码的读取结果保存为文件，然后运行以下命令：

```
python <skill>/scripts/slides_helper.py outline deck.json
[3] 幻灯片 s4_slide  版式 BLANK
  s4_title   形状  x=0.50 y=0.35 w=9.00 h=0.70  文本框 32pt 'Revenue grew 42% year over year'
  s4_table   表格  x=3.70 y=1.30 w=5.80 h=1.20  2x3 表格，首行为 ['Metric', 'Q1', 'Q2']
  s4_note    形状  x=0.50 y=4.60 w=4.00 h=0.30  文本框 12pt 'This footnote is...'  !! 文本可能溢出（需额外 ~0.80 英寸）
```

它会标记页面上被移除的元素、相互重叠的框、可能溢出其容器的文本，以及空的占位符。“继承尺寸”表示字体大小来自布局，因此会跳过对该框的溢出检查。重叠标记意味着这些框发生了交叠；请查看渲染结果以确认内容是否真的发生碰撞。

## 构建幻灯片

使用 `slides_helper.py build` 命令，根据基于英寸的规格构建新的幻灯片和元素。该工具会将其转换为 EMU 单位，设置未缩放的变换，检查 ID，设置文本样式，填充表格，并对无法容纳的文本发出警告。

```json
{"slides": [
  {"id": "s4_slide", "layout": "BLANK", "index": 3,
   "elements": [
     {"id": "s4_title", "type": "text", "x": 0.5, "y": 0.35, "w": 9, "h": 0.7,
      "text": "收入同比增长42%", "size": 32, "bold": true, "color": "#1F2937"},
     {"id": "s4_card", "type": "round_rect", "x": 0.5, "y": 1.3, "w": 2.8, "h": 1.6,
      "fill": "#E8EEF7", "text": "ARR\n$4.2M", "size": 24, "bold": true, "color": "#1F3864", "align": "CENTER"},
     {"id": "s4_table", "type": "table", "x": 3.7, "y": 1.3, "w": 5.8, "size": 14,
      "rows": [["指标", "Q1", "Q2"], ["ARR", "$3.0M", "$4.2M"]],
      "header": true, "col_align": ["START", "END", "END"]}]},
  {"id": "s3_slide", "existing": true,
   "elements": [{"id": "s3_label", "type": "text", "x": 0.5, "y": 2.1, "w": 4, "h": 0.5,
                 "text": "已转化的试点比例", "size": 16}]}]}
```

```
python <skill>/scripts/slides_helper.py build spec.json --revision <revisionId> [--page 10x5.625]
```

输出包含用于 `update_presentation` 的完整请求和 `writeControl` 数据；警告信息会输出到标准错误流。在提交前应修复所有警告，除了那些“应用设计规则”允许的小字号警告。幻灯片不会自动缩小文本以适应空间，因此被标记的文本框仍会出现溢出。此外，该工具还会对小于 14 磅且并非位于幻灯片底部简短页脚的文本框或形状，以及带有类型化项目符号的文本发出警告。元素类型包括：`text`（文本）、`rect`（矩形）、`round_rect`（圆角矩形）、`ellipse`（椭圆）、`table`（表格）。对于文本元素，设置 `"bullets": true` 可将每行变为一个项目符号，而 `"space_below"` 则会在每个段落后面添加间距（约 8 至 10 点适合项目符号列表）。对于表格，`"col_widths"` 以英寸为单位设置各列宽度（给标题列比数字列留出更多空间），`"col_align"` 则对齐各列内容（数字列使用 `"END"` 对齐）。设置 `"existing": true` 可将元素添加到已存在的幻灯片中。如果演示文稿的尺寸不是 10 x 5.625 英寸，请使用 `--page` 参数。

## 编辑配方

每个配方都是单次 `update_presentation` 调用的一部分，其中 `writeControl.requiredRevisionId` 来自您上次的读取操作。

**全局更改文本。** 使用 `replaceAllText` 并指定 `containsText: {"text": ..., "matchCase": true}` 时无需提供 ID。可通过 `pageObjectIds` 限制仅修改部分幻灯片。模板中可使用 `{{placeholders}}` 实现此功能。

**替换某个框中的文本。** 先使用 `deleteText` 删除全部文本（`textRange: {"type": "ALL"}`），再从插入位置 `insertionIndex: 0` 插入新文本。新文本将保留原框的样式。如果尝试删除已为空的文本框，则会失败，因此请先进行读取操作以确认状态。

**使用版式中的占位符。** 使用 `createSlide` 并指定 `slideLayoutReference: {"predefinedLayout": "TITLE_AND_BODY"}`，同时通过 `placeholderIdMappings` 指定要填充的占位符：

```json
{"createSlide": {"objectId": "s2_slide", "insertionIndex": 1,
  "slideLayoutReference": {"predefinedLayout": "TITLE_AND_BODY"},
  "placeholderIdMappings": [
    {"layoutPlaceholder": {"type": "TITLE", "index": 0}, "objectId": "s2_title"},
    {"layoutPlaceholder": {"type": "BODY", "index": 0}, "objectId": "s2_body"}]}}
```

然后将文本插入到 `s2_title` 和 `s2_body` 中。占位符文本会沿用主题的字体和字号，从而保持整个演示文稿的一致性。预定义的版式包括：`TITLE`、`TITLE_AND_BODY`、`TITLE_AND_TWO_COLUMNS`、`TITLE_ONLY`、`SECTION_HEADER`、`BIG_NUMBER` 和 `BLANK`。使用自定义主题的演示文稿可能会为版式指定不同的名称；掩码读取会列出这些版式，而 `slideLayoutReference: {"layoutId": ...}` 则通过 ID 选择其中一种。请填充或删除您创建的每个占位符，因为空白的占位符会在编辑器中显示提示文本。

**项目符号。** 插入以换行分隔的行，然后调用 `createParagraphBullets`，并设置 `textRange: {"type": "ALL"}` 和 `bulletPreset: "BULLET_DISC_CIRCLE_SQUARE"`。手动输入的 `- ` 是普通文本而非项目符号，且 `createParagraphBullets` 会将手动输入的标记保留为文本，因此请在插入的行中不要包含此类标记。

**设置文本样式。** 使用 `updateTextStyle` 方法，并传入 `style` 参数以及相应的 `fields` 列表，例如 `"fontSize,bold,foregroundColor"`。字体大小的格式为 `{"magnitude": 24, "unit": "PT"}`；颜色的格式为 `{"opaqueColor": {"rgbColor": {"red": ..., "green": ..., "blue": ...}}}`，各分量值范围为 0 到 1。对齐方式是段落属性：使用 `updateParagraphStyle` 方法，设置 `style.alignment`（可选值为 `START`、`CENTER`、`END` 或 `JUSTIFIED`）。

**设置形状的填充和边框。** 使用 `updateShapeProperties` 方法，设置 `shapeBackgroundFill.solidFill.color`，并将 `outline.propertyState` 设置为 `"NOT_RENDERED"` 以移除边框。

**移动或调整大小。** 使用 `updatePageElementTransform` 方法，设置 `applyMode: "ABSOLUTE"` 并提供完整的变换参数。请注意，元素的基础尺寸不会改变，因此应将 `scaleX` 和 `scaleY` 设置为渲染后的尺寸除以基础尺寸。移动通常比调整大小更安全：如果要调整文本框的大小，往往直接删除并重新创建一个合适尺寸的文本框更为简便。

**表格。** `insertText` 和 `updateTextStyle` 方法支持指定 `cellLocation: {"rowIndex": r, "columnIndex": c}`。使用 `updateTableCellProperties` 方法并指定 `tableRange` 可以设置单元格的填充。`insertTableRows`、`deleteTableRow`、`insertTableColumns` 和 `deleteTableColumn` 用于更改表格结构。`updateTableColumnProperties` 方法可以设置列宽，单位为 EMU。

**从 Sheets 导入图表。** 调用 `createSheetsChart` 方法，传入工作表的 `spreadsheetId`、`chartId`（来自 Sheets 的 `addChart` 响应，或通过 `get_spreadsheet` 并指定 `fields: ["sheets.properties.title", "sheets.charts.chartId", "sheets.charts.spec.title"]` 获取）、`linkingMode: "LINKED"` 以及 `elementProperties`。链接的图表会与其数据保持关联；当工作表内容发生变化时，调用 `refreshSheetsChart` 可以更新图表。请勿将图表作为图片粘贴。

**图片。** `createImage` 方法需要一个 Google 可公开访问的 URL。对于本地图片，您可以先使用 `.pptx` 技能制作幻灯片并上传，或者提示用户自行插入图片。

**重新排序、复制、删除。** 使用 `updateSlidesPosition` 方法，传入 `slideObjectIds` 和 `insertionIndex`；使用 `duplicateObject` 方法复制幻灯片或元素（通过 `objectIds` 指定副本的名称）；使用 `deleteObject` 方法删除幻灯片或元素。请按演示文稿当前的顺序列出 `slideObjectIds`，否则整个操作将被拒绝；所列幻灯片会作为一个整体移动，并保持原有顺序。`duplicateObject` 会将每个副本紧接在原对象之后，因此多次复制同一张幻灯片会导致副本的顺序与您发送请求的顺序相反。若要在一次操作中按指定顺序生成多个副本：针对每个副本分别复制一次原对象，并按照所需顺序的逆序发送请求，这样最终副本就会按您期望的顺序排列在其后。随后填充内容。如果这些副本需要放置在演示文稿的其他位置，可通过一次 `updateSlidesPosition` 将它们作为一个整体移动，并按目标顺序列出。

## 幻灯片常见问题

| 症状 | 原因 | 解决方法 |
|---|---|---|
| 读取结果达到 100 KB 或以上 | 没有字段掩码，导致版式和母版一同返回 | 在读取时使用掩码。 |
| 元素位置或大小错误 | 使用了未经过变换缩放的基础 `size` | 对于实际几何形状使用 `slides_helper.py outline`，对于新元素使用 `build`。 |
| 表格尺寸与预期不符 | 表格尺寸由列数和行数决定，且行高会随文本增长 | 读取 `tableColumns` 和 `tableRows`；使用 `updateTableColumnProperties` 设置列宽。 |
| 文本溢出文本框 | 幻灯片不会自动缩小文本 | 可以扩大文本框、截断文本，或拆分幻灯片（“适配文本”提示中说明了允许使用更小字号的情况）。`build` 会在发送前发出警告。 |
| “对象 ID (ab) 长度不应少于 5”，或出现重复 ID 错误 | ID 过短、重复使用，或包含非法字符 | 使用具有描述性的 ID，例如 `s4_title`，且每个演示文稿中的 ID 应唯一。 |
| “未知的尺寸单位 UNIT_UNSPECIFIED” | 尺寸或变换未指定 `unit: "EMU"`，或新建形状未设置尺寸 | 为每个新元素提供完整的带单位的 `size` 和 `transform`。`build` 会自动处理这一点。 |
| 出现“单击添加标题”等占位符文本 | 占位符为空 | 填充或删除该占位符。`outline` 会标记此类情况。 |
| `createImage` 失败 | URL 无法公开获取 | 使用公开可访问的 URL，或使用 .pptx 上传接口。 |
| `deleteText`: “起始索引 0 必须小于结束索引 0” | 文本框中没有可删除的文本 | 当读取结果显示无文本时，跳过删除操作。 |
| `createSlide`: “占位符 (…) 不在页面上” | `placeholderIdMappings` 中指定了版式中不存在的占位符 | 仅映射版式中存在的占位符；`TITLE_ONLY` 版式中没有 `BODY` 占位符。 |
