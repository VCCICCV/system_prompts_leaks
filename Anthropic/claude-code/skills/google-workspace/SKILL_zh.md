# Google 文档、表格和幻灯片

Google 连接器是对 Google 原生 API 的轻量封装，自身几乎没有提供任何指导。本技能则提供了这些指导：每个连接器的作用、确保编辑保留在用户文件中的规则，以及在每个应用的参考文档中详细说明各 API 的实际行为。参考文档中大部分与应用相关的规则已在 Google Docs、Sheets 和 Slides 的 API 上进行了测试；其余部分通过连接器进行了验证，还有少数尚未校验。

## 操作文件前请先阅读参考文档

| 操作对象 | 首先阅读 | 为何重要 |
|---|---|---|
| Google 文档 | `references/docs.md` | 文档编辑会基于 UTF-16 编码的位置进行操作，而每次插入都会导致位置偏移，每次写入后该位置即失效。制表符和待处理的建议也会改变位置。 |
| Google 表格 | `references/sheets.md` | 两种写入工具都会像 Sheets 用户界面一样解析输入，因此文本可能被静默转换为数字或日期。格式化需要使用以 0 开始的数值型工作表 ID、范围和不含括号的字段掩码。 |
| Google 幻灯片 | `references/slides.md` | 位置以 EMU 为单位，元素的实际尺寸为其原始尺寸乘以缩放比例，未加限制的读取操作在三张幻灯片上可能超过 150 KB。幻灯片不会自动缩小文本以适应版面。 |

在对任务涉及的每个应用执行首次编辑前，请务必阅读其对应的参考文档。如果要在幻灯片中嵌入表格图表，则需同时阅读两份文档。这些参考文档篇幅较短，若跳过其中任意一份，就可能导致编辑落在错误的位置。

## 1. 开始前先检查连接器

| 连接器 | 功能 |
|---|---|
| Google 云端硬盘 | 创建文件、上传并转换内容、重命名、将文件读取为纯文本、导出（PDF 及其他格式）、搜索、放入回收站 |
| Google 文档 | 读取文档的完整结构并就地编辑，可直接编辑或以建议形式修改 |
| Google 表格 | 读取值与结构、写入值与公式、设置格式、添加标签页和图表 |
| Google 幻灯片 | 读取演示文稿、添加与编辑幻灯片、形状、文本、表格及链接图表 |

云端硬盘可以创建上述三种类型的文件，但创建后无法再编辑。如果没有配套的编辑连接器，每次更改都意味着生成一个新文件和新链接，用户将失去原有的链接。

1. 检查本次对话中可用的 Google 工具。在工具延迟加载的平台上，应先搜索并加载所需工具，例如“google sheets update”。不同平台上的工具名称可能不同，请使用所在平台列出的名称。若搜索无结果，在判断连接器缺失之前，请先列出所有可用工具，因为该工具可能以其他名称存在。
2. 如果缺少编辑工具，请告知用户。当您可以列出对话中的连接器时，请明确是哪种情况：要么是已配置但在当前聊天中关闭的连接器（请用户在聊天的连接器设置中将其开启后再继续），要么是根本未连接的连接器（告知用户应添加哪个连接器及其功能）。
3. 若缺少编辑连接器，创建新文件的请求将由云端硬盘代为完成；对现有文件的修改请求则会停止并提示用户。具体规则参见第 2 节的“缺失连接器”规则。
4. 如果用户仅要求创建新文件，请使用云端硬盘完成。若编辑连接器处于关闭状态，应在回复中注明后续编辑仍需启用该连接器。

示例：“我现在可以创建该表格。如果您之后需要修改，请先在本聊天中启用 Google 表格连接器。这样我才能编辑此文件，且链接保持不变。”

## 2. 每个文件的通用规则- **同一文件中的变更。** “变更”“更新”“修复”“添加”“切换为”等表述均意味着用户希望对同一文件和链接进行操作。切勿为了跳过编辑而重新创建文件。
- **缺少编辑器连接器是用户的选择，而非您的变通方案。** 当用户请求对现有文件进行更改，但编辑器连接器缺失时，您的整个回复应仅限于简短的提问，而非提供实际成果。即便您提供了次优方案，用户的原始文件仍未被触碰，反而产生了两个独立的产物，而这正是本技能旨在避免的错误情形。请先提出解决方案：告知用户所需的连接器名称，并说明启用该连接器后，编辑将直接应用到其现有文件中，且链接保持不变。您可以提供备选方案，例如草拟好的文本供用户粘贴，或手动导入的文件，但必须明确标注为可选项，并且仅在用户选择后才予以实施。完整回复示例：“要将幻灯片直接添加到您的演示文稿，请在此聊天中启用 Google 幻灯片连接器，我将为您完成操作。演示文稿不变，链接不变。或者，我可以将幻灯片以文件形式草拟，供您手动导入。您更倾向于哪种方式？”
- **切勿删除用户未要求删除的文件。** Drive 可以将文件移至回收站，但无法恢复已彻底删除的文件。文档、表格和幻灯片连接器均无法打开已被移至回收站的文件。
- **先读取再编辑，严守写入控制。** 每次读取文档或幻灯片时都会返回一个 `revisionId`。在下一次批量更新时，请将其作为 `writeControl.requiredRevisionId` 传递。如果两次读取之间文件内容发生了变化，整个批量操作将因 400 错误（“与最新修订版本不匹配”）而被拒绝，从而避免写入过时的内容。写回响应不会返回新的修订版本，因此在下一次受控写入前需再次读取。若遭拒绝，请重新读取并重建请求；切勿在未加保护的情况下重试。表格则有所不同：`references/sheets.md` 中的表格读取操作不会返回 `revisionId`，因此在写入表格之前需再次读取，并在不使用 `writeControl` 的情况下发送。
- **将单个步骤的所有操作合并为一个批次。** 批量请求按顺序原子执行：若其中一项无效，所有操作均不生效。每个逻辑步骤单独调用虽更快，却可能导致半成品状态。
- **验证结果。** 每次编辑后请再次读取文件，并在汇报前检查结果是否符合预期。工具成功接收请求并不意味着内容正确。每项参考文档均设有“验证”章节。
- **使用 Drive 的 `update_file` 进行重命名。** 重命名操作会保留原有链接。
- **为您命名的每个文件添加链接。** 当您创建、复制、找到或编辑了某个 Google 文件并为其命名时，请在说明操作的句子中将文件名设为链接，例如：“我已将该行添加至[团队名单](其链接)。”不要在冒号后或另起一行单独列出文件（如“我已为您创建了一个文件：团队名单”）。如果 Drive 返回的结果显示用户已可通过聊天查看或打开某文件，则除非用户主动询问，否则无需再次提供该文件的链接。当用户主动索要链接、希望将其转发给他人，或表示无法查看或打开该文件时，无论先前结果如何，都务必提供链接。除非结果明确提示，否则不要建议用户使用卡片或预览功能。编辑完成后，请告知用户链接保持不变。

## 3. Drive，适用于所有三个应用- **查找文件：**当用户未提供文件链接而仅给出文件名时，请使用云端硬盘的搜索功能。若匹配到多个文件，请与用户确认具体是哪一个。
- **创建：**调用 `create_file` 并将 `contentMimeType` 设置为 `application/vnd.google-apps.document`、`.spreadsheet` 或 `.presentation`，即可创建一个空文件。若上传包含源格式的内容（如 HTML、CSV、.xlsx、.pptx 等），系统会将其转换为对应的 Google 文档类型。各参考文档均说明了每种应用适用的创建方式。
- **以文本形式读取：**`read_file_content` 返回紧凑的文本表示——对于文档而言为 Markdown 格式。其大小通常只有几 KB，而编辑器连接器的完整读取可能超过 100 KB，因此建议先用此接口了解内容，需要获取位置信息时再使用编辑器读取。
- **导出：**调用 `download_file_content` 并设置 `exportMimeType: "application/pdf"`，可将渲染后的文件以 Base64 编码返回。此类文件体积较大（例如四页幻灯片约为 65 KB 文本），因此仅适用于视觉检查，且需在支持运行代码的环境中使用。

## 4. 辅助脚本

位于本文件旁的 `scripts/` 文件夹中存放着经过测试的辅助脚本。这些脚本能够将 API 的原始 JSON 转换为简明易读的摘要，并将简单的规范转化为正确的请求批次，从而避免人工进行繁琐的计算。凡是可以运行 Python 的地方均可使用它们。请在本技能目录下按完整路径调用这些脚本；参考文档中该目录记作 `<skill>`。

| 脚本 | 命令 | 用途 |
|---|---|---|
| `docs_index.py` | `outline`、`find`、`new-table`、`fill-table` | 获取文档中的位置信息、带加粗和建议状态的文本搜索、一次性添加并填充表格、填充已有表格 |
| `sheets_helper.py` | `range`、`format`、`cells` | 将 A1 表示法范围转换为网格范围、根据简要规范批量设置格式、读取公式及错误单元格 |
| `slides_helper.py` | `outline`、`build` | 处理幻灯片的真实几何布局并提示溢出与重叠问题、根据基于英寸的规范构建幻灯片 |
| `render_export.py` | 单个命令 | 将 PDF 导出解码为页面图像以便查看 |

**如何将 JSON 传递给脚本。**大型工具的输出结果通常由应用保存至文件，结果中会注明文件路径。请将脚本指向该路径；脚本会按应用保存的原样读取文件。若结果较小且随上下文返回（如掩码读取或表格元数据等，通常只有几 KB），则可先将其写入文件，再运行脚本处理。切勿手动将大型结果重新录入文件：这不仅会使成本翻倍，还容易引入复制错误。如果大型结果被截断且未保存，应改读较小的部分（如字段掩码、某个区域或单个工作表），而非凭猜测处理。

每个脚本都可通过 `--help` 查看完整用法。各参考文档也在相应上下文中列出了相关命令。

## 5. 各应用中的常见问题

| 症状 | 原因 | 解决方法 |
|---|---|---|
| “无此可用工具” | 工具尚未启用，或当前界面显示的名称不同 | 搜索并加载该工具，务必使用界面所列的确切名称。 |
| 对自己创建的文件权限不足 | 文件已被移至回收站 | 请用户从云端硬盘的回收站中恢复该文件。连接器无法执行恢复操作。 |
| 400 错误：所需修订 ID 不匹配 | 文件在读取后发生变更，通常是由于您之前的写入操作所致 | 请重新读取文件，根据新读取的结果重建请求，并使用新的修订版本提交。 |
| 整批请求因一条错误而全部失败 | 批量请求具有原子性 | 修正指定的错误请求后，重新发送整个批次。失败调用中的任何操作均未生效。 |
| 读取结果过大或被截断 | 未掩码的编辑器读取会包含所有内容 | 请改用云端硬盘的 `read_file_content`、字段掩码、指定范围或单个工作表。也可对已保存的结果运行辅助脚本。 |
| 用户预期只有一个文件，却出现两个 | 编辑操作通过创建新文件完成 | 请使用编辑器连接器直接在原文件上进行修改。告知用户多出的文件，未经许可请勿将其删除。 |

各参考文档末尾均列出了该应用特有的常见问题。

## 6. 连接器无法实现的功能当请求遇到这些问题时，请明确告知并提供替代方案。*已报告*：可通过连接器或其工具架构查看。*未测试*：尚未验证。

- **Claude 无法看到用户的屏幕。** 没有连接器能够显示用户当前选中的内容，以及他们打开的是哪个文件、哪个标签页或哪一张幻灯片。如果聊天中“这个”或“这里”的指代不明确，请询问用户具体指的是哪个文件、哪个标题、第几张幻灯片或哪个单元格区域。*已报告*。
- **评论：** 即使设置了 `commentsIncluded: true`，`read_doc` 仍然未返回任何评论。要读取评论，请使用 Drive 的 `read_file_content` 并设置 `includeComments: true`，或者请用户将评论粘贴过来。在一份报告中，`update_doc` 接受了 `insertComment` 参数，尽管其说明在列出该参数之前就截断了；如果该请求失败，请说明无法添加评论，并在回复中列出您的备注。*已报告*。
- **建议模式可能被拒绝**，提示“Unsupported WriteControl mode”。切勿在此模式下直接进行编辑：可选择列出拟议的修改，或直接编辑（参见 `references/docs.md`）。*已报告*。
- **请求列表被截断。** `update_doc`、`update_spreadsheet` 和 `update_presentation` 的说明在其请求列表中途就中断了。虽然描述中遗漏了一些请求，例如 `addDocumentTab` 和 `addChart`，但这些请求仍能正常工作，因此在判定不支持之前，可先尝试一次。*已报告*。
- **上传操作发生在调用内部。** `create_file` 需要以文本或 Base64 格式传入整个文件，因此上传 .xlsx 或 .pptx 文件既慢又容易失败。尽可能在编辑器连接器中直接构建文件，并尽量控制上传文件的大小。*已报告*。
- **图片需要公共 URL。** Slides 的 `createImage` 和 Docs 的 `insertInlineImage` 会从 Google 可访问的 URL 获取图片；无法通过聊天中的文件直接插入图片。如果是演示文稿，可推荐使用 .pptx 方式；否则请用户自行插入图片。*未测试*。
- **Slides 中的图表必须先在 Sheets 中创建。** 先在 Sheets 中使用 `addChart` 创建图表，再通过 `createSheetsChart` 将其嵌入到 Slides 中。*已报告*。
- **Drive 搜索使用 `title`，而非 `name`。** 使用 `name contains '…'` 会报错“Unsupported query field: name”；应改写为 `title contains '…'`，并将文件类型放在 `mimeType` 子句中。*已报告*。
- **对 Slides 的编辑可能不会立即反映在已打开的演示文稿中。** 如果用户未看到更改，请先让他们重新加载演示文稿，然后再进行其他修改。*已报告；可能已修复*。
