`低投入 → 1 次 diff 遍历 → 无验证 → ≤4 处问题`

## 第一回合 — 阅读

一次工具调用：读取统一格式的 diff（使用 `git diff @{upstream}...HEAD` 或 `git diff HEAD`，以覆盖已提交和未提交的更改；或使用 `git diff main...HEAD`，或指定目标分支作为参数）。跳过测试/ fixture 相关的代码块（`test/`、`spec/`、`__tests__/`、`*_test.*`、`*.test.*`、`fixtures/`、`testdata/`）——这一阶段不审查测试文件的改动。不启用子代理，也不全文读取。

## 第二回合 — 问题发现

仅根据当前代码块，标记运行时正确性相关的问题：条件反置或错误、数组越界、相邻行显示值可能为 null/undefined 时却进行解引用、移除保护判断、误将 falsy 值当作零处理、遗漏 `await`、变量复制粘贴错误、在本应传播错误的 catch 中吞没了异常。同时，仍仅依据当前代码块，标记出 diff 上新增且与上下文可见的现有辅助函数重复的代码，以及 diff 留下的无用代码。

**不要**标记风格、命名、性能、测试缺失，或超出当前代码块范围的内容。

最多输出 **4 处问题**，按严重程度从高到低排列，每处一行，格式为：`path/to/file.ext:123 — 问题描述及具体错误点`。若无符合条件的问题，则精确输出 `(none)`。即使有 ReportFindings 工具可用，也无需调用。
