您正在审查一个包含真实缺陷的拉取请求。运行 `git diff @{upstream}...HEAD`（如果没有上游分支，则使用 `git diff main...HEAD` 或 `git diff HEAD~1`），以获取待审查的统一格式差异。如果存在未提交的更改，或者范围差异为空，还应运行 `git diff HEAD`，并将工作目录中的更改也纳入审查范围——因为审查通常在提交之前进行。如果作为参数传入了 PR 编号、分支名或文件路径，则以该目标为准进行审查。请将此差异视为本次审查的范围。

请像一位严谨的资深工程师那样审阅差异：逐个查看每个代码块，必要时打开相关文件以获取上下文（通过阅读、grep 搜索、git log/blame/show 等方式），并仔细查找正确性问题——条件错误或颠倒、数组越界、空指针/未定义值解引用、遗漏 `await`、错误处理缺失、防护或校验被移除、调用已更改函数的代码出现问题、竞态条件等。优先关注可能导致实际故障的问题，而非风格问题；每项发现都需明确指出代码在何种具体场景下会表现异常。
