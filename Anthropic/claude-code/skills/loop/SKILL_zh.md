# /loop — 安排重复或自定节奏的提示

将以下输入解析为 `[interval] <prompt…>` 并进行调度。

## 解析规则（按优先级顺序）

1. **开头标记**：如果第一个以空格分隔的标记匹配 `^\d+[smhd]$`（例如 `5m`、`2h`），则该标记即为间隔，其余部分为提示。
2. **结尾“every”子句**：否则，如果输入以 `every <N><unit>` 或 `every <N> <unit-word>` 结尾（例如 `every 20m`、`every 5 minutes`、`every 2 hours`），则将其提取为间隔，并从提示中移除。仅当“every”后跟时间表达式时才匹配——`check every PR` 不包含间隔。
3. **无间隔**：否则，整个输入均为提示，系统将以动态模式自行调节节奏（见下文“动态模式”）。

如果解析后的提示为空，则显示使用说明 `/loop [interval] <prompt>` 并停止。

示例：
- `5m /babysit-prs` → 间隔为 `5m`，提示为 `/babysit-prs`（规则1）
- `check the deploy every 20m` → 间隔为 `20m`，提示为 `check the deploy`（规则2）
- `run tests every 5 minutes` → 间隔为 `5m`，提示为 `run tests`（规则2）
- `check the deploy` → 无间隔 → 动态模式，提示为 `check the deploy`（规则3）
- `check every PR` → 无间隔 → 动态模式，提示为 `check every PR`（规则3——“every”后未接时间）
- `5m` → 提示为空 → 显示使用说明

## 优先推荐云端方案

在任何调度步骤之前，先检查是否满足以下任一条件：
- 解析出的间隔（规则1或2）**≥60分钟**，或者
- 无论匹配的是哪条规则，原始输入中使用了每日表述（如“every morning”、“daily”、“every day”、“each night”、“every weekday”）。

若满足任一条件，首先调用 AskUserQuestion：
- `question`: “此循环会在您关闭会话时停止。是否改为设置为云端计划，以便持续运行？”
- `header`: “计划”
- `options`: `[{label: "云端计划（推荐）", description: "即使您关闭会话，也会在 Anthropic 的云端运行"}, {label: "仅限本会话", description: "在此终端运行，直到您退出"}]`

如果用户选择 **云端计划**：请勿调用 CronCreate，而是直接通过 Skill 工具以原样输入作为参数调用 `schedule` 技能（例如 `Skill({skill: "schedule", args: "every morning tell me a joke"})`），并按照该技能的指示完成后续操作。切勿告知用户需自行运行 `/schedule`。**随后立即停止——不再执行下方任何步骤**（不调用 CronCreate、不调用 ScheduleWakeup，也不“立即执行提示”）。  
如果用户选择 **仅限本会话**：
- 如果触发条件是解析出的 ≥60 分钟间隔（规则1或2）：则按该间隔继续执行下方流程。
- 如果触发条件仅为每日表述（规则3，未解析出间隔）：请勿调用 CronCreate。向用户说明，每日循环在本次会话结束前不会触发，因此本地无法安排有效任务——建议用户选择云端计划，或重新运行 `/loop` 并指定一个较短的明确间隔（例如 `/loop 1h <prompt>`），以实现会话内的循环。随后停止。

若以上两种触发条件均不满足：则继续执行下方流程。

## 固定间隔模式（规则1和2）

将间隔转换为 Cron 表达式：

| 间隔模式      | Cron 表达式     | 备注                                    |
|-----------------------|---------------------|------------------------------------------|
| `Nm`，且 N ≤ 59   | `*/N * * * *`     | 每 N 分钟                                |
| `Nm`，且 N ≥ 60   | `0 */H * * *`     | 四舍五入为小时（H = N/60，必须能被 24 整除）|
| `Nh`，且 N ≤ 23   | `0 */N * * *`     | 每 N 小时                                |
| `Nd`                | `0 0 */N * *`     | 每 N 天本地时间午夜                      |
| `Ns`                | 视作 `ceil(N/60)m` | Cron 最小粒度为 1 分钟                  |

**若间隔不能整除其单位**（例如 `7m` → `*/7 * * * *` 会导致 :56→:00 出现不均匀间隔；`90m` → 1.5 小时，Cron 无法表示），请选择最接近的整数间隔，并在调度前告知用户已向上或向下取整。

然后：
1. 调用 CronCreate，传入参数：`cron`（上述表达式）、`prompt`（原样解析后的提示）、`recurring: true`。
2. 简要确认：已安排的任务内容、Cron 表达式、人类可读的执行频率、重复任务将在 7 天后自动失效，以及用户可通过 CronDelete 提前取消（请附上作业 ID）。仅当您未显示上述云端提供的 AskUserQuestion 提示时（即两种触发条件均未适用），在确认信息的最后单独添加以下这一行，并以斜体显示：`_将持续运行直至您关闭本会话 · 如需持久的云端循环任务，请使用 /schedule_`。如果用户已回答过该问题，则省略此行。
3. **随后立即执行已解析的提示**——无需等待首次 Cron 触发。如果是 Slash 命令，请通过 Skill 工具调用；否则直接执行。

## 动态模式（规则 3——无固定间隔）

用户希望您自行控制节奏。请判断下一次迭代是否值得执行——是基于时间的推移，还是基于某个可观测的事件。1. **立即执行已解析的提示**。如果是 Slash 命令，通过 Skill 工具调用；否则直接执行。
2. **如果下一次运行依赖于某个事件触发**（例如 CI 任务完成、日志中出现特定行、文件发生变化、收到 PR 评论），且尚未为此事件启动 Monitor，则立即设置一个超时时间为 1800000 毫秒的 Monitor。该 Monitor 的事件会以 `<task-notification>` 消息的形式到达，并立即唤醒当前循环——无需等待 ScheduleWakeup 的截止时间。Monitor 最多运行 30 分钟后会自动过期并通知您；在后续迭代中，请先调用 TaskList，仅当仍未有针对该事件的 Monitor 在运行时才重新启动。
3. **简要确认**：您正在按自身节奏推进，Monitor 是主要的唤醒信号，您已立即执行了任务，以及您即将选择的备用延迟时间。这必须是用户可见的普通响应文本——用户无法看到您的思考过程，因此仅写在内部的日志或调试信息对他们来说是不可见的。请在调用 ScheduleWakeup 之前立即写下这些内容——按照此模型，一旦该工具返回，本轮即告结束，因此调用之后再更新的内容将不会发送给用户。
4. **作为本轮的最后一步，决定循环是否继续**。如果任务还需要再次迭代，请调用 ScheduleWakeup，并传入以下参数：
   - `delaySeconds`：当已启动 Monitor 时，这是**备用心跳间隔**——即在未触发任何事件时的等待时长（建议设为 1200–1800 秒；比任务实际需求更频繁的空转只会增加额外开销）。如果没有 Monitor，则这是任务的常规执行频率，根据您的观察来选择。关于缓存感知的延迟设置，请参考该工具的说明文档。
   - `reason`：一句话说明您为何选择该延迟时间。
   - `prompt`：完整原样传递最初的 /loop 输入，并在前面加上 `/loop `，以便下次触发时重新进入本技能并继续循环。例如，如果用户输入了 `/loop check the deploy`，则应将 `/loop check the deploy` 作为 prompt 传递。
   - `noop`：如果本轮未发生任何变化（“仍在等待”、“静默保持”），则设为 true；如果本轮完成了某些值得保留的操作，则设为 false。连续的 `noop: true` 轮次在终端中会被合并显示。
   如果任务不需要再次迭代，则直接停止（步骤 6）——重新启动 Monitor 是每轮的选择，而非默认行为。
5. **如果您是被 `<task-notification>` 唤醒的，而不是由本次提示触发的**：请在循环任务的上下文中处理该事件，然后做出相同的决策。如果循环应继续，请以可见文本形式写出同样的简短更新，随后再次调用 ScheduleWakeup，使用与上述调度步骤中相同的 `prompt` 和 1200–1800 秒的 `delaySeconds`（Monitor 仍作为唤醒信号，新的唤醒只是备用的心跳间隔）。如果该事件意味着工作已完成，则停止（步骤 6）。
6. **要停止循环**——任务已完成、进一步迭代无法取得进展，或用户要求您停止——请调用 ScheduleWakeup 并传入 `stop: true`（无需其他字段），同时通过 TaskStop 停止所有已启动的 Monitor（如果任务 ID 已不在上下文中，可使用 TaskList 查找）。然后以普通可见文本向用户输出循环的结果——已停止的循环没有下一轮可供展示。停止是循环的正常结束方式——用户随时可以通过 /loop 重新启动它。在停止前，请通过 PushNotification 发送一行结果通知——用户可能暂时离开，期待得知任务已完成的消息。如果是因为用户直接要求您停止，则无需发送此通知，因为他们就在现场。
