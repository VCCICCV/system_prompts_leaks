# 另存为 PDF

将当前的 HTML 设计重新排版为分页、适合打印的 PDF 文件。“即时”导出已按设计的原始像素尺寸向用户提供 PDF；而此路径则适用于用户需要真正分页的情况。

**切勿将页面栅格化为 PDF。** 绝不要使用 jsPDF、html2canvas、dom-to-image 或任何其他基于画布/截图的 PDF 生成方式——它们会生成模糊、不可选中且文件过大的结果，也不应自行生成 PDF 二进制文件。PDF 导出以打印为基础：一份可供打印的副本会被传递给 `show_pdf_export_dialog`，由浏览器自身的打印引擎渲染出清晰、可选中且基于文本的页面。使副本具备打印就绪状态的唯一支持方式是使用能够管理自身打印布局的组件——文档类的 doc_page 启动器，或已基于 `<deck-stage>` 或 `<doc-page>` 构建的源文件。请勿手动编写 `@page` 规则或打印 CSS 重置样式，也**绝不要**自行声明 `<meta name="omelette-owns-print">`——启动器会在运行时声明其对打印的控制权，而手动添加的元标签会指示平台信任您随后必须手动编写并维护的打印 CSS。在该元标签之后手写打印 CSS 是旧有做法；doc_page 启动器已在所有适用场景中取代了这一做法。

### 步骤

1. **读取当前的 HTML 设计文件**，以了解其结构和内容。每次请求 PDF 时都需重新读取，即使在此对话中之前已读取或生成过打印副本——用户可能自那时起修改了内容或调整了参数（“Tweaks”面板会直接写入源文件）。请注意读取结果头部中的 `[version: v<N>]` 标记——步骤 2 的来源戳记需要它，且只有本次请求中读取的版本才可用于标记。

2. **生成带有来源戳记的打印副本。** 始终根据刚刚读取的源文件全新生成——先前请求中已有的 `-print` 副本只是过时的快照，重复使用或仅部分更新都会导致过时的数据被写入 PDF。打印文件的路径是在源文件扩展名前插入 `-print`——目录与基名不变。例如，若源文件为 `slides/deck.html`，则打印文件为 `slides/deck-print.html`；若源文件为 `web/index.html`，则打印文件为 `web/index-print.html`。**切勿**以幻灯片标题或项目名称作为文件名，**切勿**在源文件位于子目录时将其写入项目根目录——任何目录层级的变化都会破坏所有相对 URL（`@font-face` 的 `src: url(...)`、`<img src>`、`<link href>`、CSS 的 `background: url(...)`），从而导致打印预览中出现图片缺失及系统字体回退。

   **为副本加盖来源戳记（只要读取头中显示版本号，此步骤的每个环节均需执行）。** 在副本的 `<head>` 中加入以下标记，其中包含步骤 1 读取头中的版本号以及源文件的项目相对路径（例如，对于读取头 `[File: designs/report.html] [version: v172]`）：
   ```html
   <meta name="omelette-print-source" content="v172 designs/report.html">
   ```
   如果副本缺少戳记或戳记与源文件当前版本不符，`show_pdf_export_dialog` 将拒绝导出——这正是过时副本无法导出的原因。若因副本过时而被拒绝，请返回步骤 1（重新读取源文件）并全新生成副本，切勿仅在现有副本上添加或修改戳记。如果读取头中未显示 `[version: ...]` 标记，则该项目未启用版本管理——此时无需加盖戳记，导出工具会跳过版本一致性检查。

   **如果源文件已基于 `<deck-stage>` 或 `<doc-page>` 构建，则打印副本只需在源文件基础上添加内容级别的打印规则即可。** 这两种组件均自主管理其打印布局——切勿额外添加 `@page` 规则或重新调整其布局。对于 `<deck-stage>` 幻灯片，需在**每个**直接子级幻灯片上设置 `data-deck-active` 属性（而不仅限于当前幻灯片），以便带有 `[data-deck-active]` 的入场动画样式能在每一页上正确生效——因为每张幻灯片本身即为一页。对于 `<doc-page>` 文档，则无需进行任何结构性调整。否则，请基于 `doc_page` 启动组件重新构建内容。调用 `copy_starter_component` 并传入 `kind: "doc_page.js"`（每个项目只需调用一次——该组件文件会持久化），然后在一开始就确定分页方式：采用流式文档（将内容作为一段正常的 HTML 流直接填充到 `<doc-page margin="0.75in">` 中，由打印引擎自动分页——这是报告、备忘录、信函及长篇文档的默认模式），或采用显式分页（每一页对应一个 `<section class="page">` 子元素——当用户要求指定页数，或设计本身暗示需要固定页数时使用：如单页简历、双面宣传单、证书、宣传册）。如有疑问，请询问用户。无论采用哪种方式，都应保持设计原有的排版、颜色和图像不变。对于流式文档，组件不固定纸张尺寸——打印引擎会根据用户实际使用的纸张进行分页。而采用显式分页的页面则按固定的页面盒打印，超出部分会被裁剪隐藏，默认为 letter 尺寸（若用户明确使用公制单位，则设置 `size="a4"`），导出时以用户选择的纸张为准；内容若超出页面盒范围，一律被裁切，绝不会重新排版——请确保每一页的设计都能填满页面盒，并同时适配 letter 和 A4 纸张而不发生重叠（不要使用视口单位——它们是相对于窗口而非页面的）。横向排版时使用 `orientation="landscape"`。组件负责管理整张纸、分页逻辑以及所有打印相关的几何布局——请勿自行编写 `@page` 规则、打印 CSS 重置样式、页面卡片容器、硬编码的纸张尺寸，或通过 `break-after: page` 模拟分页效果。在流式文档中，仅在某个章节真正开始新章节时才使用 `break-before: page`；对于较长的表格，请添加 `<thead>`，以便表头在每一页重复显示。

对于固定画布的设计（海报、社交类图形、信息图），同样需要通过 `doc_page` 组件重建，唯一的决定点在于“页面”的设定。您可以按其真实尺寸打印——例如 `<doc-page width="18in" height="24in" margin="0">`，此时页面即为设计本身（只有在用户明确给出或暗示实际物理尺寸时才使用显式的宽度/高度）；或者将其缩放到标准纸张上——例如 `<doc-page size="letter" content-width="960px" content-height="1440px">`（若用户明确使用公制单位则设置 `size="a4"`），此时内容按原稿尺寸排版，组件会将其缩放以适应该纸张的可打印区域。缩放适配是唯一需要指定纸张尺寸的场景：组件必须基于已知的纸张规格来计算缩放比例（在导出时，若可用，导出对话框会根据用户实际选择的纸张再次调整）。如果用户的需求在这两种方式之间不够明确，请在导出前以通俗易懂的方式询问清楚（是要按海报尺寸打印，还是缩放到普通纸张上？）。切勿自行通过 CSS 变换来手动缩放，无论哪种情况，缩放都应由组件统一处理。

在每次复制时，请加入颜色调整规则，使背景和颜色与预览一致——切勿去除设计中的背景：
```css
* { -webkit-print-color-adjust: exact; print-color-adjust: exact; }
```

将动画跳转至最终状态。切勿使用 `animation: none`（这会导致淡入效果恢复为初始的隐藏状态）。相反，应将所有动画冻结在其最后一帧，并禁用过渡效果：
```css
* { animation-delay: -99s !important; animation-duration: .001s !important;
    animation-iteration-count: 1 !important; animation-fill-mode: both !important;
    animation-play-state: running !important; transition-duration: 0s !important; }
```

3. 使用 `show_html` 预览并测试文件，确保没有 JavaScript 错误。除非另有要求，否则无需截屏。4. 使用项目相对路径调用 `show_pdf_export_dialog` 工具，传入可用于打印的文件。在调用该工具时，打印触发代码会自动注入到打印副本中——请勿自行编写自动打印或 `window.print()` 脚本。除非导出是由用户主动点击“导出”按钮触发的，否则该工具本身不会打开任何内容：它只会弹出一个导出对话框，只有用户在该对话框中点击“继续导出”后，才会打开打印预览界面。工具的返回结果会明确告知当前状态——如果结果显示对话框正在等待用户操作，则表示打印预览尚未打开，请务必如实说明，切勿声称已打开。如果文件（及其打印源）不具备打印条件，工具将失败并给出相应原因——第 2 步中的 doc_page 重建正是确保内容符合打印要求的关键步骤。

### 重要说明

- 目标是生成可在真实纸张上清晰打印的文件——分页由 doc_page 组件负责；您的职责是提供内容。
- 保持视觉一致性——确保设计的排版、颜色和图像效果完整无损。
- 对于 `<deck-stage>` 幻灯片，每张幻灯片单独占用一页；而 `<doc-page>` 文档则会自动流动并进行分页。
- 对于由提示驱动的导出，`show_pdf_export_dialog` 会等待用户操作：只有用户在导出对话框中点击“继续导出”后，打印预览才会打开，在此之前不会有任何内容被打开——请根据工具返回的结果如实报告当前状态，而非您期望的状态。
- `-print.html` 文件仅用于打印页面的内部处理，并非最终交付物——`show_pdf_export_dialog` 是唯一的交付环节。请勿将其作为下载项提供给用户；其相对资源路径仅通过项目文件服务器解析，独立打开时会失效。
