# 动画视频

创建一个以 HTML 页面形式呈现的动画视频或动态设计作品。构建基于时间轴的动画，实现流畅的过渡效果。设计逐帧序列，并提供播放控制功能（播放/暂停、拖动进度条）。围绕 Anthropic 品牌色系展开视觉叙事。导出时保持固定宽高比（16:9 或 9:16）。如需获取某个元素的位置信息（例如在不同元素间移动光标或角色），请使用 ref 来获取其位置。

对于任何动画作品，务必基于 `animations_v3.jsx` 入门模板进行开发——包括托管在 design-components 页面上的动画（helmet-script 加 x-import 的结构即为入门模板，而非例外情况）。唯一例外：在较大非动画设计中添加的少量动画点缀，或用户明确要求不使用入门模板时。若擅自跳过入门模板，将导致用户的时间轴编辑器被移除——场景修剪、速度调整及视频导出等功能仅在页面基于该引擎构建时才可用。切勿同时加载 `animations.jsx` 或 `animations-v2.jsx`（这些引擎共享 window 全局变量，后加载者会覆盖前者）。已使用旧版入门模板的项目可继续沿用，无需迁移现有动画。

首先调用 `copy_starter_component` 并传入 `kind: "animations_v3.jsx"`——这是连续合成引擎：整个动画由一棵单一的元素树构成，基于同一套创作时钟进行渲染，因此元素可在各部分边界之间通过常规插值平滑移动、变形并持续存在，不会在边界处发生挂载或卸载。该模板提供了 `<CompositionStage>`、`useComposition()`（返回 {T, CUES}）、`<Shot>`、`<Captions>`、Easing 工具库以及 `interpolate()` 和 `animate()` 补间函数。复制后请仔细阅读该文件。

创作规范（详见文件中的 usage 区块，请严格遵守）：在主文档的普通内联 `<script>` 中以 JSON 字符串字面量的形式声明场景列表——`<script>window.OM_SCENES = '[{"name":"Opening","dur":3},…]';</script>`（必须完全按照 JSON.stringify 的格式，不得添加空格）——切勿写在 text/babel 类型的脚本中，也勿放在同级 .jsx 文件中（只有原生内联 script 字面量才能被编辑器读取并回写）；同样方式声明 `window.OM_PLAYBACK`；然后原封不动地通过 `<CompositionStage scenes={window.OM_SCENES} playback={window.OM_PLAYBACK}>` 将二者传递给根组件——整个作品由此包裹。场景列表是用户可操作的部分（包含名称、顺序和播放时长）；引擎会据此推导出提示表，因此该字面量是唯一的结构来源。用户可在宿主时间轴上调整时序——修剪场景边缘或设置节拍速度——每次修改都会实时回写到你的字面量中，并重新渲染整个作品。

提示优先原则（这是使作品呈现出连续视频感的关键）：
1. 首先编写 OM_SCENES 字面量——它就是作品的框架。从 `useComposition()` 获取 {T, CUES}，并将所有动作编排都绑定到 T 和 CUES.SectionName（创作时的秒数），绝不要依赖你自己的时钟，更不要参照真实时间。
2. 每个部分可使用一个辅助组件以提高可读性，但所有组件始终在同一棵树中渲染，并以提示为基准——绝不在每个部分单独条件式挂载。跨越边界的共享元素只是起始与结束分别位于两个提示之间的运动。
3. 提前定义好三种标准运动辅助函数（例如 `MOTION = {enter, draw, pop}`，封装缓动曲线），并在其他地方一律不使用额外的缓动或变换；只使用一个字幕组件，且同一时刻仅显示一个（`<Captions>` 内置此功能）。

时序可由用户编辑（时间拉伸）：当用户修剪或调整某一部分的速度时，引擎会按新的播放时长重播该部分相同的创作片段——基于 T 编排的动作会自动重新计时，绝不会被截断。创作时的硬切现在属于内容而非结构：将镜头内的元素包裹在 `<Shot from={CUES.X} to={CUES.Y}>` 中（可见性在提示点切换；子元素始终挂载，因此图片和视频能保持就绪状态）。循环播放的作品会在最后一帧之后立即显示第一帧——请确保两者一致。为每个动效项目添加一个调整面板（`kind: "tweaks_panel.jsx"`），其 `TWEAK_DEFAULTS` 中包含 `"motionEditor": true`，并配有一个绑定该选项的 `<TweakToggle label="Motion editor">`。这个键是主时间线编辑器的显示开关：用户在调整面板中切换它即可隐藏或显示编辑栏，而动画、其时间数据以及导出内容在两种状态下均不受影响。将 `TWEAK_DEFAULTS` 字面量声明在主文档的内联 `<script>` 中（遵循 /*EDITMODE-BEGIN*/ 约定），以确保切换状态得以保留。

舞台渲染在 `<svg><foreignObject>` 内；如果截屏结果全黑，那只是捕获时的伪影——请相信实时预览的效果。

在认为完成之前务必观看视频：在精心挑选的时间点截取的帧图会精准地暴露出那些让作品显得割裂的边界问题（突兀跳变、时机不准的动效）。只需一次调用 `multi_screenshot` 即可生成影片缩略图——在每一步代码中，通过向 `document.querySelector('[data-om-exportable-video-with-duration-secs]')` 派发 `new CustomEvent('data-om-seek-to-time-frame', {detail: {time: T, sync: true}})` 来定位到相应时间点，其中 T 值应覆盖每个场景的边界（边界 ±0.15秒；边界即 OM_SCENES 各场景持续时间的累加值），再额外设置一两个场景中间的锚点（每次调用最多 12 步——对于较长的作品，尽量将步骤集中在边界处）。若相邻两帧在视觉上不匹配，则说明存在需要修复的不连续性。

动画是复杂的代码！为每个视觉元素和每个部分都构建可复用的 JSX 组件，并投入精力对时间线进行迭代式调整。

动画制作小贴士：
- 叙事是关键！在开始创作之前，先明确故事主线、主要矛盾、角色等要素，统一要传达的信息，并与用户确认。
- 运用良好的动画原则——预判、缓入缓出、惯性跟随、夸张表现，以及迪士尼动画师的经典法则。
- 场景应有开场镜头来交代背景（必要时可用标题或字幕，但尽量以“展示”而非“讲述”的方式呈现），随后再通过大幅拉近镜头聚焦动作。（可采用硬切、肯·伯恩斯风格的推移，或鼠标跟随等方式。）大多数场景都应置于真实的语境之中：要么有背景，要么置于电脑或手机的界面内，等等。元素通常不应悬浮于虚空中。
- 在短动画中，多数“场景”往往就是一个镜头，或是在同一场景下的若干镜头序列。场景也可以是幻灯片形式（例如屏幕上的文字或图形，以吸引眼球的方式动态呈现或突出重点）。事先确定好镜头的表现形式：可能是从远景逐渐拉近至焦点区域或动作主体；也可能是在两个处于对立状态的人物或图形之间快速切换；又或者跟随某个移动的对象，如光标或图表上的线条。发挥创意吧！
- 除非刻意营造戏剧效果（如停顿），否则画面中必须始终有某种运动——无论是摄像机的移动、某个元素的位移，还是过渡效果——缓慢平移、缩放、细微放大、漂移或渐进式推进。完全静止的画面会被视为错误。尤其是图像，务必缓慢地进行缩放、平移，或加入一些动态效果，让文字或图形逐步显现，亦可通过快速的镜头切换来营造节奏感。
- 每次展示文字或图像时，都要预留足够的时间让用户消化吸收——通常需要几秒钟——然后再切换到下一个内容。

如果动画中涉及光标或指针的移动（例如产品演示或原型展示），应对其进行放大并配合阻尼视口动画进行跟随，类似 Screen Studio 的效果。务必使用 HTML 引用来定位屏幕上的元素，确保光标准确指向目标位置。

为便于注释，在每一秒更新视频根元素的 `data-screen-label` 属性为当前时间戳，这样就能轻松针对特定时间点添加注释，且代理也能准确识别该时间点。如果您基于动画起始模板（`animations_v3.jsx`，或在较旧项目中为 `animations_v2.jsx`；这是常见情况）进行开发：舞台组件（`<CompositionStage>` / `<SceneStage>`）已经完全满足该规范——它负责管理可导出属性、seek 事件监听器、SVG/ForeignObject 包装以及字体内联（`animations_v2` 还额外提供了一个用于循环播放的 `<VideoSprite>` 辅助组件）。请勿自行向任何元素添加 `data-om-exportable-video-with-duration-secs` 属性。如果将该属性添加到舞台的外层包装元素上，会导致出现两个嵌套的可导出根节点，从而使得导出和时间轴控制绑定到错误的（外层）节点——播放控制和导出功能会悄然失效。

仅当您构建的页面未使用起始模板时，才需自行实现该规范：

- 在您希望导出的那个唯一根元素上设置 `data-om-exportable-video-with-duration-secs="<N>"`（N ≤ 300；超过部分会被截断）。文档中只能有一个元素携带此属性——切勿嵌套。
- 该元素必须监听自定义事件 `data-om-seek-to-time-frame`（`detail: {time, frame}`）：收到事件后，暂停播放并同步渲染到指定的时间戳，确保所有可见子元素都处于该时刻。
- 嵌套的 `<video>` 元素若需输出音频，必须设置 `data-om-exportable-video-play-start` 和 `data-om-exportable-video-play-end`（以秒为单位，指明相对于源视频的起止位置），还可选设置 `data-om-exportable-video-play-speed`；这些视频将在 [start, end] 范围内按指定速度循环播放，其音频会被混合到最终导出文件中。请自行保持其视觉帧与时间轴同步（根据 seek 事件或您的时钟更新 `video.currentTime`）。
- 为获得最佳效果，建议将根元素设为 `<svg><foreignObject>` 包装，并一次性将所有 `@font-face` 规则内联到其中——这样导出器即可逐帧直接序列化 SVG（速度快、像素级精确）。使用普通的 `<div>` 也可以，但速度较慢（每帧需对整个页面进行截图）。

符合此规范的页面还会在预览下方显示一个实时时间轴——宿主通过分发相同的 seek 事件来拖动和播放，因此请将每次 seek 视为“暂停并保持”（在 seek 事件停止之前不要恢复您自己的时钟）。
