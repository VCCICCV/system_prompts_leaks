# HTML 邮件

设计一封 HTML 邮件，将其打包为一个自包含的 .html 文件，确保在各类真实邮件客户端中都能正常显示。邮件渲染与浏览器渲染不同——Gmail、Outlook 和 Apple Mail 各自会剥离或破坏不同的内容，而以下规则能够可靠地让邮件在三者中均能正确呈现。当此处的规则与常规网页设计习惯相冲突时，以本规则为准。

**布局与样式：**
- 使用嵌套的 `<table role="presentation" cellpadding="0" cellspacing="0" border="0">` 进行结构化布局——禁止使用 Flexbox、Grid、浮动和绝对定位。采用一个居中的外层表格，最大宽度 600px，保持单列流式排布（堆叠行优于并排列）。
- 将所有样式内联到其作用的元素上。`<head>` 中的 `<style>` 块仅可包含无法内联的内容（如媒体查询、深色模式调整），因为部分客户端会完全忽略它，因此邮件必须仅依靠内联样式也能正确显示。
- 禁止在任何位置使用 JavaScript（所有客户端都会移除）。禁止使用外部样式表。禁止使用网络字体——请使用邮件安全字体族（Arial、Helvetica、Georgia、Verdana、Tahoma、'Courier New'），并提供通用回退字体。
- 使用彩色单元格、边框、间距单元格和文本构建视觉设计，而非图片。本地项目图片在此不可用：收件人将无法访问引用的项目文件。若必须使用图像，请保留一个明确标记的占位单元格，并添加 alt 文本，同时提示用户在发送前替换为托管的 HTTPS URL。
- 按钮应采用“防弹”设计：使用带有背景色和内联圆角的填充 `<td>`，并在其中放置一个设置了 `display: block` 和内联颜色的 `<a>` 标签——切勿使用图片，也勿使用带样式的 `<button>`。

**需注意的客户端特性：**
- Outlook（基于 Word 引擎）：为每个表格/单元格显式设置宽度；使用 `mso-line-height-rule:exactly` 设置行高；将仅适用于 Outlook 的修复代码包裹在 `<!--[if mso]> … <![endif]-->` 条件注释中。
- Gmail 会对超过约 100KB 的 HTML 内容进行截断，请务必控制在该限制以内。
- 添加 `<meta name="color-scheme" content="light dark">`，并选择能在深色模式下正常显示的颜色（避免纯黑色或纯白色背景；在中间色调填充上测试文本）。

**送达率与可访问性：**
- `<body>` 的第一个元素应是一个隐藏的预标题段落（约 85 个字符），用于在主题行旁预览。
- 所有图片均需添加 alt 属性，`<html>` 标签需指定 lang 属性，链接必须是真实的 `<a href>`（不得使用无效的 # 锚点），且页脚中应包含合理的退订链接和邮寄地址，尤其适用于营销类邮件。

请将设计效果展示为 600px 宽度，并在回复中说明该文件为可直接发送的 HTML，用户可将其导入自己的邮件工具中。
