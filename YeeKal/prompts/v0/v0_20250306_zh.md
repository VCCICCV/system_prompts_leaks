自 Next.js 13 起，`next/image` 组件经过重写，以提升性能和开发者体验。为提供向后兼容的升级方案，旧版 `next/image` 被重命名为 `next/legacy/image`。

## 对比

与 `next/legacy/image` 相比，新版 `next/image` 组件有以下变化：

-   去除了 `<img>` 外层的 `<span>` 包裹，改为使用原生计算的宽高比
-   增加了对标准 `style` 属性的支持
  -   移除了 `layout` 属性，改用 `style` 或 `className`
  -   移除了 `objectFit` 属性，改用 `style` 或 `className`
  -   移除了 `objectPosition` 属性，改用 `style` 或 `className`
-   移除了 IntersectionObserver 实现，改为使用原生懒加载
  -   移除了 `lazyBoundary` 属性，因为没有对应的原生实现
  -   移除了 `lazyRoot` 属性，因为没有对应的原生实现
-   移除了 `loader` 配置，改为使用 `loader` 属性
-   将 `alt` 属性由可选改为必填
-   将 `onLoadingComplete` 回调改为接收 `<img>` 元素的引用

## 必填属性

`<Image />` 组件需要以下属性。

### src

必须是以下之一：

-   静态导入的图片文件
-   路径字符串。可以是绝对的外部 URL，也可以是内部路径，具体取决于 `loader` 属性或 `loader` 配置。

使用默认加载器时，对于源图片还需注意：

-   当 `src` 是外部 URL 时，必须配置 `remotePatterns`
-   当 `src` 是动画图或非已知格式（JPEG、PNG、WebP、AVIF、GIF、TIFF）时，图片将以原样提供
-   当 `src` 是 SVG 格式时，除非启用了 `unoptimized` 或 `dangerouslyAllowSVG`，否则将被阻止

### width

`width` 属性可以表示渲染后的宽度或原始宽度（单位为像素），具体取决于 `layout` 和 `sizes` 属性。

当使用 `layout="intrinsic"` 或 `layout="fixed"` 时，`width` 属性表示渲染后的宽度（单位为像素），因此会影响图片的显示大小。

当使用 `layout="responsive"` 或 `layout="fill"` 时，`width` 属性表示原始宽度（单位为像素），因此只会影响宽高比。

`width` 属性为必填项，但静态导入的图片以及设置了 `layout="fill"` 的图片除外。

### height

`height` 属性可以表示渲染后的高度或原始高度（单位为像素），具体取决于 `layout` 和 `sizes` 属性。

当使用 `layout="intrinsic"` 或 `layout="fixed"` 时，`height` 属性表示渲染后的高度（单位为像素），因此会影响图片的显示大小。

当使用 `layout="responsive"` 或 `layout="fill"` 时，`height` 属性表示原始高度（单位为像素），因此只会影响宽高比。

`height` 属性为必填项，但静态导入的图片以及设置了 `layout="fill"` 的图片除外。

## 可选属性

除了必填属性外，`<Image />` 组件还接受许多其他属性。本节介绍 Image 组件中最常用的属性。有关较少使用的属性，请参阅“高级属性”部分。

### layout

图片在视口尺寸变化时的布局行为。

| `layout` | 行为 | `srcSet` | `sizes` | 有包装器和尺寸调整器 |
| --- | --- | --- | --- | --- |
| `intrinsic`（默认） | 缩小以适应容器宽度，最大不超过图片尺寸 | `1x`、`2x`（基于 imageSizes） | 不适用 | 是 |
| `fixed` | 精确按照 `width` 和 `height` 设置尺寸 | `1x`、`2x`（基于 imageSizes） | 不适用 | 是 |
| `responsive` | 缩放以适应容器宽度 | `640w`、`750w`、... `2048w`、`3840w`（基于 imageSizes 和 deviceSizes） | `100vw` | 是 |
| `fill` | 在 X 和 Y 轴上同时拉伸以填满容器 | `640w`、`750w`、... `2048w`、`3840w`（基于 imageSizes 和 deviceSizes） | `100vw` | 是 |

-   演示 `intrinsic` 布局（默认）
    -   当设置为 `intrinsic` 时，图像会在较小的视口上缩小尺寸，但在较大的视口上保持原始尺寸。
-   演示 `fixed` 布局
    -   当设置为 `fixed` 时，图像尺寸不会随视口变化而改变（无响应式），类似于原生的 `img` 元素。
-   演示 `responsive` 布局
    -   当设置为 `responsive` 时，图像会在较小的视口上缩小尺寸，在较大的视口上放大尺寸。

-   演示 `fill` 布局
    -   当设置为 `fill` 时，图像会同时拉伸宽度和高度以适应父元素的尺寸，前提是父元素是相对定位的。
    -   这通常与 `objectFit` 属性配合使用。
    -   确保父元素在其样式表中设置了 `position: relative`。

在上面的沙盒中，输入仅会更新 `message` 状态变量。从用户的角度来看，这本不应该影响聊天连接。然而，每次你更新 `message` 时，组件都会重新渲染。当组件重新渲染时，其内部代码会从头开始执行。  
在每次 `ChatRoom` 组件重新渲染时，都会从头创建一个新的 `options` 对象。React 会发现这个 `options` 对象与上次渲染时创建的那个对象“不同”。这就是为什么它会重新同步你的 Effect（该 Effect 依赖于 `options`），导致你在输入时聊天连接被重新建立。  
**这个问题只会影响对象和函数。在 JavaScript 中，每个新创建的对象和函数都被视为与其他所有对象和函数不同。即使它们内部的内容完全相同也无妨！**  
// 第一次渲染时const options1 = { serverUrl: 'https://localhost:1234', roomId: 'music' };// 下次渲染时const options2 = { serverUrl: 'https://localhost:1234', roomId: 'music' };// 这是两个不同的对象！console.log(Object.is(options1, options2)); // false  
**对象和函数作为依赖项会导致你的 Effect 比预期更频繁地重新同步。**  
因此，只要可能，你应该尽量避免将对象和函数作为 Effect 的依赖项。相反，可以尝试将它们移到组件外部、Effect 内部，或者从中提取出原始值。

const options = {  serverUrl: 'https://localhost:1234',  roomId: 'music'};function ChatRoom() {  const [message, setMessage] = useState('');  useEffect(() => {    const connection = createConnection(options);    connection.connect();    return () => connection.disconnect();  }, []); // ✅ 所有依赖项均已声明  // ...

# AI SDK 概述

AI SDK 是一个 TypeScript 工具包，旨在简化使用各种框架（如 React、Next.js、Vue、Svelte 和 Node.js）构建 AI 驱动应用程序的过程。它提供了一个统一的 API，用于与不同的 AI 模型协作，使将 AI 功能集成到你的应用程序中变得更加容易。

AI SDK 的主要组成部分包括：

1. **AI SDK 核心**：它提供了一种标准化的方法，用于通过大型语言模型（LLM）生成文本、结构化对象和工具调用。
2. **AI SDK UI**：它提供了与框架无关的钩子，用于构建聊天和生成式用户界面。

---

## API 设计

AI SDK 提供了若干核心功能和集成：

- `streamText`：这是 AI SDK 核心中的一个函数，用于从 LLM 流式传输文本。它非常适合交互式用例，例如聊天机器人或需要即时响应的实时应用。
- `generateText`：这也是 AI SDK 核心的一部分，用于根据给定的提示和模型生成文本。它适用于非交互式场景，或者当你需要为撰写邮件、总结网页等内容时使用。
- `@ai-sdk/openai`：这是一个与 OpenAI 模型集成的包，允许你通过标准化的 AI SDK 接口使用 OpenAI 的模型。

### 核心功能

#### 1. `generateText`

- **用途**：根据给定的提示和模型生成文本。
- **适用场景**：非交互式文本生成，例如撰写邮件或内容摘要。

**签名**：
```typescript
function generateText(options: {
model: AIModel;
prompt: string;
system?: string;
}): Promise<{ text: string; finishReason: string; usage: Usage }>
```

#### 2. `streamText`

- **用途**：从给定的提示和模型中流式输出文本。
- **使用场景**：聊天机器人或实时内容生成等交互式应用。

**签名**：
```typescript
function streamText(options: {
model: AIModel;
prompt: string;
system?: string;
onChunk?: (chunk: Chunk) => void;
onFinish?: (result: StreamResult) => void;
}): StreamResult
```

### OpenAI 集成

`@ai-sdk/openai` 包提供了与 OpenAI 模型的集成：

```typescript
import { openai } from '@ai-sdk/openai'

## 语言模型中间件

语言模型中间件是 AI SDK 中的一项实验性功能，允许通过拦截和修改对语言模型的调用，来增强语言模型的行为。它可以用于以与语言模型无关的方式添加安全防护、检索增强生成（RAG）、缓存和日志记录等功能。

```typescript
import type {
Experimental_LanguageModelV1Middleware as LanguageModelV1Middleware,
LanguageModelV1StreamPart,
} from 'ai';

export const loggingMiddleware: LanguageModelV1Middleware = {
wrapGenerate: async ({ doGenerate, params }) => {
  console.log('doGenerate 被调用');
  console.log(`参数：${JSON.stringify(params, null, 2)}`);

  const result = await doGenerate();

  console.log('doGenerate 完成');
  console.log(`生成的文本：${result.text}`);

  return result;
},

wrapStream: async ({ doStream, params }) => {
  console.log('doStream 被调用');
  console.log(`参数：${JSON.stringify(params, null, 2)}`);

  const { stream, ...rest } = await doStream();

  let generatedText = '';

  const transformStream = new TransformStream<
    LanguageModelV1StreamPart,
    LanguageModelV1StreamPart
  >({
    transform(chunk, controller) {
      if (chunk.type === 'text-delta') {
        generatedText += chunk.textDelta;
      }

      controller.enqueue(chunk);
    },

    flush() {
      console.log('doStream 完成');
      console.log(`生成的文本：${generatedText}`);
    },
  });

  return {
    stream: stream.pipeThrough(transformStream),
    ...rest,
  };
},
};

// 使用示例

import { openai } from '@ai-sdk/openai';

const wrappedModel = wrapLanguageModel({
model: openai('gpt-4o'),
middleware: loggingMiddleware,
});

const result = streamText({
model: wrappedModel,
prompt: '解释软件开发中中间件的概念。',
});
for await (const chunk of result.textStream) {
console.log(chunk);
}

          }
          setTime(0);
          setIsRunning(false);
        }, []);
