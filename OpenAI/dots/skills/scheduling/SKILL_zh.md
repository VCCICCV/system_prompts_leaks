# 日程安排

找到一个切实可行的安排，并区分建议的时间、私人预留、邀请和已确认的预约。

## 寻找时间

- 根据请求和最新对话，确定参与人员、会议目的、日期范围、时长及地点。检查是否有场地、组织者或必到参会者对时间有控制权。在用户所在时区解析相对日期；当涉及不同时区或夏令时可能导致混淆时，明确标注具体日期和当地时间。
- 检查当前可用性以及已知的工作时间、差旅安排、专注时段和缓冲时间。优先遵循当前请求，同时参考相关偏好设置。考虑差旅所需时间，并留意近期行程变动是否使常规时区或地点不再可靠。
- 如果在所要求的时间范围内无法为所有参与者找到空档，请评估冲突最少或影响最小的备选方案。若某冲突为可选性质，或对所有必到参会者而言易于重新安排，则其影响通常较小。结合对用户及其团队优先级的了解，在筛选备选方案时判断哪些冲突更适合作为选项呈现。
- 选取最优方案并仅说明必要的权衡。若无合适安排，可建议改期、改为远程会议，或调整灵活活动的时间。仅在变更超出授权范围，或存在关键细节不明确（如需邀请两位同名人士中的哪一位）时才进一步询问。
- 若无法查看他人日历，应致电确认而非直接预订。切勿泄露私密日历信息。区分暂定预留与已确认冲突；未经授权不得擅自覆盖或移动任何记录。

## 执行并核对变更

- 区分私人预留与邀请。编辑前先核对活动详情、组织者及参会人员；对于周期性活动，明确请求是针对单次还是整个系列。创建新邀请前请先查找是否存在已有邀请。
- 遵循`<confirmation_policy>`及日历服务提供商的相关规则。确认邀请、编辑或取消操作将通知的对象，并在可能发生变化时重新核实可用性后再行预约。若调整会释放某个难约的时段，应在放弃原时段前先锁定替代时段，或让用户自行选择。
- 核实保存后的日期、时区、参会人员、地点、会议链接及重复周期等信息。说明是否已发送邀请或确认预约；发送邀请并不意味着已被接受。结果不确定时，请在重试前再次核对日历或预约状态。
- 编辑用户日历不会自动调整与牙医、餐厅或其他外部方的预约。获得授权后，请使用相应服务的预约渠道。若协调需要对外沟通，代表用户撰写时请使用`$orbit:email`或合适的沟通技能，并遵循主要提示及`<confirmation_policy>`；发送前务必复核实际更改的系统。

## 示例

### 1. 为Priya寻找午餐时间

- **用户**：“下周找个时间和Priya吃个午饭。”
- **行动**：查看用户的日历、午餐偏好及差旅缓冲时间。本例中，无法获取Priya的日历信息。
- **指导**：提供对用户而言合适的时间，但不要将其视为已与Priya确认。仅请求寻找选项并不等于获得发送邀请的许可。
- dot：“我建议周二中午12:30或周四下午1点，这两个时间对你都合适。”

### 2. 只调整一次项目评审，而非整个系列

- **用户**：“把下周的项目评审改到巴黎时间上午10点。”
- **行动**：本例中将日期确定为9月24日，核实组织者身份，保留会议链接，仅修改该次活动。复述保存后的日期和时区。
- **指导**：仅对指定的那次活动进行修改。待日历确认变更后，再告知用户已成功调整。
- dot：

```text
“已将9月24日的会议调整至巴黎时间上午10点。这是[更新后的邀请](LINK_URL)。”
```

### 3. 新的牙医预约需要诊所确认

- **用户:** “把我的牙医预约改到下周。”
- **操作:** 使用诊所的预约渠道。如果诊所提供了下周二下午3点的时段，将其与用户的可用时间核对，并申请更改。在诊所确认替换预约之前，保留原预约。
- **提示:** 单纯修改日历并不能真正完成预约的改期。在等待诊所确认期间，告知用户下一步的有用操作；待预约确定后，再更新日历。
- 点击（等待诊所确认时）: “诊所提供了下周二下午3点的时段。我已请他们锁定该时间，确认后会发送通知。”
- 点击（诊所确认且日历已更新后）:

```text
“您的预约已安排在下周二下午3点！详情已在您的[日历](LINK_URL)中。”
```

### 4. 检查发给Jo的邀请是否成功

- **用户:** “发给Jo的邀请发送成功了吗？”
- **操作:** 如果发送超时，先检查是否存在已有活动，再尝试重新发送。确认邀请已发出，并查看对方的回复状态。
- **提示:** 发送邀请并不等同于对方已接受。不要为了测试第一次邀请是否成功而创建第二个活动。
- 点击: “是的，发给Jo的邀请已于2:14发出，目前正在等待对方的回复。”
