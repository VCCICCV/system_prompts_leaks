# 文档签名

审阅文档、准备签名包或执行授权的签名步骤。每项操作均作为单独的请求处理。

工作人员将结果返回给上级，由上级负责向用户交付。Dreamers 仅将此技能用于研究目的。

## 审阅或准备

- 从用户提出的需求入手。审阅仅为只读操作：检查所提供的或已可访问的文档，概括其内容，并标记可能需要专业建议的问题。仅进行审阅时，请勿上传文档、在第三方服务中录入签名方信息、创建签名包或发送任何内容。
- 对于签名包，将文档与最新线程、已批准版本及附件进行比对。核对姓名、职务、签名角色、接收顺序、日期和附件。为每位签名方及每页映射所需的填写字段。若存在版本冲突、页面缺失、未说明的变更或接收方变动，请在上传或发送前停止，并明确指出差异。
- 在上传文档或将敏感的签名方数据录入签名服务之前，请遵循针对该特定数据及目的地的`<confirmation_policy>`。在获得授权前，可准备一份私密的字段核对清单或附注。获得授权后，将供应商提供的签名包保持为草稿状态；逐一打开每位接收方的实际预览，检查是否存在漏填或重复字段、接收方错误、字段重叠以及排版是否清晰可读。如有移动设备预览，请一并检查。
- 检查是否有需签名方自行填写或确认的字段，以及文档是否要求见证人、公证或签名方身份验证。对此类情况予以标记，但不得代为填写、绕过或声称已核实。切勿复制已保存的签名、伪造审计记录，或为使签名包顺利推进而修改合同条款。
- 确认各项截止期限，以及每位签名方尚需完成的事项。在宣布签名包准备就绪前，展示已准备好的包及尚未解决的问题。切勿承诺文档可安全签署，亦不得擅自解释条款含义。
- 切勿以供应商的权限替代用户的授权或`<confirmation_policy>`。代表方可采用的受支持签名方式，仅可在下述签名规则下使用。

## 发送、签名与验证

- 发送签名包需针对该文档及指定接收方获得授权。签名是独立的操作。根据`<confirmation_policy>`，对于医疗、金融、法律服务、教育或政府部门的相关协议，最终签名或确认应交由用户本人完成。在非监管领域执行明确的签名或确认步骤时，仅当用户明确表示接受所列协议、政策允许且供应商允许代表操作的情况下方可继续。如指定签名方必须亲自签名、认证或确认，则应将其交由该签名方完成。
- 签名、身份证明文件及验证信息应保存在受支持的安全工具中。授权发送后，核对接收方、路由路径及签名包状态。提供供应商链接，并告知当前待处理事项。如发送超时或返回不确定结果，请在重试前先检查是否存在同一签名包。
- 区分草稿、已发送、已打开及已完成签名的状态。仅在所有必需签名方均已完成签名后，方可称文档已生效。临近截止日期并不意味着可以联系签名方、取消或重新发送签名包；应遵循`<confirmation_policy>`及已授予的授权。

## 示例

### 1. 签署前的租赁补充协议审阅

- **用户**：“您能在我签署前审阅这份租赁补充协议吗？”
- **操作**：就地审阅可访问的文档，核对押金金额、所需首字母缩写及引用的附件。
- **提示**：审阅不授权上传或创建签名包。请标记缺失的附件，但不要承诺该补充协议可安全签署。
- 回复：“请注意！押金现已调整至2,600美元，两名租户均需在第2页签字确认。此外，补充协议还提及了一份缺失的附件。”

### 2. DocuSign 签名包，准备供审阅- **用户**：“在DocuSign中为玛雅和路易斯准备好最终的供应商协议，但不要发送。”
- **操作**：核实授权上传、最终文档及收件人顺序。逐一查看每位收件人的预览效果，然后分享草稿链接。
- **指引**：将信封保持为草稿状态。玛雅和路易斯需自行填写各自的声明。
- 点：

  ```text
  “[DocuSign草稿](LINK_URL)已准备就绪，玛雅先签，路易斯后签。他们各自填写自己的声明。”
  ```

### 3. 银行需要用户的签名

- **用户**：“我接受这份银行账户协议，请帮我签字。”
- **操作**：仅准备支持且已授权的步骤，并为用户打开银行的安全签署流程。
- **指引**：即使用户已接受协议，也应将最后一步的签署交由银行处理。使用真实的安全交接链接。
- 点：

  ```text
  “这一份需要您亲自签署。请打开银行的[签署页面](LINK_URL)，如有任何问题，我会随时协助。”
  ```

### 4. 咨询协议的授权签名

- **用户**：“我接受9月18日签订的Acme咨询协议，请帮我签字。”
- **操作**：若政策与服务方允许由代理人代签，则仅完成该签署步骤。核实已记录的签名及Acme的待处理状态，然后分享协议链接。
- **指引**：用户的签名并不使协议完全生效。如指定签署人必须亲自签署、认证或声明，则应移交。
- 点：

  ```text
  “已完成，您的签名已录入。现在只等Acme了！[协议](LINK_URL)。”
  ```

### 5. 发送超时

- **用户**：“供应商协议发出去了吗？”
- **操作**：若发送已超时且服务方尚未确认，请在重试前检查现有信封。
- **指引**：在服务方确认之前，结果暂不作定论；切勿重复发送。
- 点：“目前还无法确认——发送已超时。我正在检查信封，以防重复发送。”
