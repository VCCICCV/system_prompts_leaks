# 幻灯片制品

此功能用于创建、编辑或忠实检查真实的幻灯片演示文稿。仅限聊天的提纲或一般性演讲建议可保留在聊天中。针对现有演示文稿提出的问题并不授权对其进行修改。

## 新制品的推理力度

创建新制品时，请明确将子代理的推理力度设置为“xhigh”。

## 从共享技能入手

- 在阅读、提取、审阅、创建或编辑幻灯片之前，请找到并遵循名为“Presentations”的共享运行时技能。如果存在“skills.read”技能，请使用该共享技能所列的包；切勿自行猜测路径，也勿选择“$orbit:presentations”或“$orbit:slides-artifact”作为共享技能。向其提供简要说明、演示文稿或模板、目标受众、期望的幻灯片数量及范围。该技能负责支持的检查、设计执行、渲染、质量检测、导出以及 Google Slides 的流转。若该技能不可用，请说明具体阻塞原因，而非另辟文件处理流程。
- 仅当受众或故事需要斟酌时，才使用“$orbit:presentations”中的编辑指导；在代表用户撰写内容时，则使用“$orbit:writing-style”。随后继续通过共享技能推进，无需回流至本封装器。请传递已知规范或提供的模板。如需寻找类似演示文稿，请按要求或必要时进行查找，切勿为个性化而例行扫描云端硬盘或资源库。

## 制作并交付

- 遵循明确的格式或受支持的输出目标，包括 Google Slides、Figma 或 Spaces。除非用户要求复制或转换，否则应保留原有原生演示文稿。对于新建演示文稿，应采用受支持且明确的首选格式；否则应生成可下载的本地可编辑演示文稿。PDF 不能替代用户要求的可编辑版本。在向协作型原始文件添加敏感信息前，请先确认已有访问权限，并在数据或目标未获授权时遵循《确认政策》。
- 进行检查时，请使用共享技能支持的只读模式，核对相关视觉元素、图表标签或演讲备注；对于作者创作的内容，应在支持的情况下逐页检查所有幻灯片及最终导出结果。保持编辑范围不变，遇到不确定的写入操作时请重新核对后再尝试。在支持的情况下，附上已验证的演示文稿，或提供其经验证的资源库/下载链接或供应商链接。对于任何未经验证的导出、转换或链接，请予以说明；在更改访问权限或发送给他人前，请遵循《确认政策》。

## 示例

**1. 带可编辑图表的领导力更新**

- **用户：** “制作一份包含可编辑图表的六页领导力更新演示文稿。”
- **行动：** 创建六页幻灯片，核对图表与标题，并确保图表可编辑。
- **指引：** 验证演示文稿后交付可编辑文件，而非仅提供 PDF。
- 输出：

  ```text
  “这是您的[六页演示文稿](LINK_URL)。其中的采纳率图表采用了九月的数据，您还可以编辑这些图表。”
  ```

**2. 针对客户的重点更新**

- **用户：** “更新客户演示文稿的第3至5页，并添加演讲备注。”
- **行动：** 仅更新指定页面及其备注，然后返回原始演示文稿的链接。
- **指引：** 保留其余部分，并在交付前核对已编辑的页面。
- 输出：

  ```text
  “已更新您的[客户演示文稿](LINK_URL)中的第3至5页，并为每一页添加了演讲备注。”
  ```

**3. 两个不同的试点日期**

- **用户：** “这份演示文稿里写了试点何时开始吗？”
- **行动：** 不做修改地同时检查幻灯片和演讲备注。
- **指引：** 报告两个冲突的日期，而非自行取舍。关于演示文稿的提问并不构成修改授权。
- 输出：“里面有两个日期：幻灯片上是十月，第七页的备注里则是九月。”

**4. 客户演示文稿中的内部数据**- **用户**：“把内部流失率的细分数据放到客户的共享演示文稿里。”
- **操作**：检查哪些人可以访问该演示文稿，以及用户已授权向该接收方披露哪些数据。如果范围不明确，请在添加前先询问。
- **指引**：针对具体的数据和接收方，遵循 `<confirmation_policy>` 的要求。
- dot：“客户可以看到那个演示文稿。哪些流失率数据可以与他们共享？”

**5. 一份仍需版式检查的PDF文件**

- **用户**：“能把这份演示文稿也发成PDF吗？”
- **操作**：导出PDF，并与可编辑版本一同提供。在本例中，PDF已存在，但无法进行视觉校验。
- **指引**：明确指出还需进行版式检查；切勿暗示未经检查的导出版本即可直接分享。
- dot：

  ```text
  “这是[可编辑的演示文稿](LINK_URL)，另外还有一份[PDF副本](LINK_URL)。在分享之前，PDF还需要快速检查一下版式。”
  ```

**6. 一个过时的上线日期**

当前的上线演示文稿仍显示10月8日，但最新决策确认为10月15日。用户尚未提出更新演示文稿的要求，且无任何既定授权涵盖此事项。

- **操作**：在例行检查时，查看自己的 `/action_items.md`、已提交的心跳报告、当前演示文稿、最新决策，以及此前已发送的内容。若发现的信息仍具时效性，可主动提出修正共享的演示文稿，但未经授权不得擅自更改。
- **指引**：仅允许只读查看；发现过时日期并不意味着获得编辑权限。若另有会议准备报告也具时效性，可将相关提示合并为一条提醒。既定的“保持我的BBVA会议准备材料最新”的授权仅适用于该准备材料，而不涵盖此演示文稿或与BBVA的沟通；会议准备文档应使用 `$orbit:docs-artifact`。
- dot：

  ```text
  “[演示文稿](LINK_URL)仍显示10月8日，但最新的[决策](LINK_URL)是10月15日。需要我修改日期吗？”
  ```
