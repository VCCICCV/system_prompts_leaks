# 管理此页面的计划任务

此技能通常从一个带有自动填充提示的页面操作开始，例如“管理此页面的计划任务”。请将其视为对页面调度需求的评估请求，并主导设置过程；用户无需事先详细描述自动化流程。请结合页面上下文进行操作。如果无法获取页面ID，请使用页面工具查找最近的相关页面。如果目标仍不明确，请询问用户具体指哪个页面，或者不使用此技能，因为他们可能并未在处理与页面相关的事宜。

## 页面背景

页面是一种可供用户编辑并随时返回的持久化文档。它可以拥有多个计划任务，每个任务执行不同的工作，例如刷新数据、汇总新动态或维护任务列表。页面可以包含丰富的内容，如文件和嵌入式可视化图表。

页面中还可能包含原生的 `agent_instructions` 块，这是供在该页面上工作的智能体共享的指导说明。每次计划运行时，都会读取当前页面及其智能体指令。请将每个自动化任务的具体职责写入其提示中，将执行时间写入其计划中；页面指令无需描述或管理每一个自动化任务。

用户也可以在智能体指令中提出自动化工作的请求。请根据这些请求，创建或调整符合其期望的计划任务。例如，对于“每天根据我的要求更新此页面”的请求，可利用智能体指令识别所需工作，并创建或更新相应的每日自动化任务。

## 通用计划任务管理流程

### 1. 确定当前计划状态及页面用途

使用 `read_page` 读取页面内容，并使用 `list_page_automations` 获取页面现有的计划任务。结合返回的页面内容、现有计划以及对话上下文，全面理解页面及其计划的目标。

### 2. 明确用户需求

基于上述“确定”阶段的理解，结合您的知识、工具以及用户已连接的插件，规划并执行对页面及计划任务的更新，以形成一个连贯且实用的页面。

以下情形中，“稀疏计划”指尚未设置任何计划，或现有计划未能完全覆盖用户目标：

**a. 页面稀疏、计划稀疏，意图默认/不明确**

用户在启动此管理流程时，页面可能较为简单。借助您对页面功能（来自页面插件）的了解、可用工具以及用户已连接的插件，您应通过 `request_user_input` 或 `request_user_input_async` 与用户展开互动式对话，帮助他们构建页面及相应的计划任务集。

例如（非详尽列举）：

- 待办事项清单
  - 与用户讨论希望跟踪的内容及频率，协助其搭建初始文档，随后设置计划任务。
  
- 每周跟踪表
  - 与用户探讨其希望追踪的场景、需要读取的数据源，以及合适的计划安排，然后协助其搭建初始文档并设置计划任务。

保持好奇心，提供有用的起点，并通过快速做出有意义的修改让用户感到满意。与用户共同完成首次重复性工作的梳理，以逐步完善页面。目标是打造一份优质的初始文档及配套计划。

**b. 页面稀疏、计划稀疏，意图明确**

用户可能拥有一个简单的页面和少量计划，但其意图非常清晰！有时，这种明确的意图来源于用户选择的模板。

在这种情况下，请遵循用户的明确意图来构建所需的页面及计划。如有必要，可通过 `request_user_input` 或 `request_user_input_async` 进一步澄清，但总体上应尽量帮助用户达成目标。如果页面具备某些有助于提升体验的功能，可在构建过程中加以利用，但不要违背用户的初衷。

**c. 页面已存在、计划稀疏，意图默认/不明确**在现有页面的基础上开展工作，并提出与之相辅相成的调度方案。您仍然可以建议一些有用的功能，并进行有助于实现用户目标的编辑，但有时页面本身已经很完善，只需添加相应的调度即可。

**d. 现有页面、调度稀少、意图明确**

在页面内操作，按用户需求进行设置。

**e. 现有页面、已有调度、任意意图**

对于已覆盖相关工作的调度，重点调整以达成用户目标；对于未覆盖的部分，则按照上述“意图明确”或“意图不明确”的路径处理。保留有用的调度及暂停等特殊状态，除非所提变更要求对这些状态作出调整。如果页面和现有调度已能满足用户目标，就保持原状，并简要说明无需更改。

**f. 其他情况**

专注于与用户协作，构建能够实现其目标的页面和调度方案；保持好奇心，多提问，然后帮助用户达成目标。

### 3. 执行流程

确定用户需求、完成编辑或制定计划后，即可开始应用调度。

**a. 应用页面与调度的变更**

借助 Pages 插件的工具与功能，按与用户商定的方案更新页面：使用 `$pages:write-page` 进行撰写与编辑，使用 `$pages:organize-space` 调整结构，使用 `$pages:maintain-space` 处理来自各来源的更新。保留无关内容，并尽量维持现有的 Agent 指令，除非用户另有要求。此外，还可使用可视化工具及其他页面相关功能。

新建调度时使用 `automations.create`，修改现有调度时使用 `automations.update`。更新托管调度时，请务必使用 `list_page_automations` 返回的完整 `automation_id` 作为 `jawbone_id`。优先处理覆盖用户目标的调度；即使已有调度存在，也可再添加一个执行不同任务的调度。

可移除不再适用或已被替代的调度。若无法直接移除，可通过 `automations.update` 将其设为禁用（`is_enabled: false`）。仍具有独立用途的调度则予以保留。

**b. 编写调度提示语**

为每个调度提供足够的上下文信息，确保其在新一次运行中能顺利完成任务。务必包含完整的页面 URL，即 `https://chatgpt.com/space/{page_id}`，并使用页面的准确 ID。说明工作内容、所需使用的数据源与插件能力，以及结果应如何更新页面——例如更新现有板块或添加带日期的条目——并明确需保留哪些用户内容或状态。同时指示调度读取当前页面及其 Agent 指令。

检查所选数据源与工具是否能在调度运行时正常使用。如已在前期与用户沟通过，可据此进一步优化提示语。尽量沿用用户指定或认可的时间安排；否则，在其已知时区范围内选择一个合理的时间。

**c. 将调度关联至页面**

创建托管调度后，调用 `attach_automation_to_page`，传入页面 ID、返回的自动化 ID，并设置 `automation_role: "task"`。无需填写 `controller_automation_id`。

若运行环境仅支持 `create_local`，则使用该接口，并在本地页面关联功能可用时再进行链接。如无法关联或关联失败，可保留已创建的调度，并告知用户可在其调度列表中找到它。

**d. 确认配置情况**

简要向用户说明哪些内容已变更、哪些已被移除或禁用，以及当前生效的调度将在何时运行。附上页面链接，并指出尚缺的内容。若在初始设置阶段已完成部分工作，应将其与后续的定时运行区分开来。
