# 远程环境

请勿将此技能用于软件工程相关工作。对于代码库调研、编码、调试、测试、产品 QA 或 PR/CI 相关任务，请改用 `$orbit:software-engineering` 技能，包括其环境选择指南。

在父节点中，可将此技能用于其他任务。如果您已经是该任务的指定执行者，请在所选环境中开展工作。

对于用户已选定环境的任务中的后续工作，请直接进入“跟进”环节，并保留其 `threadId` 和所选环境。

本技能涵盖 `cloud_threads.list_environments` 返回的两类集合：一类是 `environments` 中的现有用户计算机和已注册的远程主机；另一类是 `codingEnvironments` 中的个人及工作区共享的已保存编码配置。云端 Dot 计算机属于独立资源，不包含在此列表中。

## 决定工作地点

除非出现以下情况，否则所有计算相关工作均应在云端 Dot 计算机上进行：

- 用户明确要求使用特定环境或计算机，请遵照其指示。
- 用户特别提及位于其本地计算机上的文件或应用，例如“我电脑上的文件”或“我桌面上正在运行的应用程序”，则应使用用户的本地计算机。
- 浏览器工具的文档要求使用本地浏览器作为回退方案时，应使用用户已连接的计算机，并保留其明确指定的浏览器和环境设置。

仅提出云端任务的请求并不会切换至其他计算机，默认仍为云端 Dot 计算机。

## 发现并选择

- 调用 `cloud_threads.list_environments` 接口。请使用返回的名称、ID、连接状态及仓库信息，切勿自行编造 ID 或维护固定环境列表。
- 遍历两个集合。当需要查找目标配置或消除歧义时，按原样将 `nextCursor` 作为 `cursor` 参数传递以获取下一页数据。若需列出所有选项，请持续调用直至 `nextCursor` 为 null，包括遍历空页。同一台计算机的信息可能在多页中重复出现，但每台计算机只需列出一次。
- 根据“决定工作地点”部分选定的目标执行操作，并尊重用户的指示。“您的计算机”指云端 Dot 计算机；“我的计算机”、“我的 Mac”、“我的笔记本”指用户的本地计算机。明确命名的远程主机即指该远程主机。若有多条匹配项且上下文无法区分，请询问用户具体指哪一台。
- 当用户选择某个已保存的编码环境时，系统将基于该环境的配置创建一个全新的工作空间，使用其指定的仓库和初始化设置。若用户特别提及位于其本地计算机上的文件或应用，则必须使用该本地计算机。
- 如果请求的环境不存在、离线或不可用，请说明具体原因，并继续执行与该环境无关的工作，切勿擅自切换环境。编码配置目录为空仅表示未返回任何配置，并不意味着不存在任何配置。

## 创建任务

请使用简短的标题和自成一体的提示，明确说明期望结果、相关背景、目标仓库或目录、约束条件以及验证内容。子任务不会继承本次对话的内容。

| 目标 | `cloud_threads.create` 的参数 |
| --- | --- |
| 现有用户计算机或已注册的远程主机 | 传入其非空的 `environmentId`。该环境必须处于 `status: "connected"` 状态，允许 `attached: false`。 |
| 基于已保存编码配置的新工作空间 | 传入配置的 `id` 作为 `environmentConfigId`，而非 `version_id`。无需关联或连接用户计算机。 |
| 通过默认关联计算机使用用户本地计算机 | 仅在上述规则确定使用用户本地计算机后方可使用。省略上述两个选择器及 `cwd` 参数；必须且只能有一台用户计算机处于连接状态。 |

- 仅检查所选环境的先决条件。未连接或未附加的用户计算机不会阻止已保存的编码环境。
- 创建授权任务时，使用请求的目标选择器调用 `cloud_threads.create`。如果被阻塞，请说明该路径适用的指令或实际工具错误，不要根据其他计算机的状态推断启动限制，也不要凭空增加额外的附加或审批要求。
- 最多传递一个环境选择器。
- 使用 `environmentId` 时，可选择传递该计算机上的绝对路径作为 `cwd`；否则将使用其默认目录。更改 `cwd` 不会扩展写入权限。
- 使用 `environmentConfigId` 时，无需指定 `cwd`。存储库引用和初始化配置均来自已保存的配置。
- 发现操作不会附加或连接计算机。显式选择不需要更改父级的附加关系。创建时应尊重任何访问权限或功能可用性方面的错误。
- 连接状态不能反映浏览器或应用程序的功能。在承诺子任务能够运行浏览器或应用程序之前，应由子任务自行检查所需工具。

## 后续处理

- 成功创建后，任务已自动附加到对话中，无需再次调用 `cloud_threads.attach`。在有支持的任务链接时直接分享，无需提及任务卡片。
- 创建操作仅确认任务已被接受，初始化或执行可能仍在进行中。需要结果时请使用 `cloud_threads.read`，并通过子任务的完成通知来跟踪进度，切勿持续轮询。
- 继续相关工作时，请在同一 `threadId` 上使用 `cloud_threads.send_message`，这样可保持所选环境不变。
- 不要对不确定的创建操作进行自动重试。如果错误中包含 `threadId`，请先读取该任务，再发送后续请求。
